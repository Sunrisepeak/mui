# 格斗游戏的素材管线：生成的美术、分层骨骼、导演式演出、每个人的声音

日期：2026-10-29。起因：维护者评 1/10，codex 按[严格评分表](2026-10-29-fighting-acceptance-rubric.md)评 2/10（基线：`/tmp/r9/codex-grade0.md` 的结论摘在 §7）。原来的做法——几何体拼的人物、手写 TOML 关键帧、写“永”字的超必杀——到不了标准，这份文档换掉它。

维护者的决定：
- 素材通过框架和引擎制作，可以由 agent 或代码驱动（编曲也是）；codex 不只评分，也可以生成图片、通过 openas 用框架的工具制作素材，同时检验 agent 语义好不好用；
- 人物的美术是分层的（画师或生成的图层都走同一条管线）；
- 配音用授权或 CC0 的语音包，按人物处理。

## 1. 实验结论

codex 的图片生成做出的墨的设定图（全身、动态站姿、袍子的层次和朱红点缀、笔杆的细节）和分件图（头、躯干、上臂、前臂和手、裤子、绑腿和鞋、裙摆、袖子、笔）达到了格斗游戏主视觉的水准，远超代码写出来的矢量图。限制：一张平面图、背景不透明、关节需要整理、比例要核对。所以：**美术的来源是生成的图（或画师的图），框架负责把它们变成能动、能打、确定的游戏画面，以及制作和检查它们的工具。**

## 2. 管线

| 环节 | 做什么 | 框架里的能力（通用的放在通用层） |
|---|---|---|
| 设定 | 每个人一张设定图、三视图、表情、配色；codex 生成，按评分表审，定稿 | 工具记录提示词和版本（素材的来历可追溯） |
| 分件 | 在可抠的纯色背景上生成分件图；工具抠图、按连通区域切出部件、命名、定支点和关节的重叠 | `openmui.image`：WebP（`mcpplibs.mwrap.libwebp`，子代理在发布）、颜色键抠图、连通区域、裁边；工具：`gongfu-studio cut`（命令行 JSON + openmui 界面） |
| 绑定 | 部件放在骨骼上，网格（三角形）按权重蒙皮，关节处平滑变形 | 渲染器的**纹理网格**绘制命令（CPU 参考渲染器和 GPU 两条路径，确定性）：`DisplayList::draw_mesh` |
| 动画 | 每个招式的关键姿势（骨骼角度 + 部件替换图 + 网格形变），曲线、拖影帧、二次运动 | 已有的 hanim 曲线、替换图（`swap`）、跟随和悬挂；新增网格形变关键帧和 IK（脚踩地、手握笔） |
| 演出 | 超必杀是导演过的镜头：预备、特写插画（生成的大图）、冲击帧、粒子和光、收尾；每个人符合人物，不用文字图形噱头 | 时间线资源（`CinematicLook` 的镜头、路径、闪光扩展为插画面板、粒子发射器） |
| 特效 | 有设计的火花、冲击波、拖影：核心、半透明边、碎屑、衰减 | 粒子和特效资源（`*.effect.omui.toml` 和 Slang），生成的纹理做粒子的形 |
| 界面 | 人物立绘、选人、对阵、HUD 的设计语言 | 生成的立绘和装饰元素 + openmui 组件和风格包 |
| 声音 | 每个人的语音集（出招、受击轻重、倒地、超必杀台词、出场、胜利）来自 CC0 语音包，按人物变调、加处理；打击声按材质和轻重 | `openmui.audio` 读 WAV/FLAC/MP3（`mcpplibs.mwrap.dr_libs`）、按人物的音高和共振峰处理、随机变化 |
| 音乐 | 每个场景的曲子：代码写的乐谱（数据），合成器和鼓、混音；自适应层 | `openmui.audio` 的音序器（`*.music.omui.toml`），agent 或代码作曲 |

每个环节的工具都是 openmui 的应用：命令行（JSON、退出码）给 agent 和 CI，图形界面给人；codex 通过 `omui mcp` 用它们做素材，遇到的问题记下来改。

## 3. 确定性和体积

- 生成的图是输入，不在运行时生成；入库的是处理过的 WebP（有损，人物部件每张 ≤ 1 MB），解码逐位确定；
- 网格蒙皮在 CPU 参考渲染器里逐位确定（固定的三角形光栅化规则），像素照样固定在测试里；GPU 路径按容差比较；
- 提示词、来源、处理参数和生成日期写在每个素材旁边的清单里（`*.asset.omui.toml`），许可证明一起保存。

## 4. 先做什么（纵切：墨和霓）

1. 渲染器的纹理网格（CPU + GPU），WebP，`openmui.image` 的抠图和切分；
2. `gongfu-studio cut` / `bind`：从分件图到绑定好的外观；外观格式加图片部件和网格；
3. 墨和霓的设定、分件、绑定、关键姿势重做（codex 生成和审，我做绑定和动画，codex 通过 MCP 试用工具）；
4. 两人的受击、拼刀、击倒重做；超必杀重做成导演式演出（插画面板、镜头、冲击帧、粒子）；
5. HUD 和选人重做；
6. 两人的语音集、打击声、一首对局曲；
7. 按评分表评审（codex + 维护者），不到 8 分的项回去改。

## 5. 要注意的

- 生成的图的风格要统一：同一个风格描述、参考图、每个人一组固定的提示词；不一致的重新生成；
- 部件之间的关节要有重叠和遮挡的设计（肩、肘、髋、膝），否则蒙皮后有缝；
- 演出和特效不靠文字或符号做主角；
- 不把专用的东西放进通用层，也不为了单点方便打乱架构。

## 6. 和原来的东西的关系

模拟、回滚、帧数据、平衡、AI、训练模式、联机都保留；`gongfu.present2d` 的骨骼、片段、跟随和悬挂、替换图、场景文件保留并扩展；几何体部件留给 Kata（训练假人）。墨的“永字八法”三气和其他靠符号的演出删掉重做。

## 7. 基线评分（codex，2026-10-29）

总评 2/10：人物造型 4、骨骼动画 3、受击 3、超必杀 2、特效 3、场景 4、界面 3、声音 4、音乐 2、手感 5、玩法 5。最大的五个问题：占位的解剖和姿势；超必杀的编排（符号、钟、换背景撑不起演出）；接触在物理上看不清；没有角色语音和音乐；人物、场景、特效、界面像各自的原型。

## 8. 进度（2026-10-29）

- 第 1、2 步完成：`DisplayList::draw_mesh`；`openmui.image` 的抠图、切分、打包和 WebP（静图和动图，`mcpplibs.mwrap.libwebp`）；`gongfu-studio cut`（`--webp`）和 `picture`（抠图、裁边、缩放、编码）；外观的图片部件、`art_scale`、`fit`。
- 第 3 步（墨）：分件绑定到骨骼，网格在肘、膝弯折；新增**握持**（两骨 IK：后手握笔杆，双脚踩地，片段可松手、可迈步）和 **`aim`**（关键姿势按世界角度写）；44 个片段全部重做；笔头成为受击框的一部分；平衡门槛重新通过（墨 0.47–0.50）。
- 第 4 步（部分）：**特效是数据**——`[fx.<名字>]` 由精灵（缩放、旋转、淡出）、笔触（贴图沿曲线展开）、飞溅（种子决定的墨滴）组成，命中、飞行道具、片段和演出都按名字播放；**切入画面**（`[cutin.<招式>]` 在超必杀定格时、`[[cinematic.X.panel]]` 在演出中）；演出可以 `hide` 攻击者，让收尾插画顶替。墨的三气重做：眼睛切入、八刀墨痕、出招切入、收尾插画、砸地；“永”字、印章和字形飞行道具全部删除（飞行道具改成墨浪）。
- 发现并修复的框架缺陷：光栅器在裁剪区边界把边的端点夹住，使斜边在区域内倾斜（现在在边界处切开）。
