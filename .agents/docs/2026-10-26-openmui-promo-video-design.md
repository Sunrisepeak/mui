# openmui 宣传片设计：对标拆解、分镜与验收

> 状态：**草案 v0.1**（2026-10-26），待 review
> 对应：实施计划的 S5（D-51，本文档把时长调整为**约 60 秒**）
> 写法说明：播放量等数据来自公开报道（来源见文末），不同来源统计的口径和时间不同，只作为量级参考。

---

## 1. 目标

- **一部约 60 秒的 openmui 宣传片**（16:9，1080p60 和 4K60），另外剪一版 **15 秒短片**（16:9 和 9:16），中英双语字幕。
- **用 openmui-video 制作**；片中的每个镜头都是**实时渲染的 openmui 真实场景**，不是录屏。
- **由 agent 制作**（Claude Code + Opus，借助 `skills/openmui-video`），人负责提要求和审核。**完整的提示词和会话记录随片公开**。
- **质量对标**：2026 年用 agent 制作、播放量达到几百万到上千万的代码动画视频（§2）。

## 2. 对标拆解

### 2.1 三个标杆

| | A《西方文明 / PROMETHEUS》 | B Remotion Agent Skills 发布视频 | C《I'm Upping My P(doom)》音乐动画 |
|---|---|---|---|
| 作者 | @IterIntellectus（vittorio） | Remotion 官方（Jonny Burger） | John Heibel（另有多个高播放量的翻拍） |
| 发布时间 | 2026-09-24（Opus 5.5 发布两天后） | 2026-01-20 | 2026 年 9 月下旬 |
| 播放量（量级） | 24 小时约 580 万；3 天后超过 1200 万；后来的报道约 1500 万 | 最初几天约 600 万；目前帖子显示约 1880 万 | 原作在 X 上约 259 万；翻拍里有约 340 万、330 万、120 万的 |
| 时长 | 2 分 16 秒 | 短片 | 一首歌的长度，分成 9 个“彩绘章节” |
| 制作方式 | 据称“一次提示”完成；通常的做法是按场景写渲染代码（`renderAt(t)`），用无头 Chrome 加 FFmpeg 渲染 | 只靠给 Claude Code 写提示完成；**公开了完整的提示历史** | 两次生成都在 Claude Code 里完成，代码全部由模型生成；**源码开源**（仓库有数千 star），引来大量翻拍 |
| 视觉语言 | 黑底或旧纸上的**金色线描**；测绘图版和标题卡的版式；画面底部有一条时间轴在走 | 干净的紫色调讲解动画，转场流畅 | p5.js 水彩；一个吉祥物角色（Clawd）；每句歌词配一段画面和转场 |
| 结构 | 片头和片尾都是标题 PROMETHEUS（天体圆环里落下一团火）；中间按时代分章节：希腊哲学 → 罗马工程 → 文艺复兴 → 工业革命 → 走向星空；最后一个词是“ACCELERATE” | 用动画说明“这段动画就是靠提示做出来的”，最后给出安装命令 | 跟着音乐走：歌词和画面逐句对应，分章节推进 |

### 2.2 它们为什么能火：共同点

| # | 共同点 | 在三部作品里的体现 |
|---|---|---|
| F1 | **开头 3 秒就有钩子** | A 的火焰和圆环、C 的角色和第一句歌词，一出来就抓住人 |
| F2 | **统一的视觉语言** | A 从头到尾都是一种配色加一种线描；C 全片都是水彩 |
| F3 | **分章节的叙事结构** | A 按时代分章，C 按歌词分章；观众每隔几秒就能拿到一个新画面 |
| F4 | **跟着节奏走** | C 的画面完全由音乐驱动；A 有一条持续推进的时间轴 |
| F5 | **强烈的排版** | A 的标题卡、C 的翻拍里逐字同步的卡拉 OK 字幕 |
| F6 | **“这是 AI / 这个工具做出来的”这件事本身就是看点** | B 最直接：视频就是它所宣传产品的作品 |
| F7 | **可以验证、可以复刻** | B 公开了提示历史，C 开源了代码，于是有大量翻拍，形成二次传播 |
| F8 | **结尾有一个明确的口号或行动** | A 的“ACCELERATE”，B 的安装命令 |

### 2.3 拆解的方法（制作前完成）

1. **逐镜头记录**：用 ffmpeg 的场景检测（`select='gt(scene,0.4)'`）自动找出剪切点，再人工校对，得到镜头列表：每个镜头的起止时间、内容、镜头运动、转场方式。
2. **统计节奏**：平均镜头长度（ASL）、每分钟剪切次数、剪切点和音乐节拍对齐的比例。
3. **视觉要素**：提取调色板（每个章节取 5 种主色）、字体的使用方式（标题、正文、数字）、线条粗细、画面留白。
4. **动效**：记录主要的缓动方式（弹性、缓出、过冲）、错峰的间隔、镜头运动（推、拉、摇、视差）。
5. **产出**：一份拆解表，放在 `showcase/promo-video/research/`。**只做分析，不复制素材**，尊重原作者的版权。

## 3. 我们的宣传片

### 3.1 一句话的创意

**“这个像素知道自己是什么。”**（This pixel knows what it is.）

片子从**一个像素**开始，镜头不断拉远：像素 → 按钮 → 语义树里的一个节点 → 一个应用 → 一面无限的 Markdown 墙 → agent 正在读取这棵树。**一镜到底的拉远**是 openmui 无限画布独有的能力，作为全片的标志性镜头。

### 3.2 统一的视觉语言（对应 F2）

- **主风格：工程图纸**。深海军蓝的底色，线描加轻微的辉光，只用一种强调色（青色）。网格、尺寸标注、节点 ID 这些“图纸语言”贯穿全片，暗示“每样东西都有语义”。
- **字体**：Inter（拉丁字母）、Noto Sans CJK（中文）、JetBrains Mono（代码和 ID）。全部由 `openmui-fonts` 提供，保证渲染结果确定。
- **唯一的例外**：风格章节会**故意打破**统一的风格，依次切换五种风格包，最后再回到图纸风格。这个反差本身就是看点。
- **后期**：调色 LUT、轻微的胶片颗粒、运动模糊、2.5D 视差和景深。全部用 Slang 着色器实现，也就是在用 openmui 自己的能力。

### 3.3 配乐（对应 F4）

- 原创配乐，**约 120 BPM**；60 秒大约是 30 小节。剪切点、文字出现、强调动作都对齐到节拍上。
- 音效：点击、划过、确认提示音，和画面里的动作逐帧对齐。
- 节拍的时间点写在时间线里（`hanim` 的标记轨道），画面直接引用这些标记。
- 版权：委托创作，或者使用可商用的授权音乐；如果用 AI 生成音乐，要确认授权条款。

### 3.4 分镜（约 60 秒）

| 时间 | 章节 | 画面 | 用到的 openmui 能力 | 对应的共同点 |
|---|---|---|---|---|
| 0–3 秒 | **钩子** | 黑暗中亮起一个青色的像素；一行小字浮现：`button#save · role=button · effect=reversible` | 像素溯源、语义 | F1 |
| 3–9 秒 | **标题** | 镜头拉远：像素属于一个按钮，按钮属于一棵语义树；树的线条重新组合成 **OPENMUI** 字标，接一道扫光。字幕：“Agent 原生的现代 C++ UI” | 文本引擎、spring 解析解、效果着色器 | F5 |
| 9–19 秒 | **代码就是界面** | 左边逐字打出一段 TS，右边的界面随之搭建；之后代码依次“变形”成 C++、Python、Lua，**右边的界面一像素都不变**。字幕：“四种语言，一棵语义树” | 代码优先、S 级语义一致 | F3、F6 |
| 19–31 秒 | **无限**（标志性镜头） | 一镜到底地拉远：一个窗口 → 一个工作区 → 上千个 Markdown 窗口组成的墙；然后快速推近到另一个窗口。角落里显示帧率 | 无限画布、LOD、高帧率 | F3 |
| 31–39 秒 | **风格** | 同一个界面卡着节拍切换五种风格（玻璃、霓虹、CRT、水墨、液态），最后一拍回到图纸风格 | 风格包、Slang 效果 | F4 |
| 39–49 秒 | **Agent** | 语义树以动态图的形式展开；agent 的光标沿着节点移动、执行操作；遇到删除时弹出“需要确认”，旁边显示 `effect=irreversible`。字幕：“每个动作都知道后果” | agent 原生、效果分级 | F6 |
| 49–55 秒 | **时间** | 游戏片段：打砖块打到一半，**整部宣传片连同游戏一起倒流**几秒，然后接着往前播。字幕：“动画是时间的函数” | 动画是时间的纯函数、确定性回放 | F6 |
| 55–60 秒 | **结尾** | 画面收回到最初那个像素；打出命令 `mcpp new app --template openmui`；最后一行字：“这部片子由 agent 用 openmui 制作 · 源码见仓库” | 模板；片子本身就是证明 | F7、F8 |

**15 秒短片**：0–3 秒钩子 → 一镜到底的无限拉远（压缩到 6 秒）→ 风格卡点切换（3 秒）→ 结尾（3 秒）。

### 3.5 发布

- 帖子里写明：“这部片子由 agent 用 openmui 制作，完整源码和提示历史都在这里”，并附上链接（对应 F6、F7，参考 B 公开提示历史、C 开源代码的做法）。
- 宣传片的合成代码放在 `showcase/promo-video/`，**欢迎二次创作**：给出一份“换成你自己的产品”的模板。

## 4. 制作流程

| 阶段 | 内容 | 产出 | 里程碑 |
|---|---|---|---|
| 1 拆解 | 按 §2.3 拆解三个标杆 | 拆解表 | M4 开始前 |
| 2 脚本和分镜 | 定稿 §3.4；写文字稿和字幕 | 分镜表、字幕稿 | M4 |
| 3 动态分镜（animatic） | 用灰色方块和占位文字，按节拍把整部片子排出来，确定节奏 | 60 秒的动态分镜（**同时也检验 openmui-video 和 `hanim` 的原型**） | M4 |
| 4 风格帧 | 每个章节出 1 到 2 张定稿的静帧 | 风格帧 | M4 |
| 5 正式制作 | agent 用 `skills/openmui-video` 编写各个镜头；直接复用 S1、S2、S4 的场景 | 第一版成片 | M5 |
| 6 声音 | 配乐、音效、混音、对齐节拍 | 音轨 | M5 |
| 7 审核和迭代 | 按 §5 的检查清单逐项打分，至少两轮 | 定稿 | M5 |
| 8 发布 | 成片、15 秒短片、源码、提示历史 | 发布包 | M5 |

## 5. 验收标准

### 5.1 自动检查（进 CI）

| 项目 | 标准 |
|---|---|
| 时长 | 主片 60 秒 ± 5 秒；短片 15 秒 ± 1 秒 |
| 规格 | 主片 1080p60 和 4K60；短片 16:9 和 9:16 |
| 确定性 | 两次渲染的结果在 CPU 路径上逐字节相同，在 GPU 路径上处于容差以内 |
| 跳转一致性 | 随机抽 100 帧直接渲染，结果和顺序播放到那一帧相同 |
| 逐帧语义检查 | 零问题：文字不重叠、不出安全区、没有空白帧 |
| 阅读时间 | 每一行字幕在屏幕上停留的时间，不短于按字数算出的最短阅读时间 |
| 节拍对齐 | 标记为“卡点”的剪切和动作，和节拍标记的误差 ≤ 1 帧；音画同步误差 ≤ 1 帧 |
| 渲染性能 | 按实施计划 §12.6：完整渲染 60 秒 1080p60 ≤ 15 秒（GPU + 硬件编码），只用 CPU ≤ 60 秒；修改一个镜头后整片重新渲染 ≤ 3 秒，没有受影响的编码块 100% 命中缓存 |
| 编辑体验 | 预览里保存代码到画面更新 ≤ 100 毫秒；在预览里调整的属性写进 `promo.timeline.omui.json`，重新渲染后生效 |
| 字幕 | 中文和英文都齐全 |

### 5.2 人工检查（维护者签字）

**对标评分**：把成片和三个标杆（§2.1 的 A、B、C）**并排观看**，按下表逐项打 1 到 5 分。**每一项都不能低于三个标杆的平均分，总分不低于 4.0**。

| 维度 | 看什么 |
|---|---|
| 钩子 | 前 3 秒能不能让人停下来 |
| 叙事 | 章节是否清楚；看完以后能不能说出 openmui 是什么、有什么特点 |
| 视觉语言 | 是否统一；风格章节的反差是否有意义 |
| 排版 | 标题、字幕、代码的排版质量 |
| 动效 | 缓动、跟随和重叠、错峰是否到位；除了有意为之的地方，没有生硬的匀速运动 |
| 镜头 | 推拉摇、视差、一镜到底的流畅程度 |
| 节奏和音乐 | 剪切和动作是否卡在节拍上；声音设计是否加分 |
| 惊艳时刻 | 至少有 3 个让人想问“这是怎么做到的”的瞬间（一镜到底的无限拉远、代码变形而界面不变、整片倒流） |
| 结尾 | 口号和行动是否清楚 |
| 可传播性 | 15 秒短片单独看是否成立 |

**另外三项**：
- 每个镜头都确实在演示它对应的框架能力，没有“只是好看”的镜头；
- 制作过程（agent 编写、人审核）有完整记录，可以公开；
- 至少 5 位外部观众试看：看完以后能说出 openmui 的至少 3 个特点。
