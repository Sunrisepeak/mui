# omui 官网重构与质量收口实施方案

2026-11-03。**状态：维护者已要求开始高质量实施；品牌与标志按本次指示更新。** 官网品牌为 **omui**，**openmui 是规范，omui 是具体实现**。按 R0–R6 逐项实现、渲染与验收，不把已开始等同于已完成，也不把尚未通过的 C2 记为完成。

本文回应维护者指出的问题：官网设计、布局、美术、创意、简洁优雅、功能均未达标；文档和官网主体混在一起；组件页、动画页、创意组合尚未形成完整产品。目标是同时解决信息结构、视觉表达、可用功能与框架能力的缺口，而不是把当前页面换一种颜色。

## 0.4 2026-11-04 维护者补充：本轮执行硬约束

本节是维护者在实际使用后的最新要求，覆盖本文较早的导航、首页和首批数量建议；原有底层能力与 C2–C6 范围继续保留。

- **推进依据**：本地真实构建、运行、交互、渲染与内存检查优先。其他平台 CI 异步跟踪，不等待它们才进入下一项工作；未验证的平台单列，不冒充通过。
- **导航**：品牌回首页；“核心特色”收纳 UI 组件、基础动画、风格化、统一接口 × 多语言；“创意 demos”独立；“Agent 原生”提升为顶级，包含开发／使用／设计的原理、方法与场景；文档与开始使用另有入口。
- **首页**：降低复杂度，以简洁、优雅、创意构图说明框架。保留有辨识度的短主张和直观主演示；不再把完整任务工作台、所有技术视角及四段工具说明叠在首页。完整工作流移入对应特色页。
- **动态标志**：O 内含 mui 的几何仍由框架代码生成；导航与首页共用来源，提供组装／反馈等实际运动，尊重减少动态效果。静止时没有装饰性全站持续刷新。
- **特色页**：开头的可用演示直接呈现区别；随后提供分类、有界的动态样张。指针或键盘焦点进入预览区域后切换真实交互；只有明确“查看详情”才进入参数、编程语言、代码与更多说明。预览不通过 disabled 阻止使用，不让自动演示抢焦点；暂停、离屏和切页停止自动播放。
- **基础动画 ≥40 个**：按表面、变换、布局、选择、文字、数据、出入与节奏等意图设计，必须不同且可复用／组合；同一方块换颜色或缓动参数不重复计数。每项有真实端点、中间帧、打断／寻址和减少动态效果证据。
- **创意组合 ≥20 个**：明确组件 × 基础动画 × 风格化效果三维构成，每项有实际用途、可操作模型和独特镜头。风格必须命中真实效果绘制，不以 style 名称或配色替代；原六组旗舰配方继续保留，不能用新增基础组合关闭尚未实现的粒子／回溯／影片项。
- **组件默认动效**：每个组件依据类型、部件形状与用途选择默认配方；配方由内置可复用操作组合，组件仍只画状态。开关的轨道／滑块、勾选标记、选择指示、数值、焦点、层级展开与弹层出入不能全用同一个统一淡入。输入和拖动即时响应，风格覆盖、低档回退、off／reduced 及作用域隔离必须验证。
- **并行方式**：已按维护者授权创建独立 worktree，分别实现 40 个基础动画、20 个创意组合、组件馆重构；根工作树负责共享播放／默认配方／导航／首页整合。本地构建限制并发和磁盘占用，合入后集中验收，最终提交仍追加到 PR #1。

数量只记录实际实现与实际验证，两者分列；不能先把目录条目计作完成。每个组件与配方交付默认／交互／细节的中英关键图或连续帧，动态 WebP／真实浏览器预览辅助维护者 review。

## 1. 目标与访客路径

官网必须同时完成三件事：**让第一次来的访客看懂并愿意继续探索；让开发者快速找到可用能力；让感兴趣的人把效果带回自己的程序。**

| 访客 | 主要路径 | 完成标志 |
|---|---|---|
| 第一次了解的人 | 首页 → 一个真实交互 → 一个精选组合 | 能说清框架的用途和至少两项特色；无需先读 API |
| 找 UI 能力的开发者 | 组件／动画／效果馆 → 一个详情 → 带走样例 | 找得到、试得动、复制后能复现 |
| 想创作的人 | 精选组合 → 实验室 → 修改 → 导出 | 导出的代码或数据在干净工程复现相同结果 |
| 已在使用的开发者 | 文档 → 搜索 → 指南／API／错误排查 | 有版本与深链接，按步骤完成实际任务 |
| 自己带 agent 的访客 | 接入入口 → 配对 → 自检 → 任务 → 查看／撤销记录 | 自己的 agent 完成任务，用户知道改了什么并能恢复 |

每个主要页面在正常浏览状态下只承担一个主要任务。源码、参数、树、哈希、性能细节按需展开；连接状态和待确认动作始终可见。简洁通过组织信息实现，不能靠删掉功能或藏掉错误实现。

## 2. 信息结构：官网主体、创作空间、文档分开

### 2.1 导航与页面职责

主导航为：**核心特色 · 创意 demos · Agent 原生 · 文档**，右侧“开始使用”；品牌回首页。“核心特色”下收 UI 组件、基础动画、风格化、统一接口 × 多语言；Agent 原生页提供使用／开发／设计三种场景。语言、设置与“连接我的 agent”是工具入口，窄屏收进菜单。详见 [本轮细案](2026-11-04-omui-site-navigation-motion-execution-design.md)。

这是信息层级收拢，原有实验室、场景和作品范围全部保留。未完成的路由留在内部验收清单，不向普通访客展示空壳入口；最终范围仍按 C6 全部验收。

| 区域 | 职责 | 默认呈现 | 下一步 |
|---|---|---|---|
| 首页 | 定位、审美、能力证明 | 有主角的交互场景、简短叙事、精选组合 | 进入馆／开始使用 |
| 组件馆 | 找组件与看真实使用效果 | 分类样张和场景化详情 | 调状态、组合、查看 API |
| 动画馆 | 选择运动方式、理解时间和打断 | 精选运动样片、逐帧交互 | 换目标、改编排、带走 |
| 效果馆 | 理解材料、叠加和代价 | 同一真实内容上的可调效果 | 组合、对照、导出 |
| 创意组合 | 展示有用途的成品设计 | 少量精心编排的可用场景 | 在实验室打开 |
| 实验室 | 编辑组件 × 效果 × 动画 | 画布、少量常用参数、源码／时间线 | 导出、重放、生成测试 |
| 场景／作品 | 完成真实任务、验证完整工作流 | 独立可用的小应用或作品 | 源码、数据、复现 |
| 文档 | 学习、查 API、排错、读规范和实测 | 文档专用壳：目录、搜索、正文、页内导航 | 完成教程或定位答案 |

### 2.2 文档边界

首页保留短说明和去向明确的 CTA，移除安装步骤、整篇特性说明、实践清单、协议说明、长 JSON 和 API 表。文档正文不再作为官网介绍页的默认内容来源。组件／动画／效果详情只放理解当前样张所需的说明与短代码，完整契约、参数参考、平台限制链接到文档。

文档分为：入门、核心概念、组件、动画与效果、agent、平台与部署、性能与确定性、API／规范。开发文档继续从现有源码、契约、指南维护，避免复制出第二套 API 真相。营销文字单独编辑，引用可验证的事实，不直接渲染 `docs/features.md` 充当产品页。

文档也用 omui 构建、保留语义和 agent 能力，但默认采用阅读布局，不常驻演示播放器或全页树镜头。可运行示例是正文中边界明确的交互区域，关闭它不会丢失阅读位置。

### 2.3 路由与状态

提议的逻辑路由：`/`、`/components`、`/components/<id>`、`/motion`、`/motion/<id>`、`/effects`、`/effects/<id>`、`/explore`、`/lab/<recipe-id>`、`/scenes/<id>`、`/works/<id>`、`/docs/...`。这些是路由模型；当前静态托管可继续编码为 `#/...`，不把新增服务器重写规则作为前提。

- `features` → 文档的核心概念入口；`practices` → 文档指南；`hello` → 文档快速开始；`timeline` → 实验室时间线工作区。保留语言与可映射锚点，并保留旧入口兼容测试。
- 页面历史、页内锚点、语言、选中样张均可恢复；开关菜单、检查器和 agent 面板不销毁当前场景，不重置滚动与编辑状态。
- 分享链接记录有限的配方与参数；较大文档通过下载／导入文件分享，超长数据不塞进 URL。无后端存储时不声称链接能恢复服务器上的作品。
- 设置、语义检查、源码和时间线是当前页面的工具状态，不冒充新的主导航页面。首次进入时工具关闭，已连接 agent 和待确认事项有独立状态提示。

## 3. 美术、布局与简洁优雅

### 3.1 统一视觉方向

继续明亮编辑风，建立 **“同一对象在不同呈现之间连续变化”** 的视觉母题。omui 的 O 内含 mui 是固定品牌骨架；对象轮廓、构造线和轨迹来自真实节点的关系与运动，必须在交互中对应具体对象。

- **主角是可用的界面。** 用精心排布的真实任务面板、卡片、文本与数据建立主视觉。首页有明确焦点、前后关系和局部放大，不再依赖几个等宽边框盒子来撑满页面。
- **留白服务构图。** 正文、主舞台和局部注释采用不同密度；大场景、近景和安静段落交替，避免五屏同一种“标题＋说明＋灰盒子”。
- **图形有来源。** 连线解释节点对应，轨迹解释运动，少量材质解释效果。标志和图标优先沿用现有矢量体系；新增插画先确定职责，需要位图时另列资产、许可与体积预算。
- **颜色有主次。** 页面外壳使用低饱和中性色与品牌强调色；展品可拥有自己的配色，但不能改变导航与文档的阅读秩序。状态色既有文本又有图形提示。
- **美术跨状态成立。** 默认、悬停、聚焦、处理中、成功、错误、空白、减少动态效果、窄屏都要有设计，不只交一张静止首屏图。

### 3.2 布局与排版规则

| 项目 | 方案 |
|---|---|
| 桌面栅格 | 以既有 1200 px 上限、12 栏、24 px 栏距为起点；首页舞台可出栅格，正文保持约束 |
| 阅读宽度 | 文档正文约 640–760 px；产品说明约 30–36 个汉字一行；组件馆采用样张网格，不沿用文档列宽 |
| 页面节奏 | 8 px 基础间距；区段依据内容取 96–160 px，不用固定一屏高度制造空白 |
| 字号 | 继承 display／title／heading／body／label／caption／code；display 在手机降级并人工调整中英断行，避免孤字 |
| 手机 | 以 390 px 为主稿，同时验 360、768、1280、1440 px；舞台重新构图，不只整体缩小 |
| 工具面板 | 桌面局部侧栏／抽屉；手机分步全高面板或底部面板，返回后保留原对象、焦点、滚动 |
| 容器 | 只有需要分组、交互或材料对照的地方才有容器；避免每段文字、每项证明都包一层卡片 |

所有颜色、字号和运动参数进入有效的主题／风格数据；布局常量集中管理。只使用当前 schema 支持的主题令牌，`signal` 等未支持名字先映射到合法令牌或局部语义样式；确有必要扩展规范时走 `spec/` 流程。主题解析错误应有可定位诊断，禁止静默回退后仍让页面测试通过。

### 3.3 先交可评审设计，再写页面

R1 交付：桌面和中文手机的首页、组件馆概览与详情、动画馆概览与详情、效果馆、实验室、文档入口的关键构图；首页与一项组合的连续帧／短动画；默认与工具打开两种密度；减少动态效果版本。

用现有 headless／CPU 参考渲染与小型设计夹具产出，设计源和截图有对应关系。夹具不接完整业务可降低返工，但必须标明哪些数据是布局样例。图稿、实现后的实图分开 review；像素哈希更新前逐张核对，不能把新哈希当作美术认可。

### 3.4 omui 标志：用框架设计自己的身份

**固定形态：一个有光学校正的闭合大写 O，内部容纳清楚的小写 mui。** 外圈和内字形成一枚完整标志；不能把 O 和 mui 横向排开代替，也不沿用原来的分叉图形作为品牌主标。

- **代码原件**：在 `openmui.site:brand` 模块分区用 omui 的 `render::Path` 与显示列表定义 O、m、u、i 的矢量几何。字形以路径构造，不依赖系统字体、外链图片或额外字体下载。导航、首页、加载、演示、静态导出读取同一份几何。
- **视觉规格**：明确外圈厚度、椭圆比例、内字笔画、字距、i 点和留白。导航、favicon、首页大图分别验 16／24／32／64／256 px；小尺寸进行同一参数体系内的光学校正，仍保留 O 与内部 mui。浅深主题、单色、品牌强调色都要成立。
- **官方作品**：增加“标志是程序”可交互配方。访客可看组装／展开、切换浅深背景、改变允许的字形比例、抓住时间、反向、重置，并查看与复制真实源码。最终还可在实验室编辑并导出；保持稳定 ID、可访问名称和 agent 动作。
- **动效归属**：O／m／u／i 是独立可检查的部件；它们声明各自状态与目标，组装、重排和镜头变化由已有槽、句柄、时间线统一驱动。标志组件不另写逐帧动画，也不为它建立网站专用渲染器。
- **官网融合**：顶栏保持安静的完整标志；首页采用一次可控制的标志构造段落，接到真实工作台的对象关系；加载时可局部绘出同一轮廓，实际就绪立即接管，不为了播完品牌片延迟内容。工具打开时可选中对应部件；语义状态、画面和源码保持对应。
- **导出**：SVG／PNG 来自同一几何和 omui 参考渲染，附尺寸、主题与版本；静态页和 favicon 不手工复制一套形状。完整标志本身不依赖动画，减少动态效果／无 JS 时仍完整可识别。
- **验收**：几何与静态导出一致；小尺寸人工看过；同输入同时间 CPU 像素可复现；组装被打断和恢复可操作；实际源码复制可运行；代码原件、截图和接入位置一起提交。

## 4. 首页：有主角的叙事与可用证明

首页只保留短主张、简短定位、一个动态代码标志主演示和进入组件／创意 demos 的去向；像素／结构／脚本 agent 视角一次只披露一个。导航与首页标志共用 O 内含 mui 的真实几何。完整发布任务工作台迁到 `scenes/release`，agent、时间、通用动画、性能的完整工作流进入对应特色／场景，首页不再叠四段工具大屏。

首屏不常驻完整 JSON、测试源码、长哈希、FPS 图和全页时间条。主视觉组装／展开可直接操作，脚本明确标记，减少动态效果与离屏停止自动预览。像素、结构与 agent 读的必须是同一真实对象。中英、窄屏／桌面分别查看实际渲染；详细交互和验收见 [本轮细案 §1](2026-11-04-omui-site-navigation-motion-execution-design.md)。

## 5. 组件馆：可浏览、可试用、可带走

### 5.1 概览

按用途分：输入与选择、动作与反馈、导航、布局与容器、数据展示、编辑与内容。提供名称／用途搜索、分类筛选；样张有简短名称和功能说明。默认展示精选常用项和分类入口，所有已实现组件均可找到，不让几十个组件的全部状态与四语言代码同时挂载。

样张具有真实场景：日期与时间用于安排任务，树与表格用于整理文件和记录，颜色选择器用于修改当前对象，代码编辑器用于编辑可验证的小片段。预览有明确命中区域，点击进入详情与在样张中操作不会混淆。

### 5.2 详情

桌面以主舞台为中心，一侧是分类目录，另一侧是默认收起的常用状态；底部按需打开“代码／行为／语义”。手机先看舞台，再打开参数或代码，舞台中的输入可完成。

每项必须具备：

1. 有用途的默认样张；可修改的真实状态；清晰的重置。
2. 适用的 disabled、empty、error、loading、长内容、焦点等状态。按组件定义列举，不为了凑数给每个组件加无意义状态。
3. 键盘操作、输入法、触摸和 agent 动作；弹出层的焦点进入、退出与恢复。
4. 局部风格切换：只改变展品，官网壳不跟着变；五种风格均保留，但只有达到质量门槛才作为精选外观。
5. “换一种动法”“在组合中使用”“查看 API”入口，进入时带上当前可序列化状态。
6. 默认显示最短的一个语言示例，其余语言可切换；复制与下载有明确反馈。

### 5.3 样例真实性

现有 `code_of` 是根据样例属性生成短表达式；它不能证明完整 signal、事件、模型与依赖已写对。改为让**同一份样例定义**驱动展品构建、参数和源码导出；不能表达复杂逻辑时，引用受测试的原生样例源，不继续字符串拼出“看起来像能运行”的完整程序。

承诺支持的四种语言均有干净消费者工程验证；C++ 可显示源码而不承诺浏览器现场编译；TS／Python／Lua 按实际 wasm 宿主能力决定可编辑范围。生成代码、视图数据、契约的职责清楚，组件依然只画状态，动画由槽和策略提供。

## 6. 动画馆与效果馆：形成独立的设计产品

### 6.1 动画馆

按访客意图浏览：状态变化、进入／离开、列表重排、组件变形、文字／数字、路径编排、粒子／碎片、回溯。首屏由精选可交互运动构成，用户选中后才打开细节；同屏最多运行一个主预览，悬停预览不能成为唯一触发方式。

动画详情必须有真实 A／B 状态、播放／暂停／反向／重置／时间寻址、速度、可见的当前目标、打断按钮；提供“把目标换成另一种组件”。默认只露出少量有效参数，“高级”再展示匹配对、路径、错开、槽、策略和时间线。每个动画有用途说明、档位降级和可运行的带走结果。

**动画馆不能变成缓动曲线文档，不能只让同一个彩色方块移动。** 同一种运动至少验证在三类结构不同的真实组件／场景上；碎片爆炸按已有要求覆盖五种组件。看起来相同的案例合并，展品数量服从差异和用途。

### 6.2 效果馆

按材料与作用组织：表面／玻璃、墨与边缘、模糊／光影、遮罩／揭示、扭曲、叠加。先完成当前引擎真正支持的目录，未支持项进入能力清单，不以静态图冒充可用特性。

每项使用文字、图形、交互控件混合的真实内容，展示前后对照、参数、叠加顺序、重置、低档替代；参数变化保留输入能力，特别验证扭曲后的命中映射与焦点。CPU／GPU 对照注明参考路径、档位、容差与例外，**不宣称跨显卡 GPU 像素逐位相同**。

效果叠加默认精选两三种可读组合；高级模式允许调整顺序，并明确不兼容项与预算。系统减少动态效果和用户设置始终生效。

## 7. 创意组合：至少二十项基础组合与六组旗舰配方

本轮先交付 [细案 §4 的二十项真实组件组合](2026-11-04-omui-site-navigation-motion-execution-design.md)，并保留下述六组进阶旗舰，不以数量达标替代底层高级能力。每个配方都同时交出用途、视觉主张、组件 × 效果 × 动画构成、输入与语义、确定性镜头、低档版本、源码／数据出口。精选组合入口展示完成的结果；实验室打开后才显示编辑器。首批六组之外，增加 §3.4 的官方身份配方“标志是程序”，先用于品牌设计与官网融合，再作为实验室的标准起始配方。

| 配方 | 用途与视觉重点 | 组合与交互 | 验收重点 |
|---|---|---|---|
| 清单变看板 | 整理同一批任务；文字和状态跨布局连续，侧重排版与空间编排 | checkbox、chip、card、segmented；morph＋reorder；可编辑任务后切布局 | ID 与数据保持，切换中再次切换无跳变，导出重放相同 |

## 8. 实验室与场景

### 8.1 实验室

默认由一个配方进入，中央是可用画布，侧栏只显示当前对象的常用参数，下方可打开时间线或代码；空白入口也有一份可运行初始配方。逐级提供：L0 换预设；L1 改组件、风格、效果与动画；L2 改配对、路径、错开与代码；L3 插件与自定义过渡。

必须完成的流程：打开 → 编辑 → 预览／寻址 → 撤销／重做 → 保存配方 → 导出 → 在干净工程导入。错误有位置和修复提示；错误编辑保留最后一个有效场景及 signal 状态。导出明确区分代码、视图、风格／动效、时间线与会话，不承诺所有组合都能无损转换为任意格式。

默认提供经过验证的搭配；高级编辑器可探索更多组合，能力矩阵中区分“支持”“不兼容”“未实现”，不默默忽略参数。预设命名和参数说明面向用途；后端名、内部节点路径和 pass 名只出现在检查器。

### 8.2 完整场景与作品

保留现有 C4／C5 范围：agent 帮你办事、重现 bug、现场改代码、同一应用五档、可倒放小游戏、影片是程序。每个场景独立加载，有任务起点、完成结果、出错恢复和带走方式。模拟设备明确标记，真机另交证据。

影片必须有四种语言的片段、三视图、浏览器实时渲染、导出与 CI 对照。格斗、打砖块、文档墙、风格工坊仍按原策略保留在待办，达标后才精选展示；不将它们的大量美术生产重新塞进官网重构的关键路径。

## 10. 工程组织与内容来源

### 10.1 网站代码

在 `openmui.site` 成员内按职责拆模块分区：路由与壳、首页、各馆概览／详情、配方与实验室、文档壳、检查器、加载清单。它们共享页面模型和公开 runtime API，避免 `app.cpp` 继续集中处理所有页面、导航、工具和文档。

`site/` 下的分区目录不是新的 workspace 成员；真正可复用的新组件或独立程序才建立自己的包、`mcpp.toml`、README 和 `path` 依赖。组件、runtime、render、host 的通用缺陷回归相应层，不从组件依赖站点内部代码。

### 10.2 数据与生成

建议增加 `site/catalog/`：`components.catalog.omui.toml`、`motion.catalog.omui.toml`、`effects.catalog.omui.toml`、`compositions.catalog.omui.toml`。这里只存用途分类、排序、短文案、配方／原生样例引用、最低档位与验证状态，不复制契约定义。新种类在生成器中有 schema 和诊断。

同一目录生成逻辑路由、目录卡片、静态 HTML 内容、搜索索引、资产依赖和验收清单；可运行展品仍用原生 builder 或已有视图／时间线格式。清单元数据不能驱动每帧脚本。

产物命名遵守 `<名字>.<种类>.omui.{toml,json}`；逐行记录用 `.jsonl`。契约绑定走已有生成器；标准变更在 `spec/` 的 `openmui-design` 分支按 D-78 提交和推送后再更新指针。此方案不授权修改 xdesk 或 xlings。

## 11. Web 交付：等待过程也应简洁完整

1. **首屏可读先于运行时。** 从同一页面源生成真实 HTML、首屏参考图和镜头几何；静态页能导航和阅读，交互按钮明确就绪状态。只在成功呈现且焦点／语义镜像就绪后接管，任何时刻只暴露一套可访问内容。
2. **创意加载局部进行。** 首页主舞台上的细线随真实阶段／字节进度长成对象结构，最后接管为像素。标题、导航和 CTA 不被全屏加载仪式遮挡；不强制播放完，不编造进度百分比，减少动态效果时直接显示静态首屏与状态。
3. **接管连续。** 同尺寸、语言、档位与固定时间的参考场景逐像素对照；跨视口用相应构图的图或受约束裁切，不能拉伸参考图后宣称逐像素相同。接管时继承滚动、输入、焦点与必要的操作队列，失败保留静态内容和重试。
4. **字体分批。** 按页静态文字子集；全站语言按钮所需字形随首屏到达；完整中文输入字体在编辑入口需要时加载，并有可恢复状态。中文首访、英语切中文、慢网输入都验证，不把缺字闪烁当正常状态。
5. **代码与资源分开。** 首先按页拆字体、图片、配方与索引；不把资源懒加载说成 wasm 代码已拆。重型实验室、脚本宿主、影片用独立程序按需进入；共享配方与返回状态，是否启用 side module 依体积分析单独决定。

拟议预算需在 R0 固定测量设备与 Chromium 版本后校准，校准理由写入预算，不因一次失败随意放宽：

| 指标 | 最终目标 | 自动验证 |
|---|---|---|
| 首个可读首屏，20 Mbit/s、40 ms RTT 冷访问 | ≤ 1 s | 明确定义可见文字和主视觉已呈现；不以 wasm 初始化代替 |
| 首屏静态批次 | 以既有 <150 KB 目标为起点实测；包含图片、文本、脚本的压缩线上字节 | 同时计响应完成和时间点前累计字节，保存误差与阶段时间 |
| 首页真实可交互 | ≤ 2.5 s；临时 CI 容差单列并逐步收紧 | 成功执行可撤销动作并读回结果；不只检测 `window.omui` 存在 |
| 新增页面资源 | 首页不下载未访问的重页面资源 | 冷访问请求清单与依赖清单对照；切页单独报告 |
| 活动帧 | 60 Hz 目标场景 p95 ≤ 16.7 ms；120 Hz 场景按其预算 | 固定真实设备／后端的呈现数据；软件 GPU 单列，不代替真机证据 |
| 空闲 | 无持续自驱帧；零分配声明只在已覆盖模块成立 | frame demand 与 allocation 计数；活动帧另列 |

首个可读首屏、程序首帧、agent ready、字体就绪和页面资源就绪分开测；英文／中文、桌面／手机、CPU／WebGPU／WebGL2、快网／慢网都保存条件。rAF 间隔保留为辅助诊断，不冒充实际绘制帧时间。

### 13.2 真实使用与视觉评审

每份验收包固定 commit、规范子模块 SHA、mcpp／工具链、浏览器、设备、后端、档位、视口、语言、构建命令和场景输入。截图、连续帧、指标、失败清单通过同一个 manifest 关联，避免评估源码 A、运行程序 B。

## 14. 本次 review 的核心决策

以下七项作为实施中的持续 review 要点；已经获得开始实施的指示，不重复等待授权：

1. **结构**：采用“组件／动画／效果／探索／文档＋开始使用”；首页与文档分开，探索容纳组合、实验室、场景、作品。
2. **美术与品牌**：官网使用 omui，规范称 openmui；大写 O 内含 mui，用 omui 矢量代码设计并作为官方可交互作品，与首页、加载和实验室融合。明亮编辑风继续，关键图和动效分镜都提供实际渲染。
3. **首页**：用同一份工作台数据串起语义、agent、时间、动画、性能；默认隐藏大部分诊断，保留可发现的对象检查与真实连接状态。
4. **组件与动画**：各馆是独立的浏览与试用产品；概览、详情、源码／文档分层；带走结果必须运行验证。
5. **创意组合**：六组首批配方及其用途和验收按 §7；所有配方进入实验室可修改、可撤销、可导出。
6. **范围与顺序**：按 R0–R6 对应 C2–C6 推进；补齐形状／粒子／回溯／MCU／影片／基准等既定范围，不用官网换皮替代底层完成。
7. **完成标准**：设计认可、实际任务、可复现证据和自动门禁同时成立；先解决已知泄漏与首屏完整性，C2 未全过前不记完成。

### 15.6 2026-11-03：首帧字形、完整字体就绪与浏览器参考回放

英文页的“中文”按钮现在由启动字集在程序第一帧绘制，完整中文字体仍在呈现后加载。中文直达页在呈现前加载完整字集，跳过启动字集；页面选择的语言优先于浏览器语言，因此中文系统浏览英文页也沿用英文加载路径。

实现位于 `openmui.build.toy`／`omui-gen dist-toy` 的 `font_initial` 选项，官网声明 `NotoSansSC=中文`。启动字集和完整字体分别以内容哈希打包；启动字符合并入完整子集，避免调用者的正文清单遗漏按钮字符。子集保持原字形 ID、度量和布局表，Unicode cmap 仅声明实际保留字符，使后续完整字体能够参与回退。启动字集原始大小 230,568 字节，gzip 后 41,244 字节。

同时修复了此前延后字体与参考回放的关联缺陷：完整字体到达后更新 `/fonts/` 的权威来源，以 `/later/fonts/` 别名交给现有运行时，不复制第二份 MEMFS 文件；字体尚不完整时保留 `.partial` 标记。参考回放在资源就绪前显示等待，保留最新帧请求和关闭／重新打开后的选择；资源就绪后才创建独立字体集合并计算像素，避免把缺字体误报成 CI 像素不一致。
