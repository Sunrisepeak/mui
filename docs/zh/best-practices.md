# 最佳实践

做作品时学到的东西，写成在 openmui 上写程序可以照着做的规则。每条注明来自哪个作品；具体怎么做的见它们的开发故事（`showcase/*/dev-story.md`）。这份文档会一直增长：作品的自省里发现了通用的东西，就加到这里。

## 1. 每样东西放在它该在的层

openmui 是分层的（D-82）：独立组件（`modules/`）、UI 框架、游戏引擎服务（`mgame`）、专用框架（`gongfu`）、应用。一项能力放在它能通用的最低一层：

- 给一段绘制命令换颜色是渲染器的能力（`DisplayList::recolor`），哪怕是一个角色的时停用到了它；
- 从编辑器的文本编译 TypeScript 是脚本绑定的能力（`compile_typescript_source`），哪怕是一个工坊需要它；
- 换主题是宿主的事：组件说它要什么（事件），应用去应用。

不要为了某一个应用方便把架构搞乱。某件事做起来别扭，就去修它所属的那一层。

## 2. 按代码做什么选语言

| 代码 | 用什么写 | 为什么 |
|---|---|---|
| 模拟、渲染、混音、布局——每帧都跑的 | C++（模块） | 不分配、热路径没有虚函数、算术精确 |
| 反复调整的内容：角色、声音、主题、关卡 | 数据文件（`*.<种类>.omui.toml` 等），诊断带位置 | 人、agent、工具都能读写；构建检查由它们生成的东西 |
| 需要现场调的逻辑：规则、场景脚本、导览、玩法模式 | TypeScript、Lua 或 Python，热重载 | 重载 200 ms 以内，不用重新构建 |

脚本永远不在一帧里跑：它在加载或重载时产出数据（规则、视图文档、动词的回答），再在一步的边界交给每帧运行的系统（打砖块第 6 关）。

## 3. 先让模拟确定，其他都变简单

- 状态是纯数据：拷贝即保存，哈希即比较（`static_assert(std::is_trivially_copyable_v<State>)`）；
- 定步长：`step(state, input) → state`，状态之外的东西都不影响结果——没有时钟、不分配；
- 数值：定点数（gongfu），或者只用正确舍入运算的双精度：+ − × ÷ 和 √，不收缩（`-ffp-contract=off`）、不用 fast-math、不用 libm 的超越函数，常数写成正确舍入的值；lint 的 `determinism` 规则管住列出的包；
- 凡是影响玩法的都放进状态，包括镜头、门的时间窗、脚本重载的规则（经这一步的输入）。倒流、回放、回滚联机、固定的测试就都是现成的（格斗、打砖块）；
- 在每个平台上把整局的哈希固定在测试里。

## 4. 画面由状态算出来，不存

一帧画面是（状态，帧号）的纯函数：粒子由事件定种子，特写是对齐到帧的时间线，二次运动由状态里的历史算。回滚不用保存任何画面状态，回放画出来一模一样（格斗）。

## 5. 契约先行，一套动作

先写组件的契约（`*.contract.omui.toml`），绑定是生成的。人、agent、测试经同一套动作操作；语义节点写清楚 agent 要玩它、用它需要知道的东西。ID 是显式的，不依赖显示文本（格斗、打砖块）。

两个及以上参数的动作收一个生成的结构，按名字取（`const GuardToArgs& args`，再 `args.x`），不会取错顺序；以前按位置传 `Value`，写反也照样编译（打砖块的一个处理函数就把 `seen` 当成了 `x`）。

## 6. 资产是构建检查的数据

数据文件在构建时嵌入（`openmui::build::embed`）；让构建拒绝过期的东西（gongfu 烘焙的受击框记着它来源的哈希）；诊断写清文件、行和怎么修（格斗）。

## 7. 在边界校验脚本

脚本的回答在进入的地方检查：字段认识、类型对、该是整数的是有限整数、在界内；不通过就保留原来的值并说明原因（打砖块的工坊）。

## 8. 测试画出精确的像素；固定要有意义

无头宿主在每个平台上画出一样的字节，测试可以固定一帧。固定的帧里不要有由无关状态算出的文字（一行校验和会在状态布局一变就让固定失效），或者只固定一个区域。README 的图也由测试画（`tools/ci/readme-media.sh`）。

## 9. 性能要测、要有预算

每个性能说法都有 `tests/bench` 里的基准和 `budgets.bench.omui.json` 里的预算。纯数据加每帧不分配，让代码同时又快又确定。先测再优化。

## 10. 带一张图

每个作品的 README 都有它的招牌镜头，由它的测试无头画出：一张静帧，或者一段 1 MB 以内的动画 PNG。动画 PNG 只存帧和帧之间变了的部分，适合界面的循环；整个画面都在动的，用视频。
