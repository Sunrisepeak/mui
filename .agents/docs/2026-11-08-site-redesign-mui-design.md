## 1. 问题诊断

依据：官网当前的 README 媒体（`site/media/*.png`），以及交付测量记录（site/README.md 的 Delivery 一节）。

| 问题 | 证据 | 后果 |
|---|---|---|
| 组件一次只显示一个 | 组件页左侧是 8 项列表，右侧一个大白框里只有一个“Save”按钮 | 看不到组件库的规模和质感；36 个组件要点 36 次 |
| 动效示例是规格样本，不是作品 | 41 个案例大多是灰色方块加一行文字，例如“表面换色”“整体缩放” | 正确但不吸引人，没表现出通用形变、书写、软体、确定性这些亮点 |
| 首页没有主角 | 一个静止的大 logo 加两行标语，像通用 SaaS 模板 | 十秒内看不到项目最强的东西 |
| 文字多于画面 | 每节都是“大标题＋一段说明＋几个按钮” | 读的比看的多，不直观 |
| UI 和动效的细节没有质感 | 按压、悬停、出现消失的动效平淡；圆角、阴影、边线没经过推敲；一个创意演示里留着半透明色块，像残留的中间态 | 让人觉得粗糙。**这一条是本次重构的硬要求，见 §3** |
| 首帧慢 | wasm 10.5 MiB，首帧约 1.6 s（20 Mbit/s）；上次评估最弱的一项 | 第一印象差 |

根本原因：官网在**讲**项目，而不是官网本身**就是**项目的作品。

## 2. 目标与原则

一句话目标：**访客 10 秒内感受到亮点，1 分钟内亲手确认，5 分钟内知道怎么用、怎么让自己的 Agent 用。**

| 原则 | 含义 |
|---|---|
| 简洁优雅 | 每屏只讲一个观点；文字最多一两行；用动效和画面来解释 |
| 创意 | 官网本身就是作品：页面切换、元素出现消失、品牌形象，都用项目自己的能力构造 |
| 直观 | 能拖就拖，能扫时间就扫；每个说法都能当场验证（看结构、比像素、下载 SVG、让 Agent 操作） |
| 质感 | 基础组件和动效的每个细节都要推敲（§3）；这些细节做成框架的默认值，不只是官网专属 |
| 人与 Agent 并重 | Agent 通过 Mui 的形象在页面上行动，它做的每一步都看得见、可以叫停，需要人确认的由人确认 |
| 可验证 | 所有画面都可以无头重现，按时间采样验收；有性能和无障碍预算 |

## 3. 质感：设计细节规范

质感来自大量小细节同时做对。这些细节**归框架所有**：omui 的主题、默认动效规则和组件本身，以及 xrender 的绘制能力。官网只是第一个消费者，所有 omui 用户都受益。

下面的数字是**默认风格的取值**，不写死在组件里：它们做成主题的动效与视觉令牌（时长阶梯、弹簧预设、阴影配方、圆角平滑度），风格包可以覆盖。

### 3.1 动效细节

| 项 | 规范 |
|---|---|
| 时长与距离 | 时长随移动距离和元素大小变化，不用一个固定值。小元素 120–180 ms，面板 220–320 ms，整页 350–450 ms；离开比进入快约 20% |
| 曲线 | 空间移动用弹簧或减速曲线，不用线性；颜色和透明度用短的平滑曲线；超调只用于有物理意义的动作（拖拽松手、弹出），幅度小 |
| 起点感知 | 缩放从触发它的点展开（菜单从按钮展开），不是从中心 |
| 打断连续 | 任何时刻被打断都从当前姿态和速度接续，不跳变（hanim 已具备，需逐个组件验证） |
| 编排 | 成组出现按阅读顺序错开 20–40 ms，总时长有上限；同一元素在两种布局之间保持身份平滑过渡 |
| 中间态 | 中间帧必须好看：文字可读、颜色不脏（在感知均匀的颜色空间插值，例如 OKLCH）、不出现残留色块 |
| 减弱动效 | 每个动效都有减弱版本（交叉淡入淡出，或直接到位），而不是简单关掉 |

### 3.2 交互细节

| 项 | 规范 |
|---|---|
| 按压 | 同一帧内响应：轻微缩小（约 0.97），阴影收紧；松开时带一点回弹 |
| 悬停 | 轻微抬升，光感变化；指针样式准确 |
| 焦点 | 焦点环有动效，形状贴合控件，键盘和指针各自恰当 |
| 拖拽 | 带物理感：越界时有橡皮筋阻尼，松手速度延续，吸附带磁性 |
| 状态切换 | 开关、勾选、选项卡之类的“指示物”连续移动（例如选项卡的指示块流动过去），不是闪变 |

### 3.3 视觉细节

| 项 | 规范 |
|---|---|
| 圆角 | 连续曲率圆角（squircle，与 iOS 一致）。**xrender 目前不支持**，是新能力（§10） |
| 阴影 | 分层：环境光阴影＋主光阴影，带一点物体颜色，不是单层纯黑模糊 |
| 边线 | 物理像素级的发丝线，按 DPR 对齐 |
| 表面 | 适度的细噪点或渐变，避免死平；玻璃材质要有透镜折射和形变（已有 liquid glass 方向） |
| 排版与网格 | 4/8 px 网格，视觉对齐（光学对齐而非几何对齐），明确的字号阶梯和行高 |
| 颜色 | 状态颜色用感知均匀的色阶；深色模式单独调色，不是简单反色 |

### 3.4 怎么验收质感

- **逐组件细节清单**：36 个组件，每个列出它在 §3.1–§3.3 下的具体要求，例如滑块的按压、拖拽阻尼、刻度吸附。
- **按时间采样的过程条带**：每个交互取端点、多个中间帧、打断、反向，像素钉住。
- **对标评审**：与业界最好的做法逐项对照打分，对象如 Apple HIG 的控件、Linear、Vercel、Stripe、Framer。每条发现进入细节台账，修复后复评。对标只在评审时使用，仓库里只记发现和打分，不提交他人产品的截图。

## 5. 首页

| 时间尺度 | 访客看到什么 | 证明什么 |
|---|---|---|
| 0–10 秒 | 标志一笔笔写出来，然后 O 活过来变成 Mui；Mui 看向你的鼠标 | 矢量书写、通用形变；这是一个活的系统 |
| 10–60 秒 | 往下滚动，三四个场景，每屏一个：①整页一键切换“像素／结构／Agent”视图；②一段文字在中英文之间切换，字形逐个变形；③把一张卡片扔下去，看它软着陆，然后拖动时间轴倒放，每一帧都确定；④点一下，当前画面变成 SVG，每个节点都带名字 | 一棵语义树多种视图；字形形变；软体和确定性；矢量截图带来源 |
| 1–5 分钟 | 去组件墙逛；或者让 Mui 带你接入自己的 Agent | 组件库的广度和质感；Agent 原生 |

每屏文字不超过一个标题加一行说明。

## 6. 组件墙

基于已有的 `omui.ui.canvas`：分档绘制，聚焦即转为活的组件，10 万节点平移每帧低于 1 ms。

- **一屏看全**：36 个组件按 6 个类别排成一面墙，每个都是活的真实组件，并展示它最有代表性的状态。
- **浏览**：拖动、缩放、甩动后有惯性；远处的组件按档画成纹理，近处的变成活组件。
- **随手交互**：鼠标移上去，那个组件就能直接用。
- **进入细节**：点击后镜头飞进去（相机飞行，`MOTION-OK`），展开变体、风格、代码、语义树和 Agent 视图；返回时飞回墙上原位。
- **搜索和筛选**：墙重新排布，组件保持身份平滑移动（universal motion）。
- **换风格**：五个风格包（glass、ink、liquid、neon、retro）一键切换，整面墙实时换皮。
- **键盘和读屏**：Tab 在组件之间移动，有清楚的焦点；画布语义项按类别列出所有组件。
- **手机**：竖向的类别带，横向滑动浏览，点按进入细节。

## 8. 品牌：几何标志与 Mui（喵）

### 8.1 标志

- 保留“O 内含 mui”的结构，但 **O 不再是一个字母**，而是一个艺术化的闭合轮廓：顶部两个像素台阶是耳朵，收笔处稍微出头是尾巴尖。静止时它是干净的几何标志，细看才发现是一只猫。
- 标志仍由框架自己的矢量代码构造（AGENTS.md 品牌规则的“O 内含 mui、用框架自身矢量构造”不变，只是把“大写 O”放宽为“O 形”）。规则文本需要相应修改。

### 8.2 Mui（喵）

- **名字**：Mui，取“喵”的谐音。
- **视觉**：像素风，但**每个像素都是一个矢量方块**。所以它在任何尺寸都锐利，可以导出 SVG，每帧确定，可以散开再拼回，Agent 能逐格编辑。
- **两种形态互相变形**：像素风的 Mui，和平滑矢量的标志。这本身就是“表示切换”的演示。
- **从标志活过来**：O 的轮廓变成身体；里面的字母重排成猫脸：i 的点变成眼睛，m 收拢成 ω 形的嘴。
- **像素格**：16×16 与 24×24 两种都出图，看效果后定。

### 8.3 A1 探索结果（2026-11-08，待维护者挑选）

由官网包的 `tests/brand_lab_test.cpp` 无头绘制（数据在 `site/brand/`：`marks.mark.omui.json`、`mui.sprite.omui.json`），每个像素都是矢量方块，标志是 SVG 路径；标志一张同时导出为 SVG（[marks.svg](media/2026-11-08-brand/marks.svg)，全部是矢量，没有像素岛）。

| 图 | 内容 |
|---|---|
| [marks.png](media/2026-11-08-brand/marks.png) | O 的四种处理：现在的椭圆、A 耳朵、B 一笔带尾巴、C 耳朵加尾巴；每种在大尺寸、32 px 和 16 px 下 |
| [mui16.png](media/2026-11-08-brand/mui16.png) | 16 格的头：平常、看向一侧、开心、睡觉；三种配色（indigo、cream、night） |
| [mui24.png](media/2026-11-08-brand/mui24.png) | 24 格的身体：坐、走；三种配色 |
| [lockups.png](media/2026-11-08-brand/lockups.png) | 四个方向放进页面的样子：页眉标志＋标语＋ Mui |

观察：
- **A（耳朵）**最干净，16 px 下仍能认出是猫；**B** 读起来像字母 Q，作为文字标志有风险；**C** 更俏皮，但小尺寸下尾巴糊成一团。
- **16 格的头**表情清楚、和标志的轮廓一致，适合页眉、按钮旁、小尺寸；**24 格的身体**能走、能坐、能推东西，适合在页面上活动。两者可以并存：同一只猫的两个尺度。
- **cream（白猫）**更安静优雅，但眼睛对比度不够，需要加深瞳孔；**indigo** 和品牌色一致但大面积时偏重；**night** 在深色模式下很好。
- 渲染细节：相邻像素方块在小数坐标上会出现发丝缝（各自抗锯齿后叠加只覆盖 3/4）；改为同色方块合成一条路径后消失。这条规则写进 C1 像素网格表示。

建议：标志用 **A（耳朵）**；Mui 用 **16 格的头＋24 格的身体**两个尺度；配色以 **indigo** 为主、深色模式 night，cream 作为风格包选项。

## 9. Mui 的行为、引导与 Agent

### 9.1 状态

| 状态 | 表现 | 何时进入 |
|---|---|---|
| 安静 | 坐在角落，偶尔眨眼，尾巴轻摆 | 默认 |
| 注意 | 目光跟着鼠标，看向你悬停的组件 | 有指针活动时 |
| 引导 | 走到某个真实元素旁边指着它，叼着一张一行字的小卡 | 你点了它，或者在接入流程中 |
| Agent 附身 | 眼睛变色；走到 Agent 正在操作的节点旁，演示那一步 | 你的 Agent 接入后 |
| 需要你确认 | 把确认卡举到你面前 | Agent 请求一个需要人回答的操作 |
| 睡觉 | 蜷起来；不再有任何动作 | 你让它睡，或者减弱动效模式下的长时间闲置 |

### 9.2 与页面互相作用

- **它对页面的反应**：
  - 目光跟着指针，看向你悬停的组件；
  - 滚动时扒住边缘；
  - 页面出错时耳朵耷下来；
  - 切换风格包时换配色。
- **页面对它的反应**：
  - 布局盒就是它的平台，它踩在卡片边上时卡片微微下沉；
  - 它能用爪子拨动演示用的开关，用的是真实的语义动作。
- **原理**：它读的是 Agent 读的同一棵语义树，所以它“理解”页面的方式就是 Agent 理解页面的方式。
- **两种驱动方式，权限不同**（2026-11-08 维护者确认）：

| 谁在驱动 Mui | 能做什么 | 身份 |
|---|---|---|
| Mui 自己（没有 Agent 接入时） | 只做轻的、不改变状态的反应：看、指、跳上卡片、蹭一下；拨动的只有专门的玩具元素 | 声明的执行者 `site:mui` |
| **访客的 Agent** | **官网上凡是能动的都能动**：每个组件（开关、滑块、输入、选项卡…）、布局（列表与卡片、拖动重排）、场景（组件墙的镜头、软着陆的卡片、动效作品的时间轴、发布工作台）、全站工具（镜头、时间条、风格包、设置）。官网是静态的，没有服务端可以破坏，访客的内容也都在本地且可撤销 | 访客的 Agent（它的 openas 身份）；Mui 是它的身体，不增加任何权限 |

- **特意的权限演示是唯一的例外**：少数操作故意要求人确认，用来展示“权限由人掌握”，例如发布工作台里不可逆的“记录发布”和“全部删除”、打开站外链接。Agent 走到这一步时，Mui 把确认卡举给人。
- **只有人能回答确认**：Mui 和 Agent 都**永远不能**回答“需要人确认”的请求（S-10），确认按钮只属于人。

### 9.2.1 Agent 怎么控制 Mui

Mui 是语义树里的一个节点，有自己的操作。它们写进官网的操作目录（ops ＋ skill），Agent 能发现、能调用：

| 操作 | 作用 |
|---|---|
| `move_to`（节点或位置） | 走、跳或爬过去，沿途以布局盒为平台 |
| `look_at`、`point_at`（节点） | 看向、指向一个节点 |
| `play`（节点，手势：点、拨、拖、推、坐上去） | 用手势完成那个节点的真实语义动作（拨开关就是开关的 `toggle`），或在场景里产生物理作用（推一张卡片、坐在它上面让它下沉） |
| `say`（一行字） | 头顶冒出一行字的气泡，限一行 |
| `pose`（状态）、`sleep`、`wake` | 换表情和姿态，睡觉，醒来 |

两条路径并存：
- Agent **直接**对节点做动作（`act`），Mui 自动走过去演示那一步；
- Agent **命令 Mui** 去做（`play`），Mui 用手势完成。

两条路径都进行动记录，都可以撤销（可撤销的那些）。

### 9.3 引导：用 Mui 代替文字步骤

**入门**：Mui 指着真实的界面一步步示范，例如“拖一下这面墙”“点进这个滑块”。屏幕上最多一行字。

**接入你的 Agent**（复用已有的 `Runtime::link_agent`、配对码和 `agent.md`）：
1. 你点 Mui，它叼来一块像素名牌，上面是配对码（十分钟有效），旁边是复制命令或提示词的按钮。
2. 你在本地的 Agent（Claude Code、Codex，或任何 MCP 客户端）里粘贴。
3. 等待时 Mui 竖着耳朵；连上后眼睛变色，它就是你的 Agent 在页面上的身体了。
4. 你的 Agent 做的每一步，都由 Mui 走过去演示；行动记录（已有的 actor log）以一条细细的轨迹显示在旁边，可以撤销。

**不托管大模型**：官网自己没有对话框、没有模型、没有密钥，Agent 由你自带。离线时 Mui 可以播放脚本化的演示，并明确标注是脚本。

### 9.4 规则：避免 Clippy 式打扰

| 规则 | 原因 |
|---|---|
| 不请自来时不说话；只在被点、被叫，或 Agent 需要你确认时开口 | 打扰是 Clippy 失败的根源 |
| 不遮挡内容；随时可以让它睡觉或收起 | 内容第一 |
| 一次最多一行字，其余靠动作和指向 | 简洁优雅 |
| 行为由固定种子模拟，可以重放 | 截图和测试能钉住，时间条能倒回 |
| 每帧开销有预算，不影响首帧 | 性能 |
| 每个动作都有语义标注；读屏听到同样的步骤（礼貌级播报）；不抢焦点，不在用户没操作时移动焦点；引导每一步都能用键盘完成；减弱动效时只做指示 | 无障碍 |
| 文档与规范页面不出现 | 不让规范显得玩具化 |

### 9.5 “Agent 在场”的框架形状（C2）

Mui 是皮肤，能力归 omui：

- **一个模型**：`agent_presence_state(services, actors)` 从运行时的行动记录（`action_journal`）和 Agent 连接状态算出：在场的是谁、它正在或刚刚操作的节点（窗口坐标的框）、最近几步的轨迹、它在等人回答的事（由应用给出），以及它说的一句话。纯函数，Agent 和测试读到的与画出来的同源。
- **默认皮肤**：组件 `agent_presence`（omui.ui.base，契约优先）铺在页面之上、不接收指针（`pointer_events: none`）：目标节点四角的取景框和执行者标签、轨迹的虚点线、待确认时的一张卡。只画状态，框从一个节点到另一个节点的移动由动效槽完成（D-93）。语义上是一个礼貌级播报的状态节点：读屏听到“agent:x 在‘保存’上执行 activate”。
- **换皮**：同一个模型交给别的画法：官网用 Mui 的像素形象走过去（C3 的行走），宣传片和打砖块改用共享的取景框与意图标注，不再各画一份。
- **权限**：它只呈现，不代答；“需要你确认”的卡上没有替人确认的按钮（S-10），回答仍走应用自己的控件。
