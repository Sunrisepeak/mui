# mlibs.image

Images in memory (8-bit RGBA, straight or premultiplied), PNG encoding and decoding through libpng's simplified API (`compat.libpng`, `compat.zlib` from mcpp-index), WebP encoding and decoding through libwebp (`compat.libwebp`, imported as `mcpplibs.mwrap.libwebp`), and JPEG encoding and decoding through libjpeg-turbo's TurboJPEG API (`mcpplibs.mwrap.libjpeg_turbo`). Errors are returned as messages; nothing longjmps through C++ frames. `decode` and `load` take any of the three, told by its signature.

Animated PNG (`encode_apng`, `save_apng`): every frame after the first is stored as the rectangle that changed from the one before, and an unchanged frame lengthens the one before, so a loop over a still background costs what moves; a viewer without APNG shows the first frame. The headless host records into it (`Headless::record`), which is how the showcases' README loops are made.

WebP (`encode_webp`, `decode_webp`, `save_webp`, `load_webp`): still images, lossy (`WebpOptions::quality`, alpha kept losslessly beside the colour) or lossless (`lossless = true`, every pixel back as it went in), `method` 0–6 trading time for size. Colours under clear pixels are kept (libwebp's `exact`), premultiplied views are written straight, and decoding gives straight alpha. Encoding is single-threaded, so a given libwebp (pinned by mcpp.lock) writes the same bytes on every platform; the tests pin a file's decoded pixels and an encoding's bytes. libwebp is built without threads, so its one-time setup is not lock-guarded: the first use of either direction encodes and decodes a tiny picture under a `std::once_flag` before anything else runs, which makes concurrent first use safe.

Animated WebP (`encode_animated_webp`, `save_animated_webp`, `decode_animated_webp`, `load_animated_webp`): shaped like `encode_apng` (the same frame list and `delay_num / delay_den`, `loops`), so a caller switches format by name; `AnimatedWebpOptions` adds `quality` (80), `lossless`, `method` and the key-frame spacing `kmin`/`kmax` (33/64: a key frame at most every 64 frames, about 1% larger than none). libwebp's WebPAnimEncoder (the `mux` feature) stores what changed between frames and merges equal ones; lossy, a README loop of soft UI and art comes out about a twentieth of its APNG (320 × 200, 36 frames: 23 KB against 490 KB in the tests). Times are whole milliseconds, each frame starting at its delay's multiple rounded, so they never drift. Single-threaded and `exact`, so the bytes are pinned like the still's. Decoding (WebPAnimDecoder, the `demux` feature) gives each shown frame as the whole canvas, straight, with its delay; a still WebP is an animation of one frame, and libwebp writes an animation that comes out as one frame as a still. The headless host's `save_recording` writes one for a `.webp` file.

JPEG (`encode_jpeg`, `decode_jpeg`, `save_jpeg`, `load_jpeg`): 8 bits a sample, baseline or progressive, Huffman or arithmetic coding; grey and four-ink (CMYK, YCCK) files come back as colours. A JPEG has no alpha: decoding gives every pixel opaque, and encoding writes each pixel as it shows over `JpegOptions::behind` (white). `quality` 1–100 (90), `full_colour` keeps colour at every pixel (4:4:4) where the default keeps it at every second each way (4:2:0), `progressive` writes coarse first. The library is libjpeg-turbo 3.2.1, built from its C code without the SIMD extensions (`mcpplibs/libjpeg-turbo-m`); its default path is whole numbers throughout, so a file decodes to the same pixels on every platform — the tests pin an encoding's bytes and its pixels, which GCC, LLVM and wasm32-emscripten reproduce — and they are the pixels libjpeg-turbo gives anywhere (its SIMD code reproduces its C code; the wrap's tests hold upstream's test image to the MD5 upstream's own regression test expects), so what a browser shows of the same file. A file cut short is refused (not shown grey below the cut), as is one of 12 or 16 bits a sample, a lossless one, one of more than 2^28 pixels, and a progressive one of more than 500 scans — each with its reason. Limit: without SIMD decoding is slower than libjpeg-turbo with it (measured here: the whole of Khronos' DamagedHelmet — five 2048² JPEGs decoded and made into textures with all their sizes, its mesh ordered and cut into clusters — is brought in by `xrender.asset` in 0.43 s in a debug build); the x86 extensions are NASM assembly, which the package's build does not have; they come back when it does, with the same pixels.

A picture of light (`Light`: three floats a pixel, linear, as much light as there is — not clamped to what a display shows) and Radiance's `.hdr` (`is_hdr`, `decode_hdr`, `encode_hdr`, `load_hdr`, `save_hdr`): the format the surroundings a scene is lit by are handed round in. Reading takes run-length coded rows and flat ones, rows from the top or from the bottom (`-Y`/`+Y`), and `32-bit_rle_rgbe`; a file of another format (XYZE), with its columns turned or mirrored, cut short, or of more than 2^28 pixels is refused with its reason. A stored pixel is three bytes and a shared power of two, so writing rounds each channel to the 8 bits beside the pixel's largest and reading what was written gives the same file again; the code is this package's own (some hundred lines, no library), whole-number work apart from the scaling by a power of two, so GCC, LLVM and wasm32-emscripten give the same bytes and the same light — the tests pin both.

How far a picture is from another (`apart(candidate, golden)`): model-viewer's render-fidelity measure, so that a number said here is a number that suite would say — over the pixels the candidate has anything at, pixelmatch's colour distance (both laid over white by their alpha, the difference in YIQ), the root of the mean of its squares over the most it can be, and `decibels()` of that (10 log10; the suite's bound for a renderer against its own golden is −22).

KTX2 textures (Basis Universal's codecs) are read by a package of its own, [mlibs.image.ktx2](ktx2), so that this one does not carry the transcoder.

Normal maps (`normal_map`): a picture's tangent-space normal map, aligned with it and the same size, for render's lit pictures (`render::Material`). The height is a rounded bevel of the silhouette — a quarter circle `bevel` pixels wide rising from the edge of the pixels whose alpha is at least `alpha` (the picture's border is an edge) — so a painted part reads as a volume, plus `detail` pixels of height from black to white (darker is deeper: painted folds and creases, in proportion to the bevel's height). The signed distance to the edge is exact (Meijster's two-pass Euclidean distance transform, in squared integers) and smoothed (`smooth`, a box twice, its sums divided once so the result is exactly symmetric under turns and mirrors) before the bevel lifts it, so the slope stays steepest at the silhouette — where a rim light catches it. Sobel slopes scaled by `strength` and an integer square root make the unit normal: R = x right, G = y down, B = out of the picture, each 128 + 127·n; A is 255. Integers only: the tests pin the bytes, which GCC and LLVM reproduce.
