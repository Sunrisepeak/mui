# omui 官网第二轮实施细案：导航、默认动效与创意演示

2026-11-04。维护者最新要求的执行清单，补充 [官网重构总方案](2026-11-03-openmui-site-redesign-implementation-design.md) §0.4。**本文件列出目标、实现方式和验收条件；目录或源码已有条目不等于整站已验收。** 当前各 worktree 的局部测试与整站集成验证分开记录。**本次补充的详细 review 入口为 §8：各页开场、渐进披露、Agent 三路径九个场景、已发现缺陷、下一批工作与本地验收。**

## 1. Review 应先确认的设计

### 导航与首页

```text
动态 O(mui) / omui → 首页
核心特色
  UI 组件
  基础动画
  风格化
  统一接口 × 多语言
创意 demos
Agent 原生
  使用 / 开发 / 设计（页内切换，有深链接）
文档                         开始使用
```

- 核心特色是一个可用鼠标、触摸和键盘打开的导航组，Escape 关闭并恢复焦点。桌面保留简短一排；窄屏进菜单。Agent 原生是顶级产品入口，“连接”是独立工具入口，二者职责明确。
- 首页只保留短定位、一个动态 O(mui) 主演示、进入组件和创意 demos 的两个去向。主演示用同一个对象的像素／结构／脚本 agent 操作展示统一语义；一次只看一个视角，初始不展开 JSON、参数、语言代码与诊断面板。
- 标志由代码中的共享几何绘制；导航中的短组装和悬停反馈、首页较大的展开／组装共用来源。初始短运动结束后可以空闲；系统减少动态效果、用户 off/reduced 和离屏均受尊重。
- 原来的完整发布任务工作台保留在 `scenes/release`，与时间线、标志构造一起进入独立场景。首页不再堆完整工具链和四段大屏。
- 官网讲“能做什么并让人试”；文档讲安装、概念、API 和限制。核心概念、实践指南、快速开始放 `docs/...`，不直接拼到首页或产品页面下方。

### 各特色页统一行为

1. 进入页面即有明确的主对象和直观演示，先用真实变化表达特色。
2. 主舞台附近提供按需打开的分类／搜索／分页目录，通常只挂载一个主样张，避免逐项往下翻完整演示。组件馆宽屏目录常驻，手机目录可展开收起；动画与创意馆默认均收起选择器。
3. 指针进入样张或 Tab 焦点进入控件：自动预览让位，真实控件直接接管。已有输入和选择保留，自动任务不得改回用户刚写的值；触摸直接使用控件。
4. 暂停、离屏、切页、off/reduced 停止自动演示；仍能正常完成任务。暂停后的运行时句柄必须允许主机停止请求动画帧。
5. 明确点击“查看详情”才显示状态、参数、语言、代码或语义。复制内容必须准确标注“接口表达式”“动画配置”或“完整工程”，不把短表达式当作可独立编译的工程。
6. 详情具有深链接、返回概览、重置和键盘路径。浏览器前进／后退跟随路由，不刷新整个应用；中文、英文状态和路由对齐。

## 2. 动画基础设施与组件默认动画

**组件只画状态；动画由统一槽解析。** 不在组件里增加私有计时器、逐帧脚本或各自插值公式。

- 可组合操作包括绘制匹配、字形匹配、透明度衔接、抬升、面板抬升、缩放、部件局部缩放、拉伸、阅读顺序错开、距离排序。配置的 `compose=[...]` 表示同时组合；槽的候选列表表示按档位回退，二者不可混淆。
- 40 个基础设计是不同目标和任务的可复用设计，下面逐项列出。不能把 40 个缓动名字当作 40 项设计，也不把同一个设计的中英、主题、速度重复计数。
- 同一播放器控制端点、暂停、反向、速度、归零和进度寻址。嵌套组件原有默认动效保留；一次变化收集实际活动句柄，按共同秒数控制，逐帧只读锚点，避免逐帧创建句柄数组。
- 默认配方覆盖当前 36 类基础组件及 actor log，共 37 类。类型／形状／用途决定组合，显式节点设置、应用规则、风格包和框架默认具有明确优先级，不能因增加类型规则而屏蔽风格或应用覆盖。

| 组件类别 | 默认变化与理由 | 应验证的实际表现 |
|---|---|---|
| Button、Avatar | 操作反馈、身份内容连续变化 | 焦点／按压可感知；不无目的跳动 |
| Toggle | 轨道、滑块和文字由同一状态驱动，匹配＋轻拉伸 | 滑块连续移动，快速切回不跳变 |
| Checkbox、Radio、Chip | 标记匹配＋局部缩放／淡入 | 勾选标记绕自己中心出现，不围绕整条长标签缩放 |
| Tabs、Segmented、Select、Combobox | 选择指示匹配＋轻拉伸，弹层有独立出入 | 指示器和目标一致；焦点进入／返回正常 |
| Slider、Range slider、Progress | 数值几何变化匹配；拖动即时 | 拖拽命中跟手，视觉不能拖着真实输入走 |
| Number input、Badge、Pagination、Time picker | 数值与字形连续，短时间收敛 | 数字与实际状态一致，中途再次修改可接续 |
| Text box、Code editor | 内容更新即时；焦点环和出入仍有默认动画 | 打字、输入法和粘贴不回放过期文本；已有焦点 morph 能被内容更新取消 |
| Accordion、Tree、Grid、Split view、Tag input、Breadcrumb、Actor log | 层级／布局／插入移除由结构配方统一处理 | 对象 ID 保持，展开让位，增删顺序清楚 |
| Card、Skeleton、Color picker | 表面、颜色、内容过渡；浮层另走面板槽 | 不用阴影／颜色掩盖错误布局或输入状态 |
| Tooltip、Toast、Alert | 短通知的匹配＋抬升＋淡入 | 入场与离开清晰，关闭后可回到原对象 |
| Dialog、Drawer、Popover、Date picker | 面板匹配＋轻缩放／抬升 | 正确摆放、裁切、焦点、Escape；组件样张浮层局限于舞台 |
| Stepper | 步骤状态、连线和文字统一接续 | 进度和当前步骤一致，不用泛化淡入替代变化 |

默认动画测试必须覆盖 A／中间帧／B、打断、off/reduced、风格覆盖、作用域隔离、文字即时性和真实输入。不能只断言“motion 字段存在”。组件预览局部浮层能力放运行时公共边界机制，不在官网复制另一套弹层实现。

## 5. Agent 原生与多语言展示

| 页面 | 先展示的创意场景 | 查看详情之后 | 真实性边界 |
|---|---|---|---|
| Agent 使用 | 用户和脚本 agent 操作同一任务；有结果回执、操作记录、单条撤销 | 动作对象、参数、权限与失败解释 | 脚本明确标注；连接我的 agent 才进入真实配对，不能把演示说成外部模型自主完成 |
| Agent 开发 | 读取已挂载对象的真实语义，执行动作并再次读回 | 公共接口、请求／返回、复现表达式、接入方法 | 不虚构协议命令；不把模拟输出伪装运行时读回 |
| Agent 设计 | 调整实际布局、间距与局部风格；把用户值带进设计提示词 | 作用域、提示词、可复现参数和设计方法 | 用户文本 origin 标为 user_content；风格影响当前对象，官网壳稳定 |
| 统一接口 × 多语言 | 同一个真实工作台边操作边呈现共享语义 | C++／TS／Python／Lua 对应表达式与当前值 | 切语言不重建业务状态；未运行的宿主不声称已经执行；完整消费者工程验证另列 |
| 风格化 | 同一组控件默认外观与局部材料并排对照 | 圆角、参数、作用域、代码与低档替代 | 左侧默认样张与导航不受右侧风格切换影响 |

## 6. 并行实施与合入顺序

| 执行包 | 负责范围 | 独立本地检查 | 合入依赖 |
|---|---|---|---|
| A 动画 worktree | 40 基础场景、统一播放器与公共配置 | 目录唯一性、真实端点／中间帧、交互／寻址、媒体 | 公共 motion 配方和 site 接口 |
| B 组合 worktree | 20 组合、风格／统一接口／Agent 页面 | 真实效果命中、输入模型、语义读回、撤销、中英窄屏 | 共享样张模型、局部作用域、统一播放器 |
| C 组件 worktree | 组件馆重排、首页与共享动态标志 | 默认控件、搜索／选择／详情、焦点／鼠标切换、暂停／空闲、关键画面 | 运行时默认配方与局部浮层 |
| 根集成 | 默认动效、运行时修复、导航／路由、静态首帧、文档、整站真实验证 | dev／release、浏览器点击链路、尺寸／中英、性能和内存 | A/B/C 可独立继续，无需等其他平台 CI |

每个 worktree 只提交自己负责的文件，禁止共享目录中互相覆盖。合回 `openmui-design` 后做一次完整本地检查，签署 commit，推送到现有 PR #1；不另开 PR，不合并主分支。构建限制并发与磁盘占用，复用合法缓存；修改构建工具时附重复构建证据，避免“无变化也全量重编”拖慢推进。

推进顺序：默认配方与播放器合同 → 三路独立内容／布局 → 导航和静态／交互路由整合 → 本地 release 浏览器与视觉收口 → 维护者 review。任一步的跨平台 CI 排队不阻塞其他独立步骤。

## 7. 本地验收与完成记录

- **数量和复用**：40 基础设计、20 创意组合逐项盘点；不按主题／语言重复计数；可复制配置能施加到其他真实目标。
- **功能**：鼠标真实点击、Tab／Escape、触摸等价路径；预览转交互；详情、深链接、前进／后退、复制、重置、撤销。不能只用直接设 signal 代替全部交互验证。
- **动态**：看实际连续帧／动态 WebP／浏览器回放；端点正确不等于中间帧正确。暂停后帧请求空闲，离屏／切页清理，减少动态效果和用户设置均检查。
- **视觉**：英文／中文，360、390、768、1280、1440；标题与标志比例、手机 CTA、溢出、裁切、浮层和长文字逐项查看真实图片，自动布局检查辅助而不替代审图。
- **发布构建**：本地真实 release 构建和浏览器交互为检查点核心。需要的 sanitizer 与回归只在相关改动后运行；明确记录设备／编译器／版本和失败边界。
- **加载**：重新测压缩传输、首帧、字体就绪与帧时；新内容不能挤爆既有 5 MB 预算。首帧构建图、真实树几何加载与共享字体交付的后续实现见总方案 §15.13–15.15；完整按页／按输入资源交付仍需继续。
- **异步 CI**：如实记 Linux／macOS／Windows 的状态；CI 发现实际跨平台问题后修，但不把等待排队或尚未跑的平台当作本地开发的前置阻塞。

| 项目 | 本轮实现检查点 | 仍需 review／关闭条件 |
|---|---|---|

## 8. 最新补充：以体验收口，再扩展场景

本节基于 `78f7eda` 的源码、已有门禁和实际图片复核制定。它细化维护者最新要求，**本节中的新增场景和修复目标尚未实现**；§7 的通过记录属于此前检查点，不是本次文档修改新跑出的结果。原始功能数量、完整产品体验、最终美术分别判断。

### 8.1 导航与页面职责

维持 §1 的层级：**核心特色 / 创意 demos / Agent 原生 / 文档**，品牌回首页，“开始使用”为明确 CTA。Agent 原生是与核心特色平级的产品入口，使用／开发／设计是其内部分流。不要再在核心特色下复制一份 Agent 入口。连接、检查与设置是工具，不扩成新的产品栏目；窄屏放进菜单，连接入口在 Agent 使用页仍可直接找到。

- 首页只回答“omui 有什么不同，接下来去哪”。一段短主张、一个代码绘制的动态 O(mui)、两个主要去向足够；完整发布工作台留在场景页。
- 核心特色回答“这项能力如何工作”。一个主舞台、一个有界目录、按需详情；安装、概念长文、API 留在文档。
- 创意 demos 回答“这些能力组合后能做什么”。保留 §4 的 **20 个独立任务**，不把组件皮肤轮换、语言变体或不同播放速度另算一项。
- Agent 原生回答“我的 agent 如何使用、开发和设计真实界面”。先给任务和结果，再解释语义、动作、权限与方法。
- 文档负责安装、公共接口、语言支持矩阵、限制和排错。特色页可以链接对应文档，不复制整篇指南在主演示下方。

现有地址 `#/components`、`#/motion`、`#/styles`、`#/interface`、`#/demos`、`#/agent/use`、`#/agent/develop`、`#/agent/design` 保持有效，中文使用 `#/zh/...`。九个新增 Agent 场景未来需要各自可恢复的地址；具体子路由随路由契约实现，不把当前尚不支持的链接发布成可用入口。

### 8.2 每个页面的开场应看到什么

下表是下一批页面验收目标，不能只用标题或说明文字代替演示。开场都使用真实组件和状态；自动预览有明确边界，真实连接和外部动作由用户主动启动。

| 页面 | 开场的一个直观镜头 | 可以马上做的事 | 进入详情后才出现 |
|---|---|---|---|
| 首页 | O 内的 mui 展开再组装，同一对象切换像素／结构／agent 视角；一次只突出一个视角 | 拆开／组装标志，进入组件或创意馆 | 标志几何、完整 SVG、动画结构去独立构造页 |
| UI 组件 | 一个紧凑的任务卡，开关、勾选、进度与弹层体现各自默认动效；焦点反馈清楚 | 直接勾选、拖动、打开面板；目录换到另一真实组件 | 状态矩阵、部件、契约、语言、完整例子与局限 |
| 基础动画 | 同一组具名对象从列表排成卡片，位置、文字和层级连续 | 接管对象；选择另一基础设计；暂停／重播 | 40 项的组合操作、寻址、反向、速度、端点和可复用配置 |
| 风格化 | 默认与一种材质表达同一数据；改变一个控件，两边状态一致 | 换材质、改实际值；窄屏同位置切换对照 | 效果参数、作用域、档位、回退与源代码 |
| 统一接口 × 多语言 | 对一个真实工作台操作，当前值与语义结果同步变化 | 编辑、执行、撤销；业务状态不因查看语言而丢失 | C++／TS／Python／Lua 表达式及分别验证的运行结果；未执行的语言明确说明 |
| 创意 demos | 默认一个有用途的精选组合，直接看见组件、运动、材料共同作用 | 完成一次小任务；换场景；重置 | 三维配方、可调项、代码、完整工程出口及限制 |
| Agent 使用 | 人和脚本 agent 接力完成本地任务，出现回执与可撤销记录 | 接管任务、停止预览、撤销；主动连接自己的 agent | 动作对象、授权范围、失败、连接方法与精确请求 |
| Agent 开发 | 读取 → 修改 → 再读确认，结果在界面上发生 | 改期望值、运行一步、看到一次真实失败再修正 | 协议、请求／返回、稳定 ID、断言与复现工程 |
| Agent 设计 | 同一任务由宽屏排为窄屏，内容、焦点与动作仍可用 | 调布局或切对照；实际输入和选择保留 | 约束、布局参数、局部材料、提示词、代码及应用差异 |

首页建议短预览只跑一轮，然后静止；确切节奏随连续帧审图调整。导航标志可以短组装、聚焦／悬停反馈，不需要永远旋转。减少动态效果时展示清楚的静态结果，功能入口仍在。

### 8.3 渐进披露是统一交互契约

| 层次 | 默认内容 | 进入／离开方式 | 状态要求 |
|---|---|---|---|
| 概览 | 标题、短说明、一个动态主对象、目录入口、少量操作 | 首次进入；详情有明确返回 | 不挂载整页代码、完整参数和所有样张 |
| 交互 | 同一对象成为可操作的真实组件 | pointer 进入舞台、Tab 焦点进入、触摸首次操作即接管 | 接管先取消待执行的自动步骤，再派发输入；离开后不擅自恢复预览 |
| 详情 | 参数、原理／方法、语义、语言、代码和带走材料 | 明确“查看详情”；保留深链接及浏览器返回 | 不重置用户数据；返回焦点到原入口；手机不把长代码挤在演示旁边 |

自动播放不得在用户打字、拖动、组合输入或使用弹层时重置状态；聚焦到目录和导航不应误触发舞台操作。切页、后台、离屏、暂停与 off/reduced 都取消待执行的自动任务；回到页面仍保留用户值。重播需要明确操作，不能在用户移出区域后突然自动接管。

目录选择只是切换主样张，不把 36 类组件、40 个基础设计或 20 个组合全部向下展开。桌面可以保留窄目录与宽舞台；手机使用可收起选择器。风格对照在窄屏优先同位置切换默认／材质视图，保留一个共享模型和明确当前视图，不把两个表单硬塞进半宽。

### 8.4 Agent 原生：三条路径、九个有区别的场景

以下 **9 项为本方案新增的场景目标**，不是维护者另加的数量硬指标，也不抵扣 §4 的 20 项创意组合。先交每条路径的主演示，再做扩展。各场景默认只呈现任务与效果，“原理／方法／实现”在详情中展开。

| 路径 / 场景 | 任务与招牌镜头 | 揭示的原理与方法 | 操作与验收 |
|---|---|---|---|
| 使用 U1 · 人与 agent 接力 | 人写下一项待办，脚本 agent 审阅并完成，记录落到同一任务卡 | 人与 agent 面向同一语义对象；先读当前状态再执行动作 | 在自动步骤之间接管并改值，后续步骤不得覆盖；动作有真实 actor、结果与撤销 |
| 使用 U2 · 随时停止 | 处理本地收件项时停止，剩余项保持待办 | 取消待执行动作与回滚已完成动作不同；结果可观察 | 停止后无残留定时步骤；已完成项保留；用户明确恢复后才继续 |
| 使用 U3 · 本人确认 | agent 整理好决定，由人完成受保护的确认 | 运行时拒绝 agent 的本人专属动作；授权不靠提示词约定 | 发出实际 agent 请求并得到拒绝，模型不变；人点击后才改变本地状态；不伪装真实发送／支付 |
| 开发 D1 · 读改验闭环 | 读取字段、改变字段、再读确认；界面与返回值同步 | 稳定 ID、公共 action、以读回值断言 | 先运行错误期望看到失败，再真实修改并通过；展示实际响应，不拼预设 JSON |
| 开发 D2 · 失败可解释 | 尝试对只读／不允许的对象操作，再选择可用动作 | 语义状态、动作发现、运行时决定与错误反馈 | 拒绝时零副作用，修正目标或动作后成功；详情能关联失败请求和当前对象 |
| 开发 D3 · 带走回归 | 把当前任务整理为可重放的最小测试 | 初始状态、动作序列、结果断言和版本是复现单元 | 导出后在干净消费者工程真实运行；短表达式继续标为表达式，不标完整工程 |
| 设计 S1 · 布局保持语义 | 同一编辑台宽窄变化，字段和选中项连续移动 | 结构 ID 不变，布局变化经公共 motion 槽完成 | 中英长文本、窄屏、输入焦点均保留；切布局不重新建业务模型 |
| 设计 S2 · 材料与降档 | 同一任务切换纸墨／玻璃等材质，再切低档显示 | 作用域与效果插件；低档替代保持信息与操作 | 只影响样张；站点壳稳定；真实效果命中，有 reduced/off 与低档证据 |
| 设计 S3 · 约束到应用 | 将当前尺寸、部件、间距和用户数据交给自己的 agent，再预览设计改动 | 角色、约束、数据来源与可复现差异；人决定是否应用 | 提示词用真实当前值并标记 user_content；脚本预设与真实模型结果分清；应用、撤销、重置可验证 |

U1／D1／S1 为首批三个主演示，U2／U3／D2 为第二批，D3／S2／S3 随完整工程出口、效果分档与真实 agent 路径交付。现有想法台可以作为 U1／D1 的基础模型；换三个标签或三段说明不能同时算九个场景。

所有脚本演示明确标为“脚本模拟”，不能把真实 runtime action 等同于外部 LLM 自主完成。自己的 agent 从真实“复制提示词／配对／自检”路径进入；真实 LLM 的操作录像与任务完成率仍按 R4 单独验收。更早记录的任意动作回溯、分支和冲突恢复继续依赖底层能力，不用简单 Undo 冒充已经完成。
