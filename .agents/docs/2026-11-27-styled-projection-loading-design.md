# 带样子的投影与引擎的加载策略（UI5）

状态：草案，待 review（2026-11-27）。决策：D-288（提议）。上级：[0.1.0 顶层方案](2026-11-26-release-0.1.0-top-level-design.md) 的 D-259、D-260、D-284；上游：[文档层](2026-11-26-web-document-layer-design.md)（UI3、UI4）；下游：ST2（每个路由的投影与加载策略）、ST3。

## 1. 事实（2026-11-27）

- 一个页面在程序接管之前显示的是静态投影：同一份映射写出的 HTML（UI1），样子是固定的一段样式——系统字体 16 px、行高 1.6、最宽 760 px。接管之后是画布画的。两个样子不同（顶层方案 §1.4 的“接管前后是两个样子”）。
- 接管之后文档层与静态投影是同一批元素（UI3：按 id 接手），文字透明，画布画看得见的。
- 一篇 10 节的文档（完整播放器，未切分）：页面 53.0 KB（gzip 12.5），启动脚本 gzip 54.5 KB，程序 gzip 2.34 MB，两份字体 1.02 MB。读者要读的内容在前 12.5 KB 里。
- 引擎现在总是立刻加载（`<script defer>`）。

## 2. 三级次序（D-185）

**① 原始性：样子从引擎自己的第一帧量出来。** 构建时页面本来就在无头宿主上求值一次（写静态投影）。那一帧里每个节点的样子是已知的事实：文字的字体、字号、字重、行高、颜色、对齐；它与上一个兄弟的间距、在父节点里的缩进、最大宽度；它自己画的底（纯色、圆角、边线）。把这些量出来写成样式，文字用引擎带的同一份字体文件，浏览器按自己的流排版——不同宽度下不需要引擎也能重排，而换行与引擎的几乎一样（同一份字体、同样的宽度）。不手写第二套样式，也不引入第二个渲染器：样式是第一帧的投影，由像素比对约束。量不成样式的画（矢量图形、图片、渐变、效果）用同一份显示列表按节点导出的 SVG 片段（mrender 的 SVG 输出，顶层方案 §5 已列）。

接管是逐元素的交接：同一个元素，文字从看得见变成透明，画布在同一处画出同样的字。差多少可以按词量（UI3 的探针已经在量词与墨迹的偏差）。

**② 前沿加组合。** 查过的（2026-11-27）：

| 做法 | 现状 | 取舍 |
|---|---|---|
| HTML-in-Canvas（WICG；把 DOM 画进画布） | 只在 Chromium 的 origin trial 里，接口名在 2025–2026 年间改过两轮（`drawElement` → `drawElementImage`／`texElementImage2D`，`layoutsubtree` → `content="drawable"`）；Firefox 与 Safari 没有表态 | 不依赖。它是反方向（DOM 进画布）；我们是画布的内容投影成 DOM，三个引擎今天都能用 |
| 岛屿与可恢复（Astro 的 `client:idle`／`client:visible`、Qwik） | 成熟 | 三档加载策略取这个思路；这里的“岛”是整块画布，“恢复”是把文档层读回成文档（D-284），不带序列化的状态 |
| 事件重放（先记下交互，代码到了再回答） | Qwik、Wiz 在用 | 取：`interaction` 策略下，引发加载的那一次按下记下来，引擎到了由文档层已有的激活通道回答 |
| View Transitions（两个状态之间由浏览器做过渡） | Chromium 与 Safari 有，Firefox 较新 | 第一步不用；样子对齐之后交接本身不需要过渡 |

**③ 低线。** 文档站的常规做法是服务端渲染加水合：前后是同一个渲染器，样子天然一致。画布框架（Flutter Web）接管之前没有内容，查找、选中要靠另外隐藏的文字。我们的低线是“接管之前可读、之后不跳”，目标是偏差按词可量并且有界。

## 3. 设计（D-288）

### 3.1 样子

- `omui.semantic` 在写投影时可以带上样子：每个节点一份量出来的样式（去重成类），连同引擎字体的 `@font-face`。量的来源是那一帧的运行时（文字的样式、行盒、节点的盒子与它自己画的底），不是组件各写一份。
- **三个来源，都是运行时已有的事实**（查过，2026-11-27）：
  - 布局：每个节点的布局样式（`mlibs.layout` 的 `Style`）本来就是 CSS 的弹性盒与网格模型——方向、间距、内外边距、宽高与最大最小、伸缩、对齐、定位。写成 CSS 是一比一的投影，浏览器照同一个模型排，不需要从盒子反推。
  - 文字：显示列表里每个节点的字形命令带着字体、字号与颜色；行高取行盒的高。
  - 节点自己画的底：显示列表里落在节点盒子上的填充、描边与阴影（第 3 步）。
- 宽度相关的不写死：换行交给浏览器。固定大小的（图片）写宽高比。
- 第 2 步定下的写法（2026-11-27）：
  - 画了文字的节点写成块（`display:block`），文字与其中的链接照行内流排；“叠放”容器写成一格的网格，格子就是容器自己的盒子（`grid-template:minmax(0,1fr)/minmax(0,1fr)`），里面的滚动视图才滚得动、不被内容撑高。
  - 一个节点的文字取它大多数字形的字体、字号、颜色；其余的字形段（链接的颜色、行内代码的字体）按它们在文字里的字节范围写在各自的行内元素上。字形命令带着每个字形的字节位置，不靠坐标对。
  - 字距（`letter-spacing`）：那一帧最后一行的宽度，减去同一段文字不带字距排出来的宽度，除以字素数。
  - 量样子的那一帧什么都不略过（`Runtime::set_draws_unseen`）：平时滚动视图只画视口前后各一屏，更远的节点没有字形可读。
  - 页面的基础规则只有一处（Web 包的页面）：盒子按边框算、清掉浏览器自带的边距与底色、字体与颜色继承、`font-optical-sizing:none`（引擎按字体的默认光学字号排，浏览器会按字号自动换）、滚动视图不显示浏览器的滚动条（它占 15 px 宽，引擎的滚动条浮在内容上）。弹性项的最小尺寸保留 CSS 的 `auto`，`mlibs.layout` 算的是同一个（Flexbox §4.5）。
  - 带“复制”按钮的代码块：节点的盒子是包住 `pre` 与按钮的一个元素，按钮按它定位。
  - Markdown 的文字块与代码块的高度不再向上取整到整像素：块高等于它的各行之和，与浏览器里同样几行的块一样高。取整时每段多出不到 1 px，往下累积（10 节的文档到底差约 10 px）。
- Web 包的页面在有样子时不再套那段固定样式。
- 深浅色：主题跟随系统偏好时（UI4），浅色与深色各量一帧，合成一份样子——两帧里值不同的声明改用自定义属性（`--o0`、`--o1`……），浅色的值写在投影的根上，深色的值由页面放进 `prefers-color-scheme: dark`。不跟随的主题只量一帧。
- 第 3 步定下的写法（2026-11-27）——节点画在自己盒子上的东西，读那一帧的显示列表里节点自己的命令（节点自己的坐标，`NodeFrame` 说它的盒子）：
  - 铺满盒子的第一个纯色是 `background-color`，圆角是 `border-radius`；贴着盒子边缘内侧的描边是一圈内阴影（`box-shadow: inset 0 0 0 宽度`，不占布局）；盒子的阴影是 `box-shadow`；整个节点的变淡（禁用）是 `opacity`。
  - 其余的色块与渐变是背景图层，按画的次序叠。一条边与盒子的边重合的，随盒子走（引用块侧边的竖条随块变高）；不贴边的小圆角形状（列表的圆点）是一张按原位置摆的小 SVG。线性渐变的角度与色标按 CSS 的渐变线换算，径向渐变按圆心与半径。
  - 不写成盒子的画的：画了文字的节点的局部色块（链接的下划线、行内代码的底——页面上是元素自己的事）；滚动视图的局部色块（它的滚动条，位置随滚动）。

### 3.2 加载策略（D-260）

每个页面一个值，三档都支持：

| 档 | 什么时候取程序 | 适合 |
|---|---|---|
| `eager` | 立刻（今天的行为，默认，直到有数据再定文档页的默认值） | 应用 |
| `idle` | 页面载入并空闲之后 | 文档：先读，稍后有交互 |
| `interaction` | 读者第一次操作一个只有程序能回答的元素（按钮、输入框、开关……），或页面自己调用 `omuiLoad.start()` | 只读的文档；可能始终不取 |

- 取程序之前页面是完整可用的文档：自己的滚动、查找、选中、链接、打印。**阅读不算操作**：滚轮、滚动的按键、选中、查找、点链接都不取程序——否则“只读的文档可能始终不取”就不成立。
- `interaction` 下引发加载的那次按下，记下它的节点（投影元素上的 `data-omui-target`）；程序呈现第一帧后由文档层的激活通道回答一次（`omuiLoad.takePress()` 只交出一次）。落在链接上的按下由浏览器自己处理。
- 记下的只是一次可信事件（`isTrusted`）落在哪个节点上，页面脚本合成的事件不记。页面里的脚本本来就能包住监听器，这条通道不比现有的边界更宽；它不经过 Agent 的总线。
- 页面的加载状态多一个阶段 `waiting`（`omui-load` 事件与 `omuiLoad.phase`），等待时不显示加载中的占位。
- 策略是页面的数据：先是 Web 包的一个选项，ST2 里成为路由表的一列。

### 3.3 接管时读者的位置

读者在程序到来之前可能已经往下读了。程序在第一帧显示之前每帧向页面问一次“读者把哪个视图滚到了哪”，页面按已有的滚动通道回答，所以第一帧就画在同一处；第一帧显示的那一刻页面再记一次，文档层接手那个视图时若与程序的不同，以读者的为准并告诉程序。投影的元素被文档层接手时，样子写的行内样式到此为止（文档层按那一帧摆它）。

### 3.4 不变的

- 文档层（UI3）、接手的条件（程序确实呈现了一帧）不变。
- 不做 HTML 模式（D-259）：样子只是第一帧的投影，没有交互与动画；可操作的东西在引擎到了之后才是活的。

## 4. 验收与测量

| 量 | 怎么量 | 界 |
|---|---|---|
| 接管前后词的位移 | 同一页、同一宽度，接管前投影里每个词的盒子与接管后文档层同一个词的盒子之差；1280、768、390 三个宽度；Chromium、Firefox、WebKit | 先量，再钉（目标：中位数在 1 px 内，换行不同的行数为 0） |

- 768 与 390 宽没有另量样子：浏览器照同一份布局模型自己重排，结果与引擎在那个宽度排的差不到 1 px。

- 据此钉的界：词位移的中位数 ≤ 1 px、最大 ≤ 2 px，换到另一行的词为 0。
- 这一步的探针还量出文档层（UI3）的三处偏差，一并修了：带空行的代码块没有按行摆（空行宽度为 0 被当成没画），行尾跟在链接后面的词掉到下一行，代码行的缩进与首词算成一个词（首词偏 12 px）。
- 样子的代价：页面 64,247 字节（gzip 13,480；不带样子时 53.0 KB、gzip 12.5 KB）；它用的两份字体在程序之前就取，843,896 + 174,896 字节。字体是大头：只带投影用到的字的子集（CF3）之后再量，量过再定带样子是否是文档页的默认。
- 未做的（第 2 步时）：按钮与代码块的底（第 3 步已做）；“复制”按钮在投影里写的是它的名字（Copy code），画布上是 Copy；浏览器的滚动条隐藏后，接管前没有可见的滚动条。

实测（第 3 步，2026-11-27；同样的三个浏览器、三个宽度、页面顶部与滚到 700 px，18 组）：词位移与第 2 步相同（中位数 0.1–0.8 px，最大 1.0 px，换到另一行的词 0）。偏好深色的读者在程序之前看到的是深色那一帧的颜色（此前是深底上的浅色主题的字）。页面 66,424 字节（gzip 13,914；第 2 步时 64,247 与 13,480）。接管前后的画面还差的：

- 行内代码的底、有序列表的序号（是节点画的文字与文字旁的局部画，不在元素里）；路径画的图形（图标、勾）——按节点导出的 SVG 片段，mrender 的 SVG 输出是它的归属，未接；
- “复制”按钮的文字：投影写的是无障碍名字，画布画的是可见标签；语义节点没有“可见标签”一项，是规范的增补；
- 界的机械检查是 `omui-devtools check takeover --page <构建产物>`（无头 Chromium，程序的 `.wasm` 由检查自己的服务端压住，量完投影再放行；三个宽度 × 页面顶部与滚到 700 px；报告 `target/takeover.report.xdef.json`）；接进 CI 的车道随第 4 步用 oweb 的文档模板做夹具；Firefox 与 WebKit 的数是这里的探针量的。
- 检查第一次跑量出一类读者的偏差：把每个字形的前进量取整到整像素的浏览器（Linux 上 full hinting 的 Chromium，无头 shell 的默认）里，投影的行宽与引擎的不同——16 px 正文的一行短 5.5 px（682 对 687.5），13 px 等宽代码的一行长 4%（940 对 902.4），接管时词位移中位数 0.8–1.9 px、有词换行。修在样子的样式表里：根上 `text-rendering:geometricPrecision`（按字形轮廓自己的前进量排，与引擎一致），控件继承它（浏览器自带的样式表把按钮的这一项设回 `auto`，按钮窄 2 px、后面的词跟着偏）。修后无头 Chromium 六组：中位数 0.13–0.35 px，最大 1.0 px，换行 0；有界面的三个浏览器 18 组重量：中位数 0.1–0.8 px，最大 1.0 px，换行 0，与修前相同。界没有动。

实测（第 4 步的后半 = ST2 第 5 步，2026-11-27；oweb 的文档模板带引擎 `--engine`，阅读程序 `oweb.reader` 从页面自己的 HTML 读回；无头 Chromium 159，`check takeover --path`，七个路由 × 1280／768／390 × 页面顶部与滚到 700 px，共 42 组）：

- 界内 24 组：`/start/`、`/agent/` 各六组全过（中位数 0.13–0.41 px，最大 0.91 px，换行 0）；`/` 五组、`/zh/start/` 四组、`/ui/` 滚动后的三组。所有词都按 id 对上（未匹配 0，中文页有 2–5 个词因为按行切分不同不参加比较）。
- 界外 18 组，各有其主：`/ui/` 顶部三组差 24 px——页面里的图片阅读程序没有画（引擎在 Web 上不取页面的图片，盒子高 0；欠项）；`/zh/` 六组与 `/zh/start/`、`/` 在 390 宽的三组差 1.4–3.4 px——夹着拉丁词的中文行，引擎逐行按用到的字体定行高，CSS 是统一行高，长页面在窄窗口里累计；文档层里长中文串内部的拉丁词位置只准到约 3 px（欠项）；`/reference/ops/` 六组——红 162（表格从不变窄，这张表在引擎里五千多像素宽），中位数 0.41 px，离群的是它的单元格。
- 检查的量法改了一处，界没有动：词的纵向位置取“它所在那一行的中点”（文档层用引擎的行盒；投影按块的行高算出它落在第几行），不取词自己字形盒的中点——后者随字体而异，同一行里的行内代码与回退字体画的字会假报 2–4 px。
- 这一轮由检查找出并修掉的：链接这类自己量尺寸的控件，引擎的盒子是“文字向上取整再加下划线的 2 px”，样子写出它的最小高度与不换行（链接组件同时报出自己的文字行，文档层与样子都按它摆）；不增长的行内项按 basis 计入行宽（表格的列）；持有块级子项的节点（列表项）不因为自己画了序号就改成块；异体字的行内片段不撑高所在的行；表头靠左（浏览器自带样式居中）；图片写出宽与宽高比。文档层的两处：第一批节点先挂进页面再设置滚动位置（否则画布在读者的位置、文档层停在顶部）；词盒内的文字不再跟着单元格的对齐再对齐一次。
- **图片由程序画出之后（同日，同一量法）：界内 27 组**——`/ui/` 六组全过（中位数 0.35–0.36 px，最大 0.43 px）。做法：程序先向页面要图片的像素（文档里已有的 `<img>`，浏览器解码，`Runtime::set_picture_reader`），页面等文档里的图片到齐再取程序；构建时由文件得到图片的尺寸（SVG 取 `width`／`height`，否则 `viewBox`）；Markdown 里单独成段的图片按自身大小，只在比栏宽时收窄（此前被拉到整栏宽）。检查自己的服务器此前把 `.svg` 当无类型字节送出，浏览器不画，已改用 `mlibs.http` 的类型表。余下界外 15 组：`/reference/ops/` 六组（红 162）、`/zh/` 六组、`/zh/start/` 两组、`/` 一组（中英混排的行高）。欠项：图片的像素是它的自然尺寸，高密度屏上 SVG 不如页面里的清晰；桌面上的 SVG 图片仍不画。
- **加了带现场示例的第八个路由之后（同日）**：`/live/` 顶部三组在界内（中位数 0.14–0.18 px，最大 0.43 px），示例在画布上按下后有回应（`check takeover` 新加的一步）。同时暴露红 163：导航折成两行，英文页里那个中文链接的字体（4.15 MB，按语言延后）在程序第一帧之后才到，第一帧的导航少一行（40 px），滚到短页面底部的读者位置差 40 px——`/start/` 在 390 宽、`/ui/` 与 `/live/` 在 1280／768 宽的滚动行出界。修法：页面自己的字体（按站点所显示字符裁好、浏览器已取到）作为程序的第一份字体，整份按需。阅读程序带视图文档后 wasm 7,920,429 字节（gzip 2,596,334；此前 7,512,316 与 2,476,705）。
- **红 163 修掉之后（同日）：八个路由 48 组里 34 组在界内**——`/`、`/start/`、`/ui/`、`/agent/`、`/live/` 各六组全过（中位数 0.13–0.41 px，最大 0.91 px）。做法：页面自己的字体是程序的第一份字体（世界页面的 `omuiFaces`），世界的整份字体按需；第一帧之后取的字体由 5,170,260 字节变为 0，接管前也不再取世界自带的 Inter 与 JetBrains Mono（1,018,792 字节）。`/` 在 390 宽滚动的那一行原先的 1.4 px 也随之进界（此前把它归为混排行高，实为迟到的字体）。余下界外 14 组：`/reference/ops/` 六组（红 162）、`/zh/` 六组与 `/zh/start/` 两组（中英混排的行高）。
- 字节：一个路由的 `index.html` 51,398 字节（gzip 13,105，预算 100 KB 之内）；引擎一份：wasm 7,506,091 字节（gzip 2,475,423）、启动脚本 211,950（gzip 53,759）。引擎这一份还没有按“阅读世界”裁剪（SDK 的 `app` 世界），是 CF 线的欠项。

实测（第 4 步的前半，2026-11-27；oweb 的文档模板，配置里 `look: true`，Chromium 159 有界面）：

| 量 | 结果 |
|---|---|
| 一个路由的 `index.html` | 首页 14,168 字节（gzip 2,694）；不带样子 7,041（gzip 2,218）。预算（可读之前 100,000 字节）之内 |
| 文档 | 带样子的页面读回的文档、它的 `index.md`，与不带样子的相同（用例） |
| 1280 宽／390 宽 | 居中的一栏（最宽 760 px）；390 宽时导航折行，没有横向溢出；浅色与深色各是那一帧的颜色 |
| 打印 | 全文都在（`look_sheet` 的打印规则：文档不留在滚动视图或窗口大小的盒子里） |
| 字体 | 页面在程序之前取它用到的每份字体：Inter 876,576、JetBrains Mono 187,208，以及为导航里两个汉字取的整份 Noto Sans SC 4,151,468 字节 |

- 样子的规则只有一个归属：`omui.semantic` 的 `look_sheet`（基础规则、深色的取值、打印）。Web 包的页面（sdk 把它写在投影之前，dist-toy 放进页头）与 oweb 的页面都用它；文档层接手元素时去掉 `data-omui-look`，规则不再作用到它。
- 根的底：根节点自己没有画底时，样子写窗口的底色（那一帧清屏的颜色，主题的 `background`）。
- **字体是这一步量出来的最大代价**，带样子因此仍是 opt-in：子集器在 `omui.gen`（工具包）里，oweb 用不到。下一步（CF3）把它移到 mlibs 成为公共能力，站点按它用到的字切字体。
- **切过之后**（CF3 第 1 步，同日）：子集器成为 `mlibs.text.subset`；站点的每份字体只留它的页面出现过的字（加上 ASCII），并去掉字形名。文档模板的三份字体从 5,215,252 字节降到 835,784（gzip 347,131）：Inter 356,452（gzip 161,097）、JetBrains Mono 97,044（gzip 44,918）、Noto Sans SC 382,288（gzip 141,116）。还大的原因：子集保留字形编号，按编号索引的表（布局表、度量、变体）不随字数缩小——为导航里两个汉字仍带 382 KB。再往下要重新编号并裁掉用不到的布局特性，或用 WOFF2；带样子在那之前仍是 opt-in。
- 未做的：引擎按路由的策略加载（第 4 步的后半：路由表里的 `load`、共用的程序、加载脚本）；宽窗口下三栏的外壳（ST2 的自己的布局）；代码块的长行在页面上被裁掉（与画布一致，默认样式表里是可横向滚动的）。

## 5. 步骤

| 步 | 内容 |
|---|---|
| 1 | 加载策略三档与按下的重放：Web 包的选项、页面脚本、用例、浏览器里量传输 |
| 2 | 最小的样子：布局、文字的字体字号颜色行高字距从第一帧量出，同一份字体；接管时读者的位置；量位移与像素差，据此定界（已做，上表） |
| 3 | 节点自己画的底（纯色、渐变、圆角、边线、阴影、不透明度）；深浅色两帧合成一份（已做）。路径画的图形按节点的 SVG 片段（未接） |
| 4 | oweb：样子随路由的投影写出（已做，opt-in）；路由表里每个路由的策略与引擎的加载（未做，ST2） |

## 6. 风险

| 风险 | 应对 |
|---|---|
| 浏览器的换行与引擎的不同（字距、连字、断行规则） | 同一份字体；量换行不同的行数，不为 0 时把行盒写进投影（按参考宽度）作为退路，只在视口与参考宽度一致时生效 |
| 样子用的字体让交互之前的传输变大 | 只带投影用到的字的子集（已有的子集机制）；量过再定是否默认带 |
| 量样子要动每个组件 | 只读运行时已有的事实（文字样式、行盒、盒子、显示列表）；组件不改 |
| `interaction` 下读者以为页面是坏的（按钮按了没反应） | 记下的按下在引擎到了之后回答；加载中有可见的状态 |
