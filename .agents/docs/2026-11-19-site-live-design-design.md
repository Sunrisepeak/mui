# 官网：一条主线，由 Live Design 做出来，设计过程就是它的视频（G4，一页设计）

2026-11-19 起草，**草案，待 review**。任务 G4（[实施方案](2026-11-18-omui-meng-implementation-plan.md)），挡着 G5、G6；提议的决策 D-252。背景：[顶层设计 §5](2026-11-18-omui-meng-top-level-design.md)（D-235 官网重做，D-236 静态 HTML 投影，D-237 Web 上的脚本）。

## 1. 要定的

新官网的内容与路由、设计过程要留下哪些镜头、预算，以及它对框架提出的要求（缺的回主线补，官网里不写引擎代码）。

## 2. 事实（2026-11-19，`d8894152`）

- 现有的官网：`site/src` 约 12,300 行 C++（顶层设计起草时连同 `site/` 其余部分计 19,079 行），内容有首页、组件墙、动效样本、风格、参考、上手。交付 3.99 MB（预算 4.0），首帧之前 1.94 MB，第一帧 1.24 s（本机）。内容多、结构复杂、有卡顿。
- 两个最小验证已完成：G0（TS 可以由页面自己的引擎运行，接口落到 wasm 的 C ABI；余下的是 G1：页面里模块求值是异步的，要一个由帧循环结清的非阻塞运行）；G3（例子 13 的 8 步设计历史回放并导出成 10 秒的 WebM：120 帧、VP9、480×420、40 KB）。
- G3 列出的缺口：影片的尺寸等于窗口（不能缩放）；字幕是步骤的原话（没有编辑）；没有 Agent 的指针与标识（D-160）；没有声音；CPU 编码约每秒 11 帧。
- 品牌：标志是 O 形轮廓内含小写 mui，由框架自己的矢量代码构造；形象 Mui 是每个像素都是矢量的像素风的猫，可与标志互相变形。

## 3. 按三级次序（D-185）

**① 原始性创新：官网不是介绍框架的页面，是框架的一次真实使用留下的记录。**

- 官网由 Agent 在 Live Design 里用 TS 做出来，过程中的每一步都是一次提交（D-151）。**同一份设计历史有三个产出**：线上的官网（历史的最后一个状态）；设计过程的视频（历史的回放，经剪辑）；可以在官网上交互地回放的那段历史本身（访问者拖时间轴，看页面怎样一步步长出来）。第三个是别人没有的：别的框架的官网放的是录屏，这里放的是可以回放、可以停在任何一步、可以看那一步的语义树的真实历史。
- **每个路由的 HTML 是同一棵语义树的投影**（D-236）：爬虫与不执行脚本的访问者拿到完整的内容；画布叠在它上面启动。
- **页面上的 Agent 入口是真的**：`window.omui` 已在；访问者的 Agent 可以读这一页的语义树、操作招牌演示。主页上那一段“Agent 在操作”的演示是回放的记录，并标明是回放（D-63：不造假的演示）。

**② 前沿加组合**：首屏的文字由静态 HTML 先出（最大内容绘制早于 wasm），画布的位置预留、布局不跳；程序按首屏用到的部分切分（已有）；脚本由页面的引擎运行，页面不带第二个引擎（D-237）。

**③ 业界做法（低线）**：每个路由是真实的地址，带标题、描述、规范地址、分享卡片、中英文互指、站点地图与结构化数据；文字可选、可复制、可页内查找。

## 4. 内容与路由

一条主线，四个地方。作品的展示、组件墙、动效样本这一版都不上，以后再加（现有的实现留在仓库里作为验证线的测试）。

| 路由 | 一句话 | 内容 |
|---|---|---|
| `/` | omui 是什么 | 标志与 Mui；一句话的定义；**招牌过程**：一段可交互回放的 Live Design（Agent 写 TS、界面随之长出、人接手改一处、动画由 hanim 呈现）；两个去处：装上它、读文档 |
| `/start` | 装上它 | 一条安装命令；`omui new` 到第一个窗口；TS 与 C++ 两条路径各一段；每条命令是文档检查跑过的（lint `docs-code`） |
| `/making` | 这个网站是怎么做出来的 | 设计过程的视频（G6）；同一段历史的交互回放；数字：步数、用时、token（进声明台账才写） |
| `/docs` | 文档的入口 | 指向已生成的指南与参考（`omui-devtools docs` 的产物），不在官网里重排 |

中英文各一套地址，互相指向。四个路由之外的旧地址给重定向页。

## 5. 设计过程的镜头（G6 的输入）

视频约 60–90 秒，由回放生成、可以重新生成；每个镜头是设计历史里的一段，不是另拍的。

| 镜头 | 历史里的哪一段 | 要让人看见的 |
|---|---|---|
| 1 空白 | `omui new` 之后的第一帧 | 起点是一个真实的模板 |
| 2 Agent 起稿 | 首页的骨架：标志、标题、两个去处 | TS 一行行出现，界面同步长出（组件级增量求值） |
| 3 形象 | 标志变形成 Mui | 矢量与 hanim 的变形 |
| 4 人接手 | 人拖动一个间距、改一句话 | 人随时接手；源码跟着变 |
| 5 核对 | Agent 查询 `ui.explain` 确认人的改动，补一条测试 | 因果记录，Agent 不靠转述 |
| 6 回退与分支 | 试一个版式、退回 | 历史可以分支与回退 |
| 7 成品 | 四个路由走一遍，停在线上的地址 | 看到的就是线上的那个网站 |

## 6. 预算（官网的门）

| 项 | 上限 | 依据 |
|---|---|---|
| 首帧之前的字节 | ≤ 1.2 MB（D-247 的低线是 1.1 MB，取更严的作目标） | 顶层设计 §4.2 |
| 交付的总字节 | ≤ 2.0 MB | 现有 3.99 MB；内容少了一多半 |
| 首屏文字可见 | ≤ 1.0 s | 静态 HTML |
| 程序的第一帧 | ≤ 1.5 s（20 Mbit/s、40 ms 的连接） | 现有 1.24 s 本机 |
| 帧时间 | 真实浏览器里 p99 ≤ 16.7 ms；长于 33 ms 的帧为零 | D-187 |
| 不执行脚本抓取 | 每个路由的文字与语义树的文字一致 | D-236 |
| 界面的 C++ | 只有性能敏感的部件；页面与文案全是 TS | D-235 |

## 7. 对框架的要求（回主线补，各有任务）

| 要求 | 现状 | 任务 |
|---|---|---|
| Web 上运行应用的 TS | G0 可行，G1 未做 | G1 |
| 每个路由的静态 HTML、元数据、站点地图 | 运行时有语义 DOM 的镜像；构建时的投影没有 | G2 |
| 影片的尺寸与窗口无关（按比例输出 1080p） | 没有 | G6 的第一步，归视频工具 |
| 字幕可编辑；Agent 的指针与标识进回放（D-160） | 没有 | G6，归设计器的回放 |
| 页面里的交互回放（时间轴、停在任一步） | 桌面的设计器有；Web 上的页面部件没有 | G5 的一部分；做成组件，官网是第一个使用者 |
| 编码速度（CPU 约每秒 11 帧） | 90 秒的 1080p 约需十几分钟 | 可以接受（离线生成）；不作为门 |
| 声音 | 没有 | 这一版的视频不带声音，写明 |

## 8. 任务与验收

| 任务 | 内容 | 验收 |
|---|---|---|
| G5 | 四个路由由 Agent 在 Live Design 里用 TS 做出；设计历史提交在仓库里；交互回放的部件 | §6 的预算在本机通过（帧时间一项见下）；`media --check site`；可被检索的检查通过 |
| G6 | 影片的缩放输出；字幕的编辑；指针与标识；§5 的七个镜头剪成视频 | 视频由一条命令从历史重新生成，两次生成的帧哈希一致；放在 `/making` |
| G7 | README 与首页的每句对外的话有 `claim` | lint `claims` |

验证状态：字节、首屏时间、不执行脚本的抓取在本机真实验证（无头浏览器）。**真实浏览器里的帧时间**在本机只能用软件光栅的浏览器量（不算性能数据，AGENTS §2 第 10 条），所以这一格在接通桌面会话或维护者手上的机器量过之前标“未验证”，并附软件路径的数与推断的依据；它不挡 G5 的完成，挡的是对外写“不卡”这句话。

## 9. 风险与降级

| 风险 | 应对 |
|---|---|
| G1 做不完或页面引擎与内嵌引擎的行为有差别 | 退路：页面与文案仍是 TS，在构建时原生化成 C++（D-146）；线上先不带运行时的脚本，交互回放用预先求值的快照 |
| Live Design 做真实产品时缺能力 | 缺的回主线补并记在 `/making` 的数字里；不在官网里绕 |
| 交互回放在 Web 上超出字节预算 | 回放的数据按需加载，不进首帧之前的字节；仍超就只在 `/making` 提供，首页放视频 |
| 做不完 | 降级写法（五项）：先上静态内容（四个路由的 HTML 投影）与视频，交互回放标预览 |
