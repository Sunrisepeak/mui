# omui.designer

The designer of Live Design (D-149, D-151): the design.* verbs, the design's history, previews and variants in stand-ins, and the timeline of an application in development mode.

- **What it adds.** A program that links it has the `design.*` verbs of Live Design's catalog (`modules/projects/omui/agent/design.ops.xdef.ts`, served by `omui-mcp` as `design_*` tools). Nothing has to start it: the designer registers itself as the program starts, and every player in development mode (`omui dev`) has one.
- **Why a package of its own.** A release is built without it (D-149: the designer is left out at build time). The entry player links it only under its `design` feature, which `omui dev` turns on. The player itself knows only that a designer may be linked (`omui::player::provide_designer`). It gives the designer its sources through its API: `sources`, `text`, `edit`, `commit_edits`, `discard_edits`, `language_of`.
- **Whose history.** The history's verbs (`design.history` and its seven) work on `DesignSources` (`:history_verbs`): the player's TypeScript, which an edit runs at once, or — in `omui-devhost` (W16) — a C++ application's files, which a build runs. There the host holds the history, so it goes on while the application's process comes and goes. The verbs are an adapter: the store and the operations themselves are the agent kernel's ([mlibs.agent](../../../base/agent) `:history` — `History`, `HistoryOperations`; D-173), the same for every domain that is designed; what is the interface's own is how a change is presented (a switch as a switch, an undo as one) and that a commit's state is the semantic tree's hash (`tree`).
- **The design as a show** (FE4, D-282). `design.show` runs each step the film's script keeps in an unseen twin and measures its beat — the regions of the picture it changed (`mrender::raster::changed_regions`), its nodes by what happened to them, its caption — and hanim's director (`hanim::timeline::direct`) makes the show's timeline of them: each beat's length, the camera, the transitions and the words. Written as `<branch>.show.timeline.xdef.json`; the design's rules are `<branch>.direction.xdef.json` beside the script, or every default. With `replay` it measures a release's replay (`replay@1`) instead, every step kept, and `pace` writes each beat's length back as its step's time on screen — what a page playing the replay in place goes by. Without a window: the application's program with the designer, `--design-verb design.show --design-args '{"replay": …, "pace": true}'` (any design verb, its answer printed).
- **What a release ships of it.** `design.history.export` writes a branch's steps as the film's script keeps them — every source's text then, the caption (what its maker said the step does — `say` on `design.edit`, `set`, `insert`, `remove` — or what it did), who made it, the time on screen — as a replay (`replay@1`, [mlibs.agent](../../../base/agent)'s kind): the application names it (`omui.config.ts`'s `generation.replay`) and plays it in place (`generate.replay`), with no designer linked.
- **What it keeps.** The history lives beside the application in `.omui/design/`: texts addressed by content, commits, branches, tags and pictures (`mlibs::agent::History`). `omui design sync` carries it into git as `design/<branch>`.

- **View documents as a workspace's sources** (`:view_sources`, D-204): `ViewSources` is a directory's `*.view.xdef.json` as `mlibs::agent::Sources`, read whole against the registered components before anything is written, its state each document's canonical form. It keeps the design adapter's contract (mlibs.agent.sources@1) and sits beside another domain's sources in a workspace (xtools's composition with hanim's).

Tests: `mcpp test -p omui.designer` (design edits, built_at both ways, structured edits, history, merge, previews, variants, timeline, scenarios).
