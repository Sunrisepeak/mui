# mgame 核心与 S4《组件打砖块：openmui 巡礼》（草案）

状态：草案。§8 是第二版的玩法设计（《闹鬼的设置》），取代 §4.2 的“六关 = 六项能力”；§2、§3、§5 的决定不变。接[结构、渲染、Web 与游戏设计](2026-10-28-openmui-structure-render-web-game-design.md)的 R8（§7、§13），和[实施计划](2026-10-26-openmui-implementation-plan.md)的 S4（§“S4 特色小游戏”、§19.3 验收）。

## 1. 要什么

- **mgame 的第一批服务**：世界（实体和组件）、模拟循环、输入、物理、openmui 接入。第一个用户是 S4，第二个是格斗游戏（它已经有自己的核心 gongfu，以后在 mgame.sim / mgame.input 上重新接一遍）。
- **S4**：一个真正好玩的打砖块。每一关的玩法就是一项框架能力（D-50）。同时它是一个确定性的 agent 评测环境：给定种子和输入就能精确回放，agent 通过语义 API 玩它。
- **验收**（实施计划 §19.3）：
  - 120 Hz，输入延迟不超过 1 帧；
  - 给定种子和输入，三个平台的回放哈希相同；
  - 最近 30 秒内可以倒流到任意时刻，倒流后继续游戏的结果和直接回放相同；
  - 三种语言写的道具都能热重载（< 200 ms）；
  - 脚本化的 agent 能通过第 5 关；
  - 每一关都让玩家明白它演示的是哪项能力；作为游戏本身好玩。

## 2. 决定

| 编号 | 决定 | 理由 |
|---|---|---|
| G-1 | **Q-25：`mgame.world` 自写列存储**，不用 EnTT / flecs。组件是纯数据，每种组件一列定长数组，实体是“下标 + 代数”，存在与否用位图；整个世界是一块可平凡拷贝的数据 | 回滚和倒流要求“整块拷贝即存档”。EnTT 的 registry 和 flecs 的 world 内部是堆上的稀疏集和表，拷贝要逐个遍历，也不是逐字节确定的；定长列可以 `memcpy`，校验和就是字节的哈希 |
| G-2 | **玩法物理用 `mgame.physics` 自己的扫掠碰撞**（圆和轴对齐盒），不用 Box2D 的世界。数值用双精度，只用 IEEE 754 精确舍入的加减乘除和平方根，不收缩、不用快速数学、不调用 libm 的超越函数（lint 的 determinism 规则检查），和 hanim 一样三平台逐位相同 | Box2D v3 的世界不能序列化成一块数据，倒流和回滚都做不了。打砖块的球在两次碰撞之间是直线：按事件推进（求下一次碰撞的精确时刻），既确定、又能解析地求任意时刻的位置——这正是实施计划写的“时间倒流靠分段解析解”。没有用定点：圆和角的相交要求平方和开方，Q16.16 在 64 位里会溢出，而上面这几种运算在双精度下本来就是确定的。Box2D v3（mwrap 已在 mcpp-index）留给不需要回滚的游戏（碎片、布娃娃），以后接 |
| G-3 | **模拟和呈现分开**：模拟 120 Hz 定步长，数值规则同 G-2；呈现按显示器刷新率插值 | 和格斗框架同一套思路；120 Hz 让输入延迟在 1 帧（8.3 ms）以内 |
| G-4 | **倒流 = 快照 + 输入记录 + 重新模拟**：每 60 帧（0.5 秒）存一次快照，30 秒 60 个；任意帧 = 最近的快照 + 之后的输入重放。倒流后继续，丢弃那一帧以后的输入，从这里开新的分支 | 快照是整块拷贝（G-1），重放是确定的（G-2、G-3），所以“倒流后继续”和“直接回放”逐字节相同，可以测试 |
| G-5 | **砖块是真实的 openmui 组件**：关卡是一个视图（按钮、开关、滑块、Markdown 卡片……），布局由 openmui 算出；关卡开始时把每块砖的布局矩形读进模拟，之后模拟只认这些矩形 | 布局是确定的（A 级），所以同一关卡在三个平台上得到同样的矩形、同样的模拟；砖块被打的时候组件真的收到动作（按钮被“按下”、开关被“切换”），语义树真的变化 |
| G-6 | **游戏的语义就是 agent 的接口**：场地、挡板、球、每块砖都是语义节点；动作 `move_to(x)`、`launch`、`rewind(frames)`、`step`。第 5 关的 AI 挡板只用这些 | agent 原生（D-61）；评测环境的接口和人看到的一致 |

## 3. mgame 的包

| 包 | 内容 | 依赖 |
|---|---|---|
| `mgame.world` | `World<N, Components...>`：定长列、实体下标 + 代数、位图；按下标顺序遍历；`checksum`；整块拷贝 | 标准库 |
| `mgame.sim` | 定步长循环（累积器、追帧上限、插值比例）；`Timeline<Game>`：快照环、输入环、`seek(frame)`、倒流后继续开分支；模拟时钟和呈现时钟分开 | 标准库 |
| `mgame.input` | 动作映射（键盘、手柄、指针 → 按钮动作和定点轴）；每帧采样成一块纯数据；录制和回放 | 标准库 |
| `mgame.physics` | 圆和盒的扫掠：“这一步里何时第一次碰到、哪一面、法线”（四个面外推半径，四个角是半径的圆弧）；已经重叠又继续向里的立即碰到；只用精确舍入的运算（G-2） | 标准库 |
| `mgame.ui` | openmui 接入：在运行时的时钟上驱动 `mgame.sim`；openmui 的按键和指针事件 → `mgame.input`（UI 没有消耗的才给游戏，D-76）；读一个视图里节点的布局矩形 | openmui、上面四个 |

前四个只依赖标准库（和 gongfu 的核心一样，可以原样拆出）；`mgame.ui` 是唯一认识 openmui 的。

## 4. S4 的玩法

### 4.1 基础

- **场地**：1280 × 720 的逻辑坐标。下面是挡板，上面是关卡视图（砖块），左右和上面是墙，下面掉出去就丢一个球。
- **球**：半径 8，速度按关卡从 6 到 9 像素 / 帧（120 Hz 下 720–1080 像素 / 秒）。打到挡板时按击中点偏转（边缘最多 60°），挡板移动时把一部分速度传给球（“搓球”）。
- **砖块**：每块有耐久（按组件种类：按钮 1，开关 2，滑块 3，卡片 1）。被打时组件收到对应的动作（按钮被按下、开关切换、滑块的值减少），耐久到 0 时溶解（`pixel_effect` 的 dissolve）并喷出粒子，然后露出下面那张 Markdown 卡片：一两句话讲这一关演示的能力。
- **道具**：碎砖有一定几率掉落胶囊（按种子决定）：变长、多球、慢动作（第 4 关的时钟倍率）、穿透。第 6 关的道具由脚本写。
- **分数和连击**：连续不碰挡板打碎的砖越多，分数越高；丢球断连击。

### 4.2 六关

| 关 | 能力 | 这一关怎么玩 |
|---|---|---|
| 1 语义 | 语义树、显式 ID | 按 Tab 打开“语义透视”：每块砖显示 role 和 ID，砖被打时侧栏实时显示语义树的变化（`toggled`、`value`、`removed`）。有几块砖是“隐形”的——画面上看不见，只有语义透视里看得见 |
| 2 风格 | 风格包、着色器效果 | 每打碎一排，整个关卡换一种风格（玻璃 → 霓虹 → CRT → 水墨 → 液态）；物理和语义完全不变——用同一局回放在五种风格下得到同一个哈希来证明 |
| 3 画布 | 无限画布、缩放 | 场地是一块无限画布：球飞出视野时镜头拉远，露出整面 Markdown 墙；有的砖只有放大到某个级别才“实体化”（缩放级别是玩法的一部分） |
| 4 时间 | 动画是时间的纯函数 | 按住 R 倒流（30 秒以内任意时刻），松开就从那里继续；“慢动作”胶囊把模拟时钟的倍率调成 0.5。关卡里有必须倒流才能过的机关：一扇只在某个时刻打开的门 |
| 5 Agent | agent 原生 | AI 控制第二块挡板（`paddle2.move_to(x)`），它的每个动作实时显示在“动作日志”里；可以选合作或对战。脚本化的 agent 必须能过这一关（验收） |
| 6 多语言 | 三种脚本语言、热重载 | 道具由 TS、Python、Lua 写，保存后立即生效；官方的三个道具三种语言各写一个；玩家可以改它们 |

### 4.2.1 已经做出来的（第 1、2 关）

- **场地组件 `field`**：自己按关卡组成子节点（`compose()`：每行一个真实的 flex 行，行的 ID 带关卡号，换关时是新节点、重新布局），第一步把布局矩形读进模拟；之后模拟的事件改组件（开关切换、滑块减值、碎砖 `visible = false`，语义树里是 hidden）；倒流和重开按模拟状态恢复每块砖。人用指针、方向键、空格和鼠标，agent 用同一组动作（`launch`、`move_to`、`step`、`rewind`、`next`、`next_style`）。
- **关卡结束**：通关显示这一关讲的能力（一两句话），Enter 或 `next` 进入下一关；没球了重来这一关。
- **第 1 关**：Tab 的语义透视除了 role 和 ID，还有“语义树的变化”侧栏（同时在场地的语义值 `changes` 里给 agent）；隐形砖看过一次之后保持淡色轮廓（评审意见：隐形碰撞体要先让人发现，不能只是陷阱）。
- **第 2 关**：每打通一行换下一个风格包（glass → neon → retro → ink → liquid，交叉淡入），S 或 `next_style` 随时换（评审意见：在球飞行中换，轨迹连续）；HUD 显示当前风格和这一局的校验和。场地只发出 `style` 事件说要哪个风格，由宿主（应用）应用——组件不碰运行时的主题。测试用同一个 agent 打两局，一局中途换三次风格：每帧校验和相同、砖块的语义节点相同、像素不同。
- **第 3 关**（评审意见：缩放不改变碰撞，玩家能控制，镜头有界）：场地高四屏（模拟的 `Level::height`），砖是一面“便签墙”——`openmui.ui.canvas` 场景里的 160 个节点（远处是一批实例化的方块，大于 60 像素时提升为真实的卡片组件），颜色从下往上渐变，拉远时整面墙是一幅图。镜头在模拟状态里（`State::zoom`，每步按精确运算缓动）：底边始终是挡板那一行，最高的球离开第一屏就拉远到刚好看见它，按住 Z 看整面墙（最远 0.25）；缩放只影响画面，从不影响碰撞。指针按镜头换算回场地坐标。
- **第 4 关**（先于第 3 关做出来；关卡按编号排，`next` 走到下一个已经做出的关）：金库那一行只能穿过“门”进去，门是一个真实的进度条组件，0:15 到 0:18 打开一次（模拟里的 `Kind::gate`：开着的帧不参与碰撞，窗口在状态里）；进度条随帧填满、打开时消失并显示倒计时、之后“永远关闭”。错过了就按住 R 倒流（每步退两帧，最多 30 秒），松开从那里继续——评审意见：同样的发球到不了一个确定的定时门，所以门只开一次，倒流之后必须换一种打法；进度条就是可见的预告。慢动作胶囊把游戏时钟的倍率调成 0.5（所有关）。
- **第 5 关**：上方的挡板归 agent。应用里自带的 agent（`Copilot`）像外部 agent 一样从场地外面玩：每秒 30 次读场地的语义节点（球的位置和速度）和语义树里还立着的砖（不是 hidden 的节点和它们的边界），算出上升的球在上挡板那条线上的落点（侧墙按镜面折回），再偏一点让球弹向最近的砖，调用场地的动作 `guard_to`（参数里带上它看到了什么），身份是 `agent:copilot`，进运行时的动作日志。画面左下角实时列出它的动作和观察（评审意见：给 agent 独立的防守区，并把观察和动作放在一起）；场地的语义值 `agent` 也有。`copilot = false` 时让给别的 agent（例如经 agent 协议连进来的）。验收：脚本化的玩家在下、copilot 在上，打通这一关（测试里 699 帧、一条命不丢）。
- **第 6 关（设计，经 codex 第二次评审）**：“工坊”。四种道具的规则由脚本给出：宽挡板 `wide.ts` 和穿透 `pierce.ts`（TypeScript），慢动作 `slow.lua`（Lua），多球 `multi.py`（Python：嵌入式的 PocketPy，标明“Python（PocketPy，支持的子集）”；openmui 的 CPython 绑定是宿主模式，不能嵌进来）。每个脚本注册一个动词 `gift.<名字>`，返回这个道具的规则；脚本里有一个标出来的参数和一笔固定的“预算”（宽挡板：半宽 × 秒数固定，越宽越短；慢动作：省下的游戏时间固定，越慢越短；穿透：越长掉得越少），让人看到脚本在计算，也让“全部拉满”行不通。按 E 暂停并打开工坊（叠在场地上的面板：三种语言的真实 `text_box`、应用、预设、撤销、状态“重载用了 12 ms”），应用就是热重载：脚本重跑、动词重新注册，工坊调用动词得到规则，校验（越界、非有限数、语法错误、超时都保留旧规则并说明原因），再经场地的动作 `set_rules` 在下一步开始时整体生效（`Input::new_rules`，回放不跑脚本）。已经生效的道具效果保留拿到时的数值，新规则只影响以后接到的胶囊。关卡里的砖带固定的道具（不靠运气），挑战和道具对应：一排耐久高的“钢”砖要穿透才来得及，一段窄缝要宽挡板接住快球……验收：三种语言的重载从“应用”到规则生效都在 200 ms 以内（测试测量），倒流跨过一次重载、再回放，结果逐字节相同。

### 4.3 好玩的部分

- 手感：挡板跟手（输入延迟 ≤ 1 帧），击球有打击感（停顿 1–2 帧、屏幕轻震、声音由 `openmui.audio` 合成）。
- 每关 2–3 分钟，有明确的“啊哈”时刻：看不见的砖（1）、风格切换而球不变（2）、拉远后发现整面墙（3）、倒流打开门（4）、和 AI 配合（5）、改一行脚本道具立刻变（6）。
- 试玩反馈作为验收的一部分（§19.3）。

## 5. 模拟（`showcase/widget-breakout` 的核心，只依赖 mgame 的前四个包）

- **状态**：一块纯数据——世界（球、挡板、砖、胶囊、粒子发射器的种子）、分数、连击、关卡帧、随机数状态。
- **一帧**：读输入 → 挡板按输入移动（限速）→ 每个球按事件推进：求这一帧内最早的碰撞（墙、挡板、每块活着的砖），推进到那一刻、反射、记录事件，直到这一帧的时间用完 → 胶囊下落、被接住 → 砖块耐久 → 事件。
- **事件**：砖被打（哪块、剩余耐久）、砖碎、球掉落、胶囊、关卡完成。呈现和 openmui 组件读事件（组件收到动作、溶解、粒子、声音）。
- **哈希**：每帧状态的字节哈希；回放、倒流、三平台对照都用它。

## 6. 实施顺序

1. **mgame 核心**：`mgame.world`、`mgame.sim`（定步长、`Timeline` 的快照和重放）、`mgame.input`、`mgame.physics`（扫掠碰撞），各自的测试（确定性、回滚和倒流逐字节一致、三平台哈希）。
2. **S4 的模拟**：状态、事件推进的球、挡板、砖、胶囊；无界面的测试（回放哈希、倒流后继续和直接回放相同、120 Hz 下挡板延迟 ≤ 1 帧）。
3. **`mgame.ui` 和 S4 的第 1 关**：openmui 视图里的砖块（真实组件）、布局矩形读进模拟、语义透视；无头测试的像素固定。
4. **第 2–4 关**：风格切换、画布拉远、倒流和门。
5. **第 5 关**：AI 挡板、动作日志；脚本化 agent 过关（CI）。
6. **第 6 关**：三种语言的道具和热重载。
7. 声音、打击感、试玩反馈。

每一步一个提交；主观的部分（关卡的玩法和“啊哈”时刻）定稿前请 codex 评价一次。

## 7. 评审记录（2026-10-29，codex，作为参考之一）

**采纳，关卡：**

- **第 1 关**：看不见的砖不能让人觉得不公平。先在安全的位置出现一块，语义透视要能揭示一条路线；发现过的砖保持描边。
- **第 2 关**：本身只是“看”。改为玩家随时可以切风格（击球途中也行），轨迹和瞄准线连续；HUD 实时显示这一帧状态的哈希，切风格时它不变——“物理和语义不变”从测试变成肉眼可见。
- **第 3 关**：缩放由玩家控制（滚轮、按键），有上下限，实体化有提示；缩放级别是模拟状态的一部分（输入改变它），回放和倒流都确定。
- **第 4 关**：同样的发球倒流后还是同样的结果，所以谜题要求倒流后打出不同的球；门的开合周期画在画面上。
- **第 5 关**：AI 有自己的“职责”——场地上方的第二块挡板，负责不让球从上面出去；动作日志旁边同时显示它读到的观察（球的位置、速度，来自语义树），过关条件、超时和动作频率上限写清楚。
- **第 6 关（最弱）**：改成“工坊”。在一次击球前暂停，三种语言写的同一个道具各有一个标出来的参数，改一个、预览轨迹、再去打一个目标排列；有预设、一键撤销、看得见的重新加载状态。

**采纳，模拟：**

- 挡板按相对运动做扫掠（球的位移减去挡板的位移），移动的挡板不会被穿过。
- 同一时刻的多个碰撞按实体下标排定。相邻两块砖接缝处的角，按面处理（不按对角线弹）。每帧最多 8 次碰撞，用完时停在原地，不前进穿过几何体。
- 扫掠只认“朝面里移动”的接触（擦过、离开的不算），避免零时刻反复碰撞。角的根用不抵消的形式 c / (−b′ + √disc)（已改，有测试）。
- 倒流时重新模拟的帧不重放声音和特效：呈现只读当前帧的事件，倒流的画面另有自己的表现。
- 砖块的碰撞几何和风格无关（砖块组件用显式的宽高，风格只改外观）。
- 道具脚本按版本保存（内容哈希）。重新加载是一条记录在输入里的事件，倒流到它之前就用旧版本。
- 验收的补充：
  - 输入延迟按“这一帧开始时采样，这一帧的模拟就用上”来测；
  - 每帧模拟和 `seek` 的最坏耗时进基准和预算；
  - 第 5 关的观察时机、动作上限、种子、胜负和超时写进测试；
  - “任意时刻”指任意一帧（120 Hz）。

**没有照搬：**

- “可平凡拷贝不等于字节规范”：世界的组件按概念要求没有填充，释放的槽清零，分配和遍历顺序确定，哈希只读这些字段。所以这一点已经满足，不需要改成逐字段哈希。
- 双精度的其余顾虑（舍入模式、x87 中间精度、次正规数、FMA）：
  - 在 x86-64（SSE2）、arm64 和 wasm 上，我们从不改舍入模式；
  - 没有 x87，不开快速数学，所以次正规数不会被冲成零；
  - 用 `-ffp-contract=off` 禁止 FMA；
  - 不产生 NaN（零向量归一化返回零）。
  - 这些写进 `mgame.physics` 的 README。
- G-3 写的“定点数”和 G-2 矛盾，这一处是对的，已改成同 G-2 的规则。

## 8. 第二版：《闹鬼的设置》（2026-10-29）

第一版的结构是“六关 = 框架的六个部门”：砖上写着框架的词，通关弹一段说明，HUD 上跳着校验和，工坊里摆着文件名和重载毫秒数。这些对开发者有用，对玩家不是奖励（维护者的意见，codex 的评审也这么说）。第二版先做一个好玩的游戏：框架的能力要么就是乐趣本身，要么藏在画面背后，想看的人打开检查器再看。没人会转发一个“讲解”，大家只转发自己玩得开心的东西。

### 8.1 一句话

**《设置》闹鬼了，每个控件都真的管用：把“亮度”打满就射出一道光，关掉“勿扰”护盾就打开，用连锁把整块面板关机。**

砖块还是真实的 openmui 组件（G-5），区别是它们有了后果：开关切换的是场地里的机关，滑块充的是电容，名字就是它的作用（“勿扰”护着核心，“亮度”发光，“深色模式”关灯）。这种幽默是间接的展示：组件的状态是真的，语义树也真的跟着变，但游戏里一个字都不讲。

### 8.2 核心循环

**发球瞄准 → 击打控件 → 机关连锁 → 接住球，把这一串连锁存成火花 → 用火花换倒流，或者带进下一个房间。**

- **连锁**：从球离开挡板开始，每碰到一个会动的东西（打碎、拨动开关、给电容充电、被弹射器弹开、光束扫过）连锁就加一；回到下挡板时结算，连锁 ≥ 3 才存进**火花**（10 × 连锁，最多 300）。球掉了，没结算的连锁也就没了。所以每一次回球都是一次押注：继续追着连锁冒险，还是稳稳接住先存起来。这一点也修正了第一版的问题（第一版碰挡板就清零连击，反倒鼓励把球困在砖墙上面）。
- **火花 → 倒流**：按住 R，最多退回 2 秒，花掉 100 火花（倒流本身就是框架的时间线，§2 G-4）。倒流还会把你退过去的那段连锁一起收回。详见 §8.4。
- **一局**：五个短房间，每个 45–90 秒，三个球。房间的目标是关掉它的**核心**（电源键），不是清光每一块砖，所以没有“满屏找最后一块砖”。核心一碎，整块面板短路：剩下的砖从核心向外一圈圈爆开，每块都算分。
- **房间之间**：两件“机关”（道具）里挑一件，另一件就错过了。每件有两档功率预设，还可以“打开外壳”看它的脚本（§8.5）。挑过的机关在之后的房间里从带标记的砖里掉出来，一局下来攒成你自己的一套，这就是重玩的理由（“下一局我先拿磁铁”）。

### 8.3 手感（先做好这一层）

| 手感 | 做法 | 为什么 |
|---|---|---|
| 发球瞄准 | 球停在挡板上时，瞄准线左右摆动（三角波，2 秒一个来回，最大 ±50°），虚线画出前两次反弹；按下就沿当前方向发出。agent 可以用 `aim(angle)` 直接定住角度 | 第一版每次都从同一个方向发球。瞄准线本身也是教学：第一个房间里，虚线会直接画到开关上 |
| 挡板搓球 | 击球时挡板的速度一部分加到出球方向上，另一部分变成**旋转**：之后每步把速度转一个小角度（只用加乘和开方，确定），转速逐步衰减，大约一秒内弯出 10°–15° | 第一版写了“搓球”，模拟里却没有。弧线球是可以练的技巧，打绕过护盾的球时用得上 |
| 击中停顿 | 核心被击中停 4 步，光束停 5 步，冲进上层停 14 步，核心碎掉停 30 步；放在模拟状态里（`freeze`），所以回放和倒流都确定；挡板在停顿中照样能动 | 只在大时刻停，从不在普通的砖上停 |
| 拖尾、形变、火星 | 球有短的高对比拖尾（穿透时是另一种颜色和形状）；击中时沿速度方向压扁几帧；挡板接球时压扁；碎砖喷出火星（定长粒子池，按事件的帧号做种子，每帧不分配内存） | 这些都只是呈现，从模拟的事件推出来，倒流时清空 |
| 震动 | 只在核心、光束和冲进上层时轻震，幅度很快衰减 | 轨迹要一直看得清 |
| 声音 | 每种控件有自己的声音（开关咔哒、电容充电时音高一档档升上去、光束呼啸）；连锁的每一下按五声音阶往上走，存进火花时是一个和弦，丢掉连锁时是一声下滑；核心碎掉时整块面板“断电” | 连锁越长，越像一段旋律 |

### 8.4 机关（每一种都说明：好玩在哪，用到了框架的什么）

| 机关 | 怎么玩 | 好玩在哪 | 自然地用到 |
|---|---|---|---|
| **开关电路**（toggle） | 开关被打一下就切换一次，沿着画出来的电线让同一条电路上的东西动起来：护盾开合、弹射器转向、电容提前放电。电线上会跑过一道脉冲，因果看得见 | 打开关是一个决定，不是“打两下”：再打一下护盾又会关上。会玩的人会算好角度，让球先拨开关、再从刚打开的口子钻进去 | 真实的 `toggle` 组件，`checked` 就是机关的状态；语义树跟着变（检查器里看得到） |
| **滑块电容**（slider） | 每打一下充一格，滑块的值真的往上涨；充满后保险丝亮几步，然后沿它那一行向两边放出一道光束，直到墙或关着的护盾，扫过的东西都受到“电量”那么多的伤害；光束扫到开关会拨动它，扫到别的电容给它充一格（预先充好的电容会被引爆），于是连锁一路传下去；刚放过电的电容冷却半秒，两个电容不会无休止地互相触发 | 先充哪一个、要不要让开关提前放电（伤害小，但现在就放），都是取舍；一道光束能引发一整串连锁 | 真实的 `slider` 组件；光束是一次确定的区间查询，不是逐像素 |
| **核心**（电源键） | 每个房间一个，耐久 3–5，常常躲在护盾、钢板或定时门后面 | 目标清楚，每次接近都很紧张；碎掉之后的短路连爆是给你的奖励 | 真实的 `button` |
| **弹射器** | 球碰到就被射向它箭头指的方向，开关可以把箭头转过去 | 有了弹球机的手感，也能故意设计“弹射器 → 开关 → 光束”这样的连招 | 真实组件，箭头由场地画出 |
| **冲进上层**（画布） | 第 3 个房间是两屏高的画布：下层是挡板和弹射器，天花板是一层“云”；打穿以后球冲进上层，镜头拉远，球在一屋子缓存里来回弹，连锁暴涨；从打穿的洞回到下层 | 空间上的发现：上面还有一层；一次冲进去就是一大串连锁 | `openmui.ui.canvas` 的场景：远看是一批实例化的方块，近看提升为真实的卡片；镜头在模拟状态里（§4.2.1 第 3 关），最远 0.5，球在屏幕上始终够大 |
| **X 光扫描** | 第 4 个房间是“深色模式”：只有球和挡板周围是亮的。按 X 扫描一次，1.5 秒内显出隐藏的缓存和电线，冷却 6 秒；找到过的缓存保持描边；球靠近隐藏缓存时它会先闪一下 | 在黑暗里找宝藏；扫描什么时候用是一个决定 | 隐藏的缓存在语义树里一直都在（hidden 的按钮）——扫描看到的就是语义树 |
| **倒流（押注）** | 按住 R，最多退 2 秒，花 100 火花；退回去的那一段时间里存进的火花也会收回；不能退过上一次倒流落下的那一帧。倒流以后，上一次那条轨迹会留下一道淡淡的“鬼影”，提示你换个角度 | 倒流换来的是一次重来的机会，不是修好一个非倒流不可的机关；第一版那种只开一次的门取消了，改成周期开合的定时门，周期画在门上 | 时间线的 `seek`（快照 + 重放，G-4）；扣火花是倒流之后第一步输入里的一项（`Input::pay`），所以回放、再倒流都确定，也刷不出火花 |
| **听你指挥的队友**（agent） | 第 5 个房间上方的挡板归 copilot。按 1–4 下命令：守住、往左打、往右打、喂给我。它会在头顶说一句它要干什么，并画出它打算回球的方向；两块挡板交替接球攒“合奏”，满了以后你的下一次接球会沿着那一列向上打出一道竖直的光束 | 你负责决定，它负责执行，它替代不了你；合作有实打实的回报 | copilot 和任何外部 agent 一样，从场地外面读语义树、调用动作（`guard_to`，身份 `agent:copilot`，进动作日志）；命令就是场地语义值里的一项 |
| **房间之间的机关** | 两件里选一件。每件有两档预设：“猛而短”和“弱而长”（宽挡板：260 宽 4 秒，或者 95 宽 12 秒；穿透：2 秒但常掉，或者 10 秒但少见……）；“打开外壳”显示驱动它的脚本（TypeScript、Lua、Python），可以改一个标出来的数、应用，脚本热重载以后马上生效 | 有意义的功率取舍；想折腾的玩家可以改代码，但这从来不是必须的 | 三种语言的脚本、热重载（`openmui.lang`）；脚本只在加载时产出规则，从不进每帧路径，规则作为一步的输入进入模拟 |
| **风格** | 每个房间是一个风格包（玻璃、霓虹、水墨、复古、液态）；通关时整块面板换上下一套“皮肤”，这就是庆祝的画面 | 换皮是奖励，不是讲解 | 风格包和交叉淡入；玩法用的颜色（球、挡板、电线、光束、核心）不随风格变，保证可读 |

### 8.5 五个房间和难度曲线

一次只引入一种后果，后面再混合使用：

| 房间 | 风格 | 教什么 | 内容 |
|---|---|---|---|
| 1 勿扰 | glass | 瞄准、开关、护盾 | 核心被“勿扰”的护盾四面围着；第一次发球时瞄准线就从开关的角度开始摆，虚线直接画到开关上；打一下开关，护盾滑开，再打一下又关上。周围的通知卡片是练手的普通砖。没有道具 |
| 2 亮度 | neon | 电容、光束、连锁 | 最上面一行是一道“坝”（缝隙比球窄），核心嵌在坝里，下面垫着一块钢板；“亮度”电容在坝的最左端，它的光束一次打穿整道坝；“音量”电容的光束扫过“自动亮度”开关，开关接着让“亮度”提前放电——第一次连招 |
| 3 云 | ink | 弹射器、冲进上层 | 两屏高。下层是“Wi-Fi”开关和两个上传弹射器；“云”是一层薄砖；上层挤满缓存，核心“存储空间已满”在最上面 |
| 4 深色模式 | retro | 黑暗、扫描、定时门、倒流 | 灯是关着的；“深色模式”开关在左上角，黑暗里微微发光，打到它灯才开（灯要靠本事挣）；核心在周期开合的“正在更新”门后面，门的倒计时在黑暗里也看得见；隐藏的缓存提供火花；有一个只能靠精确角度才拿得到的宝藏，倒流就是为它准备的（可选） |
| 5 同步 | liquid | 指挥队友、合奏、混合 | copilot 守上方，一开始就是“喂给我”；核心有一个固定的顶棚（copilot 不能从上面直接砸），两侧和下面是护盾；两侧的电容在核心那一行，护盾打开后光束直达核心；合奏的竖直光束也是一条路 |

速度从 6.0 逐步升到 7.0 像素 / 步；房间小而密，不靠砖多拉长时间。每个房间的目标时间是 45–90 秒（由 bot 测量，§8.8）。

### 8.6 不讲解的教学

- 用后果来教：第一个房间只有一个开关、一条电线、一个护盾，护盾后面是一个让人忍不住想打的目标。瞄准虚线一开始就画到开关上，球会先替你演示一遍因果。
- 提示只在需要的那一刻出现一次，然后淡出：第一次发球前显示“空格 发球”；火花第一次够 100 时显示“按住 R 倒流 2 秒”；第一次进入黑暗时显示“X 扫描”；第一次见到 copilot 时显示“1–4 指挥队友”。
- copilot 用动作和一句短话表达意图，没有动作日志。
- 通关时庆祝的是刚才发生的事（“7 连锁！”“一道光束扫掉 6 个”），紧接着就是下一个选择。

### 8.7 能力怎么透出来，而不是讲出来

- 砖就是真实的组件，所以“它们是真组件”根本不用讲：开关真的拨动了，滑块真的涨满了。
- **检查器**（Tab，可选）：叠在场地上，显示每个组件的 role 和 ID、隐藏的缓存、语义树最近的变化、这一帧状态的校验和，还有一段“这个房间是怎么做的”（第一版的每关说明改写之后放在这里）。
- “打开外壳”展示多语言脚本和热重载；倒流展示确定性的时间线；copilot 展示 agent 原生；第 3 个房间展示画布；房间之间换风格展示风格包。每一项都是因为好玩才出现在那里。
- 回放和三平台哈希相同仍然是验收项，但它们留在测试和检查器里，不放进玩法。

### 8.8 好玩的指标，和 bot 检查

给不关心框架的人试玩，记录：主动开始第二局的比例、第一次打出漂亮连锁用了多久、第一个房间就放弃的比例、空飞时间（3 秒内什么都没发生的时间占比）、死得公不公平（问卷）、玩家能不能说出自己为什么那么打。先问“下一局你想换什么打法？”，再提 openmui。

确定性的 bot（测试里，无头，只跑模拟）：

| 检查 | 怎么做 |
|---|---|
| 每个房间都能通关 | “懂机关”的 bot：每次球落向挡板时，把几个击球偏移各模拟往后几秒，选核心伤害和连锁最大的那个；发球时同样挑瞄准角。每个房间在 90 秒内通关 |
| 没有躲不开的漏球 | “只接球”的 bot 用模拟预测落点，挡板直接去那里：每个房间 60 秒里一个球都不丢（单球、没有道具） |
| 没有无尽的循环 | 任何一段超过 10 秒的时间里，必须有球碰到挡板或碰到会动的东西；模拟自己也有保险：球的竖直速度不低于速度的 28%（不会水平来回），6 秒没有进展时，下一次撞墙会偏转一个小角度 |
| 倒流刷不出火花 | 反复“打出连锁、倒流、再打”，可用的火花不会增加；倒流后的分数和那一帧一样；火花不足 100 时拒绝；不能退过上一次倒流落下的地方 |
| 懂机关确实更强 | “懂机关”的 bot 通关时间明显比“只接球”的短（或者后者根本通不了关）：理解这台机器应该带来实质的优势 |

### 8.9 去掉的（生硬的部分）

- 六关按框架部门划分、关名“语义 · Semantics”之类；
- 砖上写框架的词（`observe/decide/act`、`role: button`、`the same hash`……）；
- 通关时的说明段落（挪进检查器）；
- 第 2 关 HUD 上的校验和、S 键换风格（校验和挪进检查器；风格变成每个房间的皮肤）；
- 第 3 关 160 块砖、四屏高的耐力墙（改成两屏高、四十来块的上层）；
- 第 4 关只开一次、不倒流就过不去的门（改成周期开合的门；倒流是押注）；
- 第 5 关左下角的动作日志（改成 copilot 的一句话和意图线；日志在检查器和语义值里）；
- 第 6 关独立的工坊（变成房间之间的“打开外壳”；重载毫秒数只在外壳里的小字状态里）。

保留：确定性（模拟的数值规则、时间线、回放哈希）、agent 接口（每个动作都在契约里，agent 和人用同一套）、三种语言的热重载，现在它们都是为玩法服务的。

### 8.10 实现的范围（本轮）

- 模拟：开关电路、护盾、弹射器、电容和光束（含连锁传递）、核心和短路连爆、周期定时门、旋转和搓球、发球瞄准、击中停顿、火花的结算和支付、合奏和竖直光束、磁铁道具、反水平和反循环的保险、冲进上层的事件；
- 界面：五个房间、房间之间的选择和“打开外壳”、检查器、手感层（拖尾、形变、火星、震动、光束、电线脉冲、倒流鬼影）、声音；
- 测试：上面所有机关的模拟测试，组件和模拟一致，像素和声音固定，五个 bot 检查；README 的循环动画改成 WebP（< 1 MB）。
- 留到以后：卡片里 5 秒的可玩预览、房间的分支路线（现在只有奖励分支）、每日种子、局后回放的检查器、减少动效的选项。

### 8.11 实现中的发现，和对结果的评审（2026-10-29，codex，作为参考之一）

**bot 先发现的问题**（都已改）：

- 第 1、2、5 个房间几秒就被打通：球卡在核心和上面的砖之间来回撞，开关、光束、合奏都用不上。于是护盾补上第四面，亮度那一行改成只有光束打得穿的坝，最后一个核心加了顶棚。改完以后，懂机关的 bot 依次用 6、14、38、18、6 秒通关，只会接球的 bot 用 49、18、22、46 秒，第 5 个房间 120 秒也通不了。第 3 个房间反过来（只会接球的更快），说明“冲进上层”的奖励不靠刻意也能拿到，这可以接受。
- 弹射器把球踢回自己身上，100 秒里踢了七万多次：改成只往离开接触面的方向踢。两个电容互相引爆、永不停止：改成光束只充一格，放过电的电容冷却。
- 新房间读到了上一个房间的布局：砖的 ID 在房间之间重复，碰巧第 1 和第 5 个房间砖数相同，模拟就用了旧节点的位置。现在每个房间的砖放在以房间命名的面板里，面板组成并布局完成后才开始模拟。

**评审意见，采纳：** 第一次因果必须一眼看懂（开局瞄准线指向开关、护盾可见地滑开）；选中的机关在下一个房间开始时马上掉一个给你；“存入”要说清楚（“BANKED”字样，火花槽亮一下）；copilot 先从“喂给我”开始、头上标出 COPILOT，合奏每一步都有提示；黑暗里仍然看得见该行动的信息（门的倒计时、核心的轮廓）；光束变细，看得见它打中了什么；浅色风格下金色和青色的提示加深，球和挡板加深色描边。

**没有照搬：** “把开关的碰撞区放大”——开关本身已经够大，问题在瞄准，用开局瞄准解决；“卡片上加动画小图”——和 5 秒预览一起留到以后。
