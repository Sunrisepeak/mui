# 独立游戏完整工作流：工具覆盖、素材资源与编辑

2026-11-04。状态：**架构／产品讨论稿，能力覆盖和实施缺口清单**。配套[顶层架构](2026-11-04-multi-engine-product-architecture-design.md)、[双视角工具](2026-11-04-dual-user-tools-validation-design.md)、[引擎细案](2026-11-04-omui-engine-framework-architecture-design.md)。问题是六类核心工具能否覆盖成熟独立游戏，并要求补充素材资源与编辑。

2026-11-05补充：[pixelpet运行时创作](2026-11-05-pixelpet-generative-capabilities-design.md)把同一素材与操作基础用于应用运行后的服装制作、穿戴、UI挂件、绘画和技能积累。可编辑源、依赖、版本与派生构件共用catalog；衣柜／技能库是视图，包裹／装备是应用状态。工具与应用不重复实现素材管线；动态UI分别管理定义、实时数据和安装实例。

## 1. 判断与产品边界

**六类工具是表现、创作和诊断基础，还不足以证明能完成、发布和维护成熟独立游戏。** 需要补场景／关卡、玩法／内容和完整素材工作流，并把角色、测试、存档、发布等环节贯通。工具有界面也不等于相关运行时已完成；游戏类型所需的渲染、模拟、输入、存储等能力必须分别验收。

建议保留六类基础工具，新增三类领域工具，形成**九类可组合工具＋共享构建／发布／验证底座**。它们可以是同一工作台中的插件，也可单独运行；不复制项目、资源、命令、历史或观测基础。独立引擎、omui UI 和通用资产处理不依赖游戏领域，玩法／关卡／存档等游戏规则归 mgame 或作品。

## 2. 补足和扩展哪些工具

| 工具／工作流 | 应交付的具体能力 | 与原六类工具的关系 |
|---|---|---|
| **新增：素材与资源工作台** | 导入／批处理、稳定资源身份、依赖与引用、缩略图／预览、重导入、增量处理、格式／目标变体、运行时内存和交付成本、来源与版本 | 通用处理器归基础／内容／媒体库；工作台统一编排，其他编辑器使用同一资源服务 |
| **新增：场景／世界／关卡设计器** | 实体和组件、层级、实例／模板及局部覆盖、坐标与吸附、TileMap／TileSet、碰撞／触发区、相机／出生点、导航数据、分区与流式边界、运行预览 | 动画场景负责表现编排；关卡场景负责玩法对象和空间。共用对象操作／资源，分别维护领域模型 |
| **新增：玩法／数据／叙事工作台** | 原生代码与数据编辑、状态机／行为图、事件与技能／数值配置；按类型加入任务、对话、物品等；运行观察、断点／单步、输入录制、测试与数据迁移 | 游戏逻辑调用公共引擎；图／表编辑使用共享面板。代码优先，声明图编译为原生计划，脚本不进入每帧热路径 |
| **扩展：动画编辑器 → 角色／演出工作流** | 2D 分件／精灵帧、骨骼／蒙皮／权重、IK／约束、动画混合／状态转换、事件／根运动；碰撞／受击框、相机、声音和特效联动 | rig、动画算法和 renderer 为公共库；战斗判定／招式烘焙是游戏插件，不塞进 hanim core |
| **扩展：音频／MIDI → 游戏音频** | 采样与循环点、音效 cue、随机／变体、总线、动态配乐／状态层、空间声音及语音／字幕关联 | DSP／音序／设备共用；游戏事件映射独立，音频回调不等待 GUI／Agent |
| **扩展：材料／算子 → 视觉制作** | 粒子／VFX、贴图与材料参数、光照／阴影、后处理、场景性能与能力档位预览 | 共享 renderer／compute，2D 和3D按实际域接入；不新建另一套场景渲染器 |
| **扩展：Inspector → 测试与设备实验室** | 运行中实体／组件／资源、脚本与原生诊断、CPU／GPU／内存、输入／回放、自动游玩、存档一致性、多实例／联网测试及缺陷复现 | 同一 provider／trace／session，Agent 可直接运行和查询任务；完整多设备验证随后逐目标实现 |
| **共享：构建／发布／内容维护** | 目标预设、资源依赖闭包、按需包、Web／Toy预算、版本与构件清单、存档迁移、更新包和回退、干净环境复现 | 复用 mcpp／插件和同一资源管线；GUI 只是公共任务入口，构建器不另起一套 |

UI／交互／风格设计器继续覆盖菜单、HUD、设置、输入映射界面、字幕和可访问性；模拟实验室继续验证物理／材料／元胞规则。上述扩展补齐工作流，保留原工具的独立用途。

## 3. 游戏运行时的覆盖矩阵

| 范围 | 常见独立游戏的基础需求 | 按类型选用的能力 | 当前边界 |
|---|---|---|---|
| 世界与内容 | 场景、对象实例、资源引用、生命周期、关卡切换 | 大世界分区、地形、程序生成、导航／寻路 | 已有 mgame.world 原料；通用场景／关卡工具与完整内容加载闭环未完成 |
| 玩法与输入 | 角色／对象动作、状态、输入映射、相机、暂停和重开 | 复杂AI、对话／任务／背包、战斗／策略规则 | 已有输入与专用格斗／打砖块逻辑；不代表各类型游戏的通用工具都已交付 |
| 动画与表现 | 时间编排、对象／组件动画、声音、效果、资源生命周期 | 骨骼、混合树、复杂粒子、3D相机／LOD／剔除／灯光 | core、部分表现和资源原料已有；完整 hanim、通用rig与完整3D仍开放 |
| 物理／模拟 | 按游戏需求选择碰撞、触发和固定步长 | 刚体／软体／流体、反应材料、Noita类活动域 | 当前简单扫掠碰撞和有限专用求解不能等同完整物理／模拟引擎 |
| 数据与存储 | 玩家设置、进度、存档／读取、版本迁移和资源兼容 | 云存档、UGC／Mod、账号、排行榜 | UI 会话／undo或内存回滚不是长期游戏存档；游戏持久化需单列设计／验证 |
| 本地化与设备 | 字体、文本／字幕、资源变体、分辨率／输入方式适配 | 配音替换、复杂IME、触觉、平台专用能力 | 有通用i18n／输入原料；整条游戏工作流和目标设备仍需实跑 |
| 联网与服务 | 单机游戏可不选择 | 多人、回滚／同步、大厅、匹配、重连等 | 已有双peer回滚包；不能据此宣称完整多人服务或任意网络游戏已支持 |
| 发布与维护 | 可重现构件、资源闭包、错误报告、性能／交付预算 | DLC／补丁／Mod、商店／平台集成 | Web／Toy已有交付路径；通用游戏发布与内容维护仍需端到端验证 |

“成熟独立游戏”没有一份所有类型都必须全选的功能表。先定可验证的游戏配置：2D单机、角色动作、3D或高密度像素模拟等；各配置有支持矩阵和最小成本。不能因为2D小游戏可运行，就把完整3D或Noita性能标为支持。

## 4. 素材管线必须形成公共能力

目标链路：**源素材 → 导入设置与编辑操作 → 依赖／派生构件 → 目标变体 → 游戏内预览 → 输出包 → 运行时资源租约**。

| 层 | 公共契约和行为 |
|---|---|
| 资源身份 | 稳定 Asset ID、内容／资源版本、类型、来源和引用；路径改名不应直接破坏逻辑引用。运行时 ImageRef／设备句柄与持久化资源ID分开 |
| 源与派生 | 保存源素材、导入参数和可重现操作；图集、压缩纹理、波形／缩略图、烘焙数据等是派生物。重导入保留公开的局部覆盖与引用 |
| 依赖与处理 | 一份依赖图，使用共享hash／mcpp缓存，记录处理器版本、参数、目标能力；只重做受影响项，处理失败继续保留上一版有效资源 |
| 目标变体 | 分辨率、色彩空间／alpha、压缩、mip／LOD、声道／采样率及精度按目标选择；Web首包／分场景／语言包和CPU／GPU驻留成本可查询 |
| 运行时 | 内容租约、CPU内容、设备副本与临时资源保持各自生命周期；异步加载、预热、卸载和设备恢复有明确结果。重载在提交边界切换，旧动画／声音可保留所需旧版本 |
| 可观察与修复 | 查询谁引用资源、为何重建／加载、缺失或过期在哪、占多少交付／内存；支持批量修改、引用修复、差异及失败重试 |

资源身份／依赖契约可以提为中立基础能力；图片／字体／音频／模型处理器分别放在对应层，由工具或上层资产流程组合。避免底层catalog反向依赖全部内容／媒体包，或每个编辑器各建一套asset数据库／缓存／importer。文件、目录和进程继续经 mcpplibs.os；构建处理经 mcpp插件。

## 5. 素材编辑要覆盖什么

| 编辑域 | 与引擎紧密相关、应具备的操作 | 公共输出与游戏内验证 |
|---|---|---|
| 图片／像素／精灵 | 裁切、缩放、颜色／alpha、分层分件、支点、九宫格、图集／帧动画、mask／法线或碰撞轮廓准备 | 图片／sprite资源、UV／边框／pivot；在真实缩放、过滤、动画和碰撞位置下检查 |
| 矢量／路径 | 节点／控制点、轮廓、填充／描边、形状部件和动画端点 | 公开几何／HObject；真实中间态、命中与多档位呈现 |
| TileSet／地图 | 切格、图块属性、地形连接、层、碰撞／导航、场景实例和区域边界 | 关卡／空间资源；行走、遮挡、摄像机和跨区加载验证 |
| 角色／模型 | 分件、骨骼／网格、权重／约束、挂点、动作片段与事件；模型导入、单位／轴向及材料映射 | 公共rig／动画／模型资源；真实运动、受击框／碰撞及材质检查 |
| 音频／音乐 | 裁切、循环点、音量／包络、音符／速度、效果链／总线、cue与事件映射 | 公共音频／MIDI／音乐资源；离线输出与实际设备时延／混音分开检查 |
| 特效／材料 | 发射／轨迹、曲线、参数、贴图／shader绑定和成本 | 公共效果／材料／算子计划；实际场景背景、透明合成与CPU／设备结果 |
| 字体／本地化／叙事 | 覆盖字符、字体fallback、字幕时序、语言资源引用、文本／对话数据 | 公共文本／语言资源及游戏内容；真实UI、字体交付和语音关联验证 |

优先内建与运行时契约密切相关的编辑、处理和验证；复杂绘画／雕刻／建模／录音等通过公开导入导出接入外部创作工具。需要支持素材从外部修改后回到同一流程，并保留覆盖层。自研某个完整创作工具应按独立产品需求和验证任务决定，不要求先复制所有DCC软件才能做游戏。

## 6. 素材与游戏编辑的双视角

人和Agent使用同一资源／场景／玩法操作模型。Agent通过openas身份、效果、授权和报告语义执行导入、裁切、绑定、布局、编曲、关卡编辑、构建或测试；人通过同一操作的GUI／适用TUI查看差异和实际效果。

一次编辑关联源版本、参数、目标ID、事务、派生产物和验证结果。准备完成前不修改有效资源；出现并发版本变化返回可定位的冲突。大量像素、网格、波形和场数据用资源／区域引用及有界读回，避免在每个控制请求中复制全部内容。

游戏本身也默认提供人与Agent共同操作的入口：公开高层动作、可配置的语义状态／场景对象和结果。开发preset聚合已注册调试能力；最终玩家可见／可控范围按开发者、用户、宿主和会话配置。AI／行为逻辑的逐tick执行是native运行时职责，不逐帧调用外部Agent协议。

## 7. 用现有作品验证一条完整游戏生产链

优先在现有打砖块／格斗纵切上补完整工程流程，保留原作品质量标准；工具界面和引擎能力随后逐项交付，不另以新增空壳作品替代。

1. 导入真实图像／字体／声音，生成目标变体，保存稳定资源引用。
2. 用关卡／场景工具组合可玩的场景、出生点／碰撞／相机与UI。
3. 编排动作、事件、声音和效果；人和Agent均可用同一动作完成一段实际游玩。
4. 源素材重导入／动作调整后，引用与局部覆盖保留，派生碰撞／资源按版本更新。
5. 保存进度、退出、加载恢复；同时验证输入回放／确定性和错误诊断，区分短期回滚与长期存档。
6. 通过同一mcpp任务输出选定参考目标，再扩展Web／Toy等目标；验证首包／按需资源、性能、设备输入与实际可玩性。
7. 修改一项内容，产生可审查更新构件并验证资源／存档兼容；干净工程无需编辑器也能构建和运行。

角色／战斗配置另外用现有gongfu验证分件／骨骼／动画／受击框烘焙及演出；3D和高密度模拟分别需要自己的真实配置与设备预算，不能从上述2D链路推断通过。

## 8. 当前事实、分期与范围

现有源码提供mgame世界／固定步长／输入／简单物理／双peer回滚，以及专用gongfu表现／数据／烘焙CLI、图像处理、基础音视频、UI／Agent和Inspector等原料。已有 `gongfu.studio` 明确CLI先行、图形工作台未完成；2026-10-29美术管线记录了部分图像和角色能力，不能当作新通用工具的完整验收。

优先级：共享引擎／资源／控制契约 → 一个参考平台的素材和可玩场景闭环 → 场景／玩法／角色等工具纵切 → 发布维护／其它后端及按游戏类型扩展。工具按底层成熟度后置；Web／Toy限制、按需资源和低档位成本从架构阶段明确。所有工具复用公开能力，默认SDK不包含整套编辑器或所有游戏模块。

当前未交付通用素材工作台、关卡／玩法设计器、完整rig／3D／物理／Noita能力、完整存档维护或上述全流程。此补充不关闭官网R0–R6／C2–C6、40项公共动画／20创意组合、Manim与既定作品质量范围。
