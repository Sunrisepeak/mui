# 通用动画：组件 × 效果 × 动画

2026-11-01 定（D-93）。这是[定位](2026-11-01-openmui-positioning-site-design.md)里的亮点 ③。它在[实施计划](2026-10-26-openmui-implementation-plan.md) §6（hanim、D-49、D-60）和[渐进式披露](2026-10-28-openmui-progressive-disclosure-design.md)（D-69 的 L0–L3）之上展开；计划里写了但还没有实现的 FLIP 和共享元素过渡，由本文的 `morph` 统一实现。性能和降档见[性能分档](2026-11-01-openmui-performance-tiers-design.md)。

---

## 1. 要解决的问题

| | 现在的 UI 框架 | 现在的 openmui |
|---|---|---|
| 组件 A 变成组件 B | 只有外框几何 + 快照淡化（SwiftUI `matchedGeometryEffect`、Compose `SharedTransitionLayout`、Flutter Hero、Framer Motion `layoutId`、View Transitions） | 没有（FLIP、共享元素在计划里，未实现） |
| 控件的动画 | 组件作者写死 | 属性过渡、`glyph_motion`、`pixel_effect`、`hanim::Timeline`、风格包的状态规则——几套各自独立的接口 |
| 动画作为对象 | Web Animations、AnimationController 有句柄，但不进语义、不确定 | 没有单个动画的句柄；一个节点只能有一个 `pixel_effect` |
| 结构级变形 | manim（离线）、Rive / Lottie（预制素材） | 原料都在：稳定 ID 的语义树、矢量显示列表、字形动画、时间线编排、时间的纯函数 |

目标：**任何组件之间、任何状态之间的动画都来自同一个通用机制**，粒度和控制达到 manim 的水平；默认就有高质量动画，不需要写；同时允许一直深入到 GPU 的自定义。

## 2. 原则

1. **一切动画都是状态 A → 状态 B 的变换。** 开关从关到开、列表重排、页面切换、按钮展开成对话框、删除、热加载前后的界面，都是同一个机制；只是 A、B 来自哪里不同。
2. **组件只声明状态和部件，不写动画。** 内置组件和用户的组件用同一个库，没有特权代码；lint 规则 `motion`：组件代码里不允许直接写动画（只能填槽、选策略）。
3. **动画作用在组件真实的"物质"上**（§4）。所以动画通用、结果因组件而异：红按钮炸开是红色的碎片，字跟着碎；带图片的卡片碎片上是图片的局部。
4. **三类对象，同一套规则**：组件、效果、动画都是数据（四种语言的 builder 一样，能写进 view 文档和时间线文档），都在语义树里可见，都按全局时钟求值、可以拖动和倒放，结果确定。
5. **语义立即生效**：语义树马上是 B，像素还在过渡；agent 和读屏不等动画。
6. **可以打断**：中途换目标时从当前画面出发，速度连续。
7. **脚本只声明**：脚本给出组件树和动画、效果对象；每帧的求值由原生引擎按批完成（脚本永远不进入每帧路径；插件按阶段、按批调用）。
8. **处处都能跑**：每个动画和效果对象带降档序列，档位由策略和环境选，选择记进会话（[性能分档](2026-11-01-openmui-performance-tiers-design.md) §3–§5）。

## 3. 三个维度，各分三级

|  | 基础 | 组合 | 自定义 |
|---|---|---|---|
| **组件** | 原语（box、text、image、painter…）和基础控件；补到约 40 个（[定位](2026-11-01-openmui-positioning-site-design.md) §2.2） | 由基础组件组成：表单、卡片、工具栏、对话框、数据表 | painter、canvas、GPU 渲染特性 |
| **效果** | 单个效果：模糊、色彩、置换、遮罩、发光、颗粒、溶解、像素化… | 效果链（按顺序叠加）：neon = 发光 + 泛光 + 着色；ink；retro；液态玻璃 | Slang 着色器插件，带 CPU 参考实现 |
| **动画** | 一个属性上的 tween、spring、关键帧、衰减；运动路径；缓动 | 编排（序列、并行、错开、嵌套）；`morph`、打散重组、爆炸、溶解、揭示、重排、字形变形、数字滚动、时间回溯 | 自定义插值函数、物理、GPU 计算 |

**组合**：同一维度内——组件是树，效果是链，动画是时间线。维度之间——

| 方向 | 例子 |
|---|---|
| 动画 → 效果 | 动画驱动效果参数（溶解进度、发光强度） |
| 效果 → 动画 | 效果作用在动画产生的物质上（粒子拖尾、碎片热光） |
| 组件 → 两者 | 组件挂效果链；组件的状态变化填动画槽 |
| 动画 → 组件 | 组合动画的输入、输出就是组件（A → B） |

**一个节点可以挂多个效果**（取代现在单个的 `pixel_effect`），效果的参数用和其他属性一样的动画接口驱动。

## 4. 物质表示

任意子树渲染出的内容，分解成统一的、多粒度的、带身份的表示：

| 粒度 | 内容 | 来源 | 用于 |
|---|---|---|---|
| **节点** | 盒子及视觉属性（位置、尺寸、圆角、颜色、边框、阴影、透明度、效果参数） | 布局和样式 | 状态过渡、重排、FLIP |
| **部件** | 绘制单元：形状、文字段、图片；身份 = 节点 ID + 部件名 | 显示列表（每一项带身份） | 语义层的匹配 |
| **字形和子路径** | 单个字形、单段路径 | 排版结果、路径 | 文字变形 |
| **点** | 按弧长重采样的轮廓点 | 路径 | 形状变形 |
| **粒子和碎片** | 从真实像素采样的点（位置、颜色、透明度），或按真实几何切出的碎片 | 子树的离屏快照（CPU 和 GPU） | 打散重组、爆炸、溶解 |

- **部件名**由组件可选地声明（开关的 `knob`、`track`、`label`），帮助匹配；不声明时用显示列表里的顺序和种类。
- 提取按需进行、有缓存，粒度和数量随档位变化（粒子数、点的密度、快照分辨率）。
- **随机数的种子 = 节点 ID + 过渡 ID**（`openmui.math` 的确定性随机）：同一个组件每次重放一样，不同组件天然不同。

## 5. 槽和策略

### 5.1 槽

| 槽 | 触发 |
|---|---|
| `enter` | 节点出现 |
| `exit` | 节点删除（物质留在幽灵层直到动画结束，§7） |
| `update` | 值或属性变了（同一节点的 A → B） |
| `state` | 悬停、按下、焦点、选中、禁用… |
| `reorder` | 在父节点里的位置变了 |
| `replace` | 子树换成另一棵（A → B，跨组件） |

每个槽放一个动画对象，或一个**策略**（几个候选和各自的条件，例如按档位、按"减少动效"、按组件角色）。

### 5.2 叠加链（后面覆盖前面）

1. 框架默认
2. 风格包的动效设定（设计系统的 `motion.*`；换风格包，整套动效跟着换）
3. 应用
4. 组件实例
5. 用户设置——只能改开发者暴露出来的部分；系统的"减少动态效果"总是生效
6. 运行环境——档位、帧预算（[性能分档](2026-11-01-openmui-performance-tiers-design.md) §5）

**选中的是哪个对象、哪一档，作为明确的输入记进会话**，所以重放和测试仍然逐位相同。agent 能读、能改这些设置（经 openas）。

## 6. `morph(A, B)`：变换

一帧之内的顺序（新增的三个阶段是管线插件，D-66）：

```
状态变化 → 布局（B 的终态先算好，动画期间不重新布局）
         → 物质提取 → 匹配 → 动画求值 → 效果链 → 光栅化或 GPU → 呈现
```

### 6.1 匹配：四层，从精细到粗略

| 层 | 规则 | 匹配上之后 |
|---|---|---|
| 节点 | 相同 ID | 插值所有视觉属性（颜色走 OKLab） |
| 语义 | ID 不同时按角色、名称、文本 | 按钮上的"删除"↔ 对话框里的"删除"按钮 |
| 字形 | 字素序列的最长公共子序列 | "保存"→"已保存 ✓"：相同的字移过去，新字长出，旧字消失 |
| 形状 | 剩下的路径按弧长重采样，对齐起点，逐点插值 | 圆角矩形 → 圆；图标 → 图标 |

都匹配不上的部分用效果过渡（淡化、溶解、揭示）。**默认只在有意义时变形**（不同字形之间硬变形难看），规则写进匹配器并有像素测试。

粒子粒度的配对（打散重组）：按颜色和位置的确定性配对（例如按空间填充曲线排序后对齐），算法是匹配器插件，可以替换。

### 6.2 编排

- 每一对匹配是一条轨道；一次变换是一个时间线对象（hanim 的 `Timeline`），可以 `play`、`pause`、`seek`、`reverse`、调速，`finished` 可等待。
- 默认编排：按距离、顺序或语义层级错开；每对可以单独指定路径（直线、弧线、任意曲线、流场）、延迟、缓动、附加效果。
- 打断：从当前的插值状态出发、带着速度，生成新的变换。

### 6.3 语义与输入

- 语义树立即是 B；离开的节点不在树里，检查器能看到幽灵层。
- 输入发给 B；动画中的节点在语义里带 `animating`，agent 可以 `wait settled`（已有）。
- 减少动态效果：退化成很短的淡化。

## 7. 幽灵层与粒子

- **幽灵层**：节点从树上删除后，它的物质保留到 `exit` 动画结束（类似 React 的 AnimatePresence，但在底层、对所有组件通用）。
- **粒子和碎片**是渲染特性 `render/particles`（D-81 原计划里就有）：GPU 计算 + CPU 参考实现；采样（像素或边缘）、碎片（按真实几何的 Voronoi 切分）、确定性的固定步长物理（重力、阻力、流场）、拖尾；数量上限随档位。

## 8. 时间线寻址与动效工作室

- 每个动画对象有地址：`节点路径 / 槽 / 匹配对`。时间线文档可以指向它，改它的关键帧、路径、编排。
- **动效工作室**：在时间线编辑器里打开页面上任意一个正在用的动画——每一对匹配是一条轨道，拖关键帧、改缓动、换效果，控件的动画实时改变；改动写回数据（风格包的动效设定、view 文档、时间线文档），同时显示等价的代码改动。
- **影片 = 场景 + 时间线**：场景只描述组件树，时间线编排场景里的任何动画对象（[定位](2026-11-01-openmui-positioning-site-design.md) §4.1）。

## 9. 定制分级（对应 D-69）

| 级 | 做什么 | 例子 |
|---|---|---|
| L0 零配置 | 状态一变就有风格包给的高质量动画 | `toggle({.checked = on})` |
| L1 声明 | 风格包的动效设定；view 文档里给槽填库里的对象、调参数 | `exit = "explode"`、`motion.spring.snappy` |
| L2 编程 | `morph` 的 builder：指定配对、路径、错开、效果；单个动画的句柄 | 下面的代码 |
| L3 插件 | 自定义动画、匹配器、效果（Slang）、过渡着色器（拿到 A、B 的快照和几何，以及进度） | 翻页、液态融合 |

**GPU 自定义默认要有 CPU 参考实现**（Slang 的 CPU 目标，或手写参考），保持逐位相同；只有 GPU 版本的允许，但必须声明 `deterministic = false`，不参与像素固定，在低档和 CPU 路径上按它的降档序列替代（Q-32 已定）。

## 10. 接口示意

```cpp
// L0：只声明状态；动画来自风格包
toggle({.id = "wifi", .checked = on});

// L1：给槽选库里的动画（也可以写在 view 文档或风格包里）
card({.id = "note", .motion = {.exit = explode{.grain = shards(voronoi), .physics = gravity, .effect = ember()}}});

// L2：组件 A → 组件 B
morph(button_view, dialog_view)
    .match("delete", "dialog/confirm")          // 语义层指定配对
    .path("label", arc(0.3))                    // 某一对的运动路径
    .stagger(by_distance, 30ms)
    .effect(unmatched, dissolve());             // 没匹配上的部分

// 打散成粒子 → 沿路径 → 重组成另一个组件
morph(card_a, badge_b)
    .grain(particles{.from = pixels, .density = adaptive})
    .match(nearest_color)
    .path(curve(p0, p1, p2), jitter(12))
    .stagger(by_position, 400ms)
    .effect(trail(0.3));

// 都是时间线对象
auto t = rt.play(morph(...));  t.pause();  t.seek(0.4);  t.reverse();
```

```toml
# 风格包的动效设定（L1）。`motions` 表：槽名对规则覆盖的所有节点生效，
# 类型或角色名对它自己的槽生效；值是一个动画对象，或候选列表（策略）。
# （`motion` 表仍是曲线令牌 motion.fast 等，两者分开。）
[style.ink.motions]
update        = ["ink", "simple"]                  # 先用 ink；档位不够时用 simple
state         = "simple"
"role:dialog" = { enter = { use = "spring", rise = 12 } }
```

C1 落地的形状（`openmui.view`）：

- 六个槽 `update / enter / exit / state / reorder / replace`；`state`、`reorder`、`replace` 没有自己的对象时用 `update` 的。变化归哪个槽：子节点同一集合换了顺序是 reorder，一个都不剩是 replace，只有悬停 / 按下 / 焦点变了（没有属性写入）是 state，其余是 update。
- 动画库 `Theme::motion_library`：`morph`、`simple`、`spring`、`liquid`（拉成水滴 + metaball，T3 起）、`ink`（慢一点的补间 + wobble，T2 起）；`travel` 是动画携带的效果，强度在半程最大、两端为零。
- 叠加链：框架默认规则 → 风格包的 `motions` → 应用的规则 → 节点的 `motion` 属性 → 用户的选择（`Runtime::set_motion_choice`，只在槽提供了这个候选时生效）→ 设备（候选的效果不在当前档位就取下一个）；用户的选择和档位一起记进会话的 `adapt` 记录。
- 句柄：`hold_motion / pause_motion / play_motion / seek_motion / set_motion_rate / release_motion / motion_time`——变形有自己的时间，握住时到终点也保留，松开后从当前位置按运行时的速度继续。
- 多效果：`pixel_effect` 可以是列表，后面的包在前面的外层，各自按档位取舍。

## 11. 组合动画库（首批）

| 动画 | 组成 |
|---|---|
| 状态过渡 | 节点层插值 + spring |
| 重排（FLIP） | 节点层 + 错开 |
| 共享元素 / 组件变形 | 语义层 + 形状层 + 效果 |
| 字形变形、数字滚动 | 字形层 |
| 打散重组 | 粒子 + 配对 + 路径 + 拖尾 |
| 爆炸 | 碎片 + 物理 + 热光；`A → 空` |
| 溶解、揭示、擦除 | 效果层 |
| **时间回溯** | hanim 的 `TimeMap`：起步慢、指数加速（倒带）、接近目标急减速、轻微回弹停住；每一步撤销是那一步原来的过渡倒放（时间的纯函数，倒放是精确的），越往前越快，多步错开成"倒流"；速度越快运动模糊、色散、颗粒越强，停下全部收回；降档只剩速度曲线和淡化。用于回溯条（[agent 接入与回溯](2026-11-01-openmui-agent-connect-rewind-design.md) §6），任何应用都能拿去做撤销 |

## 12. 验收用例

| # | 用例 | 层 |
|---|---|---|
| 1 | 开关开 / 关 | 节点层 + 风格包的 spring |
| 2 | "保存"→"已保存 ✓" | 字形层 |
| 3 | 按钮展开成对话框 | 语义层 + 形状层 |
| 4 | 列表重排 | 节点层 FLIP + 错开 |
| 5 | 打散 → 沿路径 → 重组（自选 A、B、路径） | 粒子层 |
| 6 | 删除爆炸：用在五个不同的组件上，结果明显不同，每次重放一样 | 碎片 + 物理 |
| 7 | 同一个开关挂三种动画对象（简洁、液态、墨），用户在设置里实时切换；低档演示 | 槽 + 策略 + 降档 |
| 8 | 自定义 GPU 过渡（翻页），CPU 参考实现验证 | L3 |
| 9 | 时间回溯：二十步撤销的倒流 | 组合 + TimeMap |

每个用例：能拖时间旋钮；能在动效工作室里打开；切镜头能看到语义树（立即是 B）；像素固定；在 bench 里有预算（[性能分档](2026-11-01-openmui-performance-tiers-design.md) §6）。
