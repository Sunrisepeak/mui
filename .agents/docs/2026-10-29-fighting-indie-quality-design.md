# 格斗游戏：顶级独立游戏的水准（设计和评估）

日期：2026-10-29。状态：设计，实施按 §9 分轮进行。

这份文档定下 `showcase/fighting`（gongfu 上的 2D 格斗游戏）要达到的水准：从独立游戏的视角看，美术、音效、配乐、界面、交互、玩法、动画、流畅度和多视角都要到顶级，同时在合适的地方、不突兀地展示 openmui / mgame 的特点（D-63：作品双视角）。人物先做 5 个设计角色（墨、霓、璃、岳、刻；Kata 是训练用的假人，不算），不加新人，但每个人的设计和细节都要到顶尖。每一项都有验收：能自动检查的进 CI，不能的有评审表。

相关文档：总体设计 §8（[structure-render-web-game](2026-10-28-openmui-structure-render-web-game-design.md)）、[角色设计 1](2026-10-28-gongfu-characters-design.md)、[角色设计 2](2026-10-28-gongfu-characters-2-design.md)、[精力和超必杀](2026-10-28-gongfu-posture-supers-design.md)。

## 1. 标杆

每一项对着这一类里公认最好的独立作品（或独立规模的作品）：

| 方面 | 标杆 | 学什么 |
|---|---|---|
| 美术 | Skullgirls、Hollow Knight、Gris | 统一的美术方向；剪影一眼可辨；线条有粗细、有手感；背景有层次、有呼吸 |
| 动画 | 街霸 III 3rd Strike、Skullgirls、Them's Fightin' Herds | 预备—动作—余势；挤压拉伸；拖影帧；受击的方向感；待机的呼吸和衣摆 |
| 打击感 | 街霸 6、Guilty Gear Strive、Nidhogg 2 | 每一下都有停顿、震动、火花、声音在同一帧；轻重分明 |
| 音效和配乐 | Hades、Celeste、Furi | 配乐跟着局势走（叠层、过门、高潮）；每个人一个主题；混音清楚不吵 |
| 界面 | Hades、Persona 5、Strive | 选人、对阵、结算有性格；动效干脆；信息层级清楚；手柄键盘都顺手 |
| 玩法 | 街霸 6、Strive、Sekiro 的拼刀 | 系统简单而深；角色差异大；平衡有数据；联机用回滚 |
| 流畅度 | 街霸 6 的 60 Hz 锁帧、Celeste 的手感 | 帧时间稳定；输入到画面最短；没有卡顿 |
| 多视角 | Strive 的超必杀镜头、Tekken 的回放、街霸 6 的训练视图 | 动态镜头；回放剧场能换机位、逐帧拖动；训练里看得到判定和帧数 |

## 2. 现在的样子（2026-10-29，诚实评估）

截图来自测试的无头渲染（`tests/fighting_test.cpp` 写进 `/tmp/openmui-tests/fighting*`）。按 1–5 打分，5 是标杆水平：

| 方面 | 分 | 现状 | 差距 |
|---|---|---|---|
| 玩法 | 3.5 | 拼刀、精力、三级超必杀、五个各有机制的角色、平衡门槛、AI、训练模式都有；回滚和联机层（`mgame.net`）有 | 没有完整的一局流程（选人、多局、结算）；联机没接进游戏 |

| 动画 | 2 | 骨骼动画、每招有关键帧；超必杀有镜头 | 身体是胶囊和圆角线段，像人偶；缺少预备、余势、拖影、衣摆和头发的二次运动；走路和待机机械 |
| 美术 | 1.5 | 每个人有配色和道具（墨的笔、璃的镜子）；超必杀的背景有主题 | 没有统一的美术方向；角色没有造型（脸、头发、衣服的形）；场景是一块纯色地面；HUD 是功能性的 |
| 音效 | 3 | 合成的分层音效库，每个人的材质（墨、霓虹、玻璃、山、钟） | 没有环境声、脚步、衣服声；混音没有响度标准 |
| 配乐 | 0 | 没有 | 全部 |
| 界面和交互 | 1.5 | 对局 HUD、训练模式的读数 | 没有标题、选人、选场景、对阵画面、暂停、设置、结算；没有改键；手柄只在宿主层 |
| 流畅度 | 3.5 | 模拟每帧 0.2 µs 级、回滚 8 帧 196 ns、零分配；无头 60 Hz 精确 | 显示刷新率高于 60 时没有插值；没有帧时间的端到端测量 |
| 多视角 | 2 | 训练模式的判定框和帧条；超必杀特写镜头 | 对局镜头不跟随、不缩放；没有回放剧场和换机位 |

结论：系统和确定性已经扎实，表现层（美术、动画、配乐、界面）离标杆最远，是接下来的重点。

## 3. 美术方向

**一句话：“墨线 + 剪纸”的风格化矢量。** 每个角色是有粗细变化的毛笔线勾边、三到四个平涂色阶（亮、中、暗、边缘光），剪影先于细节。全部用 `render.vector` 画（没有位图素材），任意分辨率都锐利。

矢量和程序化只是手段，水准来自**亲手定的关键姿势**（评审意见）：骨骼负责中间帧，每个招式的关键帧可以给任意部件换一张手画的矢量形（替换图：拳头的透视、甩出的袖子、拉长的腿），可以有破坏剪影的形变和非对称的节奏。五个人共用一套“世界规则”（形的语言、线的粗细、材质和光的规则），霓虹、玻璃、墨才像在同一个世界里。换风格包不作为美术水准的证据。

- **线条**：轮廓用变宽笔触（沿骨骼方向粗、关节处细，端点尖），按镜头远近统一粗细；`render.vector` 加“变宽描边”（宽度沿路径插值），是渲染器的能力，也给别的作品用。
- **明暗**：每个部件有亮面和暗面两个形（由光的方向和部件角度决定，纯函数），再加一道边缘光（场景的主光色）。
- **造型**：每个人有脸（眼、眉、嘴的简笔，随招式换表情）、头发（几束有重量的形）、衣服（下摆、袖子、腰带是跟着骨骼的形，不再是线段）、手（握拳、张开、持物三种）。剪影测试：五个人涂成纯黑，在 64 px 高时也一眼分得出。
- **配色**：每人一组主色和两套换色（已有），全局保证两人同屏对比度（两人主色在 OKLab 里距离 ≥ 阈值）。
- **场景**：五个场景，每个属于一个人（§5），4–6 层视差，前景有遮挡物，远景有天气和光；场景的动态（灯笼、霓虹闪、玻璃反光、云、钟摆）是时间的纯函数（hanim），回滚不需要保存。超必杀时场景压暗、主色换成发动者的。
- **特效**：火花、冲击波、残影、碎片统一成“墨点、纸屑、光线”三种语言，每个人在这三种上换材质（墨、电光、玻璃、石、金属）。

## 4. 动画和打击感

- **动画原则靠关键姿势和评审，不靠公式**：每个招式按它自己的节奏设计预备、动作和余势（三帧的快招不强加预备）；快的肢体在动作帧有拖影形（smear）。`gongfu.studio` 里全速和逐帧对照标杆片段看。
- **二次运动**：衣摆、袖子、头发、腰带用弹簧，但输入是模拟状态的历史（最近 N 帧的位置和速度，状态里已有），所以仍然是（状态，帧）的纯函数，回滚不存画面状态。
- **受击**：按命中方向和高度分上、中、下、腹、浮空五种受击姿势；重击有慢镜头的挤压拉伸。
- **待机和移动**：呼吸、重心摆动、走路的步伐和身高起伏；每人的走路节奏不同（墨慢而稳，霓弹跳）。
- **插值**：模拟 60 Hz，画面按显示刷新率（120/144 Hz）在两帧之间插值骨骼角度（`mgame::Clock::alpha`），打击停顿时不插值。
- **打击感数据**：已有的冲击配置加上手柄震动曲线（SDL3 rumble）和击倒慢动作（最后一击 0.5 秒 0.25 倍速、镜头推近）。

## 6. 音效和配乐

- **音乐引擎**：`openmui.audio` 加音序器（`*.music.omui.toml`：速度、拍号、音轨、乐器、段落和过门），乐器是声音数据（已有的层、包络、滤波）加采样式的打击乐合成；按样本精确，离线渲染逐位确定（和音效一样）。
- **自适应**：每首曲子分层（基础、紧张、高潮），由对局状态驱动——双方都低血时加紧张层，三气特写时切到发动者主题的高潮过门，击倒时收尾和弦；切换落在小节线上。
- **混音**：音乐、音效、界面三条总线，侧链压缩让打击声压过音乐；整体响度对准 −16 LUFS（游戏常用），峰值 ≤ −1 dBFS，测试里测。
- **环境声**：每个场景一条循环（雨、风、钟、虫鸣），脚步和衣服声随动作。

## 7. 界面、交互和多视角

- **流程**：标题 → 模式（对电脑、本地双人、联机、训练、回放）→ 选人（立绘由角色的造型数据在定格姿势下渲染，换色预览）→ 选场景 → 对阵画面 → 出场 → 三局两胜 → 击倒落幕 → 结算（胜利台词、本局数据、保存回放）→ 再战。每个界面都是 openmui 的组件和视图，有语义树（屏幕阅读器和 agent 都能操作，D-63），动效是 hanim。
- **交互**：手柄和键盘全程可用（焦点导航），改键；输入缓冲和指令宽容已有；暂停菜单；设置（音量三条总线、画面效果强度、闪光减弱——光敏保护、色弱配色、简易操作）。
- **联机**：`mgame.net` 的回滚会话接进对局（本机两个窗口、局域网 UDP），显示延迟和回滚帧数。
- **多视角**：
  - 对局镜头：跟随双方中点，按距离缩放，跳跃时上移，角落时偏移；
  - 超必杀特写（已有）；
  - 回放剧场：确定性回放可以逐帧拖到任意时刻（`Timeline::seek`），换机位（对局镜头、特写镜头、自由镜头）、换视图（画面、判定和帧数、语义树——agent 看到的、输入历史），这是框架“确定性 + 语义”的自然展示；
  - 训练模式的判定框和帧条（已有）。

## 8. 流畅度和验收

**自动（进 CI）——这些只证明正确和完整，不证明好（评审意见）：**

| 项 | 标准 |
|---|---|
| 模拟和回滚 | 已有的预算（每帧、回滚 8 帧、零分配） |
| 画面帧时间 | 1080p 一帧画面（两人、场景、特效）CPU 光栅 ≤ 8 ms，GPU 路径 ≤ 2 ms（lavapipe 的基准另算）；基准进 `budgets.bench.omui.json` |
| 延迟和节奏 | 桌面宿主测量输入到上屏（input-to-photon，有硬件时）、呈现间隔、p95 / p99 帧时间和卡顿次数，在 60 / 120 / 144 Hz 下进报告；插值不增加延迟、不模糊有效帧的接触 |
| 确定性 | 模拟哈希逐位相同；画面和声音的逐位固定只对 CPU 参考渲染器和离线混音（GPU 输出按容差比较） |
| 回滚的观感 | 有延迟、抖动、丢包时，纠正不重复声音、不打断特效、不闪（录下来逐帧检查） |
| 可读性的底线 | 剪影（黑影在 64 px 高时两两可分）、两人主色在 OKLab 的距离（同色对战用换色）——只是底线，真正的可读性由下面的评审决定 |
| 声音 | 响度 −16 ± 1 LUFS，峰值 ≤ −1 dBFS，无削波；每个人每类命中都有声音 |
| 界面 | 全流程能只用手柄、只用键盘、只用 agent 动作走完（测试脚本走一遍） |
| 联机 | 已有的链路模拟测试，加上整局在两个实例上的哈希一致 |

**评审（不能自动的，决定“好不好”）**：

- **对照片段**：每一项挑标杆作品的片段做对照（同一类动作、同一类场面），评审看对照而不是看绝对分数；
- **分项评审**：美术、动画、音频、格斗玩家各一个视角（维护者、试玩者、codex 作为参考之一），**每个角色单独过**；动画按全速和逐帧两种看招式的姿势、节奏、接触和收招；声音看整局下来的疲劳、音色辨识、打击的辨认和互相遮盖；
- **可读性测试**：真人在混战片段里认出谁是谁、攻击的高度、命中 / 防住 / 拼刀的结果，覆盖同角色对战、每个场景、灰度和色弱模式；
- **玩法**：机器人的平衡门槛只是底线；新手的上手（五分钟能打出必杀）、老手的对策（每个对位有可说出的打法）、无障碍任务；
- 每轮都评审，不等到最后。README 的图（每个 ≤ 1 MB）只是展示，评审用的片段不受这个限制、不进仓库。

## 9. 分轮

先做**墨和霓的完整纵切**（评审意见：镜头、声音、联机都会改变动画的观感，后补会返工），定下可读性和延迟的预算，再按同样的标准一个一个做另外三人：

1. **画面基础**：`render.vector` 的变宽描边；present2d 的部件形（衣服、头发、脸、手）和关键姿势的替换图、两色阶加边缘光；世界规则（形、线、材质、光）；墨和霓的造型换新。
2. **动画**：墨和霓的全部招式按关键姿势重做；二次运动（由状态历史算）、拖影形、五种受击、待机和走路；显示刷新率插值。
3. **对局的其余部分**：对局镜头、击倒落幕、HUD 重做、手柄和震动、三局两胜和再战。
4. **声音**：音乐引擎、一首完整编曲（先做墨和霓的对局曲，段落之间按编曲设计过门，不是每次超必杀都换曲）、混音和响度；环境声。
5. **联机**接进游戏（本机两个实例、局域网），延迟和回滚观感的测量。
6. **纵切评审**：§8 的全部评审，墨和霓都过了才往下。
7. **璃、岳、刻**：每人一轮（造型、场景、动画、声音），每轮评审。
8. **界面和流程**：标题、选人、选场景、对阵、结算、暂停、设置、改键。
9. **回放剧场和训练工具**：换机位（预先设计的机位，不做无约束的自由镜头）、逐帧拖动、判定和帧数、输入历史；语义视图只在分析工具里，不是默认视图。

每轮一个提交，CI 全绿后接着做；每个 showcase 的 README 带一张关键帧或一段 ≤ 1 MB 的短片。

## 10. 评审记录（2026-10-29，codex，作为参考之一）

- 美术：矢量能到标杆，程序化配方本身不能——会做成“精致的人偶”。要亲手定的关键姿势、透视、破坏剪影的形变、能表达的手和脸、不对称的节奏；骨骼之外允许替换图；五个人共用世界规则；先在动态里证明墨**和霓**再扩。“换风格包”不是美术水准的证据。→ 采纳：§3、§9 第 1–2 步。
- 验收：§8 多半在量正确和完整。剪影 IoU、配色距离、强制的预备帧和余势、“相邻帧不同”、LUFS 都是弱代理；要真人的可读性测试、按全速和逐帧看动画、输入到上屏的延迟和帧时间分布、GPU 输出按容差、回滚的观感检查、分项的独立评审、每个角色单独过、新手和老手的测试。→ 采纳：§8 改写；强制预备帧的数据检查去掉（它会伤到三帧的快招）。
- 顺序：先做两个人的完整纵切（美术、动画、音效、一首完整的曲子、HUD、镜头、手柄、再战、联机），每轮都评审。→ 采纳：§9 改写。
- 融合：刻的历史机制、训练和回放工具是自然的；默认的语义视图、给角色分配框架效果、霓的全局扫描线、风格切换会像在推销。诊断放进分析工具；2D 的“自由镜头”要预先设计机位；超必杀时每次换主题会让音乐碎掉；前景遮挡、玻璃扭曲、持续的震屏都不能伤可读性。→ 采纳：§9 第 4、9 步；霓的扫描线只在她的超必杀特写里。
