## 本轮已经处理的

- **站点性能**：显示改用 GPU，有硬件就用 WebGPU 或 WebGL 2。CPU 光栅提速 3.8 倍，结果逐位相同。顶栏加了帧率表。站点的 `performance` 维度会在下一次评估复核（v1 时这些改动还没部署）。
- **运行中帧的分配**（ui-framework 的 `code_quality`）：
  - layout 的样式比较不再构造临时 vector；
  - bounds 阶段复制 watchers 时改用一个保留下来的 vector。
- **mgame**（game-engine 的 `input_net`、`code_quality_tests`）：
  - `World::add/remove` 拒绝失效的句柄，加了测试；
  - 网络会话的参数超出范围时取最近的有效值，不再出现负的环大小或对 0 取模，加了测试；
  - 输入按自身字节发送：编译期要求没有填充字节、目标是小端。
- **基准门禁**（ui-framework 的 `performance`）：CI 加上 `--all-budgets`，少跑一个基准、或基准被跳过都算失败。本机 48 个预算全部检查通过。
- **文档**：hanim 的 README 改为“只依赖标准库和 `openmui.math`”。
- **测试速度和磁盘空间**：诊断写成了 [mcpp#874](https://github.com/mcpp-community/mcpp/issues/874)。

## 采纳，排进后面的轮次

按对“总评”（最低维度）的影响排序：

1. **作品的人机体验**：
   - 文档墙：保存布局和镜头，文档之间的链接可以跳转，加上返回和搜索；
   - 风格工坊：retro 的可读性，参数显示名字、数值和单位，撤销和重置；
   - 打砖块：第一分钟的教学，暗模式下状态可读；
   - 宣传片：小屏幕上的字号，结尾。
2. **官网**：按“同一个节点的四种呈现”重做首页，加上品牌标志和视觉语言、阅读宽度，全景页用真实的缩略图。
3. **原生无障碍**：Windows UIA、macOS NSAccessibility、Linux AT-SPI 的适配，以及真实读屏的验收。这是 ui-framework 最低的一项，也是框架核心论点（语义树）还没有兑现的地方。
4. **网络**：确认号范围、包大小、未来帧窗口的校验；输入按字段编码、带版本号（本轮只做到编译期约束）；一个在线对战的垂直切片。
5. **渲染**：
   - 和 Skia、Blend2D 用同一组输入对比的工具，按 D-56 优先用 mcpp 生态里的库；
   - 一个独立的质量用例集，测文字和极端几何，留下误差图，不只看哈希；
   - 颜色语义，包括色彩空间和混合空间。
6. **动画和角色**：
   - 动画创作的完整循环：属性、关键帧、曲线，可以拖动预览；
   - 按 D-88 从 present2d 抽出 `openmui.rig`；
   - 布局动画和状态机。
7. **帧管线**：阶段失败要明确传到帧和宿主，而不是只记日志、照常出帧。

## 暂不采纳，或打折采纳

- **“要有第二个独立实现”“要有外部用户验证”**：方向对，但现在做不到。先把一致性测试（CTS）做成可移植的。
- **“去掉官网的常驻侧栏”**：导航仍然需要。改成按“学习 / 构建 / 探索”分组、左对齐、选中态和主要按钮区分开。
- **“把渲染的 GPU 结果和 Vello、Skia Graphite 比”**：要等有真实 GPU 的测试环境；现在的数据来自 lavapipe，只能说明能跑通，不能当性能证据。
