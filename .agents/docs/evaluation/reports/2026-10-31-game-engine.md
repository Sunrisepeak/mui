## Benchmark summary

**Unreal Engine 5** sets the strongest target here for integrated cinematic and sound authoring, effects, and production tooling. Its [Paper 2D documentation](https://dev.epicgames.com/documentation/unreal-engine/how-to-use-paper-2d-in-unreal-engine?lang=en-US) and [MetaSounds API](https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/Metasound?lang=en-US) establish relevant capabilities; this comparison does not require matching its 3D scope.

**Unity 6** provides the most directly relevant integrated 2D production benchmark: sprites, tilemaps, physics, lighting, animation, and UI workflows. [Unity 6 documentation](https://docs.unity.com/en-us/engine/6000.0/manual/unity2d).

**Godot 4** is the closest target for a compact engine with approachable visual composition, dedicated 2D physics, and integrated audio workflows. [Physics documentation](https://docs.godotengine.org/en/stable/tutorials/physics/index.html), [audio documentation](https://docs.godotengine.org/en/stable/tutorials/audio/index.html).

openmui's clearest differentiated strength is the connection between actual game components, semantic inspection, agent actions, and reproducible simulation. Its largest deficits are authoring completeness and demonstrated operational reliability.

Against the references: the world model is considerably simpler than Bevy-style scheduling; gongfu follows the save/restore/predict approach exemplified by [GGPO](https://github.com/pond3r/ggpo), but simulated-link tests do not establish equivalent online maturity. The supplied animation frames also fall short of Skullgirls' demonstrated pose clarity and animation richness; its developers describe the deliberate animation investment in [their production account](https://skullgirls.com/2011/04/on-animation-in-skullgirls/). That comparison concerns achieved presentation, not a requirement to use hand-drawn sprites.

## Highest-priority changes

1. **Harden network boundaries:** validate options, frame arithmetic, acknowledgement ranges, packet sizes, and accepted future windows before mutating session state.
2. **Replace native-memory input serialization** with versioned, field-wise codecs and explicit value validation.
3. **Ship an actual online fighting vertical slice:** connection establishment, transport loss/reordering, pacing, timeout, disconnect, and desync diagnostics.
4. **Define fixed-point overflow and division behavior**, and validate content against safe arithmetic limits.
5. **Correct shared-action input ownership** and add stale-entity mutation checks.
6. **Complete graphical fighter authoring:** timeline, poses, boxes, impacts, cinematics, undo, and live diagnostics.
7. **Make sound and rumble rollback-safe**, with event identity, deduplication, and cancellation policies.
8. **Publish complete performance evidence**, including raster/GPU work, semantic updates, sound, networking, worst-case content, and platform details.
9. **Validate the semantic advantage with users:** controller/keyboard navigation, assistive technology, external agents, and independent content authors.

## Specific defects and inconsistencies

These code consequences are inferred unless described as visible.

- **Stale handles can mutate successors:** `mgame/world/src/world.cppm:93` and `:99` index directly without checking generation or liveness. An invalid index can also access outside storage. `get` at `:111` has similarly undocumented unchecked access.
- **Deterministic arithmetic has undefined boundary cases:** `mgame/gongfu/src/fixed.cppm:26`, `:38`, `:41`, and `:50` permit signed overflow; divisions at `:29`, `:47`, and `:51` lack zero-divisor handling.
- **A malformed message can alter session bookkeeping before rejection:** `mgame/net/src/net.cppm:112` updates acknowledgement/frame state before checking payload length at `:114`.
- **Session options can produce invalid operations:** constructor `net.cppm:70` accepts invalid ring-sizing inputs; `:208` takes modulo `checksum_every` without rejecting zero.
- **Peer input can advance through excessive future frames:** `net.cppm:115` has no adequate upper receive-window bound before writing ring slots.
- **Wire portability is overstated:** headers are little-endian, but `net.cppm:102` copies native `Input` bytes. The generic concept permits padding and architecture-dependent representations.
- **Action release loses another held source:** `mgame/input/src/input.cpp:16`–`:17` tracks one bit per action. Releasing one of two bound sources clears the shared action.
- **AI can allocate during decisions:** `mgame/gongfu/ai/src/ai.cpp:196` creates a temporary vector and pushes cancel candidates. Simulation-only allocation budgets do not cover this.
- **CLI malformed numbers can throw:** `mgame/gongfu/studio/src/main.cpp:65`–`:69` uses `stof`/`stoi`/`stoll` without a visible conversion-error boundary.
- **Platform abstraction is bypassed:** `studio/src/main.cpp:42` uses `std::ifstream`, contrary to the repository's required `mcpplibs.os` route.
- **Hash implementation is duplicated:** `mgame/gongfu/src/match.cpp:27` implements its own byte hash despite the repository's centralized-hash rule.
- **Documentation disagrees with implementation:** `mgame/world/README.md` says standard-library-only, while `world.cppm:21` imports `openmui.hash`.
