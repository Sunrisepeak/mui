# mlibs.text

A text engine (module `mlibs.text`) over SheenBidi — imported as a C++ module (`mcpplibs.mwrap.sheenbidi` from mcpp-index; no header is included) — and mlibs.unicode. How a face is read and a run of text becomes glyphs is a shaper's, installed at the slot `mlibs.text.shaper` ([`mlibs.compose`](../../base/compose), a preview, `lower` in the manifest): [HarfBuzz's](harfbuzz) where pixels are drawn (`omui::run` and the headless host install it), the cell measure of a terminal here. A program installs one; the other is not in it — a terminal links no HarfBuzz (terminal design §9).

- **Fonts**: files and data, variable instances by weight (and italic), metrics; the default set in [`fonts/`](fonts) (D-48), Inter with every program that draws text and each other script a pack an application depends on (`mlibs.text.fonts.<pack>`, D-214); fallback per grapheme cluster through the family list and a fallback chain, emoji presentation to the colour face. With HarfBuzz, a file's face is described from the few tables that say what it is and read whole when first needed (shaped with, its bytes asked for); whether it has a character is answered from its character map: Latin text holds Inter's 0.9 MB, not the defaults' 7.5 MB (`bytes_held`).
- **Paragraphs**: bidi levels (SheenBidi, Unicode 17), script runs, shaping (the shaper's) with features and language, UAX #14 line breaking with hanging spaces and overflow breaks inside overlong words, UBA L2 reordering per line, start / end / center / justify alignment, `max_lines` with an ellipsis, styled ranges (size, weight, colour, letter spacing, line height, underline, strikethrough), intrinsic widths for layout.
- **The cell measure** (`mlibs::text::cells`): text as a terminal's grid shows it — a grapheme takes its cells (`mlibs::unicode::columns`), a line is a row, whatever the size; a glyph is its code point, so a cell renderer reads the characters back. The grid (a column, a row, the baseline) is the host's.
- **Without a shaper**: a collection has no faces, says how to install one, and lays text out to nothing — the same path as a platform without the provider (compose: absent is unsupported).
- **Queries**: hit testing, carets, selection rectangles, vertical caret movement — bidi-aware, by grapheme cluster.
- **Glyphs as geometry**: `FontCollection::outline` (ems, y down, mlibs.geom's path encoding) and `color_layers` (COLR v0 from the palette), from the shaper. Text knows no renderer: [mrender.text](../../projects/mrender/text) rasterises and paints them (convergence plan §5.3).
- **Editing**: `TextEditor` — selection on grapheme boundaries, word movement and deletion (UAX #29), IME composition, undo / redo with typing coalescing, length and single-line constraints.

Text lays out the same on GCC, LLVM and the Windows target with the default fonts; its pixels (a mixed Latin / Chinese / Arabic / emoji paragraph, pinned) are mrender.text's tests. Its own tests are the cell measure, the absent shaper and editing; shaping with fonts is tested where HarfBuzz is ([harfbuzz/tests](harfbuzz/tests)): an owner's tests cannot depend on its provider.
