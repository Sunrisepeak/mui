# omui 动画中间态：文字、约束与真实交互

2026-11-04。接续[官网重构方案](2026-11-03-openmui-site-redesign-implementation-design.md)和[导航与动效执行细案 §9](2026-11-04-omui-site-navigation-motion-execution-design.md)。**状态：实施与验证中。** 本文记录已复现的公共运行时缺陷与修复契约；40 个基础设计、20 个组合的数量通过，不代表中间态、迁移、美术和全部真实任务已经验收。

## 1. 本轮优先级与原因

上一检查点 `d03145a` 的手机入口、风格对照、Agent 参数披露和预览交接已落地。浏览器稳态截图同时暴露了模式切换中的字形散落、明暗合成与对象交叉。本轮继续保留组件默认动画，以真实连续帧定位问题；不能用关闭动效、只截停止后的画面或延长测试等待解决。

| 已复现的问题 | 证据与影响 | 实施方向 |
|---|---|---|
| 不相关文案逐字匹配 | 默认按钮将两段不同句子中的偶然同字母连起来，字形各自旅行 | 默认使用保守的相关性策略；无关文案整行淡出／淡入，相关编辑保留字形连续性 |
| 字形快照打断不连续 | 旧实现只使用目标 GlyphStyle，源 transform／opacity／tint 丢失；专项 baseline 两例失败 | 从真实源轮廓矩阵插值，保留完整样式，不改变普通字形的既有轨迹 |
| 历史主题层污染当前范围 | 同一节点的历史 BeginNode 被当作当前范围，导致不平衡命令栈和过期运动 | 历史层保持原绘制与所有权；当前范围索引、嵌套替换和下一次匹配明确排除历史范围 |
| 明暗交换时文字接近同色 | Agent 真实生产视图、真实字体：中间帧对比度最低约英文 1.13779、中文 1.13983 | 在能证明的实色承载面上协调文字与背景颜色，不把两者独立混成同色 |
| 响应式布局与点击不一致 | 1280↔360 的中英记录每条出现 8 个命中不一致；目标布局无重叠不能证明中间画面正确 | 真实呈现几何驱动 drawn_bounds、命中、局部坐标与语义；默认组件适应当前父约束，显式变形仍保留 |
| 有效空白误报缺字 | 真实空 Coverage 在字形缩放／显示列表旋转分支被当成 missing；baseline 两检查失败 | 只识别非空指针所指的空 Coverage；真正空指针、无轮廓的非空 bitmap 仍明确报告不支持 |

### 1.1 当前数量与组合的准确口径

维护者追问“通用像素级动画”的数量时，按实际代码分开记录：

| 对象 | 当前内置数量 | 计数来源与边界 |
|---|---:|---|
| 基础动画设计 | 40 | `site/src/basic_motion.cpp`；包括几何、布局、选择、文字与出入，不等于 40 个独立像素算法 |
| 图层／像素效果 | 16 | `render/vector/src/effects.cpp` 的内置注册；包括进度动画与静态处理器，后者可由动画驱动参数 |
| 风格包 | 5 | glass、neon、retro、ink、liquid；plain 为恢复默认，不重复计数 |
| 创意组合场景 | 20 | `site/src/creative_motion.cpp`；数量是案例数，不是任意组合矩阵全部验收 |

16 个效果为 dissolve、wipe、reveal、particles、displace、noise、chromatic、blur、pixelate、neon、crt、paper、wobble、metaball、liquid_glass、tone。不能将它们全叫作已经完成设计的时间动画，也不能用 40 个目录设计宣称已有 40 种通用像素级动画。

当前组合接口：`compose` 组合基础运动操作；`pixel_effect` 列表按顺序形成效果链；动画可以驱动效果参数，`travel` 可在变形期间抬高效果强度再回落；风格可作用于独立子树。`motion` 候选列表用于选择与降档，不代表列表内全部同时播放。完整风格包目前通过 `apply_style` 选择并应用；多套完整风格直接相加并自动解决令牌冲突，不属于已经验收的能力。任意同属性动画混合、几何碎片、像素打散后跨对象配对重组等进阶项仍按通用动画总方案单列。

## 2. 可组合的文字策略

`MotionSpec` 和公共 `motion::Options` 提供 `glyphs / replace / automatic` 三种文字模式。数据入口为 `text: "glyphs" / "replace" / "auto"`，小幅整行位移由 `text_rise` 控制；内置 `readable-text` 是可复用原语，默认 action 配方组合 match、readable-text 与 fade。组件继续只画自身状态，未增加组件时钟。

- **automatic**：同字体、同行、保持完整 cluster 边界；连续前缀／后缀至少一段有 2 个字形，并覆盖较长 run 的 60%，才保留字形对应。完全相同文字也保留；其它情况整行替换。该规则保守，不能把字形 ID 等同于文本语义理解。
- **replace**：原句与新句各自保持真实 shaping、相对位置与原裁切；整行淡出／淡入，可加小幅垂直位移，不把无关单字散落到新句里。中点短暂淡出是明确选择的节奏，需要连续帧审图。
- **glyphs**：继续提供原有显式 LCS 设计能力，供文字重排等创意使用。默认可读策略不删除高级动画能力。
- **reduced / off**：`MotionLevel::reduced` 的整行位移为零，保留短淡变；off 不启动新运动。现有系统偏好 `reduce_motion=true` 继续采用不创建 Morph 的兼容行为。打断后的源 GlyphStyle 和目标样式都参与插值；tint 的 RGB 与叠加强度分别保持连续。

真实字体验证使用英文、中文按钮整句替换及 `Save → Saved` 相关编辑。检查生产显示列表中的完整 run、实际中间像素和寻址；不能只用合成字形 ID 证明可读性。

## 3. 明暗风格交换的可读性边界

公共颜色数学集中在 `openmui.math:color`，使用确定性数学实现相对亮度与对比度。计算依据为 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；这里的动画保护不是对整站 WCAG 合规的认证。

`MotionSpec.minimum_text_contrast` 默认为 4.5，数据键 `text_contrast` 接受 0（关闭）或 [1, 4.5]。直接构造低层 `motion::Options` 默认关闭，保留独立图形创作的原有行为。配方解析拒绝非法值并报告；低层选项规范化后由 `options()` 暴露实际阈值。

保护用于**内容不变、不透明的字形，以及能够证明的实色承载面与实际底色合成链**。字号可以变化；打断快照中的字形样式必须有真实字体边界证明。必须验证祖先身份、绘制顺序、实际圆角包围、裁切和端点对比度；背景取承载面自身的曲线、延迟、几何与颜色，而非文字自己的进度。普通插值不满足阈值时，对文字颜色作最小修正；亮暗极性交换允许文字颜色分支切换，几何运动继续。

玻璃样张的 surface 实际为 0.94 alpha，不能把其 RGB 当作最终底色，也不能预设下方为白色。候选先要求端点墨色对该实色与任意不透明底色合成的最坏亮度区间仍可读；当帧再从实际显示列表证明覆盖整段真实笔画的、均匀且最终不透明的底色链。部分覆盖、图像、渐变、未知效果和非完全不透明组会中断证明；后来的完整不透明实色覆盖可以重新建立证明。

效果的采样范围与输出范围分开：原 `reach` 继续为 CPU／GPU 捕获背景与分配缓冲；可选 `output_reach` 说明相对输入内容新增／改变像素的范围，消费方仍须合并真实输入内容。液态玻璃在覆盖为零处保留 source，多形状平滑合并的输出扩展以 smoothness 作保守界，不按效果名字在动画里硬编码。未声明者回退 capture 范围，未知或范围不可靠时跳过保护。CPU 和 Vulkan/lavapipe 已有实际域外逐像素回归，不能将软件 Vulkan 路径称为独立显卡性能证明。

构造时缓存候选，当帧对已发出的嵌套绘制和其它字形作保守复核，不重复调用 nested 绘制。字形边界来自真实 mask／轮廓／受支持的彩色 bitmap，不用 em 猜测；混合字体的多个 run 也不能凭粗略文本框互相排斥。DPI 由当次 draw 读取。证明暂用每线程 8 层独立槽，每层最多 64 个嵌套范围、128 个待修正 run；层级或容量超限保留绘制并跳过修正，不据此宣称任意规模均有保证。暖路径标量分配检查只证明该保护相对于同一绘制序列没有新增分配，不能冒充整个渲染器零分配。

以下情况仍不能声称有保证：未能证明底色的透明承载面、复杂背景或未知效果覆盖、透明字、故意低对比的 disabled 内容、不相关文案替换，以及不支持的字体／裁切／变换。它们保留原绘制结果，需要各自真实合成验证。**已经存在的主题作用域通过 whole-layer history 交叉淡变切换明暗，仍是另一项未关闭的合成问题**；不能用首次 develop→design 的结果替代它。

验证分两层：公共 Morph 对实际发出的 paint 作精确阈值检查；官网真实字体连续 24 帧，在同一生产显示列表上分别得到完整画面、去目标文字底图和字形覆盖掩码，检查笔画内部。后者考虑 8-bit 量化误差，使用 4.4 的测量门槛，不能把反锯齿边缘颜色直接当文字设计色。中英、390／1280 分别记录，GPU、复杂材料与所有文字仍须扩大验证。

## 4. 目标布局与呈现几何

`screen_bounds` 保留已经文档化的目标布局语义。运动中的 `drawn_bounds`、指针命中、事件局部坐标与语义 bounds 必须来自同一时刻的呈现几何，不能一套看当前位置、另一套点击未来位置。Headless 的真实 click helper 也必须点击呈现位置，滚动／揭示目标仍按目标布局规划。

采用不绘制的 NodeFrame 元数据：记录显式节点身份、边框盒、透明度、父内布局位置、分配与自身视觉变换；显示列表的真实 transform／clip 仍是唯一坐标来源。独立记录不生成伪 BeginNode 包装，不进入可见 Piece 匹配、边界、错开序号、视觉统计、档位预算或运动结束时间。历史层不进入当前呈现索引。语义 bounds 保留完整的当前边框（包括负坐标），让 agent 仍能将离屏对象滚入视图；offscreen 状态和命中单独使用实际裁切。

验收必须同时证明：加入元数据前后像素不变、可见统计与时序不变；平移、缩放、旋转、嵌套与裁切下点击当前对象；透明交互节点也有几何；离场或旧历史对象不能冒充新对象接受输入。元数据本身只解决一致性，**不自动解决响应式中间态重叠**。

响应式约束另作 typed 公共策略：`placement: "follow_layout"` 采用当前布局分配，内部 thumb、选择、路径、字形、颜色和焦点等状态运动继续；内置默认组件配方选择该策略，因此结构容器的自然 border 尺寸也直接跟随新分配，不承诺所有自然布局都平滑插值。`automatic` 的显式 morph 保留模型布局运动，只有外部约束事务才重基；`animate` 明确保留跨布局轨迹。策略不靠配方名字判断。

`Runtime::resize` 自动开启外部约束事务，`constraints_changed(boundary)` 可标记其它外部布局输入并限制子树。事务跨越 laid_out 导致的下一帧重构，在布局／树／region 工作静止后关闭；普通动画和语义变化不能无限续期。不根据父容器的自然高宽变化推断外因，避免把同一窗口中的 list-grid 模型变换静默关掉。

重基不按宽度比例拉伸字体。分配尺寸改变时，文字整段对齐 origin 跟随当前分配，内部字形轨迹保留；普通内容编辑且 border 未变时仍按文字策略运动。外边框包括半线宽内缩，不能只认等于整 frame 的矩形。继承的 scroll／圆角裁切保持当前祖先位置；临时 allocation crop 不得改变确切 B 端点。验收既看实际绘制范围，也检查**裁切前完整字形**，不能把截掉文字后剩余像素在按钮内当作成功。

## 5. 实施、证据与推进

使用独立 worktree 并行调查文字、组件／真实测试、公共主题与几何；根串行整合公共接口。相关本地 dev／release／必要 sanitizer、真实浏览器和连续帧是推进依据，跨平台 CI 异步反馈。每个失败先保留日志，再验证修复，不改阈值或盲目更新像素哈希。

阶段性实跑包括：公共文字打断专项 8 项、历史范围 release 7 项、对比度专项早期 8 项（后续扩充）、空白字形 release 4 项、颜色数学 2 项通过。随后 `/tmp/omui-site-agent-quality-second.log` 中 guard 3／preview 9／contrast 1／transition-layout 3，共 16 个用例通过；真实中英各 390／1280、24 帧的原 80 个失败已关闭，实际最低约英文 4.42643、中文 4.42795，按前述 8-bit 门槛测量。**这些是各自运行时的局部结果，不是最终集成候选的整套通过记录。** 最新快照上下文／浮点边框补丁仍待重新验证；segmented 响应式选择面错位、显式父布局动画与默认子动效协调及已存在主题作用域的明暗交叉淡变仍开放。

维护者进一步明确 hanim 须交付 core＋库＋效果、hobject／hengine.play、真实像素物质插值与完整 Manim 功能目标，见[完整引擎讨论稿](2026-11-04-hanim-animation-library-playback-design.md)。本轮 UI 中间态修复不能替代该基础设施，后续通用对象／算法应归入 hanim 家族，UI 保留适配与默认配方。

后续局部验证：`/tmp/omui-motion-snapshot-context-final.log` 的 motion 对比度／上下文快照 21 项通过；`/tmp/omui-view-snapshot-context-final.log` 的 release view 七程序共 103 项通过（presentation 8、adapt 4、motion 10、constraint 13、text-policy 9、theme 7、原 view 52）。这覆盖上下文快照打断连续性与浮点边框回归，未关闭上述 segmented／父子布局策略问题，也不证明目标 hanim 对象引擎已实现。

不以本轮修复关闭其它原范围：三条 Agent 路径的九个真实场景、40 个设计的意图迁移、20 个创意任务的完整操作、复杂组件部件与低档质量、干净工程出口、需求式字体及源字形覆盖、真实外部 agent、R3–R6 仍按总方案继续。

### 后续整合证据

此前开放的两个具体缺陷现已补上：segmented 的选择面／标签通过稳定 part 与布局 reference lineage 在外部 320→1120 分配中保持对应；显式父级重排包住默认子反馈的布局位置，并保留父级曲线和 stagger。`selection_layout_test` 3 组检查实际字形、预裁切 ink、选择面、真实命中及正常选择动画，`motion/reference_test` 4 组验证引用与打断；不以裁掉错位字尾取得通过。节点寻址 Agent input 改取呈现位置，3 组覆盖移动中点击、显式坐标原样与 H1。

更广回归还发现 packing-board 的父级未识别只有默认动效子节点的分配变化，原 17 个 seek 画面全相同。父级比较现在计入 follow_layout 子节点的布局分配；临边排布选有界 simple 配方，避免 gentle spring 的合法 7.35% 过冲把可用控件带出舞台。逐帧交互控件范围与至少三个真实画面继续验证。完整尺寸轨迹、部件随重排的避让和美术评审仍要继续；位置动画与范围通过不代表所有重排尺寸策略已达标。

嵌套 travel 的共享 TLS 列表另引发真实 heap-use-after-free，已用独立重入 CTS 复现并改为递归租约池，见 [hanim 讨论稿 §2](2026-11-04-hanim-animation-library-playback-design.md#2-三角形--圆的核对结果)。修复后的 motion／SDK／site 在 dev、release、LLVM sanitizer 各 27 程序、187 组通过；之后官网实例授权迁移新增 2 组，Site 全部 19 程序、125 组在三配置通过。历史局部日志继续保留，不能将它们与首次失败混写为一次通过。

59 帧参考中有 16 帧随本轮修复变化，实际中英开场、组件、授权、设置、时间回放与代表参考帧已审图，原表保存在 `target/site-motion-reference-review`；新表和总像素 pin 经 GCC／LLVM 重查通过。真实 Web 构件／浏览器连续输入、新媒体与冷访问预算仍须重新构建验证，旧 579 项浏览器结果只归属旧检查点。
