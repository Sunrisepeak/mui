# pixelpet（PPet）：全双工混合语言插件应用、运行时创作与可穿戴UI

2026-11-05。**应用／架构讨论稿，待review，不是已交付功能。** 应用正式名称为 **pixelpet**，简称 **PPet**，承接[feature／AI／局部style方案](2026-11-05-features-ai-agent-scoped-style-design.md)和[顶层×子系统架构](2026-11-05-system-subsystem-architecture-and-api-design.md)。本仓基线 `7b748a4`。目标是让人、内置Agent或配置的外部Agent使用公共系统创作、编辑、装备、执行和积累内容，并用实际产物检验底层能力。应用采用**C++核心＋项目自身TS及所选语言的混合实现、可动态组合的业务插件，以及主交互session／worker session分离的全双工机制**；底层公共引擎继续负责实时执行。PPet是应用身份，不作为通用AI／插件／动画引擎的名称。

## 1. 产品定位：角色本身是一个小型创作与交互空间

pixelpet的对话入口可以发起“做一顶帽子戴上”“把衣服改红”“从这里用酷一点的动作到那里”“画一幅画”“把token用量设计到头顶或衣服上”。每项任务都对应可观察的工程操作和产物，后续还能修改、保存、重启加载和复用。

| 用户意图 | 公共能力完成的工作 | 最终可检查的结果 |
|---|---|---|
| 制作非内置帽子 | 新建几何／图层，指定材料和挂点，准备并试穿 | 新资产ID／版本、可编辑源、穿戴关系、真实预览 |
| 给衣服换红色 | 选择服装实例的染色通道／mask，修改材料参数 | 目标区域变色，身体／其他实例／非染色区域不被覆盖 |
| A→B酷动作 | 参数化路径、root motion、局部pose、效果及事件编排 | 达到B、可打断、可替换目标；保存成可复用技能 |
| 画画给我看 | 创建画布／图层／笔画，绘制并导出 | 可编辑绘画文档与实际图像；角色作画动作是配套表现 |
| 显示token用量／额度 | 创建UI组合，绑定可用数据源，挂头顶或装备表面 | 随数据变化的UI、来源／时效、可查询语义、可保存设计 |
| 教会一个新技能 | 从成功操作提取参数、依赖和执行条件，验证并注册 | 有版本和输入输出的技能定义，可换目标再次执行 |

核心不是预置若干宠物专属命令，而是开放可组合的内容、动作、视图和控制契约。高层任务可以由Agent规划；细节操作由公开算子完成；每帧运动、渲染和数据呈现由native引擎负责。

## 2. 架构边界与表示选择

```text
人类指令 / 内置Agent / 外部openas Agent
    → 查询能力、角色profile、资源、可编辑范围
    → 创作草稿（几何 / 材料 / UI / 动作 / 绘画）
    → 领域校验、资源准备、真实预览
    → 提交版本和引用，装备 / 执行 / 展示
    → 记录结果，提取技能，保存与复用
```

pixelpet负责角色、衣柜／包裹、装备和交互体验；它消费公共asset／rig／hanim／renderer／UI／AI／control能力。底层引擎不出现帽子种类、宠物名字、某套衣服或特定提示词分支。代码实现位置可沿现有作品层使用 `showcase/pixelpet`；真正通用能力在所属模块提取，不复制第二套资产管理器、播放器或renderer。

像素风是呈现策略；角色表示可以不同：

| 表示配置 | 适用任务 | 额外契约 |
|---|---|---|
| 二维分层sprite／矢量 | 首批新帽子、简单衣服、绘画、UI挂件 | 支点／挂点、遮挡层、方向视图、mask和材料区域 |
| 二维rig＋图像网格 | 抬手、袖子弯曲、装饰跟随 | 骨架、绑定／权重、接缝、pose及混合 |
| voxel | 可旋转块状体积、逐块编辑 | 空间数据、表面生成／体绘制、深度和绑定 |
| 真3D mesh＋rig | 多视角服装与表面UI | 单位／轴向、骨架、inverse bind、权重、UV、相机、深度、拾取 |

推荐首批用二维分层内容验证完整生产链，保留rig／3D的表示能力契约。像素风可以约束分辨率、色板和着色成本；穿戴适配、遮挡、运动混合、资源生命周期仍需实现。一张正面图不能自动提供背面；已有二维纹理三角网格不能记作完整3D支持。

### 2.1 主交互session与worker session分离，全双工通信

主session只服务人与pixelpet的交互：理解意图、回应、接受新消息／打断、轻量委派与状态查询。制作、检索、规划、导入、编译、验证、导出等具体任务交给worker session，主session提交后立即取得任务句柄，**不等待worker完成、future或线程退出**。用户可以在造帽子的同时聊天、改要求、移动角色或发起其他任务。

| 执行域 | 职责 | 不依赖的等待 |
|---|---|---|
| native实时运行 | 输入／布局／角色动画／渲染／音频、已绑定数据呈现 | 主对话模型、worker模型和远端工具 |
| 主人类交互session | 对话与用户意图、派发、查询、取消／改目标 | 后台制作或准备任务的完成 |
| worker session | 独立上下文中的规划、工具调用、创作与验证 | 主会话是否空闲、用户是否正在聊别的话题 |
| 公共宿主／任务控制 | 有界调度、消息路由、权限／版本检查、结果提交和状态记录 | 主会话LLM再次批准已经授权的自动提交 |

这里的session分别有类型：人类对话、worker任务上下文、脚本执行环境、openas授权会话、记录文件不是同一个对象；使用明确ID关联，不因同名共用历史或生命周期。worker可以是规则／native任务、内置Agent或外部Agent，不要求每项工作创建模型或操作系统线程。

**全双工是交互和执行协议的属性**：人→pet的新输入与pet→人的反馈可持续交错；pet→worker的提交／取消／调整与worker→pet的进度／结果可同时在途，不等一个请求结束才能接收下一条。沿用openas操作／事件或所选transport的异步适配，不另造宠物协议，也不要求物理连接必须是某一种传输。单个worker内部的工具依赖可以串行；同一装备槽、运动域的冲突写入经仲裁／版本检查，其他域继续运行。

结果作为任务事件和资产引用返回；worker不能直接拼接主会话历史或以主session身份自行对用户发言。公共状态视图先反映真实进度和已提交结果，主会话按需解释，避免大量后台日志挤占对话。用户换话题不自动取消有效后台任务；取消、关闭后继续、挂起或恢复由明确策略控制。

### 2.2 可用性依赖资源隔离，不能仅拆会话

复用可选AI／Agent产品的任务broker与已有公共执行基础，不在pixelpet自建第二套线程池／调度器。worker取得任务相关的不可变上下文、资源引用、read-set／write-set、epoch、权限、预算和deadline；Client与可变conversation独立，主会话不复制全部工具日志。模型请求并发、队列、CPU工作量、内存、GPU批次、上传／读回和提交成本均有界，前台输入、控制和主会话请求保留处理能力。

控制消息不排在长任务后面；进度可合并／限频，完成、失败和取消状态可持久查询，不能静默丢失。模型额度或provider限流影响前台时优先暂停／拒绝后台任务，但本地优先级无法保证远端立即响应。取消分为受理、禁止旧结果提交、底层执行真正停止；不可中断调用仍持有资源，主会话不用等待回收。

CPU线程隔离不自动解决GPU竞争；预览／导入／纹理上传分批、限额，在预算不足时排队或降低频率，保留已有有效形象。worker不直接操作Runtime／Engine私有状态，由owner在有界边界提交准备结果。GPU长kernel不能假定可抢占。Web默认无pthread路径使用真实异步I/O、分片计算或显式worker后端；`async`／Promise名称本身不是隔离证据。

“不被阻塞”的验收是任务饱和、模型长时间无响应和worker失败时仍能输入、拖拽、取消、接收新消息、运行角色与更新徽章。主对话自身的模型文本可能等待远端；应分别测本地输入处理、任务回执、帧延迟、取消受理／停止、模型首token和状态数据年龄，不承诺远端零延迟。

## 3. 一份资产基础，多种产品视图

统一资产catalog保存稳定ID、版本、kind、依赖、可编辑源、来源、所需能力及派生预览。衣柜、技能库、画廊和UI挂件库是分类／检索视图。包裹保存角色持有的条目／实例，装备状态保存槽位到实例的关系；这些业务状态与不可变资产内容分别拥有责任。

| 实体 | 持久化内容 | 不能代替它的东西 |
|---|---|---|
| AssetDefinition | 几何／图像／材料／源配方，版本与依赖 | 当前GPU纹理句柄 |
| ItemInstance | 资产引用、实例参数、拥有者及状态 | 再复制一套全部素材文件 |
| EquipmentBinding | 槽位／挂点、局部变换、适配版本、占用关系 | 某只宠物固定像素坐标或骨骼数组下标 |
| SkillDefinition | 参数化操作／动画配方、条件、依赖、预算和证据 | 聊天记录或一句“我记住了” |
| UiBlueprint | 组件结构、绑定schema、style引用、布局和兼容安装点要求 | 把当前数值烘焙进PNG或写死某个角色／会话 |
| PaintingDocument | 图层、笔画／路径、颜色、资源引用与编辑记录 | 只有作画动作但没有图像结果 |

材质颜色默认是当前装备实例的覆盖；明确保存为新变体时才产生可复用资产版本。两只角色共用一件基础衣服，可以分别染色。撤销装备恢复引用，不无条件删除仍被其他实例／技能引用的资产。

运行资源继续使用lease／generation，保存时使用稳定资源身份；加载后重新绑定对象和后端。模型、图片、界面和技能都可产生派生构件，但共用依赖图、版本、缓存和失效机制。上述新文档kind／schema先定义版本及诊断，再增加解析／生成绑定，不在此假装已有文件格式支持。

## 4. 非预置服装如何现场制作和穿戴

以“给自己制作一顶帽子”为例：

1. 读取角色的表示类型、rig profile、head.top挂点、可修改范围和预算。
2. 创建独立草稿，通过路径／primitive／网格／材料或图像处理操作生成新的内容；服装不必来自启动时的预置库。
3. 声明坐标／单位、挂点、占用槽、染色通道及二维层次或三维深度关系。刚性帽子可绑定一个挂点；袖子等变形衣物必须具有对应绑定／权重／适配数据。
4. 校验格式、引用、顶点／纹理规模、兼容性及能力；准备所选目标资源，用同一renderer和角色pose预览。
5. 按配置直接提交或保留供审查的草稿；保存资产和实例引用，在安全边界切换装备。无需每个内部步骤都打断用户确认。
6. 在移动、转向和代表姿势下检查接缝／遮挡，保存后重启还能使用。

公共生成操作可包括路径编辑、挤出／旋转成形、区域填充、图像分层、材料组合等；尚未实现的算子先作为领域插件交付。模型／外部生成器可提供候选内容，进入同一导入、验证与编辑管线，不能用生成效果图代替已经装备的实际渲染。

“变红”定位具体服装及命名染色区域，保留皮肤、眼睛、纽扣、高光与其他实例。资源没有对应染色能力时应说明需要创建mask或材料区域，不能默认全图染色。pixel style可统一色板和边缘语言，角色形状／识别特征由profile约束及用户配置控制。

动态新内容和动态新原生能力分开：通过已有算子生成数据、UI组合、动作配方可以在运行时完成；新增底层算法／shader能力／原生插件需要相应feature、构建和安装流程，不能执行模型返回的任意代码就宣称获得能力。

## 5. 动作组、细节控制与技能积累

### 5.1 一次酷动作包含多个不同所有者

A→B任务分成：目标与可达约束、root运动、局部pose、挂件跟随、渲染效果及可选声音。移动状态有单一owner，hanim采样表现；不能由模拟和动画同时写位置。walk／jump／dash／teleport是不同动作语义，可用能力与最终位置都须明确，视觉“穿越”不能绕过领域规则。

细粒度接口允许修改路径控制点、速度／时长、相机、局部关节、材料通道、效果参数和画布区域；通过typed selector和批量数据操作执行。走路、呼吸、挥手、帽子摇晃需要通道、mask、混合和优先级。当前严格整对象Program不具备完整混合，不能只把几个动画parallel就声称叠加正确。

技能可以组合其他技能，但执行分为任务／操作编排与纯动画计划。领域动作经control提交，动画经hanim；视觉seek或重复截图不能再发物品、再写一遍画布或重放外部动作。暂停、取消、retarget、恢复外观、撤销编辑分别返回明确结果。

### 5.2 “学会”首先落实为可执行内容

一个技能至少记录：ID／版本、名称／说明；参数类型、单位、范围和默认值；前置条件及所需rig／挂点；动作／动画／子技能引用；资产依赖；读写范围；权限需求；预算；取消／补偿语义；示例、预览与验证来源。

交互学习流程为：**示范或成功执行 → 提取可替换参数和依赖 → 用户纠正或规则验证 → 保存技能候选 → 多个输入上验证 → 注册供发现和复用**。例如一次A→B轨迹变成输入目标点、时长和风格的技能；不能保存旧ObjectRef、GPU句柄或绝对屏幕录像后称为通用技能。

角色可以逐步学会“摘帽致意再戴回”“旋转跳到目标并摆姿势”“按指定主题作画”。这是动作／资源配方积累，不要求每次训练模型权重。偏好记忆、历史事实和可执行技能分别保存；真实训练可作为未来独立插件，不与第一阶段混淆。

注册技能使其可被查询，但不授予新权限。调用时检查展开后的动作、子技能、资源和当前策略；更新依赖或取消某项能力时重新验证。旧版本可继续被显式引用，默认升级须可观察，不能悄悄让“打招呼”获得额外删除／发布能力。这里的业务技能定义不等同本开发环境的 `SKILL.md`。

技能组合必须有界：静态子技能引用检测循环，限制展开深度、节点数、总资源及执行步数。需要重复／条件时使用任务编排的显式有界控制，不靠A引用B、B再引用A。prepare固定具体版本依赖闭包及传递效果／权限需求；运行中不跟随latest漂移，每次实际操作仍检查当前权限和预算。

## 6. 可穿戴UI：把实时状态设计到头顶或衣服上

### 6.1 UI定义、数据绑定和安装点分开

用户说“把当前token使用量／额度放到自己头上，和形象协调”时，Agent应组合现有label、meter、图标、容器等组件，选择当前style的色板、边框和motion，并创建可编辑UiBlueprint。它声明数据绑定槽和兼容安装规则，完成一次预览／验证后动态加载。实际数据源选择、角色／服装实例、挂点与局部变换属于实例绑定；可复用定义不写死这些运行时身份。

日常数值更新由绑定系统处理；无需每增加一个token都重新调用Agent、生成布局定义或编译shader。运行时区分数据、文字测量、布局、资源和绑定的失效：固定尺寸状态条可以只重绘，`999→1,000`、中文状态说明或字体迟到可能触发重排、surface尺寸及安装映射更新，脏区覆盖旧、新范围。Agent可以随后按“再小一点”“改到衣服左胸”“剩余少时提醒”等指令修改定义。

| 安装方式 | 管线 | 主要验证 |
|---|---|---|
| 头顶状态牌 | 角色挂点／pose→屏幕位置，UI按可读尺寸布局 | 跟随、遮挡、屏幕边缘、DPI、角色转向与文字稳定 |
| 二维衣服徽章／面板 | 衣服局部surface＋transform/mask承载UI输出 | 只作用目标区域、clip、层次、形变与点击映射 |
| 三维衣服表面 | UI渲染到共享surface，再映射到mesh UV／材质槽 | 深度／蒙皮、纹理密度、ray→triangle→UV→UI坐标及交互能力 |

renderer／rig只消费surface／纹理／几何与版本化映射，不反向依赖UI组件。应用adapter连接omui输出与角色呈现；同一render graph管理资源和更新。不建立另一套“衣服UI渲染器”。没有3D能力时使用明确支持的二维安装点，不把平面叠图标作真实3D表面UI。

surface producer按数据、布局、style、DPI和动画时钟产生更新需求，不能只在数值改变时渲染，否则组件自带动效会停住。合并允许合并的显示更新，保留计量账本的完整事件；脏区绘制／上传、帧边界版本切换与旧帧lease统一由公共资源管线处理。暂停、隐藏、卸载和恢复要明确订阅／动画策略；现有ImageStore快照不等于动态GPU纹理桥已经完成。

表面效果显式声明背景采样源、pass顺序和排除自身的规则；玻璃效果不能采样已经合成自身的衣服，造成render graph循环。需要历史帧时显式声明历史资源／延迟，不偷偷替换当前背景。popover／tooltip等portal选择留在表面或投影到屏幕overlay，并在所选出口绘制一次；未支持的组合返回能力诊断。

布局保持角色视觉语言：可用帽沿小铭牌、胸口徽章、袖口条或头顶气泡；初始只显示必要状态，详情交互再展开来源和完整数值。pixel style不要求把小号汉字、caret、focus一起低分辨率化；复杂形变中需保持最小可读性，必要时切换到可读的屏幕附属视图。

### 6.2 token和额度必须有真实来源

| 数据 | 来源与语义 | 缺失时 |
|---|---|---|
| 本次／会话token用量 | 模型provider实际usage，或外部Agent授权提供的遥测 | 标记未报告／待更新，不从输出字符数冒充精确token |
| 上下文占用 | 对端提供或明确标为估算的当前上下文数据 | 不与累计计费用量相减 |
| provider／账户剩余额度 | 相应服务／配置的可信接口，并带账户范围和时间窗口 | 显示未知；不能假定llmapi或任意外部Agent都能读到账户额度 |
| 应用配置预算 | 开发者／用户设定的任务或会话预算 | 明确标作本应用预算，不标作供应商账户余额 |

公共telemetry view至少带kind、value、unit、scope、来源、时间窗口、观测时间、精度／估算标记和状态；已确认、估算、未知、过期和无权限分别可呈现。外部Agent自报用量标明来源，不冒充账户服务统计。主交互与各worker分别计量，可查看分项和总体；聚合使用request ID和范围防止父／子任务重复统计，输入／输出／缓存按来源的计量口径处理。仅在分子分母属于同一单位／窗口／范围且分母有效时显示百分比；断线或过期数据保留时间标记，避免伪造实时性。

数据流使用source epoch和单调序号拒绝乱序／旧连接消息；完整快照、累计值和增量事件有不同合并规则。显示刷新可以降频，预算核算不能丢增量。读取自身会话usage、其他Agent统计、账户额度和修改预算分别授权；允许显示进度不意味着可以提高任务预算。

数据可见范围也约束语义读取、区域像素和自动预览／缩略图的保存与导出。权限撤销与普通断线不同：撤销后停止订阅，在后续发布中清除／遮蔽当前值及框架管理的派生视图／缓存，不继续显示“过期余额”。已经获准导出或被外部接收的内容不能承诺远程抹除；敏感值不默认固化进可复用UI资产。

UI设计绑定稳定schema／选择器，而不是把当时的用量快照写进布局。创作期间持续增长的数值不应让UI草稿过期；提交校验数据schema、可见范围、安装点和style契约版本。保存的UI资产不嵌入凭据或会话裸句柄，加载时绑定当前获准的数据源。

### 6.3 语义和交互仍然存在

状态牌保持稳定UI节点身份、label、值和可用动作；Agent和无障碍能查询语义，不必OCR衣服上的纹理。同一数据可有多个视图实例，各有明确presentation身份，映射回逻辑节点和操作，不重复统计、朗读或执行动作。

交互表面需依据当前呈现帧的变形几何、遮挡与UV映射屏幕输入到本地UI坐标，并维护指针捕获；不能用静止网格或动画终点命中中途画面。被遮挡／背向／太小的区域不能成为不可见热点。复杂3D映射未实现时，可明确声明只读展示，并通过头顶／屏幕详情视图操作。普通token显示只读即可，不能因装饰位置变化而获得模型配置编辑权限。

表面分别声明read-only、pointer、keyboard、text-input和portal能力，点击可用不等于完整输入已支持。文本输入需要caret／候选框到宿主屏幕的当前映射；表面卸载或不再可交互时，明确取消捕获、迁移／清除焦点和结束IME composition，不能把后续拖动交给另一个面板。K2可先验收只读和按钮级交互，完整输入另列。

换衣服时，挂件按配置迁移到兼容surface、转存包裹或暂时停用；不得随旧衣服一起丢失UI定义。style切换与衣服surface更新重新校验显示计划；数据订阅和运行资源有明确卸载／重载生命周期。

### 6.4 动态加载是一条可观察的内容发布管线

Agent提交受支持组件和算子构成的视图草稿，复用view文档／生成器／领域校验；定义本身不携带任意网络请求、凭据或逐帧脚本。schema与能力检查后，准备字体、布局、style和surface，生成真实预览，再切换当前版本。失败保留旧版本并返回具体诊断。组件行为与motion仍由框架公共运行时执行。

热替换按稳定节点ID和兼容schema迁移可保留状态；焦点、指针捕获、订阅和动画不能全部无条件沿用。解绑／删除时推进实例generation、撤销旧订阅，晚到响应不能恢复已经删除的挂件。重启加载保存定义后重新解析数据源并校验当前授权；不能把上次的授权或私有数据写进资源就永久复用。

CLI可以完成创作、校验、准备、装备、查询、修改、保存和撤销；GUI为可选观察／编辑入口。GUI关闭仍可驱动相同布局、动画和renderer，获取指定时刻／区域的真实像素与语义、资源版本及数据源状态，使人和Agent审查同一个结果。

## 7. 控制范围、版本和事务

### 7.1 可配置的修改表面

开发者规定角色profile、公开挂点、可编辑属性／部件、兼容表示和上限；用户选择允许的自主行为；session继续收窄。可以分别允许改衣服颜色、生成配饰、编辑UI挂件、执行移动、保存技能，限制身体／面部／识别特征、网络分享、删除和原生扩展等。

高层权限与细粒度selector共同检查；技能声明所需能力而不自授权限。查看数据、创建草稿、修改实例、试穿、保存、执行、删除／发布各有实际效果。实例内部身份、资源generation和授权规则不能当成普通外观属性任意修改。现有openas操作级基础仍需扩展并验收槽位／属性／区域粒度，不声称已经具备全部配置。

策略支持授权范围内自动完成制作／装备，也支持只生成草稿；由开发者／用户配置，不给所有创作默认增加逐步确认流程。人、内置Agent和外部Agent使用相同操作入口和审计记录。

### 7.2 校验读写集合，避免全角色版本锁死

造帽子需要校验rig／挂点／外观等相关版本，角色每帧的位置或呼吸变化不应使任务永远过期。UI徽章需要校验绑定schema／安装点，实时计数不属于阻止发布的结构版本。任务记录实际read-set／write-set及版本，提交时检查相关冲突。

移动、装备、绘画和UI设计可以有不同控制epoch／租约。人拖动只撤销旧移动控制；合法的帽子草稿继续生成。人手动换装后，迟到任务可以保存草稿，但不能继续覆盖新装备。跨域技能声明所需写入域，统一仲裁，不能持有全局锁等待网络或模型。

### 7.3 分阶段提交与失败恢复

`draft → validated → prepared → previewed → committed → reusable`分别可查询。生成和准备在有效内容之外完成；校验资源预算、引用、版本、能力及当前权限，再在明确边界切换。

资产保存、catalog／包裹／装备引用应由项目模型协调；资源先准备好，引用提交保持一致。磁盘保存、网络调用、跨域设备状态不是天然原子事务：需要提交记录、幂等action ID、恢复／补偿和明确部分成功。例如“已入库，装备失败”保留资产可重试，不能误报全成功或删除共享作品。

旧帧／动画继续持有旧资源lease，未使用版本按引用规则回收。撤销修改、停止动画、撤销装备与删除资产分别处理；重复seek／预览不重复执行业务动作。取消等待时保留仍执行的生成请求资源；取消、超时、来源切换继续遵守已有DecisionPort与llmapi适配方案。

### 8.1 pixelpet使用项目语言层，支持C++核心＋TS及其他语言混合

PPet是应用身份，**不限定整款应用必须使用TS**。首批采用C++稳定核心＋项目TS动态业务层；开发者可按职责混用项目支持的其他语言，新增语言必须通过同一契约与生成绑定接入。应用入口、交互、插件装配、任务编排和事件响应可使用项目的 `openmui.lang.js`／TS支持，通过 `import ... from "openmui"` 的builder、signal、表达式、verb／invoke和已生成native绑定消费能力。TS视图形成同一语义树；布局、公共motion、hanim采样、渲染、模拟、DSP和逐像素工作留在native。事件处理可以提交批量参数／计划，不能创建每帧TS回调驱动角色。C++也能实现业务插件，语言选择不改变其权限、状态owner和观测要求。

| 插件／执行形态 | 热更新方式与边界 |
|---|---|
| 数据、衣服、UI定义、style、已准备动画配方 | 校验新版本、准备资源、owner边界原子切换；旧资源按lease／GPU完成状态回收 |
| TS及所选脚本语言 | 独立实例准备、稳定状态schema迁移、交换入口；代际隔离迟到回调，失败保留旧实例 |
| 静态链接C++核心／实时算子 | 正常构建或宿主重启升级；不能因“插件化”宣称可在线卸载 |
| 可选native动态插件 | 仅后端明确支持时启用版本化生成ABI；停止入口、排空在途调用／回调／任务，释放插件拥有资源后才卸载；无法证明静默则重启隔离进程或宿主 |
| worker进程／外部服务 | 经同一任务／openas契约交换版本化数据和资源引用；替换进程端点，重建会话，不共享裸指针 |

语言是实现选择，热更新是独立能力。清单分别声明执行后端、契约版本、reload模式、状态迁移版本和依赖feature；只装配实际使用的语言运行时。C++ Modules本身不是跨编译器动态ABI；不跨语言传递STL对象、异常、虚表或借用无期限的指针。复用现有生成C ABI／native契约和稳定handle，批量计划交给引擎执行；同一个对象、任务和资产只有一个owner，多语言视图不能各维护一份可写真相。Web／Toy不默认支持native动态库，选择构建期链接、脚本／数据替换或已声明的worker能力。

本地证据：[TS/JS语言层](../../lang/js/README.md)、[语言接口](../../lang/js/src/js.cppm)、[TS编译与player接入](../../lang/js/src/language.cpp)、[纯TS应用示例](../../examples/02-hello-ts/logic/main.ts)和[工程清单](../../examples/02-hello-ts/mcpp.toml)。现有原生路径使用QuickJS-ng，TS通过esbuild转JS，已有组件builder和Script::reload。以下阻塞点需要先修复／补齐，不能从现有TS示例推导PPet的目标能力已经成立：

| 当前源码事实 | 对PPet底座的实施要求 |
|---|---|
| [Web JS runtime](../../lang/js/src/native/web/runtime.cpp)的run/reload返回EXTENSION_NOT_PRESENT | 补Web执行／bridge后端；页面无esbuild，预编译JS本身也不能补上缺失的执行接入 |
| [Player::watch/poll](../../modules/ui/player/src/player.cpp)在runtime timer中调用加载器，TS加载同步执行esbuild | 编译／校验／准备移到公共worker；owner只提交有界结果，不在帧回调里等待进程 |
| [Host::run_on_script](../../lang/src/host.cpp)等待脚本完成，脚本队列回调同步逐项执行 | 耗时verb返回任务句柄；长脚本与主交互队列隔离，验收时间／内存及Promise-job预算，urgent队列不能抢占已运行代码 |
| [Script::reload](../../lang/js/src/native/quickjs/runtime.cpp)先清旧watch，再在同context执行；默认signal按创建顺序复用 | 插件显式稳定状态key／schema；新实例准备、迁移、切换及失败保留另行实现，不把现有reload当事务式热替换 |
| [player入口清单](../../src/entry/player/mcpp.toml)无条件依赖Lua、JS、embedded Python | 按语言／能力选择入口闭包，分别量测原生与Web构件；不能以“源代码只写TS”证明产物仅含TS运行时 |

上述为本轮源码核查，没有新增运行或跨平台通过证据。Web后端保持公共契约一致，native／Web各自声明支持的插件能力；不复制第二套PPet业务代码作为绕行方案。

本方案扩展公共语言／native契约，再由生成器产出AI任务、资源、hanim及surface等所需TS入口；不手写宠物专用引擎绑定，也不在TS中复制供应商SDK／llmapi或渲染器。TS类型声明用于开发期，运行时仍校验数据与能力。不是所有浏览器／Node API都属于项目脚本环境的默认能力。

  native/                        可选C++应用适配／高成本业务；公共能力仍归原模块
  plugins/                       可独立注册／停用的业务插件

### 8.2 动态插件是应用组织方式，底层feature仍然有效

角色呈现、交互面板、衣柜、技能、数据源、创作工具、行为来源和style均通过公开插件契约装配；UI／服装／动画等数据插件也可由worker生成和热加载。保留最小稳定宿主负责消息路由、任务句柄、授权、资源owner和卸载边界，普通业务插件不能在后台自行替换这条控制链。宿主本身可以升级，但不与任意服装一起热卸载。

插件描述包含稳定ID／版本、实现语言与执行后端、契约与入口、所需能力／依赖闭包、公开操作、配置／状态schema、读写范围、资源预算及reload能力。生命周期覆盖准备／校验、激活、暂停、导出状态、迁移、停用与释放；具体命名经最小接口实验再定。代码插件和数据插件区分，后者优先表达组件／材料／动作配方；动态插件不会重新启用构件中已裁剪的native feature。

热替换先在隔离上下文准备新版本，校验或迁移失败保留旧版本；成功后在发布边界切换，旧插件停止接收新任务，回调／订阅／资源等待其生命周期结束。任务记录使用的插件版本和generation，迟到结果不能写入同ID的新实例；独立任务可按显式所有权策略继续，无需把所有任务都取消。共享资产按引用回收，不随插件退出任意删除。

TS插件需明确可用imports／native操作、运行时间／内存和事件预算；长同步脚本不允许与主交互共享可被堵住的执行队列。隔离、超时／中断、Promise回调和关闭行为需要实际验证，不能从“支持热reload”推导“恶意／错误插件可安全热加载”。Web可加载预编译JS或数据；若要现场编译新TS，另选可取消的编译worker／编译服务，仍由mcpp产物流程定义依赖与版本，不默认把编译器带进首包。

## 9. 实施与验收：优先未知新内容的完整生命周期

| 阶段 | 用户任务 | 退出证据 |
|---|---|---|
| K0 混合语言插件与全双工底座 | C++核心＋项目TS；主交互＋worker隔离；两个角色实例／明确挂点；公共任务／资源操作 | C++／TS消费同一对象／任务；后台饱和仍可交互和取消；状态迁移／热替换失败保留旧插件；CLI／headless及实例隔离；未选语言不进入依赖闭包 |
| K1 动态创作与穿戴 | 运行后创建非内置帽子→试穿→染红→保存→重启 | 新源内容、资产／实例ID、真实像素与引用恢复；失败保留旧装扮 |
| K2 生成UI挂件 | 设计用量状态牌，挂头顶再移到二维衣服区域 | 同一UI定义可改；真实／未知／过期／撤权状态；无模型刷新、位数增长／中文／字体迟到、断线重连、保存重启、解绑后的迟到事件 |
| K3 参数化技能 | 组合A→B移动和动作，教会后换目标复用 | 参数／依赖／权限／证据齐全；打断、越界、重放、reduced/off均明确 |
| K4 真实绘画与纠正 | 创作并保存画作；修改一部分，形成可复用配方 | 可编辑源与实际输出；旧版本可查，撤销不破坏其他作品 |
| K5 rig与多表示 | 变形衣服、角色转身、兼容rig、所需3D/voxel | 接缝／遮挡／绑定、深度／拾取及目标后端实际通过，不用二维替代 |

K2可先在独立headless UI surface验证，再接角色安装点；K1–K4从公共契约交付，不等待全部3D／模拟完成。3D、复杂布料和完整编辑器单列，不收窄最终目标。上述属于原P1–P5/F1–F4的真实应用验收，官网40／20和既有作品质量范围继续保留。

实施先在本地原生TS路径完成K0的最小闭环，Web执行／bridge作为同阶段重点工作分别交付。在已验证平台继续K1–K4，不等待其他平台CI；PPet的Web交付仍以其真实运行、无pthread隔离和产物预算为独立门槛，不能用原生通过替代。

最小闭环无需模型即可用CLI确定重现；随后内置和外部Agent执行同一任务，证明语义接入而非预编排台词。预算分别测生成、导入、准备、热播放、UI数据更新、纹理上传、读回和库存规模；长期使用要验证资源回收／订阅卸载，不能只测第一件帽子。

K0还需注入worker卡住、进度风暴、provider限流、取消／卸载竞态和后台GPU压力；原生与默认无pthread Web分别测输入→状态→呈现分位数、队列／内存上限、取消受理与实际结束时间。pixelpet无需等所有worker空闲才能回应人、保存主会话或展示当前状态；截图标明frame／revision／数据年龄。具体性能预算由本地基线确定，不能用队列分离的代码结构代替交互证据。

混合语言还需覆盖：TS重载时C++动画继续执行、迁移失败仍保留原交互、旧generation任务不能提交新实例、句柄失效可诊断、脚本与native读到同一资产revision。native动态卸载单列可选验收；暂不支持的后端应返回明确能力诊断，不以成功重载脚本冒充native热更新。

## 10. 自我review与仍需实证的风险

| 反例 | 设计约束／验收 |
|---|---|
| 库里预置100顶帽子，按名字挑选就称为现场制作 | 验收必须使用启动后才创建、初始库不存在的可编辑内容 |
| 只有生成预览图，装备时使用另一张固定图 | 预览与运行引用同一资产版本、绑定与renderer；核对 provenance |
| 角色一直移动，使慢速创作反复过期 | 使用相关read-set版本和分域控制epoch |
| 人刚换装，旧Agent随后覆盖 | 保存草稿与自动装备分离；提交检查装备租约及write-set |
| 正面衣服转背面穿帮，袖子挥动断裂 | 视图／绑定能力明确，姿态和多视角检查，不隐蔽裁切假过 |
| 呼吸／挥手／移动各自正确，组合抢写姿态 | 公共通道、mask、混合与单一状态owner，组合CTS |
| 学到技能只保存屏幕坐标／裸句柄 | 稳定ID、参数、空间、适配条件和重启后复用 |
| 用量增加一次就重新设计UI，或误报未知额度 | 稳定view＋数据绑定；来源／范围／时效明确，未知不伪造 |
| 纹理上有数字，却无法被Agent查询或实际点中 | 保留UI语义和presentation mapping，能力不足时只读＋可访问详情 |
| token没变，组件动效就停住；或卸载后旧消息复活UI | 共享帧需求、时钟与resource lease；订阅epoch／实例generation及晚到事件验收 |
| 位数增长截字、玻璃采样自身或换装后留下隐藏焦点 | 文字／布局失效、无环合成、表面输入能力和卸载契约 |
| 撤权后仍在纹理／语义／缩略图中公开旧值 | 数据可见范围覆盖受管理派生出口；撤权不当作普通stale |
| 换色改了整个共享资产，所有角色一起变红 | 不可变定义＋实例覆盖，显式另存变体 |
| 保存成功／装备失败被当作一个完全回滚事务 | 明确提交记录、部分成功、恢复与补偿 |
| 学习新技能自动获得新权限或加载缺失原生能力 | 声明依赖和完整效果集合，每次按当前策略验证，feature边界保持 |
| 组合技能循环引用，或执行中latest变成新动作 | 有界展开、固定版本闭包、传递权限及执行时校验 |
| 创建多个session却共用阻塞Client／脚本队列，造帽子时无法取消 | 主交互／worker状态与执行隔离、有界broker、控制优先、饱和实测 |
| 后台GPU上传卡住画面，或热卸载后旧回调写新插件 | 批次／提交预算、owner边界、插件generation和资源生命周期 |

本稿建议review重点：**项目TS实现与动态业务插件、主交互／worker全双工隔离、运行时生成可编辑资产、共用catalog与参数化技能、分域版本／权限、UI定义×绑定×安装点分离，以及先二维完整生产链后扩3D。** 本轮只分析并维护设计；没有生成宠物图像、实现应用、调用付费模型或新增性能承诺。
