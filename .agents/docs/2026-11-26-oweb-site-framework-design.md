# oweb：基于 omui 的站点框架（ST1，一页设计）

状态：草案，待 review（2026-11-26）。决策：D-284、D-285（提议）。上级：[0.1.0 顶层方案](2026-11-26-release-0.1.0-top-level-design.md) §4.4 与 D-259–D-261、D-264、D-265、D-274、D-275；下游：ST8（立项）、ST2–ST7、AG5、RL5。身份、位置、与 omui 的分界见顶层方案 §4.4，本文不重复，只写它留给 ST1 定的五件事。

## 1. 事实（2026-11-26）

- 现在的官网是一个包（`omui.site`）：`app/main.ts` 一页、`omui.config.ts`、`design/` 的历史；构建是 `omui build --web`，产出页面、wasm 与一份静态 HTML 投影。没有路由、没有内容管线。
- 投影已不丢东西（UI1，同日）：树 → HTML 读回后与源文档整篇相等；树 → Markdown 再解析后与源文档相等，仓库 `docs/` 的 34 页全部通过（UI2）。`mlibs.markdown` 的 `from_html`（463 行，不带 md4c）能把这份 HTML 读回文档模型。
- 一篇指南（`ui.md`）的 HTML 投影 15.4 KB，gzip 3.9 KB；引擎首帧前的一半 gzip 约 1.07 MB。
- 页面里已有给 Agent 的入口：`agent.md`、端点的自述、WebMCP、配对（G9）。

## 2. 三级次序（D-185）

**① 从本体系出发。** 一次无头的求值得到每个路由的语义树，四种读者各取一种渲染：人看画布，搜索引擎读 HTML 投影，只会抓取的 Agent 读 `.md`，接入的 Agent 走语义协议。因为投影不丢东西，**页面自己的 HTML 就是它的数据**：引擎到达后把文档层的 HTML 读回成文档，不必再带一份 Markdown 源、一份序列化的状态或一个解析器。路由表是唯一的来源，导航、站点地图、站点自述、搜索索引都由它生成。**结论：取这一级。**

**② 前沿与组合。** 查过的做法与取什么：

| 做法 | 取什么 |
|---|---|
| 岛屿式（静态 HTML 加按需激活的组件） | 每页的加载策略；我们是三档（D-260） |
| 可恢复式（状态序列化在 HTML 里，不重放激活） | “HTML 带着状态，不带第二份”——我们由无损投影直接得到 |
| 服务端组件的数据流 | 不取：HTML 之外另带一份内容，正是要避免的重复 |
| 给 Agent 的 `llms.txt`、每页的 `.md` 孪生、按 `Accept: text/markdown` 协商 | 取 `.md` 孪生与站点级的索引；协商需要服务器，静态托管做不了，只在适配器支持时开 |
| 页内向 Agent 暴露工具（WebMCP） | 已有（G9），站点的操作目录照这条路进去 |

**③ 业界通行的做法**（静态生成加整页激活：HTML 一份、脚本里的内容再一份）不取。

## 3. 设计

### 3.1 目录约定

```
my-site/
  mcpp.toml            包；构建阶段是 oweb 的插件
  omui.config.ts       开放程度、记录、设计器（omui 的，不变）
  oweb.config.ts       站点的配置（§3.2）
  pages/               路由按目录生成：*.md 是文档，*.ts 是用视图写的页面
  layouts/             可选：TS 写的外壳，带槽
  theme/               可选：主题包
  public/              原样拷贝
  design/              可选：设计历史与演出
```

只有一页的站点没有 `pages/`，入口仍是 `app/main.ts`（现在官网的样子），其余相同。

### 3.2 配置与路由表是两种数据（D-285）

- **`oweb.config.ts`**（`defineSite`，xdef 种类 `site`，拥有者 oweb）：预设（`page`、`docs`、`site`）；标题、基地址、语言；路由的取法（没有／按目录／声明）；用哪些模块及各自的选项；文档页默认的加载策略；部署的适配器；预算。
- **路由表**（xdef 种类 `routes`，由构建生成，也可以手写或由脚本生成）：每个路由一条——地址、来源、标题、语言、外壳、加载策略、世界、各级标题与锚点、上一页与下一页。它是导航、`sitemap.xml`、站点自述（`site.describe`）、搜索索引的唯一来源；自定义的导航读的也是它。

### 3.3 页面在交互之前带什么（D-284）

每个路由产出一个目录：

| 文件 | 内容 | 谁读 |
|---|---|---|
| `index.html` | 外壳与正文的 HTML 投影（带样子，UI5），加一段小的加载脚本 | 人（引擎到达之前，以及之后的文档层）、搜索引擎 |
| `index.md` | 同一棵树写成的 Markdown（`markdown_of`） | 只会抓取的 Agent |
| 引擎 | 不在这个目录：按世界共用，按策略加载 | 需要画布时 |

- **不带**：Markdown 源、序列化的文档或状态、Markdown 解析器。引擎到达后由文档层的 HTML 读回文档（`from_html`），往返相等由 UI1 的检查保证；“阅读”世界因此不含 md4c。
- 用视图写的页面（`*.ts`）照旧由脚本构建界面；它的投影同样进 `index.html`，`index.md` 由树写出。
- 预算的依据：文档页在引擎到达之前要取的只有 `index.html` 与样式。`ui.md` 的投影 gzip 3.9 KB，所以“可读之前 100 KB”这个假设值留有余地；实际的数在 UI5 之后量。

### 3.4 模块的契约

一个模块是四样东西的组合，各自可选，用一份清单声明（xdef 种类 `site-module`）：

| 一样 | 例 |
|---|---|
| 构建阶段的贡献 | 搜索：由每个路由的树生成索引 |
| 组件，以及它填外壳的哪个槽 | 导航：侧栏填 `nav` 槽 |
| 操作目录 | 搜索：`docs.search` |
| 数据种类 | 路由：`routes` |

内置的模块：内容、路由、导航（侧栏、面包屑、上一页与下一页）、页内目录、搜索、高亮、国际化、主题、Agent 的门、演出、Pages 适配器。预设只是选好的一组。清单同时说明模块往页面的闭包里加什么，Web 上的世界由它推导（UI6、UI7）。外壳是一份 TS 布局，槽有 `header`、`nav`、`content`、`toc`、`footer`；换掉任何一个槽里的东西就是自定义。

### 3.5 构建的七步

收集（配置与 `pages/` → 路由表）→ 求值（每个路由在无头宿主上装好外壳与内容并静止）→ 投影（HTML、Markdown）→ 索引（搜索、站点地图、站点自述）→ 引擎（按世界与策略打包）→ 清单（每个文件的字节、gzip 后的字节、对预算的结论）→ 适配器（Pages：基地址、`404.html`、`.nojekyll`）。每一步是 oweb 的 mcpp 插件里的一个阶段，可以单独运行与检查。

### 3.6 最小核心文档集（D-274 的清单）

| 页 | 覆盖 |
|---|---|
| `index.md` | 一到三级标题、带全部行内格式的段落、页内锚点与跨页链接 |
| `start.md` | 从安装到第一个窗口（RL3 的那一页）：有序与嵌套的列表、命令行的代码块、一张表 |
| `ui.md` | 三种语言加无语言的代码块、图片、引用、HTML 注释 |
| `agent.md` | 带对齐的表格、任务列表 |
| `reference/ops.md` | 由契约生成的参考（ST3 把生成变成公开能力） |
| `live.md` | 带一个现场示例的页（加载策略 `idle`） |
| `long.md` | 一篇长页（三十屏以上） |
| `zh/index.md`、`zh/start.md` | 中文的两页（国际化的路由、非 ASCII 文字） |

它是 `docs` 模板的样例，也是往返 CTS、搜索的检查、冷启动评测的问题集、并排对照时两边构建的同一批内容。

### 4.1 引擎按路由加载的做法（ST2 第 5 步，2026-11-27 实施）

- **页面自己的 HTML 是数据（D-284）的落地**：引擎到达后向页面要两样——每个写出的节点（id、元素的名字 `aria-label`、地址、只含文字的元素的文字，`omui::shown_document()`）与文档节点的标记（`shown_document(id)`）；外壳的各部分（站点的页面、本页目录、上一页与下一页）和文档都从这里读回。不取路由表，不带序列化的状态，不带 Markdown 源与解析器。
- **一个视图函数，两处用**：`oweb.shell` 的 `page(parts, layout)`；构建器由路由表得到 `Parts`，页面加载的程序由页面读回得到 `Parts`。节点的 id 因此在“写出的页面”与“画出的页面”里相同（都挂在应用的挂载点 `main` 下：`main/page/nav/r0`、`main/page/main/doc/b3`），文档层按 id 一对一接手。检查：最小文档集的每一页从自己的 HTML 读回再写一遍，与原先写出的逐字节相同（带样子与不带样子）。
- **世界是一张等文档的页面**：`omui-gen dist-toy --world` 产出的 `index.html` 有四处位置——页头（`<!--omui:head-->`）、文档（`<!--omui:document-->`）、世界的文件所在的目录（`var omuiRoot = "";`）、何时取程序（`var omuiTakes = "eager";`），另有标题与语言。oweb 只替换文字，不依赖生成器的代码；世界的其余文件在站点里只存一份（`engine/`）。这样的页面里 `#` 之后是文档里的位置，不是程序的参数，也不为它重新载入；按语言取的字体看文档自己的语言。
- **阅读程序 `oweb.reader`**：不带脚本引擎与运行时生成的 C++ 应用（SDK 的 `app` 世界），所有路由、所有用默认外壳的站点共用。
- **滚动**：带引擎的页面写成窗口大小的滚动视图（画布不随窗口滚动），与 UI5 量过的形态相同。更好的做法是“应用的根滚动视图就是窗口的滚动”（画布固定、文档层撑开窗口的高度、两者同步），移动端的地址栏收起、返回时恢复位置都随之而来；它要改 Web 宿主的文档层，记为待做，重启条件是 ST4 的模板定稿之前。
- **给丢失地址的页面**（`404.html`）不取程序：它在任何地址下被送出，只负责可读并带回首页。

## 5. 不做的

- 不做服务器端的任何东西：产物是静态文件。
- 不做 HTML 模式与 webview 前端（D-259）；不带第二份内容。
- 博客、多版本文档、个人主页与项目主页的专门预设：0.1.0 只保证能由模块拼出。
