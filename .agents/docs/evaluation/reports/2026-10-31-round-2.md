# 第二轮评估（2026-10-31）：亲手使用之后再打分

维护者的要求：评估不能只看素材，评分者要真的去用。具体做法：
- 通过 openas 操作这些作品，点击、拖动、输入都走真实路径，再给出真实的反馈；
- 用的同时也在评框架、引擎和 openas 本身的能力。

这一轮起，标准升到 v2（见[评估标准](../README.md) §2–§4）：
- 证据新增“使用”一类；
- 人会直接碰到的维度，没有使用证据最高只给 70 分；
- 报告里要先列使用记录，再写“框架和 openas 的反馈”。

## 评分者怎么用这些程序

- **`tools/eval/eval.sh`**：
  - 先按对象文件里的 `**Run:**` 用 `--profile release` 构建程序，再以 `--serve` 在无头模式下启动；
  - 每个程序在一个临时目录里提供 agent 端点；
  - codex 通过 `omui mcp` 连接，MCP 工具的批准交给 openas 裁决，不再走 codex 自己的审核，因为那个审核曾把只读的 `reading` 也拒掉了。
- **新增的能力：agent 像人的设备那样输入**（协议的 `input` 操作，MCP 的 `ui_input`）：
  - 支持点击、双击、拖动、滚轮、按键和文字，经过真实的命中测试、焦点和手势；
  - 每次的回答说明按下时命中了哪个节点、执行了哪些动作、由谁执行。
- **默认开启**：用框架写的应用默认就有这项能力（`AppSpec::agent_input`）。开发者可以关掉，运行时用 `--no-agent-input` 关掉。
- **按 openas 处理**：
  - 这些输入做的事算作 agent 自己的，记录为 `agent:<名字>;via=service:input`；
  - 按它的请求同样裁决：人自己的动作一律拒绝（S-10），受上限和授权约束（S-11），不可撤销的动作要人的答复；
  - 有测试覆盖：经输入点击不可撤销的按钮，得到 needs-answer；经输入点击人专属的按钮，被拒绝。
- **`ui_clock`**：暂停、单步、跳转，用来逐帧看动画。
- **`--agent-name`**：同一个应用可以开第二份，例如手机尺寸的官网。

## 用出来的问题，以及处理

### 框架

| 问题（谁用出来的） | 处理 |
|---|---|
| 程序自己维护的状态无法撤销：官网“发布”撤销时退掉的是上一个勾选，“已发布”还在（site） | 新增 `Runtime::taken_back_by(undo, redo)`。动作的处理函数可以说明怎样撤销、怎样重做，这个动作就进入历史，和组件给出逆操作的动作一样。按钮和动词都适用 |
| 拖动滑块不进历史，撤销退掉的是更早的一次按键（style-gallery） | 新增 `Services::performed`：组件自己的输入处理已经完成的动作，连同它的逆操作记入日志和历史，不再执行一遍。一次滑块拖动算作一步 |
| 画布镜头下的活节点，语义树报告的是排版坐标，与绘制位置差了一个镜头变换，点它的中心会点错（自己用 agent 点击墙上链接时发现） | 节点增加 `screen` 边界，经过变换、取设定值：语义树、agent 的 `node` 点击、截图区域都用它。`bounds` 仍然是排版框 |
| 覆盖在内容上的 HUD 挡住了它下面的链接 | `pointer_events: none` 像 CSS 一样作用于整棵子树。文档墙的 HUD 不再接收指针 |
| CRT 曲面把内容画得往中间收，点击落在别处（style-gallery） | 效果可以声明 `source_of`（某个像素取自哪里），命中测试据此映射坐标。复古风格包里，点击落在看到的位置 |
| `wait settled` 在镜头飞行、风格交叉淡化时提前返回（site、style-gallery） | 画布在镜头移动和等待晋升期间标为 animating；交叉淡化期间根节点标为 animating |
| 滚动内容变短后，偏移超出末尾（style-gallery） | `ScrollNode::laid_out` 把偏移收回到有效范围 |
| 请求减少透明时，风格包里的透视效果仍然在画（style-gallery） | 读背景的效果在减少透明时不画；禁用的控件不再套用风格效果，比如霓虹灯管 |
| 霓虹灯管是矩形，按钮却是圆角，角上出现暗楔（style-gallery） | `Button::effect_shapes` 给出它自己画的圆角框 |

### 作品

- **官网**：
  - 发布可以撤销和重做；
  - 撤销之后，三块面板跟着回到当前节点；
  - 首屏标题是 heading；
  - 手机布局：窄于 720 时，导航和镜头切换放进“菜单”，面板占满宽度，首页的演示改成一列，示例 01 和出招表改成竖向滚动；
  - 代码保持原有换行，可以横向滚动；
  - “Clicked once”；
  - 新增“绘制”面板：选择由谁来画（自动、GPU、CPU；网页上重新加载并带上 `?renderer=`），以及镜头移动时地方的画法（先用图片、一直实时、只用图片），这样才能看清飞行中到底掉不掉帧。这一项是维护者的追加要求，也对应 canvas 的新属性 `promotion`；
  - 静态页里的文档链接指向对应的分节；
  - 页面允许缩放；
  - 跟随浏览器的减少动态和减少透明设置。
- **文档墙**：
  - 墙上的链接会跳到它指向的文档，支持相对路径和 `..`；地址交给系统打开；
  - HUD 不再挡住点击。
- **风格工坊**：
  - 撤销、重做、重置：同一字段连续的修改算一步；重置本身也算一步；
  - 不合法的值不会生效，并说明原因：人在字段下方看到，agent 在 `styles.set` 的回答里看到；
  - 范围由出厂时的风格包决定，拖动不会改变两端；
  - 参数显示名字、数值和单位；
  - 圆角同时作用于面板；
  - Save 和 Cancel 真的生效，并说明结果；
  - 新增“减少透明”开关；
  - 导出整份写入，不会写出半个文件；
  - 复古风格包更亮更易读，同时保留扫描线；
  - 图表有星期标签，可访问名称里带上数值。
- **格斗游戏**：
  - 在维护者的追加要求之前就排上了：可以一个人对电脑玩。选人界面上，2P 的座位由电脑占着，2P 按任意键即可加入；1P 选好后电脑也会选人；
  - 新增回合制（`--turns N` 或舞台的 `turn_frames`，以及 `turn` 动作）：两个 agent 轮流说下一回合按什么键，比如 `2,3,6LP`，一回合帧数为 N；回合结束后，回答里说明这一回合发生了什么。两个 codex 可以这样对战。
  - 新增 `--fight P1 P2 --cpu 1 --level 3`，可以直接进入对局。

## 还没做的（排进下一轮）

- **文档墙**（这次评估里分数最低）：
  - 保存布局、镜头和任务的修改；
  - 修复任务勾选框的指针激活：只接受 `toggle`，不接受 `activate`；
  - 文字选择不被画布平移抢走；
  - 搜索界面；
  - 后退和前进；
  - 移动窗口可以撤销；
  - 双击进入阅读；
  - 远景能认出每个文档。
- **官网**：全景页的缩略图仍是占位。
- **风格工坊**：墨水风格里文字的抖动。
- **跨平台**：浏览器里的真实点击（web 宿主的输入映射）。
- **评估**：两个 codex 用回合制对战之后录像并分析；渲染、动画、引擎、UI 框架这几个对象的“使用”评估。
