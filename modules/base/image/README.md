# openmui.image

Images in memory (8-bit RGBA, straight or premultiplied), PNG encoding and decoding through libpng's simplified API (`compat.libpng`, `compat.zlib` from mcpp-index), and WebP encoding and decoding through libwebp (`compat.libwebp`, imported as `mcpplibs.mwrap.libwebp`). Errors are returned as messages; nothing longjmps through C++ frames. `decode` and `load` take either format, told by its signature.

Animated PNG (`encode_apng`, `save_apng`): every frame after the first is stored as the rectangle that changed from the one before, and an unchanged frame lengthens the one before, so a loop over a still background costs what moves; a viewer without APNG shows the first frame. The headless host records into it (`Headless::record`), which is how the showcases' README loops are made.

WebP (`encode_webp`, `decode_webp`, `save_webp`, `load_webp`): still images, lossy (`WebpOptions::quality`, alpha kept losslessly beside the colour) or lossless (`lossless = true`, every pixel back as it went in), `method` 0–6 trading time for size. Colours under clear pixels are kept (libwebp's `exact`), premultiplied views are written straight, and decoding gives straight alpha. Encoding is single-threaded, so a given libwebp (pinned by mcpp.lock) writes the same bytes on every platform; the tests pin a file's decoded pixels and an encoding's bytes. libwebp is built without threads, so its one-time setup is not lock-guarded: the first use of either direction encodes and decodes a tiny picture under a `std::once_flag` before anything else runs, which makes concurrent first use safe.

Animated WebP (`encode_animated_webp`, `save_animated_webp`, `decode_animated_webp`, `load_animated_webp`): shaped like `encode_apng` (the same frame list and `delay_num / delay_den`, `loops`), so a caller switches format by name; `AnimatedWebpOptions` adds `quality` (80), `lossless`, `method` and the key-frame spacing `kmin`/`kmax` (33/64: a key frame at most every 64 frames, about 1% larger than none). libwebp's WebPAnimEncoder (the `mux` feature) stores what changed between frames and merges equal ones; lossy, a README loop of soft UI and art comes out about a twentieth of its APNG (320 × 200, 36 frames: 23 KB against 490 KB in the tests). Times are whole milliseconds, each frame starting at its delay's multiple rounded, so they never drift. Single-threaded and `exact`, so the bytes are pinned like the still's. Decoding (WebPAnimDecoder, the `demux` feature) gives each shown frame as the whole canvas, straight, with its delay; a still WebP is an animation of one frame, and libwebp writes an animation that comes out as one frame as a still. The headless host's `save_recording` writes one for a `.webp` file.
