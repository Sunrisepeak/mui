# 官网：一个页面；它演示自己是怎样被 Live Design 做出来的，一段提示词让你的 Agent 装上并接入（G4，一页设计）

2026-11-19 起草，**第四版，草案，待 review**。任务 G4（[实施方案](2026-11-18-omui-meng-implementation-plan.md)），挡着 G5、G6、G8；提议的决策 D-252、D-253。背景：[顶层设计 §5](2026-11-18-omui-meng-top-level-design.md)（D-235、D-236、D-237）与运行时生成（D-144、D-148）。

- 第二版（review 之一）：只做一个页面；点播放就回放官网自己的设计过程；可以切进 Live Design 接上 Agent；右上角一个 GitHub 链接；文档等都先不放。
- 第三版（review 之二）：**切进去的是有限的 Live Design**——发布的应用按开发者的配置开放的定制面，不是开发模式的设计器；**官网不内置 Agent**，接入的是访问者自己的 Agent，入口是“一键复制提示词”；页面是结合艺术设计的单页创意作品（参考 `anomalyco/hex` 的 `site/`：一个页面，首屏是一场演出）。第二版里“设计器成为发布时可带的能力”一条撤回，D-149 不动。
- 第四版（review 之三）：那个键就叫 **Live Design**，不用“播放”二字；**安装、接入、验证安装、之后的体验是同一个动作**——复制一段提示词交给自己的 Agent；Agent 接入时官网的画面要有动画的回应；参考站只取“单页的原创创意”这一点，不取它的布局与细节；原则是少即是多乘以创意：用尽量少的元素，让同一个元素做几件事，不堆功能。

## 1. 要定的

这一个页面上有什么、它的艺术方向；Live Design 这个键做什么；安装、接入、验证与体验怎样合成一个动作；访问者自己的 Agent 怎么接进一个网页；预算；对框架提出的要求。

## 2. 事实（2026-11-19，`30c322ca`）

- 现有的官网：`site/src` 约 12,300 行 C++，交付 3.99 MB（预算 4.0），首帧之前 1.94 MB，第一帧 1.24 s（本机）。
- **发布的应用里的定制面已经有了**，就是运行时生成（D-144）：应用声明若干**表面**（视图里的一个槽，写明它是做什么用的）；开放程度四级 `off`、`data`、`limited`、`all`（`omui.config.ts` 的 `generation`）；操作是 `generate.surfaces`（有哪些表面、开放到哪一级、限制是什么、`limited` 下可以用哪些组件与操作）、`generate.draft`（一份视图文档、A2UI 消息，或在 `limited`、`all` 下的一段 TS）→ `generate.preview`（不保留地挂上去，前后的画面与语义的变化）→ `generate.commit`（成为该表面的下一个版本，记下是谁做的，可撤销）；还有 `generate.versions`、`generate.restore`、`generate.keep`（留作可复用的片段）。它是组合框架里的一项能力（`generate`，只在 `full` 世界里；实测带入约 0.8 MB）。
- **主题还不是可定制的表面**：风格包与主题令牌是构建时的数据，运行时没有“换一组令牌”的操作目录。
- **设计器只在开发模式里**（D-149），发布构建不带；它多出的是源码、设计历史、分支、预览与变体、时间线这些开发用的辅助。
- **页面上已有 Agent 的入口** `window.omui`，与桌面的 Agent 说同一种协议，经总线由 openas 判定；它只对同一个页面里的脚本可见。
- **Web 上还不能运行应用的 TS**（G0 可行，G1 未做）。视图文档与 A2UI 是数据，不需要脚本引擎。
- 设计历史的回放已能导出成影片（G3）。缺口：尺寸等于窗口；字幕未编辑；没有 Agent 的指针与标识（D-160）；没有声音。
- 参考（`anomalyco/hex` 的 `site/`，2026-11-19 读它的 README）：一个页面；首屏是一场有情节的演出（WebGPU，Canvas 2D 回退）；一个安装切换器；标签页不可见或首屏滚出视野时暂停，手机上限制帧率与像素比；减少动态效果时首屏静止，按键后只放平缓的版本；分享图与视频由同一场演出生成。

## 3. 按三级次序（D-185）

**① 原始性创新**

- **页面是它自己的设计历史的最后一帧。** 按 Live Design 键，页面在原地从空白把自己重做一遍——不是放视频，是那棵语义树一步步长出来，hanim 呈现每一步。这场回放就是首屏的演出：别人的首屏演的是一段编排好的动画，这里演的是这个页面真实的制作过程，暂停在任何一步都是一个真的界面。
- **定制是叠在应用上的一层数据。** 访问者的 Agent 做的修改不改应用，只在它上面加一层：换掉的令牌、某个表面的新版本。这一层是一个值——可以预览、提交、撤销、清空、导出成一个小文件带走。应用更新时这一层照样叠上去，叠不上的部分说明原因。
- **有限的 Live Design 与开发模式的 Live Design 是同一件事的两档。** 同一套“起草 → 预览 → 提交 → 版本”的事务，同一个协议。开发模式改的是源码，有历史、分支、变体这些开发用的辅助，全部开放；发布的应用改的是开发者声明的表面，按开放程度受限。Agent 学会一档就会另一档。这对任何 omui 应用都成立（换主题、调布局、让 Agent 给自己生成一块面板），官网只是第一个把它摆在首页的。
- **官网不内置 Agent。** 框架的主张是人和 Agent 都是一等用户，Agent 是用户自己的；页面给的是接入的办法：一键复制一段提示词，访问者把它交给自己的 Agent。
- **安装、接入、验证、体验是同一个动作。** 主路径是人 → Agent → 系统（D-136），所以官网的“安装说明”是写给 Agent 的：那段提示词让 Agent 装上 omui、接进访问者正看着的这个页面。接上了，页面上的画面动起来——这一下同时是三件事：安装成功的证明（装好的 `omui` 在访问者的机器上跑起来并与页面握了手）、接入的确认、体验的开始（Agent 接着就能改这个页面）。别的框架的官网把这三件事放在三个地方：一段安装命令、一句“运行 hello 看看”、一个另开的演示。
- **少即是多，靠复用而不是靠删。** 页面上一个主体做三件事：它是标志，是 Live Design 的时间线，也是接入的状态（§4）。每加一个元素之前先问已有的元素能不能承担。

**② 前沿加组合**：首屏的文字由静态 HTML 先出（D-236），画布叠在上面；回放的数据与定制的能力按需加载；演出不可见时暂停、手机上限制帧率与像素比、减少动态效果时改为静止加逐步切换（参考站的做法，做成框架的默认，不是官网专有）；分享图与影片由同一段回放生成。

**③ 业界做法（低线）**：真实的地址、标题、描述、分享卡片、结构化数据；文字可选、可复制；键盘可达。

## 4. 页面与艺术方向

**页面上一共五样东西**，默认只有这一个页面：

| 元素 | 是什么 | 它还是什么 |
|---|---|---|
| 主体 | 标志：O 形的环，里面是 mui；可以变形成 Mui | **Live Design 的时间线**（进度沿着环走，沿环拖动就是拖时间）；**接入的状态**（等待配对时环是开口的、在呼吸；接上时环合拢）；**Agent 在页面上的形象**（接入后标志变形成 Mui，带着这个 Agent 的标识，D-160） |
| 一句话 | omui 是什么 | 静态 HTML 里的标题，搜索引擎读到的那一句 |
| **Live Design** 键 | 演示这个官网是怎样被 Live Design 做出来的（不写“播放”） | 进行中再按是暂停；结束时它旁边的提示词亮起 |
| 提示词 | 一行可以点一下复制的文字：让你的 Agent 装上 omui 并接进这个页面 | 安装说明；接入的入口；安装是否成功的检验 |
| GitHub | 右上角的链接 | 唯一的外链；文档与手动安装在仓库的 README |

没有导航、文档、作品墙、页脚的链接列表、语言切换、单独的时间线条、单独的“连接状态”面板、单独的安装区。

**一个画面的四种状态**（艺术方向；细化在 G5 开工前的一轮草图里定）：

| 状态 | 画面 | 说的是 |
|---|---|---|
| 静止 | 成品：标志、一句话，大量留白；材质与光用框架自己的效果 | 像素 |
| Live Design | 画面退回草图，再一步步长出来；进度沿环走；每一步标明是谁做的与那一步的源码片段 | Live Design 与动画 |
| 等待接入 | 复制提示词之后，环开口、呼吸；配对码就在提示词里，页面上不另显示 | 人把事情交给了自己的 Agent |
| 已接入 | 环合拢，标志变形成 Mui，带着 Agent 的标识与它装好的 omui 的版本；之后 Agent 的每一次修改，画面按 hanim 的配方过渡，结构（表面的边界、令牌的名字）在修改的那一刻浮现、随后隐去 | Agent 与语义树；安装成功 |

- 四种状态是同一个画面的连续变化，由 hanim 过渡，可以互相打断（Live Design 进行中 Agent 接入，演示让位）。
- 质感来自设计细节（时长与曲线、起点感知、打断连续），是框架的默认值与主题令牌，不是官网专有的代码（AGENTS §6）。
- 不引入框架之外的素材；演出不可见时暂停，弱设备上限制帧率与像素比，减少动态效果时四种状态之间改为平缓的切换。

**这一版官网开放的定制范围**（在它的 `omui.config.ts` 里声明）：

| 开放程度 | 是什么 | 官网上 |
|---|---|---|
| `data` | 主题：颜色、圆角、字体、密度、动效的风格（令牌，纯数据） | 整个页面 |
| `limited` | 声明的表面里放视图文档或 A2UI，只能用列出的组件与操作 | 一个表面：主体旁的一块“你的 Agent 的作品” |
| `all`（任意 TS） | — | 不开放 |

语言随浏览器，中英文是同一个页面的两个地址，互相指向。

## 5. 一个动作：安装、接入、验证、体验

**访问者做的只有一件事：点一下提示词（复制），交给自己的 Agent。** 之后的事都是 Agent 与系统做的，人在页面上看着：

| 步 | 谁 | 做什么 | 页面上 |
|---|---|---|---|
| 1 | 访问者 | 点提示词，粘给自己的 Agent | 进入“等待接入”：环开口、呼吸 |
| 2 | Agent | 按提示词里的那一行装上 omui（已装就跳过） | 不变 |
| 3 | Agent | 运行 `omui connect <配对码>`：本机起一个端点，页面连上它；握手里带着这份安装的自检结果（版本、平台、能不能出一帧） | **“已接入”**：环合拢，标志变成 Mui，带着 Agent 的标识与 omui 的版本。到这里安装已经被验证了 |
| 4 | Agent | 调用 `describe`：得到入门与典型任务（D-186）——改这个页面的主题；在表面里放一件自己的作品；把这一版带走，在本机 `omui new` 成一个项目接着做 | Agent 动手，画面跟着变 |
| 5 | 访问者 | 看、指、调；随时撤销、回到原样 | — |

**提示词的内容**（三样，一段话）：装 omui 的一行命令；`omui connect <配对码>`；“先调用 `describe`，照它说的做”。它不解释怎么改页面：没有背景知识的 Agent 只凭端点就能学会（D-186）。它是给 Agent 读的，人也读得懂——想手动装的人照着第一行做，或去 GitHub。

**一个标签页不能被外面拨入**，所以是页面去连本机的端点：

| 情况 | 办法 | 状态 |
|---|---|---|
| 访问者的 Agent 能在本机运行命令（主路径） | 上表 | `omui connect` 没有；https 的页面连本机端口，各浏览器有各自的限制与授权提示，**未核对**——G9 第一步先做最小验证。浏览器弹出的那一下授权正好是“权限由人掌握” |
| 页面连不上本机的端点 | `omui connect` 改为在本机打开同一个官网（原生的 omui 应用），接入的动画在那个窗口里发生；浏览器的标签页保持“等待接入”并说明去了哪里 | 退路；安装的验证反而更强（真的出了第一个窗口） |
| Agent 在浏览器里、操作这个标签页 | 页面上已有的 `window.omui`；页面不为它另设入口 | 入口已有；定制的操作未接到 Web 宿主 |
| Agent 在远处，够不到访问者的机器与浏览器 | 需要中转服务 | 不做；官网是静态托管的 |

**权限**（AGENTS §2 第 5 条）：点提示词是访问者的一次明确操作，它开一个有时限的会话并生成配对码；会话里开放的只有官网声明的范围；每个请求由 openas 判定；提交之前有预览；改动只在访问者的浏览器里，页面不向任何服务器发送；关掉会话即收回。

**与发布通道是同一条路**：提示词里的安装那一行，就是通道线要做的“从空机器一条命令装上”（E1、E2）。所以官网的接入场景、通道线的“干净机器”检查、发布门里 Agent 的冷启动任务，是**同一个可重复的场景**：一个只拿到这段提示词的 Agent，在干净的环境里装上、接入、把页面换成暗色并放一张卡片。它只做一次、守三处。由此的一个约束：官网对外上线要等 omui 能公开安装（对外发布是本文之外的决定，D-216）；在那之前这个场景用本地索引在本机跑。

## 6. 预算（官网的门）

| 项 | 上限 | 依据 |
|---|---|---|
| 首帧之前的字节 | ≤ 1.2 MB（D-247 的低线 1.1 MB 作目标） | 顶层设计 §4.2；不含回放数据与定制的能力 |

| 定制所需的追加字节 | 先量再定（运行时生成在桌面上约 0.8 MB） | 按需 |

| 帧时间 | 真实浏览器里 p99 ≤ 16.7 ms，回放与定制时同样；长于 33 ms 的帧为零 | D-187 |

| 不执行脚本抓取 | 文字与语义树的文字一致 | D-236 |
| 界面的 C++ | 只有性能敏感的部件；页面是 TS | D-235 |

## 7. 对框架的要求（回主线补）

| 要求 | 现状 | 任务 |
|---|---|---|
| **主题是一种可定制的表面**（D-253 提议）：运行时换一组令牌，按开放程度 `data`；预览、提交、版本、撤销与界面的表面同一套事务；变化按 hanim 的配方过渡 | 没有 | **G8** |
| **定制是一层可以导出与再叠上的数据**（D-253）：一个 xdef 种类，归运行时生成 | 版本存在进程里 | **G8** |
| 运行时生成在 Web 宿主上：`generate.*` 经 `window.omui`；版本存浏览器的存储；按需加载 | 桌面与无头有；Web 宿主未接（compose K6 余下的那一项） | **G8** |
| 设计过程在应用里原地演示：时间线是一个没有固定外形的部件（官网把它画在标志的环上）；Agent 的指针与标识（D-160） | 桌面的设计器能回放并拍成影片 | **G8** |
| 访问者的 Agent 接进标签页：`omui connect`（握手里带安装的自检）、配对、页面一侧的连接；连不上时在本机打开同一个应用 | 没有 | **G9**，先做最小验证；安装那一行来自通道线（E1、E2），验证可以先用本机构建的 `omui` |
| 接入是画面的一种状态：Agent 的标识与进出场由 hanim 呈现（D-160），是宿主与风格包的默认，不是官网专有 | 桌面的设计器里有指针标识的底座；页面上没有 | **G8** |
| 演出的资源规矩：不可见时暂停、弱设备上限制帧率与像素比、减少动态效果时的平缓版本 | 部分有（静止不画、减少动态） | G5 里补成宿主的默认 |
| Web 上运行应用的 TS | G0 可行 | **G1**（官网自己的界面是 TS；回放与这一版的定制不依赖它，见 §10） |
| 一个页面的静态 HTML 与元数据 | 构建时的投影没有 | **G2** |

设计器不进浏览器，D-149 不动。

## 8. 设计过程的章节（Live Design 键演示的内容，也是 G6 的输入）

演示约 60–90 秒；每一章是设计历史里的一段，不是另拍的。

| 章 | 历史里的哪一段 | 要让人看见的 |
|---|---|---|
| 1 空白 | `omui new` 之后的第一帧 | 起点是一个真实的模板 |
| 2 Agent 起稿 | 标志、一句话、Live Design 键 | TS 一行行出现，界面同步长出 |
| 3 形象 | 标志变形成 Mui | 矢量与 hanim 的变形 |
| 4 人接手 | 人拖动一个间距、改一句话 | 人随时接手；源码跟着变 |
| 5 核对 | Agent 查询因果记录确认人的改动，补一条测试 | Agent 不靠转述 |
| 6 回退与分支 | 试一个版式、退回 | 历史可以分支与回退 |
| 7 到这里 | 演示停在线上的页面，环走完一圈，提示词亮起 | 你看到的就是它做出来的；下一步交给你的 Agent |

| G5 | 一轮艺术方向的草图（四种状态各一张，离屏渲染）给 review；官网这一个页面由 Agent 在 Live Design 里用 TS 做出，设计历史提交在仓库里；§8 的七章；演出的资源规矩 | G1、G2、G8、G9、K7 | §6 的预算；`media --check site`；演示的收尾与线上的页面逐像素一致；§5 的那个场景从头到尾通过，接入的那一刻的画面按时间采样核对（端点、中间态、被打断） | 5 |
| G6 | 同一段设计过程导出成影片与分享图，放在仓库的 README 里 | G5 | 一条命令从历史重新生成，两次的帧哈希一致 | 2 |
| G7 | README 的每句对外的话有 `claim`（首页的那一句同样） | C2、C3 | lint `claims` | 2 |

G8 与 G9 不依赖 G1（令牌与视图文档是数据），与 G1 并行；G5 等它们。Web 线最长的链是 **G1（5）→ G5（5）→ G6（2）**；通道线经 G9 汇入 G5（E1 → G9 → G5）。G 组的总量约 24。

验证状态：字节、首屏时间、不执行脚本的抓取、设计过程的演示、定制的正确性、命令行的 Agent 经本机端点接入，在本机用无头浏览器真实验证。真实浏览器里的 GPU 帧时间在本机只能用软件光栅的浏览器量，不算性能数据，这一格标“未验证”并附软件路径的数与推断的依据。接入在本机没有的浏览器里的行为标“未验证”。

## 10. 风险与降级

| 风险 | 应对 |
|---|---|
| https 的页面连不上本机的端点 | G9 第一步就验证；不成则命令行的 Agent 改为“在桌面上打开同一个页面”（`omui connect` 起一个本机的窗口，载入同一个应用与访问者的那层定制），浏览器里只留 `window.omui` 一条路，写明 |
| G1 做不完，页面上不能运行应用的 TS | 官网的界面在构建时原生化（D-146）或由构建时求值的快照驱动；回放用每一步预先求值好的记录；这一版的定制只用数据（令牌、视图文档），都不需要页面运行 TS。受影响的只有以后开放 `all` |
| 定制的能力太大 | 只在点“复制提示词”时加载；仍过大就这一版只开放 `data`（主题），表面一项按五项写明后标预览 |
| 访问者把页面改坏 | 每次提交前有预览；“回到原样”始终可用；每个版本可撤销 |
| 艺术上不够好 | G5 开工前先出一轮草图给 review；质感的细节回到框架的默认值里 |
| 做不完 | 降级的次序：先去掉导出，再去掉 `limited` 的表面，再把命令行的接入标预览；回放、主题的定制与静态内容不降 |

## 11. 多视角自我 review

| 视角 | 看到的 | 结论 |
|---|---|---|
| 少即是多 | 五样元素；主体一个元素承担标志、时间线、接入状态、Agent 的形象四件事；没有单独的时间线条、状态面板、安装区 | 成立。要守住的是以后不往上加：新增任何元素之前先在 §4 的表里找承担者 |
| 创意是否来自框架本身 | 三处别人没有的：页面演示的是自己真实的制作过程；安装的成功由页面上的画面证明；访问者得到属于他的一版官网。三处分别用到设计历史、Agent 端点、运行时生成 | 是原创而不是装饰；素材全部来自框架，符合“作品只消费公开能力” |
| 第一印象 | 不认识 omui 的人看到的只有一个标志与一句话，可能不知道该做什么 | 风险。草图里要解决：静止状态下 Live Design 键与提示词的主次要一眼分得清；一句话必须自己说得清 omui 是什么。减少动态效果与不执行脚本的访问者只有静态内容，那一句话更要立得住 |
| 没有 Agent 的访问者 | 能看 Live Design 的演示，读得懂提示词里的安装那一行，能去 GitHub；不能定制 | 接受：这是有意的取舍（Agent 是用户自己的）；提示词要人也读得懂 |
| 安装与接入合一的代价 | 官网上线依赖 omui 能公开安装；主路径依赖浏览器允许页面连本机 | 两个都是硬依赖，都已写明：前者等对外发布的决定，之前用本地索引验证；后者 G9 第一步验证，退路是在本机打开同一个应用 |
| 安全与权限 | 页面主动连本机端口；Agent 能改页面 | 会话由人的一次点击开启、有时限、配对码一次有效；开放范围只有主题与一个表面，不开放任意代码；不向服务器发送任何改动；浏览器的授权提示保留不绕过。还要补的：配对码的长度与失效规则、本机端点只接受这一个页面的来源——G9 的设计里写 |
| 复用 | 同一个场景守三处（官网的接入、通道线的干净机器、发布门的冷启动）；主题定制、定制层、时间线部件、Agent 的进出场都是框架的通用能力 | 官网不写专用的引擎代码；这些能力别的 omui 应用直接可用 |
| 关键路径 | G8、G9 不等 G1；G9 的完整场景等 E1 | Web 线与通道线在 G5 汇合；任何一条晚了，官网都晚。两条线从第一轮起并行 |
| 性能与体积 | 首帧前 ≤ 1.2 MB 不含演示数据与定制能力，两者按需加载；定制能力在桌面约 0.8 MB，Web 上未量 | 先量；过大就这一版只开放主题 |
| 可验证 | 设计过程的演示、定制、命令行 Agent 的接入都能在本机无头真实验证；真实浏览器的 GPU 帧时间与别家浏览器的接入行为不能 | 按“先真实验证，做不到的推断并标注”处理 |
| 艺术质量 | 文字描述不能证明画面好看 | G5 之前先出四种状态的草图给 review，不通过不开工 |
