# CPU 光栅：一帧不分配，覆盖按带（一页设计）

状态：第一步已实施（2026-11-27），第二步实施中，待 review。决策：无新的，沿用 D-43（同一画面同样的字节）、D-184（CPU 是参考）、D-185（三级次序）。上级：[0.1.0 顶层方案](2026-11-26-release-0.1.0-top-level-design.md) §7 的 FE3、FE4；前文：[细描边的覆盖](2026-11-20-thin-stroke-coverage-design.md)、[帧的光栅按活分给线程](2026-11-27-raster-pool-fan-out-design.md)。

## 1. 一帧不分配（AGENTS §4：热路径每帧零分配）

### 1.1 事实

- **量到的**（release 的 `tests/bench`，`OMUI_BENCH=1`，程序自己数 `operator new`，2026-11-27 08:47，1 分钟负载 6.0–7.2）：仪表板整帧（`ui/raster/full-1080p`，一条线程）每帧 **6,367 次分配、4.07 MB**；列表滚动一格只画变了的行（`core/list-scroll/raster-serial`，含损伤跟踪）每帧 **933 次、0.84 MB**；同一帧按活分给帧线程组（`ui/raster/full-1080p-parallel`）每帧约 570–605 次。
- **从哪里来**（新测试 `mrender.vector` 的 `cpu_frame_alloc_test` 按命令种类分开数，每种 100 帧；路径一类〔两个填充、三条描边，含虚线与修剪〕每帧 217 次，分带画时 3,275 次；阴影一类〔外、内阴影各一与一个填充〕每帧 57 次，分带 483 次）：
  - 描边：`stroke_outline` 每次新建压平的折线、每条线一个 `vector`、修剪与虚线各返回一份新的（每段虚线一个 `vector`）、外轮廓、法线、角度、长度；分带画时每段各描一遍。
  - 阴影：`box_shadow_coverage` 一开头把输出赋成空的（扔掉上一帧的缓冲），形状、盒子的路径和覆盖都是局部的，模糊的两块整数缓冲每次新建。
  - 矩形的解析覆盖（渐变或带遮罩的矩形、不在像素边上的矩形裁剪、图像）每次新建一列的覆盖。
  - 效果：每帧新建一份变换栈、每个效果一份参数；`blur` 复制一份源图、`box_blur` 新建一张同样大的中间图。
  - 损伤跟踪：每帧清空再重填一张 `unordered_map`（每张图一个节点），每个效果一份参数。

### 1.2 三级次序

- **① 本体系**：渲染器与它的画布本来就活得比帧长（`CpuRenderer` 的 `Scratch`、`Canvas` 的缓冲“只增不减”，D-43 的注释里写着“同样形状的帧不分配”），缺的只是把每次调用里的局部量也归它们所有。所以每一处都改成由拥有者持有、清空后复用：画布持有描边的 `StrokeScratch` 与阴影的 `ShadowScratch`、一列覆盖的缓冲；渲染器持有效果的变换栈与参数；损伤跟踪的图像版本改成按编号排好的两张表（清空不释放，查找用二分）；效果的中间图归各自的线程（与 `:paint` 的图像列缓存同一种做法：只增不减）。算术一处没改，字节不变。**取这一级**。
- **② 前沿与组合**：查过的做法——Skia 的 `SkArenaAlloc`（每次绘制一块栈上的区，绘完整块丢）、Blend2D 的 `ArenaAllocator` 与零分配的光栅上下文、Vello CPU 的 `RenderContext` 复用（每帧 `reset`，缓冲保留）。三者都是“上下文拥有、帧间复用”，与①一致；区分配（arena）适合大小不定的一次性对象，我们的缓冲大小随形状变化但种类固定，用持有的 `vector` 更简单，不另引区分配。
- **③ 业界通行**：每次调用自己分配、交给分配器的线程缓存。这就是改之前的样子，不取。

### 1.3 结果

- **新测试**（`mrender.vector/tests/cpu_frame_alloc_test.cpp`，自带 `operator new`，所以单独一个程序）：九类命令（矩形、圆角与边框、外阴影与内阴影、填充与描边〔虚线、修剪〕、渐变与混合、图像与宿主的纹理、字形〔遮罩、样式、轮廓〕、各种裁剪、层与混合模式、效果〔折叠的淡出、淡出、模糊〕）各自与合在一起，在节点里画（对象号也写），预热 64 帧后再画 100 帧：同一帧整帧、每帧移动的整帧、分带（在调用线程上依次画，每段一张画布的轮次）、损伤跟踪给出的行，**都是 0 次**。
- **真实的帧**（同上的 release 基准）：仪表板整帧 6,367 → **0**；按活分给帧线程组 ~590 → **0**；列表滚动的光栅与损伤跟踪 933 → 平均 **0.96**（最多 16：滚进来的新字形第一次栅格化并进字形缓存，冷的，不是每帧的；用 gdb 在 `DamageTracker::update` 到这一帧的计数之间断在 `operator new` 上逐个看过）。`ui/frame/animate-all` 每帧 1,120 → 35、`motion/switches-100` ~3,710 → 600–730（剩下的是视图与布局，不在光栅里）。
- **不慢**：改前改后的两份 release 程序逐轮交替各跑 3 轮（09:02–09:06，1 分钟负载 5.5–13.3，别的会话在构建），画帧的 14 个基准的三轮中位数：`ui/raster/full-1080p` 9.07 → 8.76 ms、`-parallel` 2.86 → 2.66、`core/list-scroll/raster` 1.25 → 1.00、`-serial` 2.93 → 3.02、`ui/frame/animate-all` 4.90 → 4.32、`one-label` 2.73 → 1.91、`glass/10-1080p-cpu` 43.8 → 38.1、`simulation/cellular-1024-frame` 0.507 → 0.533、`render/gradient-fill-1080p-linear` 3.97 → 4.15；负载在 5.5 与 13 之间跳，同一程序三轮之间相差 10–50 %，3–5 % 的差分不出来。安静时的复测见 §3。
