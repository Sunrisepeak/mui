## 1. 定位：一个基础，三个亮点，一个前提

只主推**真正远超同类**、而且能在官网上当场证明的能力；其余降为"另外还有"。还没有证据的不说"远超"。

| | 亮点 | 一句话 | 怎么证明 |
|---|---|---|---|
| 基础 | **一棵语义树** | 像素、无障碍、agent、测试是同一棵树的不同渲染 | 透视镜 |
| ① | **agent 原生且安全** | agent 用语义协议直接操作（不是看截图点像素）；有效果声明、授权、撤销和日志（openas）；用户叫自己的 agent 就能操作任何 openmui 应用 | 访客自己的 agent 操作官网；模拟演示和真实录像 |
| ② | **时间与确定性** | 任意时刻可以重现；跨平台逐位相同；可以倒放、回放、回溯，能把一段操作变成测试 | 时间旋钮、即时回放、回溯条、"你的哈希 = CI 的哈希" |
| ③ | **通用动画** | 组件 × 效果 × 动画任意组合；任意组件之间的变形达到 manim 的粒度；动画不由组件写死，结果因组件本身而异 | 变形实验室、爆炸对比、动效工作室 |
| 前提 | **处处都快** | 同一套代码从嵌入式到独立显卡，自动适配，开发者和用户可控 | 档位演示、对比基准 |

贯穿的原则：**代码即一切**——唯一的事实来源是代码或代码读取的数据文件；编辑器是数据的视图；agent 能写代码就能做出一切。

### 1.1 和同类的对比

| 能力 | 同类现状 | openmui |
|---|---|---|
| 语义 | 无障碍树是渲染之后附加的；测试读另一套结构 | 语义树是出发点，其余都是它的渲染 |
| agent | 截图加坐标点击（computer use），或借道无障碍 API；没有效果、授权、撤销 | 语义协议原生操作；openas 决定每个请求；动作可撤销、有日志 |
| 确定性 | golden 测试每个平台各存一份；动画不能倒放 | 三个平台两种编译器逐位相同；动画是时间的纯函数 |
| 组件之间的过渡 | SwiftUI `matchedGeometryEffect`、Compose `SharedTransitionLayout`、Flutter Hero、Framer Motion `layoutId`、View Transitions：只有外框几何加快照淡化 | 节点、语义、字形、形状、粒子五层的匹配和变形，时间线级的控制 |
| 动画的来源 | 控件的动画由组件作者写死 | 组件只声明状态；动画来自通用库，由风格和策略选择 |
| 形状变形 | Rive、Lottie 只用于预先制作的素材 | 作用于真实运行中的 UI，带语义 |
| 编排 | manim、Motion Canvas 是离线工具 | 同样的编排能力作用在交互界面上，也用于做视频 |

对比表在官网的文档里，每一行附证据链接（测试、基准、可运行的页面）。

## 2. 官网的信息结构

**导航**：组件 · 动画 · 效果 · 实验室 · 场景 · 作品 · 文档 · 开始使用

### 2.1 首页：一屏一个主角，往下每屏一个亮点

| 屏 | 内容 |
|---|---|
| **首屏** | 一个真实组件，配透视镜和时间旋钮；一句话定位；"开始使用""看它能做什么" |
| **agent** | "复制提示词"交给你自己的 agent；连接状态和操作记录；没有 agent 的访客看模拟演示，或真实 agent 的录像回放 |
| **时间** | 拖时间旋钮；"回放刚才"；"你的浏览器算出 X，CI 在 Linux / macOS / Windows 上也是 X ✓"——对照的是语义树哈希（与档位、显卡无关）和 CPU 参考渲染在同一档位下的像素哈希（不同显卡的 GPU 输出不逐位相同） |
| **通用动画** | 首屏的组件打散成粒子，沿路径飞到这一屏，重组成另一个组件；**滚动就是这段动画的时间轴** |
| **处处都快** | "你的设备：T2 · WebGPU · 粒子上限 5000"；可以切换模拟档位，对比同一个动画在 T1 和 T4 下的样子 |

### 2.2 各页

| 页 | 内容 |
|---|---|
| **组件** | 每个组件的全部状态、语义信息、四种语言的代码、五种风格；都能用透视镜看，能被 agent 操作 |
| **动画** | 基础、组合、自定义三级；每个都有时间旋钮；切换档位看降级 |
| **效果** | 参数实时可调；效果叠加；CPU 和 GPU 对照，哈希一致 |
| **实验室** | 任选组件 A 和 B、动画、效果、风格，导出代码或数据；精选的创意设计；**动效工作室**（在时间线里打开页面上任何一个动画来改，见[通用动画](2026-11-01-openmui-universal-motion-design.md) §8） |
| **场景** | §3 |
| **作品** | §4；只放达标的 |
| **文档** | 特性、实践、对比表（附证据）、性能报告 |
| **开始使用** | 安装、第一个程序、叫你的 agent 按它的按钮；示例 01 |

### 2.3 全站共有的

| 元素 | 内容 |
|---|---|
| **透视镜**（签名元素） | 一块可拖动的液态玻璃镜片，下面显示的不是放大的像素，而是另一种渲染：语义树、agent 看到的 JSON、测试断言；拖过正在动画的控件，树里同步看到 `animating` 和已经生效的目标状态 |
| **时间旋钮** | 任意动画都能抓住拖动、倒放、慢放；按住一个键全页慢动作 |
| **即时回放** | "回放刚才 10 秒"：按原样重演（输入加时间完全确定），可以慢放、换镜头；"把刚才的操作变成测试"生成断言语义树、固定像素哈希的测试代码 |
| **回溯条** | 状态真的回到过去（[agent 接入与回溯](2026-11-01-openmui-agent-connect-rewind-design.md) §6）；页面被你或 agent 搞乱了可以回去 |
| **设置面板** | 动效（完整 / 精简 / 减少 / 关闭）、效果档位、渲染器（自动 / GPU / CPU）——本身就是"开发者暴露、用户控制"的演示 |
| **agent 状态** | 是否有 agent 连接、是谁、它做过的每一步（可撤销）；**没有光标**：agent 是原生控制，不是 computer use |

## 3. 场景

每个场景是一个可用的小应用，对应一个亮点：

| 场景 | 内容 | 亮点 |
|---|---|---|
| **agent 帮你办事** | 笔记或邮件小应用；访客的 agent 查找、修改、请求确认、撤销；按 actor 回溯 | ① |
| **重现一个 bug** | 一段出了错的操作录像精确回放，拖到出错的那一帧，一键生成复现测试 | ② |
| **现场改代码：四种语言，五种风格** | 左边代码编辑器（TypeScript / Python / Lua，或 view 文档、风格包），右边运行中的应用，下面是树的哈希；改一行就地热加载，状态不丢，差异用 `morph` 呈现；换一种语言写同样的界面，哈希不变；写错了界面不动、错误在行内；C++ 版只读并且哈希一致；agent 也能改 | 基础 + ③ |
| **同一个应用，五种设备** | 同一个仪表盘在 T0–T4 的模拟下并排运行，动画自动降档，语义完全一致 | 前提 |
| **可以倒放的小游戏** | 引擎：倒放、即时回放、agent 上场，checksum 一致 | ② + 引擎 |
| **影片是程序** | §4.1 | ② + ③ + 基础 |

热加载用现成的 `openmui.player`（view 保留节点和状态、组件保留实例、脚本保留 signal；有错不改）；需要确认 player 和三个脚本宿主都能编译到 wasm（Q-33）。

## 4. 作品

上官网的门槛：单独评估 ≥ 85；交互扫描全过；体现至少一个亮点。

### 4.1 影片是程序

- **影片 = 时间线 + 片段**；每个片段是一个场景组件，用一种语言写；四种语言都至少一段：

| 片段 | 语言 | 浏览器里 |
|---|---|---|
| 开场像素、标志、结尾品牌卡 | C++ | 🔒 身份元素，只读源码 |
| 代码与语言对照 | TypeScript | ✏️ 可改 |
| 无限文档墙 | C++（最重） | 🔒 |
| 风格切换 | Python | ✏️ |
| agent 演示 | Lua | ✏️ |
| 时间、倒带、重放 | C++（游戏引擎） | 🔒 |

- 时间线上每个片段标出语言徽标和锁；选中可改的片段就打开它的源码；改动热加载，只重新渲染读到改动的帧（帧缓存已有），差异用 `morph` 呈现；用另一种语言重写同样的东西，片段每一帧的哈希不变。
- **片段脚本只声明**（场景的组件树和它的动画、效果对象），加载或重载时运行一次；每帧的求值全由原生引擎做——脚本永远不进入每帧路径，所以哪种语言写的片段播放性能都一样。片段拿不到墙上时钟和系统随机数：时间来自时间线，随机数由片段确定的种子给出。
- **三个视图双向同步**：时间线编辑器（轨道、片段、关键帧）、数据（`*.timeline.omui.toml` 原文）、代码（等价的 builder 和所选片段的源码）。
- **完整影片在浏览器里实时渲染**，每一帧的哈希等于 CI 渲染的结果；"帧准确，速率自适应"：拖到哪一帧画的都是准确的那一帧，慢的设备连续播放时按时间跳帧；可以导出（浏览器里 WebCodecs，或命令行）。
- 有了[通用动画](2026-11-01-openmui-universal-motion-design.md)，场景里的每个动画对象都能被时间线寻址，时间线成为完整的编排（现在只编排到镜头之间、镜头内部写死在 C++ 里）。

### 4.2 其他

- 时间线编辑器：本身是可用的工具。
- 格斗、打砖块、文档墙、风格工坊：达标前不上（[待办](2026-11-01-openmui-strategy-backlog-design.md) §4）。

## 5. 视觉

**方向 B：明亮的编辑风**——浅色、大字号、大量留白、动效作为点睛（参考 Linear、Stripe）；透视镜和时间旋钮是签名元素，在安静的页面上一出现就醒目。

流程：调研参考网站 → 定设计语言（字号阶梯、栅格、色彩、动效原则，动效原则写成风格包的动效设定）→ 用框架离线渲染关键页面的设计稿（静态图加短动画）→ 人工评审 → 实现。

## 6. 加载

分四批（细节和预算见[性能分档](2026-11-01-openmui-performance-tiers-design.md) §7）：

| 批 | 内容 | 目标（Q-34） |
|---|---|---|
| 0 | 极小的加载脚本 + 构建时导出的首屏语义树 JSON + 构建时渲染的首帧图 + 真实的 HTML 文本 | < 150 KB，约 0.3 s 看到首屏 |
| 1 | 核心 wasm + 拉丁字体子集 | 首屏可交互 |
| 2 | 按页面用字做子集的中文字体 | — |
| 3 | 各页的资源进入时再取 | — |

**创意加载**：加载脚本先用细线画出首屏的语义树（节点框、层级、ID），按真实下载的字节逐层生长；它用的是构建时导出的、框架"语义树镜头"的同一份几何，所以接管时不跳。首帧图到了就先显示，结构线叠在上面；wasm 就绪后由框架接管，从语义树镜头过渡到像素（镜头过渡已有，加上 `morph`）；页脚说明"你看到的结构就是这一页的语义树，它现在被画成了像素"。首帧图由 CPU 参考渲染画出，浏览器接管后的第一帧也走 CPU 路径，两者逐像素相同、接管时不闪（之后再切到 GPU）——这本身是确定性的证明。加载很快时，这段压缩到 0.3 s。
