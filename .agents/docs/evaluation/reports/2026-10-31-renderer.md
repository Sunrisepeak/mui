### Benchmark summary

**Skia’s strongest advantage is breadth:** colour management, text, images and rendering facilities form an established integrated system. Its documented colour-space conversion pipeline exposes a clear gap against openmui’s inspected sRGB byte pipeline. [Skia colour management](https://skia.org/docs/user/color/), [rendering facilities](https://skia.org/docs/user/)

**Vello’s strongest advantage is specialized vector processing.** Its current renderer families include SIMD/multithreaded CPU rendering, hybrid GPU rendering and an experimental compute renderer. Therefore, CPU preprocessing alone is not a defect; the missing evidence is whether openmui’s particular mask strategy scales competitively. [Vello renderer families](https://github.com/linebender/vello/blob/main/README.md), [architecture](https://github.com/linebender/vello/blob/main/ARCHITECTURE.md)

**Blend2D’s strongest advantage is CPU execution:** architecture-aware JIT pipelines, multithreading and analytic antialiasing. It also documents gradient dithering and broad composition operators. [Blend2D](https://blend2d.com/)

Openmui’s strongest differentiators are explicit deterministic reference arithmetic, pixel provenance, damage/parallel equivalence tests and integrated backdrop/style effects. Those are credible design strengths. **No inspected evidence establishes overall quality or speed leadership over any of the three.** The largest gaps are comparative measurements, colour/text quality coverage and hardware/backend validation.

### Highest-priority changes

1. **Create a common comparison harness.** Feed identical paths, text masks, images, clips and layers to openmui, Skia and Blend2D; add Vello for vector/GPU comparisons. Fix output dimensions, quality settings and worker counts.
2. **Build an independent quality corpus.** Include acute miters, nearly coincident edges, extreme zoom, tiny CJK, variable fonts, transparent gradients and heavily minified images. Store error maps, not only hashes.
3. **Remove steady rendering allocations.** Start with graph planning and gradient stop preparation; gate full raster and representative changing frames, not only idle frames.
4. **Measure GPU worst cases.** Animate geometry/transforms to defeat mask reuse; report encoding time, upload bytes, cache misses, atlas rebuilds and memory peaks.
5. **Implement explicit colour semantics.** Tag sources/destinations, define working-space interpolation and blending, and validate wide-gamut/video conversions.
6. **Strengthen text rendering.** Compare actual Latin/CJK fonts at small sizes and fractional positions; document hinting policy and colour-font format coverage.
7. **Improve graph resource analysis.** Add overwrite-aware liveness, reusable planning storage and safe within-frame transient reuse.
8. **Publish a reproducible determinism matrix.** Include x86-64/ARM64, GCC/LLVM, debug/release, serial/parallel and browser CPU results, plus GPU tolerance distributions.
9. **Validate the advertised platform range.** Exercise native D3D12, mobile GPUs and multiple browser engines, including loss/recovery and unsupported-feature fallback.

### Detailed defects and limitations

- **Curve error bound can stop holding:** `modules/gfx/raster/src/rasterizer.cpp:49` clamps subdivision to 256 segments. At sufficiently large transformed curvature, the requested tolerance cannot be maintained. This is a code-derived risk, not a reproduced bad pixel.
- **Gradient setup allocates:** `modules/gfx/raster/src/paint.cpp:56` constructs a stop vector and sorts it during shader setup. This conflicts with an unconditional allocation-free steady-rendering claim.
- **Gradient precision is restricted:** `paint.cpp:59` builds only 256 samples. Large smooth ramps and tightly spaced stops need independent banding/error tests.
- **Graph culling retains overwritten work:** `modules/gfx/render/src/graph.cpp:53` accumulates needed textures without killing an earlier value after a later write satisfies it. A fully overwritten producer can remain live.
- **Graph validation is narrow:** `graph.cpp:42` checks transient read-before-write; it does not itself establish full resource validity or command/declaration agreement. RHI validation remains necessary.
- **Graph planning allocates repeatedly:** `graph.cpp:34`, `:40`, `:53` and `:63` create temporary/result containers per plan.
- **GPU masks have a width ceiling:** `modules/gfx/render/vector/src/gpu.cpp:222` fixes atlas width at 4096; `:515` handles wider masks as an error path. Large targets/zoomed paths require tiling or another fallback.
- **GPU effect geometry is bounded:** `gpu.cpp:80` allows eight shapes; `:1082` stops accepting further shapes. Larger glass groups need explicit diagnostics or equivalent processing.
- **Hot glyph lookup remains virtual:** `modules/gfx/render/vector/src/resources.cppm:45` explicitly defines one virtual call per glyph, an exception to the repository’s stated hot-path rule that should be resolved or documented.
- **GPU text tests are insufficient for typography:** `modules/gfx/render/vector/tests/gpu_test.cpp:56` substitutes rectangles for glyphs. This validates mask transport, not hinting, CJK counters or real outline complexity.
- **Custom effects lose semantics on CPU:** `modules/gfx/render/effect/README.md:42` confirms skipped effects rather than equivalent software rendering.
- **Historical documentation disagrees:** vector README quotes wall-zoom p99 around 5.7 ms, while the inspected benchmark table reports 7.11 ms. Results need run identifiers and commit provenance.
- **Glass frame:** `styles-glass__glass.png`, Settings panel’s lower-left edge, shows a conspicuous dark blurred wedge. The backdrop may explain it, but the frame alone does not establish a compositing defect; add an isolated reference case.
- **Neon frame:** `styles-neon__neon.png`, Save/Cancel and sidebar button corners, shows small dark diagonal corner marks inside the glow. Check mask/stroke joins against intended output.
- **CRT frame:** `crt.png`, outside the curved screen, contains a hard black rectangular surround. It may be intentional CRT housing; its alpha/compositing policy needs an explicit reference expectation.
- **Missing visual evidence:** none of the supplied frames establishes tiny-text/CJK quality, image minification quality or managed-colour correctness. The clean basic effect plates cannot substitute for those tests.
