# 官网：一个页面，它能回放自己的设计过程，也能当场接着设计（G4，一页设计）

2026-11-19 起草，**第二版，草案，待 review**。任务 G4（[实施方案](2026-11-18-omui-meng-implementation-plan.md)），挡着 G5、G6、G8；提议的决策 D-252。背景：[顶层设计 §5](2026-11-18-omui-meng-top-level-design.md)（D-235、D-236、D-237）。第二版按 2026-11-19 的 review 改：**只做一个页面**；点播放就进入 Live Design 模式、回放官网自己的设计过程；可以切进 Live Design 模式接上 Agent 修改与设计；右上角一个 GitHub 链接；文档等都先不放。核心是简洁、优雅、有创意。第一版的四个路由（上手、制作过程、文档入口）取消。

## 1. 要定的

这一个页面上有什么；“播放”与“Live Design”两种模式各是什么、怎么互相进入；Agent 怎么接进一个网页；预算；对框架提出的要求。

## 2. 事实（2026-11-19，`1bcbadd0`）

- 现有的官网：`site/src` 约 12,300 行 C++，交付 3.99 MB（预算 4.0），首帧之前 1.94 MB，第一帧 1.24 s（本机）。
- **Web 上还不能运行应用的 TS**：G0 证明了可行（页面的引擎执行脚本，接口落到 wasm 的 C ABI），余下是 G1（页面里模块求值是异步的，要一个由帧循环结清的非阻塞运行）。
- **设计器现在只在开发模式里**（D-149）：`omui.designer` 给程序加上 `design.*` 操作与设计历史；发布构建不带它；历史存在应用旁边的 `.omui/design/`（文件），由 Agent 内核的 `History` 管（内容寻址的文本、提交、分支、标签）。它面向的是播放器运行的 TS 源码：一次编辑立刻运行。
- **页面上已有 Agent 的入口**：`window.omui`（`snapshot`、`find`、`act`、`invoke`、`wait`、`capture`、`describe`、`changes`、`request`），与桌面的 Agent 说同一种协议，经总线由 openas 判定。
- 设计历史的回放已能导出成影片（G3：8 步、10 秒、WebM）。缺口：影片的尺寸等于窗口；字幕是步骤的原话；没有 Agent 的指针与标识（D-160）；没有声音。

## 3. 按三级次序（D-185）

**① 原始性创新：这个页面就是它自己的设计历史的最后一帧；回放与接着设计是同一条时间线上的两个方向。**

- 页面只有一条时间线。**它的终点是线上的这个页面**；向回拖，页面在原地退回到设计过程里的某一步；按播放，页面从空白开始把自己重新做一遍——不是放一段视频，是真的那棵语义树一步步长出来，由 hanim 呈现每一步（D-149：呈现与状态分离）。
- **Live Design 是这条时间线越过终点的那一段**：从终点（或者暂停在的任何一步）接手，访问者或他的 Agent 做的每一处修改都是接在后面的新提交，落在访问者自己的一条分支上。“看回放”与“自己动手”因此不是两个功能，是同一个控件的两个方向。
- 世界是值，复制即分叉：访问者改的是他自己这一份（存在浏览器里），线上的页面不受影响；刷新可以回到线上的版本，也可以回到自己的分支。
- 别的框架的官网放的是录屏与文档。这里访问者第一分钟看到的是框架的三样招牌同时在工作：Live Design、动画、Agent——并且可以当场验证它不是摆拍：暂停在任何一步、看那一步的语义树、接手改。

**② 前沿加组合**

- 首屏的文字由静态 HTML 先出（D-236：语义树的投影），画布叠在上面启动，布局不跳。只有一个路由，所以投影只有一份。
- 脚本由页面自己的引擎运行（D-237），页面不带第二个引擎；Agent 发来的 TS 经同一条路径增量求值。
- 回放的数据与设计器按需加载：不点播放的访问者不为它们付字节。

**③ 业界做法（低线）**：真实的地址、标题、描述、规范地址、分享卡片、结构化数据；文字可选、可复制；键盘可达；减少动态效果的系统设置下回放改为逐步切换。

## 4. 页面

| 位置 | 内容 |
|---|---|
| 中央 | 标志（O 形轮廓内含 mui）与 Mui；一句话的定义 |
| 标志之下 | 一个播放键，与一条收起的时间线 |
| 右上角 | GitHub 的链接（唯一的外链；安装与文档在仓库的 README 里） |
| 其余 | 没有：没有导航、没有文档、没有作品墙、没有页脚的链接列表 |

两种模式，都由页面上看得见的控件进入，都可以随时退出回到线上的版本：

| | 播放 | Live Design |
|---|---|---|
| 怎么进 | 按播放键 | 时间线末端的“接着设计”，或回放暂停时的“从这里接手” |
| 页面变成什么 | 页面退到空白，按设计历史重做一遍；时间线展开，可暂停、拖动、逐步；每一步显示是谁做的（Agent 的指针与标识，D-160）与那一步的源码片段 | 时间线停在访问者的分支上；页面可以直接改（选中、拖动间距、改文字）；出现“接上你的 Agent”的入口与当前的 TS 源码 |
| 谁在操作 | 记录的回放，页面上标明是回放（D-63） | 访问者本人，与他接上的 Agent |
| 结束时 | 停在线上的页面，时间线末端出现“接着设计” | “回到线上的版本”，或把自己的分支导出成一个 omui 项目带走 |

语言随浏览器，中英文各有一份静态 HTML（同一个页面的两个地址，互相指向）；页面上不放语言切换。

## 5. Agent 怎么接进一个网页

| 方式 | 是什么 | 现状 | 这一版 |
|---|---|---|---|
| A 页面里的 Agent | 浏览器里的 Agent（浏览器自带的、扩展里的、驱动浏览器的）经 `window.omui` 操作；Live Design 模式下它多出 `design.*` 的操作 | `window.omui` 已有；`design.*` 没有接到页面上 | **做**：不需要访问者装任何东西 |
| B 机器上的 Agent | 访问者机器上的 Agent（命令行里的那种）经 `omui design connect <配对码>` 接进这个标签页：本机的 `omui` 起一个 MCP 端点，页面连到本机的它 | 没有；要求访问者装了 `omui`（这同时是“装上它”的入口） | **做，排在 A 之后**；页面从 https 连本机端口在各浏览器里的限制未核对，先做最小验证 |
| C 中转服务 | 页面与远处的 Agent 经一个服务中转 | 没有；官网是静态托管的 | 不做 |

没有 Agent 的访问者照样能用：直接改，就是 Live Design 里“人随时接手”的那一半。

**权限**（AGENTS §2 第 5 条）：进入 Live Design 是访问者自己的一次明确操作，它给这个会话开放 `design.*`；退出即收回。Agent 的每个请求仍由 openas 判定；改动只落在访问者的分支上；页面不向任何服务器发送访问者的改动。官网在 `omui.config.ts` 里声明这一开放范围。

## 6. 预算（官网的门）

| 项 | 上限 | 依据 |
|---|---|---|
| 首帧之前的字节 | ≤ 1.2 MB（D-247 的低线 1.1 MB 作目标） | 顶层设计 §4.2；不含回放数据与设计器 |
| 播放所需的追加字节 | ≤ 0.6 MB | 设计历史的文本与每一步的记录；按需 |
| Live Design 所需的追加字节 | 先量再定 | 设计器与完整的组件目录；按需 |
| 首屏文字可见 | ≤ 1.0 s | 静态 HTML |
| 程序的第一帧 | ≤ 1.5 s（20 Mbit/s、40 ms 的连接） | 现有 1.24 s 本机 |
| 帧时间 | 真实浏览器里 p99 ≤ 16.7 ms，回放与编辑时同样；长于 33 ms 的帧为零 | D-187 |
| 一次编辑到画面 | ≤ 1 帧（组件级增量求值，D-149） | 在页面的引擎上量 |
| 不执行脚本抓取 | 文字与语义树的文字一致 | D-236 |
| 界面的 C++ | 只有性能敏感的部件；页面是 TS | D-235 |

## 7. 对框架的要求（回主线补）

| 要求 | 现状 | 任务 |
|---|---|---|
| Web 上运行应用的 TS，并能增量求值 | G0 可行 | **G1** |
| **设计器是一项可以随发布带上的能力** | 现在只在开发模式里，发布构建一律不带（D-149） | **G8**（新）：设计器成为组合框架里的一项能力（`design`），不在任何世界里，应用在 `omui.config.ts` 里开放时才带；D-149 的“发布时去掉”保持为默认 |
| **设计历史在 Web 宿主上** | 历史存文件 | **G8**：`History` 的存储在页面里换成浏览器的存储；随页面发布的那段历史是只读的底，访问者的分支叠在上面 |
| **回放在应用里原地进行** | 桌面的设计器能回放并拍成影片 | **G8**：时间线的页面部件（组件，官网是第一个使用者）；Agent 的指针与标识进回放（D-160） |
| `design.*` 经 `window.omui` 可达；Live Design 模式的开关与授权 | 没有 | **G8** |
| 机器上的 Agent 接进标签页（方式 B） | 没有 | **G9**（新），依赖 E1（要有装得上的 `omui`） |
| 一个路由的静态 HTML 与元数据 | 运行时有语义 DOM 的镜像；构建时的投影没有 | **G2**（范围缩小到单页与两种语言） |
| 把自己的分支导出成项目 | 桌面有 `omui design sync` | G8 的最后一步；做不完就标预览 |

## 8. 设计过程的章节（回放的内容，也是 G6 的输入）

回放约 60–90 秒；每一章是设计历史里的一段，不是另拍的。

| 章 | 历史里的哪一段 | 要让人看见的 |
|---|---|---|
| 1 空白 | `omui new` 之后的第一帧 | 起点是一个真实的模板 |
| 2 Agent 起稿 | 标志、一句话、播放键 | TS 一行行出现，界面同步长出 |
| 3 形象 | 标志变形成 Mui | 矢量与 hanim 的变形 |
| 4 人接手 | 人拖动一个间距、改一句话 | 人随时接手；源码跟着变 |
| 5 核对 | Agent 查询因果记录确认人的改动，补一条测试 | Agent 不靠转述 |
| 6 回退与分支 | 试一个版式、退回 | 历史可以分支与回退 |
| 7 到这里 | 回放停在线上的页面，时间线末端亮起“接着设计” | 你看到的就是它做出来的；下一步轮到你 |

## 10. 风险与降级

| 风险 | 应对 |
|---|---|
| G1 做不完，页面上不能增量求值 TS | 回放用每一步预先求值好的快照（构建时由内嵌引擎求值，D-139），不需要页面运行 TS；Live Design 一项按五项写明后标预览，页面上先只有回放 |
| 设计器与完整目录太大 | 只在进入 Live Design 时加载；仍然过大就先只开放页面用到的那几种组件，写明 |
| 页面从 https 连本机端口被浏览器拦住（方式 B） | 先做最小验证；不成就只留方式 A，并在页面上给出“在桌面上打开这个设计”的命令 |
| 访问者把页面改坏 | 改的是他自己的分支；“回到线上的版本”始终可用；历史可以回退 |
| 做不完 | 降级的次序：先去掉导出，再去掉方式 B，再把 Live Design 标预览；回放与静态内容不降 |
