# Cellular RHI execution, v0.2

| Boundary | Contract |
|---|---|
| Preparation | Requires a prepared CPU plan of encoding 1, 2 or 3 (at most 32 channels) and compute capability. Copies the plan, walks its words once for where its stages are, creates the pipelines (the cells' pass; the blocks' pass where cells move) and the rule buffer, and submits one rule upload. `ready()` names that submission; later work on the same queue observes it in order. Unsupported formats/resources return RHI errors. |
| Ownership | Device outlives kernel and field uses. Kernel owns only pipeline/rule buffer; host owns state buffers, queues, state revision, checkpoints and lifetime. A borrowed Field must truthfully name its device owner; raw handle numbers do not identify a device globally. |
| Record | Validate shape, channels, boundary (a bath: one value a channel), live resources, size and usages before appending. A step is one pass a cell, and where cells move a second pass a 2 × 2 block of the tick's cut; the tick is the caller's, as `Execution::tick` is the CPU step's. Any validation error leaves the existing command list/payload unchanged. The caller must append at a legal pass boundary. RHI validates the whole list on submit. |
| Execution | Input/output are separate fields. The cells' pass: one invocation writes one cell from immutable old data — the rules (counts, sums, least, greatest; writes with terms), the reactions on the table, the transfers (both ends compute a flow from the same two values), the resets. The blocks' pass: one invocation a block reads the old data to decide and permutes the carried channels of its four cells in the output, which no other invocation touches. No race or order-dependent write. Host records ping-pong fields and handles publication. The arithmetic is the CPU reference's (32-bit unsigned, saturating, the exchange's coin `mix32` of a key the host folds from seed and tick), so the state is the CPU step's bit for bit: the CTS compares every value of every stage, tick after tick. |
| Failures | Record atomicity is not GPU transactionality. Device creation, allocation, dispatch limits, asynchronous backend errors and loss can still fail. Host does not publish an unconfirmed result; restore/rebuild and replay from its authoritative checkpoint. No implicit cross-device copying or recovery. |
| Scope | Dense full-field dispatch only: sparse execution (`Execution::activity`) is the CPU's scheduling and gives the same bits, so the device's dense step equals it too. No changed-tile mask or statistics from the device yet. CPU tile size, GPU workgroup size and render tile size are distinct. No physical halo transfer, generic compute scheduler, frame-graph auto-registration, GPU timestamps, field renderer or Noita performance guarantee. |

The optional adapter depends on CPU rules, RHI, trace and shader build rules. Neither CPU simulation nor RHI depends on this adapter at runtime. Backend test-only dependencies exercise the domain contract; selecting a plain RHI backend in an application does not pull in this test suite.
