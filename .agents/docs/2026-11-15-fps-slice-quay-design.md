# FPS 纵切：Quay（M6.4 收尾）设计

日期：2026-11-15。所属：[底层架构综合方案](2026-11-12-foundation-omui-xengine-emergent-world-design.md) M6.4 的验收作品（§12 表中“与参照物同等内容的 FPS 纵切”）。状态：设计，逐检查点落地。

## 1. 是什么

**Quay** 是一款原创的第一人称射击小品：雨夜的港口，守夜人要在潮水退去前点亮防波堤尽头的信号灯；集装箱之间巡逻着锈蚀的看守机（warden），它们靠**听**和**看**找人。场景沿用 M6.3 的里程碑画面（雨夜港口：湿地面、多光源阴影、雾、泛光），玩法、角色、关卡、美术与声音全部是本项目自己的。

参照物只用来对照**内容规模**（§1 表：浏览器 FPS，PBR、阴影、雾、实例化、蒙皮、雨与湿地面、贴花、泛光与色调映射、程序化声音），不复刻它的名字、关卡、美术、声音或外观。

验收（方案 §12）：可玩、可回放；Agent 玩家在人类档通关；适配器过契约 CTS（或如实列出不支持项）；记录制作成本，与参照物公开的数字并列。

## 2. 三级次序（D-185）

| 级 | 试了什么 | 结论 |
|---|---|---|
| ① 原始性创新 | **一条感知通路**：看守机、Agent 玩家和人听到、看到的是同一份数据——`xengine.audio.space` 的 `heard()`（到达双耳的实测电平、方位、穿过几面墙）与射线可见性。看守机不读游戏状态里“玩家在哪”，只读它听到和看到的；Agent 玩家在人类档也只拿这些。**世界是值**：每一帧可分叉，Agent 在分叉上试打再决定。**每次命中有因果**：一发子弹从扳机到看守机倒下的链条可查询 | 采用：这是本体系独有的（一棵语义树多种渲染、世界是值、因果记录、Agent 在架构底层），同类引擎的 FPS 模板里 AI 直接读玩家位置 |
| ② 前沿组合 | 物质规律进玩法：照明弹是带物质的粒子（`xengine.particles`），点燃信号灯的木柴靠物质规律；看守机的金属被击中溅出铁火花并按规律冷却；空间声音的多普勒与双耳时差来自同一条传播规则 | 采用，按检查点逐步接入 |
| ③ 业界顶尖做法 | 标准 FPS 循环：角色控制器（Jolt CharacterVirtual）、命中扫描、寻路人群（Detour）、蒙皮动画（ACL 压缩的姿态通道）、粒子、泛光与色调映射 | 作为低线，全部经已落地的适配器 |

## 3. 架构（只消费公开能力，D-63）

```
showcase/quay/
  sim       世界与规则：港口的静态几何与可推动的货箱（xengine.dynamics.rigid3）、守夜人（角色控制器）、
            看守机（xengine.nav 的人群 + 小状态机）、武器（命中扫描）、照明弹（xengine.particles）、
            潮水计时、胜负；状态是值（mlibs.simulation::Branching 包着 Jolt 与 Detour 的世界）
  headless  xengine.runtime 的 Playable；Agent 玩家：人类档只给 heard() 与视野内可见的东西
  picture   xrender.mesh（港口、雨、湿地面、雾、泛光）+ hanim.skeleton 的蒙皮看守机 + xrender.particle
  sound     xengine.audio.space：枪声、脚步、撞击、看守机的伺服声，从世界的事件生成
  play      SDL3 窗口、指针锁定（omui 视口节点）
```

依赖只向下：作品 → xengine/game → omui → 内核。sim 不依赖渲染与声音；picture、sound 只读状态。

## 4. 检查点

| # | 内容 | 验收 |
|---|---|---|
| F1 | sim：港口与货箱、守夜人的移动与视角、命中扫描、看守机巡逻→听到→追→开火、生命、潮水计时、信号灯；`Branching` 让 Jolt 与 Detour 的世界成为值 | 同一输入同一哈希；拷贝即分叉；脚本玩家通关；看守机只凭 `heard()` 与视线找到玩家（关掉声音它就找不到） |
| F2 | headless：Playable、Agent 玩家（人类档：视野与听觉；完整档：加哈希） | Agent 在人类档通关；分叉试打；关卡里预埋的问题被找出并说明原因。**已完成**：27.4 s 通关（生命 88，16 发，分叉试走 336 次）；防波堤被堵的关卡在 10.5 m 外停下并说明“路被堵死” |
| F3 | picture：港口、蒙皮看守机、枪口火花与雨、贴花（弹孔）、泛光 | 无头出图；CPU 参考与设备一致（lavapipe、RTX 4080）；帧预算按 D-187 实测。**第一部分已完成**：CPU 参考出图（港口、骨骼蒙皮的看守机、枪与枪口火光、9 m 桅杆上的信号灯、雾、泛光）；画面像素的归属与人类档视野逐帧一致（59／59）。设备并排：lavapipe 与 RTX 4080 上与 CPU 参考相差超过 6 级的像素 0.02%／0.22%／0.01%；帧预算：RTX 4080、1920×1080、dev 构建，模拟一步 + 画面准备 + 设备一帧 p99 4.41 ms（D-187 低线 8.3 ms）。雨与弹孔：雨是 900 道随风斜落的雨线和 160 个落地水花，位置由步数决定（同一帧同样的像素），亮度按与灯和信号灯的距离取，有光的地方才看得见雨，CPU 参考与设备（`xrender.particle.gpu`）都画；守夜人的子弹打在不动的东西上留下弹孔（位置、朝向、帧，状态里保留最近 48 个，算进哈希），画成焦痕和中间的孔。集装箱表面：波纹钢板的法线图（梯形波纹，间距 0.28 m），按米铺在一个集装箱网格的每一面上，设备载入同一张图，与参考仍相差 0.02%／0.22%／0.01%。余下：弹孔边缘的柔化等设备上的半透明层接好再做 |
| F4 | sound：空间声音接到世界事件 | 枪声在右侧时右耳先到更响；穿墙变暗；离线渲染逐位一致。**已完成**：右侧 8 m 的枪声右耳早 24 个采样、响 4.2 dB；同距离隔着集装箱（两面）低 35.1 dB、明亮度 0.084（开阔处 0.673）；向导一局 30 s 的声音两次逐位一致 |
| F5 | play：窗口与指针锁定 | 人可以玩；回放文件逐位重现。**已完成**：`quay` 窗口（键鼠游玩，按下即锁定指针，Esc 放开），画面在宿主自己的设备上画并原样显示；无头下点击、向右移动手转 0.53 rad、W 两秒走 7.06 m、左键连发 4 发，HUD 跟随；逐步输入的录制无窗口回放哈希一致；SDL3 窗口在 RTX 4080 与 lavapipe 上节点处显示世界（1,459 种颜色，灯 255） |
| F6 | 并排对照与成本记录 | 与参照物逐项并排（落后／持平／领先，D-135）；时长、检查点数、人介入次数。**已完成（按公开数字）**：见 §6；同机并排待做 |

## 5. 暂缓与边界

- HRTF、混响按世界形状、绕射：Steam Audio 的封装暂缓（磁盘空间；重启条件：可用空间回到 30 GB 以上），声音先用 `xengine.audio.space` 自己的模型。
- 网络对战不在本切片内（`xengine.net` 另有其期）。

## 6. 并排对照与成本（F6，2026-11-15）

参照物 Saltline 的事实取自公开报道（作者自述，经 [TweakTown](https://www.tweaktown.com/news/114611/saltline-is-a-playable-fps-created-by-anthropics-fable-5-2-in-8-hours/index.html)、[Hugging Face 博客](https://huggingface.co/blog/softroyals/how-saltline-ai-game-was-built-1-4mb-html)、[CellCog](https://cellcog.ai/blog/fable-5-2-one-shot-game-cost/) 转述）；本表没有把两者放在同一台机器上跑，画面与帧时间的同机并排还没做（重启条件：在本机浏览器里无头跑 Saltline 的公开构建，按同一分辨率截帧、测帧时间）。

### 6.1 逐项

| 项 | Saltline | Quay | 判断 |
|---|---|---|---|
| 形态 | 一个 1.4 MB 的 HTML（内含 three.js），浏览器直接玩 | 桌面窗口（SDL3，画面在宿主自己的设备上画）；`picture` 可为 Web 构建，但还没有 Web 上可玩的版本 | 落后：触达面 |
| 内容规模 | 切断三个中继、无人机与机械犬两种敌人、龙门吊、乘船撤离 | 一个目标（点亮信号灯）、一种敌人（看守机）、集装箱与货箱、灯柱与泛光灯 | 落后：内容量 |
| 画面要素 | PBR、阴影、雾、实例化、蒙皮、雨与湿地面、贴花、泛光与色调映射 | 同一组要素都有：GGX 的 PBR、月光的阴影图与八盏灯的六面阴影、雾、实例、骨骼蒙皮（设备上弯曲）、900 道雨线与 160 个水花、湿码头、弹孔、波纹钢板法线、泛光 | 持平（按清单）；弹孔边缘是硬的，落后一小项 |
| 画面的真值 | 只有浏览器里的像素 | CPU 参考与设备逐帧对照：与参考相差超过 6 级的像素 0.02%／0.22%／0.01%（RTX 4080 与 lavapipe 一致）；同一帧同样的比特 | 领先：可核验 |
| 帧时间 | 未公开 | RTX 4080、1920×1080、dev 构建：一步模拟 + 画面准备 + 设备一帧 p99 5.27 ms（D-187 低线 8.3 ms），每帧分配 10.3 次 | 无同机数据 |
| 声音 | 程序化声音（Web Audio） | 声音是数据（`quay.sound.omui.ts`），在世界里的位置上发声，经集装箱钢板到达双耳：右侧 8 m 的枪声右耳早 24 个采样、响 4.2 dB；隔着集装箱低 35.1 dB、变暗；离线渲染两次逐位一致，窗口里播放的就是离线渲染的采样 | 领先：空间与穿墙有实测；落后：没有 HRTF 与混响（Steam Audio 暂缓） |
| 敌人怎么找人 | 未公开 | 看守机只凭听到的（与玩家耳朵同一条传播规则 `reach`）和看到的（射线）；60 m 外的听不到 | 领先：感知与玩家同源 |
| 回放 | 无 | 窗口里每一步的输入录下，无窗口重放哈希一致 | 领先 |
| Agent | 无 | Agent 在人类档（0.1 s 反应、每秒 10 个动作，只看人看到的）通关：27.4 s，生命 88，分叉试走 336 次；预埋问题的关卡在 10.5 m 外停下并说明“路被堵死” | 领先 |
| 可复用 | 单文件作品 | 作品只用公开能力；做的过程中补回主线的：omui 的设备画面（`Services::device`、`add_device_picture`）、`xengine.ui` 的 `Shown::texture`、`xengine.audio.device` 的 `Feed`、`xrender.particle.gpu` 每帧零分配的排序、`omui::Desktop` 的销毁次序 | 领先：能力回到引擎 |

### 6.2 成本

| | Saltline（公开报道） | Quay（本次） |
|---|---|---|
| 时长 | 约 8 小时生成，另有作者约 2 小时修复 | 约 2 小时（2026-11-15 04:41 首次进入设计到 06:44 最后一个检查点，F0–F5 与 F3 的雨、弹孔、波纹钢板） |
| 人介入 | 一条提示词；可玩版本含作者约 2 小时修复 | 0 次（期间只有两次上下文续接和一次目标核对，都是自动的） |
| 检查点 | — | 13 个提交 |
| Token | 约 4.45 亿输入、270 万输出，约 550 美元 | 新输入约 74 万（缓存写入 741,919 + 未缓存 972），缓存读取 1.20 亿，输出 34 万；476 次回答、504 次工具调用 |
| 代码 | 1.4 MB HTML（含 three.js） | `showcase/quay` 约 3,100 行（C++ 与 TS 数据） |
| 不计在内 | three.js | M6.0–M6.3 已有的引擎（物理、寻路、蒙皮、渲染、声音），Quay 只消费它们 |

结论：画面要素按清单持平，可核验性、确定性、回放、Agent 与感知同源领先，内容量与浏览器触达落后。下一步按落后项排：Web 上可玩（`picture` 已能为 Web 构建；缺 Web 宿主的设备画面与声音的 `Feed`）、第二种敌人与多目标、弹孔的柔边（设备上的半透明层接入 `OnDevice`）、同机并排。
