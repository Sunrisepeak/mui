# Hanim：多表示对象、分级控制与可组合动画策略

2026-11-05，实施基线 `033cf2e`。本方案补充总体架构的 S2，按维护者最新要求修正 UI 接入边界。**内容／布局／业务状态的 owner 不等于动画控制的分界。** 文字、组件、图像和 3D 模型都应能作为整体、部分或几何参与 Hanim 动画；不固定划分“这部分由 Hanim 动、另一部分由 UI 动”。以下区分目标契约与已实现证据。

## 1. 同一对象的多种表示

HObject 是稳定对象身份、部件结构、类型化属性和可用表示的组合。可视源按需提供以下表示；不要求普通位移动画先生成网格，也不把当前闭合 2D 轮廓当作完整对象模型。

| 等级 | 可控制的内容 | 典型使用 | 成本与契约 |
|---|---|---|---|
| 属性 | transform、颜色、透明度、材质参数、相机属性等 | 常见组件反馈、移动、镜头 | 轻量参数计划；不触发几何转换 |
| 语义部件 | 对象组、子组件、文字段／字形、模型部件、选定区域 | 同一组件内的不同动画策略 | 稳定身份和层级；选择集在 prepare 冻结，动态更新走显式重编译 |
| 几何 | 2D 轮廓／曲线控制点、3D 顶点／索引／网格、骨骼绑定 | morph、局部形变、路径扰动、蒙皮 | 拓扑、空间、匹配与属性迁移；声明细分精度、元素数量和预算 |
| 采样／状态 | 像素／纹理样本、粒子、体素、材质或状态场 | 像素解体、局部效果、反应与模拟 | 分辨率／步长、确定性等级、资源驻留与重建；状态反应由对应模拟模块提供 |

同一对象可同时采用不同等级：卡片整体做轻量位移，标题按字形形变，徽标固定朝向，某个装饰区域做粒子效果。精度、作用范围、时间安排、效果及性能等级是不同维度，不能捆成固定全局档位。

### 1.1 顶点化是按需转换能力

各引擎以 representation adapter 请求并租用相应数据，转换属于共享几何／可视基础设施，**不是 Hanim 独占的顶点化实现**：矢量源提供曲线或细分网格；文字提供已有排版／字形轮廓；模型提供实际 mesh／rig；位图可选择平面纹理网格或像素采样表示；程序化内容声明可生成的表示与能力。

转换必须携带：源对象／部件和版本、坐标空间／相机、元素稳定身份或映射、拓扑、精度／误差、材质／UV／法线及需要的蒙皮属性、资源租约与失效规则。对应信息缺失时返回能力诊断，或在明确允许的策略中选择近似表示。位图平面网格不等于恢复原始 3D 模型；2D 到 3D 的 lift／投影需要显式空间与深度策略。

匹配与采样控制分别表达：来源映射可为一对多、多对一或分组；顶点数／拓扑不一致时选择有契约的重采样、细分、场表示或拒绝。禁止把“找不到对应顶点”静默改成成功但跳变的动画。几何变化时，UV、颜色、权重和语义归属的迁移规则与位置一样需要记录。

GPU 是同一计划的执行后端：编译后按批运行，几何／材质／模拟数据可驻留 GPU，跨阶段读写、同步、临时资源、上传／读回和取消由资源图描述。Agent 按需读取选择集、诊断、统计和指定区域／时刻像素；不让 Agent RPC 进入顶点／像素热循环。不能因选了顶点级控制就默认逐帧回读到 CPU。

### 1.2 共享基础设施与领域控制

“顶点化是渲染基础”应落为**共享表示与几何处理能力**。本仓库 renderer 当前已有 Path、DrawGlyphs、DrawImage 等输入，不能要求每个高层对象都先在 CPU 上展开成三角网格。保留源表示，按渲染／动画／模拟任务生成适当表示；渲染器所需的设备顶点布局是最终后端适配，不替代通用几何契约。

| owner | 唯一职责 | 消费者 |
|---|---|---|
| 共享几何／可视数据基础 | 曲线／mesh／采样数据、元素身份、拓扑、细分／离散化、来源和属性映射、包围与空间查询 | renderer、Hanim、模拟、UI／工具 |
| renderer 与后端 | 选择可绘制表示、设备格式／上传、可见性／LOD、材质与实际像素；设备派生缓存 | 各引擎与应用，不负责业务动画策略 |
| Hanim | 选择／匹配、随时间的插值与形变、部件／元素／属性控制、编排与动画 effect | UI、工具、游戏或独立动画用户 |
| 模拟与计算模块 | 物理／材料／反应／元胞状态和求解，提供声明的状态输出 | Hanim、renderer、游戏、工具 |
| UI／应用 | 内容和语义树、布局／输入／业务状态，将公共计划输出映射回呈现、命中和审查 | 人与 Agent 的同一应用能力 |

共享不等于所有引擎共用一个可随意改写的万能对象。源表示按版本租用，动画／模拟通过明确的写入集合、派生输出或增量发布结果；渲染与命中读取同一已发布版本。缓存按源版本、表示参数／误差、所需属性、数值等级和后端能力区分；多个 LOD／设备变体可以并存，但不重复实现同一种转换算法。

通用数学继续归 mlibs.math，通用几何先扩展现有 mlibs.geom 及相应包内目录；GPU 转换按需接计算／RHI 后端。当前 mlibs.geom 仅依赖标准库，hanim.core 的 std＋math 边界也保持。提取现存曲线／路径辅助前要审计真实复用与依赖，不能为“统一”建立几何→Hanim→几何的环。领域匹配策略仍归 Hanim，字体排版仍归 text，材质反应仍归模拟；不是将这些领域算法全部塞入几何库。

### 1.3 分级天然包含性能契约

能力等级、表达精度、执行后端、更新频率和呈现质量分别记录。高阶几何动画可以走 GPU，简单属性动画通常不需要几何转换；“低档位”不固定等于 CPU，“高档位”也不要求全部对象精细形变。

- 准备阶段解决选择、转换、匹配、资源预留、shader／kernel 准备；热路径批量求值和发布，避免临时分配、逐元素脚本／虚派发和无必要读回。
- 优先处理活动对象／区域／通道，复用不可变几何和已准备计划；几何／材质／状态的脏范围独立传播。对象只移动时不重新生成文字轮廓或 mesh。
- 每种配方声明所需能力、误差／精度、准备与热路径成本、峰值内存／带宽和允许的降级链。应用、用户、设备能力和实际预算共同决定可用计划。
- 可配置降级包括减少细分／采样、降低次要效果、复用缓存、降低自动更新频率、选择轻量配方或立即呈现终态；只在许可范围内选择。世界空间保持不能悄悄改成跟随，显式效果不能静默丢失并报告完整成功。
- 自动质量切换需有稳定阈值／滞回、连续姿态和可复现记录；复杂转换与 shader 编译不塞入切换当帧。固定步长模拟与呈现频率分开，不能跳过反应步骤来冒充降帧优化；降低呈现频率也不改变动画时长。
- 自动播放遵守减少动态效果与输入保护，显式 Agent／人的离线时间采样仍能审查真实结果。平台不支持时返回明确能力限制或已声明的近似等级。
- profiling 分开记录 prepare、求值、模拟、渲染、同步、读回及观测成本，报告所选表示／档位、切换理由和实际使用范围。以公共 benchmark／budget 和实际设备结果验收，不以 CPU／GPU 标签或单次截图宣称性能。

这些是框架与引擎的计划／执行契约；具体优化可以迭代或按 feature 选用。低性能 Web／移动／TUI 等目标仍复用上层语义，保留各自呈现能力边界，不要求它们假装拥有相同的像素／3D 输出。

### 1.4 性能策略在三个阶段生效

维护者补充：分级本身具有性能目的，具体优化应在上述统一框架下实现，不能为低性能平台复制一套不兼容的上层动画。

| 阶段 | 决定什么 | 不应付出的成本 |
|---|---|---|
| 构建／feature | 应用是否需要 player、几何、模拟、GPU、特定效果与设备后端 | 未选择的库、设备代码和资源不进入交付闭包；目录不自动变成独立包 |
| prepare／能力规划 | 所选对象、表示／精度、读写通道、许可近似、CPU／GPU 批次与资源预算 | 纯 transform 不生成文字轮廓／mesh；匹配、细分、kernel 准备不重复进入每帧 |
| 执行／预算调节 | 脏范围、可见区域、缓存／资源复用、呈现频率、预先许可的质量切换 | 不因固定时间采样重新编排；不为 Agent 观测常驻读回；不让浮层再次缓动已采样的锚点位置 |

质量与交互语义分开：减少曲线细分或效果分辨率可以是许可的近似；漏掉子对象、命中仍在旧位置、文字变得不可读、固定世界空间变成跟随、反应跳过步骤不是性能优化。设备不足时，计划说明所选档位、原因、预计／实测成本、误差和回退；严格请求不满足时应拒绝。时间预算调节需要滞回，资源准备和连续状态转移需要事先完成。

分级验证按实际能力拆开记账：同一任务先验证语义／交互和过程画面，再记录 prepare、求值、发布、paint、raster／GPU、同步／读回的耗时、分配、峰值资源及交付体积；单段零分配或软件 GPU 正确性不推广成整帧／低端硬件性能承诺。当前 UI 属性接入包含显式采样发布与可选原生 Playback 宿主；未运行、不可见、后台、交互和动态偏好抑制时释放持续帧请求。完整自动预算／降级计划仍是后续能力。

## 2. 对象选择与动画策略分别配置

选择对象、选择属性、选择表示、选择动画、选择 effect 与选择合成方式独立。UI adapter 将角色、部件、语义路径等选择器解析为稳定 ObjectRef／PartRef／元素集；Hanim 编译和执行这些目标，不认识“按钮必须怎样动”“文字不能形变”等硬编码场景规则。

| 策略 | 确切语义 |
|---|---|
| inherit | 使用所在组或上层配置的动画策略 |
| animate | 对显式选择的属性／元素应用指定配方，可覆盖继承 |
| hold-local | 保持所选局部属性；仍可能随祖先变换移动 |
| hold-world | 保持所选世界空间属性，作为显式约束求解；不是简单排除一个子节点 |
| snap | 业务目标更新时直接呈现新值，不做过渡 |
| simplify | 使用显式许可的低成本配方／表示，例如字形形变降为整段文字淡入淡出 |

“没有选中”不自动等于世界空间固定，也不自动冻结业务内容。保持位置、保持颜色、保留原文字、跳过顶点形变可以分别配置。父组变换、子对象自己的变换、文字内容变化与输入保护必须分别可见。

策略合并顺序目标为：显式动画绑定 → 实例覆盖 → 应用规则 → 风格包动效 → 组件默认配方 → 框架默认。权限、用户减少动态效果、平台能力与预算是最终约束，不能被普通配方偷偷扩大。对显式人工／Agent 时间采样与自动播放分别处理，避免关闭自动动态后连离线审查也不可用。

同一套 UI 配方可以声明：面板整体随组移动；标题位置随组、字形不变；数字执行简单插值；图标独立旋转；工具栏某个控件保持世界朝向；输入中的文本暂停相关动画、其他部分继续。文字可以整段动画、按字形／轮廓动画或只动画位置／颜色；排版和 IME 的业务职责仍归 UI／text，动画求值归共享 Hanim 能力。

## 3. 通道与编排 IR

写入身份至少需要：对象、部件／元素选择、属性通道、空间、时间区间、合成操作及来源版本。整对象冲突只适合作为旧实现的保守边界，不是最终架构。

- 不同部件／通道可并行，未选择的状态保留或按声明继承；共同使用一条对象／资源发布事务。
- 同一通道重叠必须显式规定 replace、add、multiply 或 blend，以及适用类型、权重和顺序。颜色、旋转、几何、模拟状态不能共用未经定义的万能加法。
- 父级效果作用域和子级动画选择互相独立。位移、匹配、顶点扰动、材质处理、合成后的图像效果保留自己的阶段；排除一个动画不自动排除组效果。
- hold-world、跟随、蒙皮、约束、模拟输入输出形成可检查的依赖图；检测循环、不可解约束和奇异变换。不能靠 UI 层随手乘一个逆矩阵来掩盖这些问题。
- 打断从实际合成结果继续；按通道说明 C0／C1、取消／恢复及保留资源语义。失败不部分发布，诊断包括选择、通道、scope 和资源阶段。

常见调用继续使用 `hengine.play(anim::move_to(object, ...))`。高级配置逐级暴露选择、策略和编排，最终降入同一计划；不再建立一个 UI 动画播放器、一个顶点播放器和一个 Agent 播放器。

## 4. 模块边界与代码树

- `modules/base/hanim/core/src/`：确定性时间、插值和通用数值算子，依赖边界不扩大到 UI／renderer。
- `modules/gfx/hanim/src/object/`：动画对象、部件、能力与共享表示租约的适配；通用几何数据与转换归共享基础，不另造 Hanim 私有 mesh／顶点化系统。
- `src/library/`：属性／部件／几何配方及编译后的数据计划；`src/program/`：选择、通道读写、组合／约束／资源 IR；`src/engine/`：调度、播放和原子发布。
- `src/effect/`：带阶段／读写契约的通用 effect；`src/render/`：消费同一计划与资源契约的 adapter。
- `modules/ui/`：提供实际 UI 内容、语义结构、布局／字形来源和交互接口，映射动画输出到同一呈现／命中几何；组件默认动效是可配置配方，不是第二套求值器。
- 通用 mesh／采样／数学／内存／计算能力先归现有相应 mlibs／renderer／模拟库；不在 Hanim 重造一份。mcpp 是构建系统，其 HPC 插件不被当作运行时计算引擎。

表示与后端通过 feature 按需进入闭包。此处列目录表示职责，不授权一目录一 `mcpp.toml`；只有真实独立产品、可复用库或必要隔离才提取包。

## 5. 实施顺序与证据

| 批次 | 实施 | 必须证明 |
|---|---|---|
| A1 | 同一属性动画的多个部件／属性目标，显式冲突检查 | 未选择部件保持；同部件不同属性可组合；重叠写入不隐式覆盖；反向采样与失败不变 |
| A2 | 属性／元素读写集与并行合成，独立时序／继承／保持策略 | 同对象并行通道、父子作用域、hold-local／hold-world 区别；当前合成输出重定向 |
| A3 | 共享几何／多表示契约与实际 2D／文字、3D mesh adapter | 稳定来源映射、局部顶点控制、转换预算和拓扑失败；renderer、Hanim 至少两个真实消费者，不依赖 UI 才能使用 |
| A4 | 配置式 UI／HObject 映射与官网真实消费者 | 同一个组合组件切换“整体／局部／文字／保持／简化”；子组件输入、裁剪、命中和 reduced/off；61 时刻及打断、逆放、resize 实图 |
| A5 | GPU 批次／资源图与跨后端消费 | 相同语义与精度约束、资源生命周期、真实设备过程及预算；CPU 参考和 GPU 能力限制分开报告 |

A2–A4 可以按同一真实场景交错推进，不能先堆 API 名字再长期停留在官网之外。A1 的同一时序多目标不等于 A2 的独立并行通道；2D 属性通过不等于 3D／像素几何通过。已有 40／20、完整默认动画、Agent／headless、UI 自适应及后续产品目标保持。

### 5.1 能力补齐与阶段（2026-11-07）

A3、A5 的具体内容与收敛方案 M3.5（§6.8）对应，按以下顺序实施：

| 顺序 | 内容 | 对应批次 | 契约要点 |
|---|---|---|---|
| 1 | glyph／path adapter | A3 | 字形轮廓经 `mlibs.geom` 路径成为 hanim 部件；记录来源字形、字体、排版位置与版本；只移动时不重新生成轮廓 |
| 2 | stroke 表示（trim／偏移／书写） | A3 | 描边是对象的一种表示：trim 起点、终点、偏移、宽度、颜色是类型化通道；按弧长裁剪归 xrender；闭合轮廓的偏移按周期取模 |
| 3 | 拓扑对齐 morph | A3 | 轮廓数、孔数不同时按声明的策略拆分、从点生长、孔出现与闭合；无合法对应时拒绝并诊断，不静默跳变 |
| 4 | 选择器＋形变器 | A3 | 软选择在 prepare 冻结（区域、锚点半径、衰减曲线）；位移／晶格／弯曲／扭曲的量是类型化通道，可由 `drive` 跟手；位移类形变允许过冲，几何插值类仍在两端内 |
| 5 | 匹配修饰与路径扰动核 | A3（IR §3） | 匹配规则按准备阶段编译；扰动以稳定载体身份、seed 和显式时间求值，包络保证端点 |
| 6 | 同通道混合层、约束与驱动 | A2 补完 | replace／add／multiply／blend 带类型、权重和顺序；依赖图检测环和奇异变换 |
| 7 | GPU 批量求值 | A5 | 与 CPU 参考同语义，误差和能力限制分开报告 |

位图网格／像素采样、3D mesh adapter 随 M6 的 mesh、粒子、场一起进行；rig 仍后置到 M6。

## 6. 当前事实与自审

`033cf2e` 已实现单部件属性目标及五个简配方，严格矢量形变与嵌套 scope 可运行；通用选择／通道混合和多表示尚未完成。维护者补充之后，未提交的“整节点独占 UI 变换、子控件固定保留原反馈”原型已撤回：它会把临时执行边界固化成公共设计，也不足以表达所需配置。没有将其构建尝试算作 UI 接入成功。

后续每个检查点需要原生／Web、公共源码／安装包、Agent 原生操作和真实过程画面的对应证据。可发现的计划应解释选中了谁、哪些通道、哪种表示、为何简化、实际写入者和性能归因。规范／架构目标不作为功能完成计数。

A1 后续实际交付：PropertySet 与多部件原子重定向、冲突检查和未选局部字段保持已实现；源码／安装包 128 项及两个 profile 的 61 帧过程证据见[实施台账 §25](2026-11-05-system-implementation-checkpoints-design.md#25-配置式局部控制的边界修正与多部件属性目标)。A2–A5 不因 A1 通过而记为完成。

A2 第一批实际交付：同一对象的位移／旋转／缩放／填充通道可用独立时间、曲线和位置路径编排，保留作者树、贡献节点和共同图像 scope，渲染只消费一个合成对象；不重复采样／绘制每个叶子的整份对象。`hengine.plan(playback)` 提供不可变计划供工具与 Agent 审查。静态几何复用、按通道查询当前分段和预热采样零额外分配已有本地证据；零时长混合编排的依赖判定仍有冷准备两两检查成本，不宣称全面性能优化完成。相同通道混合、hold-world、选择性重定向后继续旧通道、通用几何／3D 与配置式 UI 接入仍未完成，见[实施台账 §26](2026-11-05-system-implementation-checkpoints-design.md#26-独立属性通道保留编排与单一对象输出)。

A3 的共享 2D 基础已开始落地：`mlibs.geom` 成为路径命令／视图、fill rule、校验／来源索引及现有曲线离散化的唯一 owner；renderer／raster 使用同一类型，删除命令数组转换。公开 `hanim::import_path` 捕获实际曲线控制点及来源范围，UI 的原路径形变和独立离屏消费者均使用它。底层 core 的 std＋math 边界保持；geom 仍仅依赖 std，不新增微型包。现有离散化的 256 段上限没有被称为精度保证；每个生成顶点的来源／误差证书、3D 与文字布局／材质的完整 adapter 继续开放。详见[实施台账 §27](2026-11-05-system-implementation-checkpoints-design.md#27-共享路径基础与公开几何捕获)。

A4 首批交付可选 `omui.hanim`：明确的根／子节点选择及位移／旋转／缩放／剪切通道，共用公共 Engine 编排和采样；文字、真实控件与整组可分别组合，呈现、命中、IME 和浮层目标跟随对应结果。它是局部 offset 表示，保留内部状态反馈，不是完整 UI 几何捕获或通用保持／简化策略。首次绑定旧活动 morph、跨 portal 选取及图像效果／几何输出均有明确限制。后续原生 Playback 在输入／布局后、bounds／paint 前采样同一时钟，复用 TimeMap 的循环／反向元数据；门控保留可见姿态、恢复不追赶隐藏时间，显式 seek 仍能审查过程。官网新增整体／部件／标题三种选择的真实便笺，详情渐进披露；它不提供 hold-world 或整组图像 effect 映射。详见[实施台账 §28–§29](2026-11-05-system-implementation-checkpoints-design.md#29-原生播放宿主与官网组件编排)。
