# openmui.render.vector

2D vector rendering (module `openmui.render.vector`, D-57), a rendering feature of [openmui.render](..) (D-81) — its GPU passes are recorded through the render graph: the display list of contract ⑤ (paths, paints, gradients, strokes, clips, transforms, layers with blend modes and effect parameters, glyph runs, images, external textures, node markers), resources by reference (an image store; glyphs from the text engine through `GlyphSource`), and backends. The CPU backend renders through openmui.raster, byte-for-byte the same on every platform, records pixel provenance, and reports what a CPU cannot draw (effects, external textures — spec R-3). Knows nothing of nodes or views.

**Incremental frames** (`:damage`, D-62). A `DamageTracker` compares a display list with the previous one, segment by segment (the node markers; a segment's hash covers its own commands and its children's order, its bounds are in device space) and returns the bands of rows that can differ. The CPU backend draws only those rows over the previous frame (`CpuOptions::rows`), skipping commands that cannot reach them, and the result is the full render byte-for-byte — `tests/damage_test.cpp` holds it to that for every kind of change (colours, moves with shadows, rotations under rounded clips, clips, layer opacity, z-order, nodes appearing and going, strokes), and the headless host's tests for real frames. On the 1000-node dashboard of M1 ⑤ at 1080p a one-label frame goes from 28 ms to under 2 ms (`tests/bench`). With a `Parallel` (`CpuOptions::parallel`, the host's task pool) the bands are cut into tasks drawn at the same time — each by its own pooled canvas, glyph masks resolved first on the calling thread — and the bytes are still the serial render's: every band is exact. `CpuOptions::measure` fills `RenderReport::kinds`: count and time per kind of command (`command_kind_name`), which is where a frame's raster time goes (the `ui/raster/full-1080p` benchmark reports it).


**Lit pictures** (`Material`). A textured mesh — a painted picture cut into parts and skinned on bones — or any image-painted fill can be shaded by the light of the scene it is in: `draw_mesh(image, positions, uvs, indices, sampling, opacity, seam, &material)` (the old signature is the same call without a material, and draws byte for byte as before). A material is a tangent-space normal map aligned with the picture (`openmui.image`'s `normal_map`: a rounded bevel of the silhouette so parts read as volumes, plus painted folds from the luminance; R = x right, G = y down, B = out of the picture) and a stylised light:

```cpp
render::Material skin{.normal = normals, .light = {-1, -1}, .light_z = 0.8f,      // toward the light, screen space, y down
                      .shadow = Color::hex(0x5b4a8a), .shadow_strength = 0.55f,  // multiplied in where unlit
                      .bands = 3, .softness = 0.06f,                             // cel bands, their edges' width in lambert
                      .rim = Color{1, 0.95f, 0.85f, 1}, .rim_strength = 0.9f, .rim_width = 0.45f};
dl.draw_mesh(arm, at, uv, tri, render::Sampling::linear, 1, 0.5f, &skin);
```

The normal map is sampled with the colour's uvs and the same filter; its xy is turned by the orthogonal part of whatever maps the picture to the device — each triangle's own affine and the list's transforms, rotation and mirror (a mirrored part flips the normal's x; a scale or shear is not applied to normals) — so a turned or flipped part is lit by the light, not by its picture. The light is a direction in device space, the same for every part of a figure: lambert n·l is cut into `bands` levels (0 or 1: smooth), each step a linear ramp `softness` wide; the colour is multiplied toward `shadow` by (1 − level) · `shadow_strength`; where n·z is below `rim_width` (an edge's grazing normals) and the normal faces the light in the screen's plane, `rim` (by its alpha and `rim_strength`, the edge as soft as a band's) is added. Premultiplied alpha is kept: the alpha never changes and no channel passes it. A material is copied into the list's arena once per mesh (its triangles share it) and hashed with the paint — a lit list hashes apart from the unlit one; a missing normal map draws unlit and is counted in `missing_images`. `Paint::Kind::image_mask` (and `draw_mesh_mask`) draws a picture's alpha in one colour — a black ink stroke as a rim of light, a silhouette — lit too with a material. The arithmetic (`raster::Shader::lit`, IEEE single precision without contraction) is the CPU reference's, pinned for GCC and LLVM; the GPU draws lit images with a second fragment entry of `ui.slang` (`ui_lit_fs`: the normal map in sampler 4, the material's constants as the CPU computes them — `raster::material_setup` — in a uniform buffer, each instance's rotation in `pgeo`), switching pipelines only where a run of lit draws begins or ends, and gives the CPU's bytes on lavapipe (`tests/gpu_test.cpp`, the `lit meshes` scene: 0 levels). A lit pixel costs about the price of a second bilinear sample, a square root and two divisions; unlit fills take the same path as before.

**GPU backend** (`:gpu`, D-33). `GpuRenderer::create(device)` builds its pipelines on an `omui.rhi` device (any backend that takes one of `gpu_shader_formats()`); `render(list, target, resources, options)` draws the list into an `rgba8_unorm` colour target and returns the same `RenderReport`. Slang shaders (`shaders/`, `effects/`), compiled at build time by `openmui.shader.rules` into every format the target's backends take, draw every primitive as an instanced quad, cut into batches only where a texture changes.

The GPU works in the CPU's bytes: coverage as raster makes it (rectangles in 1/256 pixel, the rasteriser's masks for paths, strokes, glyphs, box shadows and clips, placed in an atlas), colours premultiplied to 8 bits, gradients read from raster's own 256-entry tables at the same index, images sampled with the same integer weights, every product a rounded `mul255`; source-over is left to the blending unit, which on an exact one gives the CPU's bytes — `tests/gpu_test.cpp` measures 0 levels of difference on lavapipe for rectangles, gradients, strokes, shadows, clips, layers, images, glyphs and every effect, and holds each scene to a stated tolerance. Rounded rectangles are the exception, and the GPU is the exact one there: it covers a pixel by the true circle's area, where the CPU's chords (1/32 pixel) are within 8 levels. A rounded rectangle's stroke is drawn on both as the area between two rounded rectangles (`stroke_ring`: the outer edge, each radius grown by half the width, and the inner, each shrunk by as much): the CPU fills the two even-odd, the GPU subtracts their exact areas (`KIND_RRING`) — neither strokes a curve, whose inner offset over-covers. A layer under a blend mode is composited by `shaders/blend.slang` over a copy of the target beneath it, with the CPU's arithmetic. On Metal the MSL asks for IEEE arithmetic without contraction (`openmui.shader`), as SPIR-V has it.

**From frame to frame** the GPU keeps what it made. A coverage mask (a glyph, a path, a stroke, a shadow) is kept in the atlas under a 64-bit key of everything that made it — the geometry, the transform, the clip it was rasterised within; a glyph by its font, size and subpixel offset — so a frame rasterises and uploads only the masks the last frames did not have: an interface that did not move sends its instances and nothing else (`RenderReport::masks_made`, `masks_reused`). The atlas grows to 2048 rows freely; past that it is first emptied of what earlier frames left and the frame encoded again (`atlas_emptied`), and grows on only for what one frame draws. Rounded and path clips' masks are kept by key too; an ImageStore image is uploaded once, in one command, its pixels borrowed rather than copied (the store holds them through `render()`), and a texture the store let go is reused for the next image of its size. In the first benchmark report (`docs/en/benchmarks/`) S2's interfaces take 0.2–0.6 ms a frame and S1's zoom sweep a p99 of 5.7 ms on an RTX 4080.

**Effects on the GPU** (D-68). An effect layer is drawn offscreen in a surface of its own — the layer plus the effect's reach, as the CPU prepares it — the effect runs on it, and the result is composited where the layer is. Each built-in has a GPU path held to its CPU reference: per-pixel effects are fragment shaders written against the effect template (`effects/lib/openmui_effect.slang`: the source, an auxiliary row texture, the parameters and values the CPU derives — trigonometry, sizes — so the arithmetic is the reference's; the 64-bit hash in pairs of 32-bit words), blur is box passes in integers, pixelate a compute pass with one invocation a block, particles one instance a cell. `EffectInfo::gpu` says how; an effect without a GPU path is drawn without it and counted in `effects_skipped`, as the CPU counts one without a CPU path. A program's own effects — a `*.effect.omui.toml` and a Slang shader against the same template, no C++ — are [openmui.render.effect](effect)'s, loaded and reloaded while the program runs; the template's text is carried in the program (`:effect_template`, generated by `omui-gen embed`). **External textures** (`OMUI_EXT_external_texture`): `GpuOptions::external` maps an `external_texture()` id to a texture the program made on the same device — a video frame it decoded, an engine's view, premultiplied — drawn over its rectangle as `draw_image` would draw the same pixels (bilinear, within a level of the CPU's image of them); an id it does not know is skipped and counted, as the CPU renderer counts every one.

**Backdrop effects and liquid glass** (`OMUI_EXT_backdrop_effect`, D-64). An effect that declares `EffectInfo::backdrop` reads what lies under its layer: the renderer captures it where the layer begins — the CPU renderer copies the target when its draw reaches the layer, the GPU renderer copies the parent target into the effect's aux texture — frosted by `backdrop_blur` with the same integer box blur on both (`box_blur`). A layer carries shapes (`EffectShape`, rounded rectangles in its space; a glass group's members), which the effect reads as signed distances (`shape_distance`, `smooth_min`; the template's `shapes_distance`). A frame with a backdrop effect is drawn by the CPU in one band, and a band that reaches such an effect takes all of its rows; the damage tracker marks a backdrop effect damaged whenever damage reaches it. The built-in `liquid_glass` is one: the backdrop bent at the bevel from the distance's gradient, split by colour, frosted, tinted darker over bright backdrops and lighter over dark ones, lit at the rim facing the light and along a fine inner edge, with the layer's content over it — its CPU reference and GPU path give the same bytes on lavapipe (`tests/gpu_test.cpp`), and its CPU pixels are pinned for every platform (`tests/effects_test.cpp`).

**The style packs' effects** (S2): `neon` (a glow outside the layer's shapes, a bright tube at their edge, a sweeping band of light), `crt` (barrel curvature, scanlines — one factor a row, the aux texture on the GPU —, an aperture grille, a vignette; black beyond the glass), `paper` (a warm tone, a seeded grain, darker edges), `wobble` (displaced by a smooth value noise and inked where the alpha changes: a hand-drawn line; a new seed, a new drawing) and `metaball` (the layer's shapes merged by `smooth_min`, the bridges filled). Each has a CPU reference and a GPU path in the same operations: on lavapipe they give the same bytes within a level (metaball within the rounded rectangles' allowance, its content being two), and their CPU pixels are pinned.

**`tone`**: the layer in one colour — each pixel's brightness (Rec. 709 luma) kept, its hue the tint's, mixed by `amount` (a fighting game's world gone grey while time stands still, a memory, a page not in use, whatever is drawn in it: shapes and pictures alike). Its CPU reference and GPU path give the same bytes on lavapipe, and its CPU pixels are pinned.
