# design operations

Design a running application live: its sources and API, edits run at once with their state kept, expectations checked, the person's turn kept as a test, edits written back to the TypeScript sources.

Generated by `omui-gen ops` from the catalog; the effect is openas's.

| Operation | Effect | Parameters | Result | Cost | Undo | Cancel |
|---|---|---|---|---|---|---|
| `design.begin` — Begins a design session with what it is for: the intent shown by your presence, the state it begins from kept as a commit, and every step after (each edit, set, insert, remove is a commit of its own) saying it | reversible | `intent`: string | json | bounded | none: it only names what follows; design.history.revert takes the steps back | no |
| `design.sources` — The scripts the application is made of: each one's path, language and the text it runs now (edited, or its file's), and the modules they import | read | — | json | bounded | — | no |
| `design.api` — How the scripts are written here: each language's API over this application's components — every builder with its properties (types, choices), handlers and actions, and the functions of the module — read before writing an edit | read | — | json | bounded | — | no |
| `design.locate` — Between a node and its source, either way: given `node`, the line of the script that built it (its path as design.sources names it, line, column, the line's text); given `path` and `line`, the nodes built on that line | read | `node`: node (optional), `path`: string (optional), `line`: integer (optional) | json | bounded | — | no |
| `design.edit` — Runs new text as a script, at once, its state kept: the semantic changes it made and how long it took — or its problems, with their lines, and nothing changed. The edit stays until design.commit writes it to the file or design.discard drops it | reversible | `path`: string, `text`: string | json | bounded | design.edit with the text before, or design.discard | no |
| `design.set` — Sets properties of a node by editing the builder call that built it (design.locate): each value written where the property is, or added to its object — the rest of the source as it was — then run as design.edit runs an edit: the semantic changes, and the lines it changed | reversible | `node`: node, `props`: json | json | bounded | design.set with the values before, or design.discard | no |
| `design.insert` — Adds an element, written as the script's language writes it, among the children of a node's builder call (at an index, or last), laid out as its siblings are; run as design.edit runs an edit | reversible | `parent`: node, `code`: string, `index`: integer (optional) | json | bounded | design.remove the node it added, or design.discard | no |
| `design.remove` — Takes a node's builder call out of the list of children it is in (with its comma, and its line when it had one); run as design.edit runs an edit. A node built outside a list (a function's result, a condition) is refused: edit the code around it | reversible | `node`: node | json | bounded | design.insert its code again, or design.discard | no |
| `design.preview` — Shows what edits would make, without making them: the application again in an unseen stand-in running the new texts, its picture laid half seen over what the person sees, with the semantic changes it would bring; design.preview.accept makes it a step, design.preview.reject lets it go | reversible | `edits`: json (optional), `path`: string (optional), `text`: string (optional) | json | heavy | design.preview.reject | no |
| `design.preview.accept` — The preview shown made real: its texts run at once, as a step of the design (a commit) | reversible | — | json | bounded | design.history.revert to HEAD~1 | no |
| `design.preview.reject` — The preview shown let go: nothing changed | reversible | — | json | instant | design.preview again | no |
| `design.variants` — Several ways for a choice of taste (style, layout): each variant run in a stand-in, kept as a branch of the design's history (variant/<name>) with its picture, and laid out side by side on a board for the person to pick; nothing the person sees changes until one is picked | reversible | `brief`: string, `variants`: json | json | heavy | design.variants.close | no |
| `design.variants.pick` — The variant chosen from the board: its texts run at once as a step of the design, and the board goes | reversible | `name`: string | json | bounded | design.history.revert to HEAD~1 | no |
| `design.variants.close` — The board put away, nothing picked (the variants stay as branches) | reversible | — | json | instant | design.variants again, or design.history.switch to a variant's branch | no |
| `design.film` — The design's history as a film: a branch's commits from its first, each run in an unseen twin of the application as a design edit runs (its presentation) under a caption saying what the step was, drawn frame by frame — the frames (PNG) and a video description beside them, which `omui video render` (or `omui design film`) makes a WebM of | reversible | `branch`: string (optional), `out`: path (optional), `fps`: integer (optional), `seconds`: number (optional) | json | heavy | delete the directory it names | no |
| `design.timeline` — The design's history and its time in one picture, shown over the application (D-151): a lane for each branch, its commits by when they were made with their pictures; a commit pressed is seen, ◀ ▶ go through time, two compared. Answers the same as data; `at` sees a commit, `step` goes back or forward, `pictures` makes the latest commits' pictures in stand-ins | reversible | `show`: bool (optional), `at`: string (optional), `step`: integer (optional), `pictures`: bool (optional) | json | bounded | design.timeline at the commit seen before | no |
| `design.history` — The design's history (D-151): the branch designed on, every branch and tag at its commit, a branch's commits newest first (message, who, when, the semantic tree's hash), and whether what runs now has changes not committed | read | `branch`: string (optional), `limit`: integer (optional) | json | bounded | — | no |
| `design.history.commit` — Keeps the design as it runs now — every source's text — as a commit on the branch designed on, under .omui/design/ beside the application (not git's: omui design sync carries it there) | reversible | `message`: string | json | bounded | design.history.revert to the commit before | no |
| `design.history.branch` — A new branch at a commit (the one designed on when absent), to try another way without losing this one; the design stays on its branch until design.history.switch | reversible | `name`: string, `at`: string (optional) | json | instant | none: a branch is a name for a commit; it changes no design | no |
| `design.history.switch` — Designs on another branch — or shows any commit — its texts running at once, each changed source shown changing as a design edit; changes not committed are refused unless `force` drops them. A commit seen leaves the branch where it was (`detached`) | reversible | `to`: string, `force`: bool (optional) | json | bounded | design.history.switch back | no |
| `design.history.revert` — The design back as it was at a commit: its texts run at once, and kept as a new commit on the branch (nothing in the history is lost) | reversible | `to`: string | json | bounded | design.history.revert to the commit it made the step from | no |
| `design.history.diff` — What changed between two states of the design, source by source: the first line that differs, the lines before and after; from a commit (HEAD) to another, or to what runs now | read | `from`: string (optional), `to`: string (optional) | json | bounded | — | no |
| `design.history.merge` — Another branch's changes brought into this one, line by line from their common commit: each side's own changes taken, the same change once; if both changed the same lines nothing is merged and the sources are named. Merged, it runs at once and is a commit of both | reversible | `from`: string | json | bounded | design.history.revert to HEAD~1 | no |
| `design.history.tag` — A name for a commit (the last on the branch designed on when absent): a state to come back to or to show | reversible | `name`: string, `at`: string (optional) | json | instant | none: a tag is a name for a commit; it changes no design | no |
| `design.expect` — What the person expects, kept to check against: `say` in their words, `query` the nodes it means (id, role, name, state, value …), `absent` when they must not be there; with no query, lists what is expected | read | `say`: string (optional), `query`: json (optional), `absent`: bool (optional) | json | instant | — | no |
| `design.check` — Each expectation read against the interface as it is now: holds or not, the nodes found with their name, value and states, and for a node that did not do what was expected, what the last press on it came to (the recorder) | read | — | json | bounded | — | no |
| `design.handover` — Hands the floor to the person: they try the design; what they do from now, done, can be saved as a scenario (design.save_scenario) | read | — | json | instant | — | no |
| `design.save_scenario` — What the person did since design.handover — their actions that were done, as semantic steps (node, action, arguments) — and what is expected, written as tests/<name>.scenario.omui.json beside the application: a demonstration as a test | reversible | `name`: string | json | bounded | delete the file it names | no |
| `design.replay` — A saved scenario played again: each step done as it was, then what is expected checked — the demonstration as a test | reversible | `name`: string | json | bounded | the steps' own (ui.undo for reversible ones) | no |
| `design.discard` — Drops every edit not committed: each edited script runs its file's text again; the dropped texts are answered | reversible | — | json | bounded | design.edit with each text it answered | no |
| `design.commit` — Writes every edit to its script's file (TypeScript stays the one source); each file's text before is answered | reversible | — | json | bounded | design.edit with each text before, then design.commit | no |
