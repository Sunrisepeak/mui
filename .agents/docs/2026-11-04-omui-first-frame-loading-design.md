# omui：构建期首帧、真实加载与按页预览资产

2026-11-04。继续落实[官网总方案](2026-11-03-openmui-site-redesign-implementation-design.md) §11、R0／R2 与 W8。本轮是加载链路的实现检查点；字体的完整按页／按编辑需求交付、重程序拆分与 R3–R6 保持原范围。

## 1. 同一个界面产生像素与加载几何

原生官网增加构建入口：

```sh
mcpp run omui-site -p openmui.site -- --first-frame opening.png \
  --route home --lang en --width 1280 --height 800
# 实际主视觉的裁切；不是重画一份静态 mockup：
mcpp run omui-site -p openmui.site -- --first-frame visual.png \
  --root main/body/view/home/page/landing/scene/visual
```

- 使用生产 `site::app`、实际主题、verb 与视图，固定 CPU、T3、scale=1、单 raster band。默认仅运行 t=0 的第一帧，不调用 `settle()`；`--time` 可选择精确的参考时间。
- `--root` 必须是真实显式 ID。导出节点边界与所有祖先裁切／viewport 的交集；未知、隐藏、完全离屏或空区域报错，不制造占位几何。
- PNG 旁的 `*.frame.omui.json` 包含 route、语言、viewport、实际 crop、时间、motion 设置、节点 ID／role／全局 bounds／状态，以及区域与完整画面的像素 hash。无 bounds 节点另列；哈希使用 `openmui.hash`。
- `--reduced-motion` 从同一生产视图得到已组装的静态首帧。它不靠 CSS 隐藏仍在播放的界面。
- 导出参数严格检查，解析错误 exit 2、渲染／IO 错误 exit 1，JSON 结果不把失败写成成功。`mcpplibs.os` 与现有 Headless／image 公共 API 负责 IO。
- 按清单选择的 `:offline` 模块分区给出 constexpr 能力；Web 入口不调用构建期 PNG／HTML 导出，避免把这些 CLI 路径带入访客运行时。不使用平台宏。

## 2. 按页生成、按页请求

`tools/ci/site-frames.py` 读取 mcpp 的 launch envelope，以它选出的原生程序及环境渲染，不猜最新二进制路径。首批覆盖首页、组件、基础动画、创意 demos、风格、统一接口、Agent 原生七个开场。

每个开场有 en／zh、390×844／1280×800、full／reduced，共 56 份图与几何引用；另有 8 份完整首页参考，用于真正首个 CPU 呈现帧的逐像素比较。相同内容通过 SHA-256 文件名去重；公开 geometry 移除临时输出路径，保持可复现的内容地址。

HTML 只嵌入引用清单 `first-frames.assets.omui.json` 的数据，不嵌图片。bootstrap 只为当前 route／语言／宽度／motion 选择一个图与一份几何，隐藏页面没有 img src。切页或切换系统减少动态效果时换对应资产；选择键包含 route、语言、viewport、motion 与图／几何引用，不能因 PNG 去重而复用旧语言说明或旧语义几何；详情没有精确捕获时保留该详情的真实 HTML，不冒充展示另一个样张。

页面文字、导航和 CTA 保持可读可用。图片仅是明确标注的预览，内部控件不能点击或进入无障碍树；它不是在启动前伪装成可操作界面。首页使用主视觉裁切，其余产品页使用主舞台裁切，不在画面内重复嵌一套导航与标题。

两个参考尺寸之外采用保持宽高比、受限尺寸的展示，不宣称缩放后的图与任意 viewport 逐像素相同。完整像素比较只针对相同尺寸、语言、CPU、scale、motion 和固定初始状态。

## 3. 真进度，不猜百分比

通用 dist-toy 加载器公开 `window.omuiLoad` 及同步 `omui-load` 事件。纯数据快照含 phase、每项资产状态／尝试次数／loaded／total、startup 及总体统计、初始化和呈现状态、错误。`retry(id?)` 是独立的显式重试入口。

- 字节口径是 fetch 解压后的实际 body bytes。打包时记录原始文件长度作为已知 total；不混用 gzip Content-Length。未知 total 保持 null，不从状态文案或时间推算百分比。
- WebAssembly 仍用同一响应流式实例化；缺少流能力或 MIME 不适合时使用受控 buffer fallback。
- 首屏树只读 startup 比率，总体比率包含稍后字体，不能混当首屏百分比。节点矩形来自本次原生导出的真实树；最多展示 64 个可见节点，按读取进度展开细线。JS 仅处理加载事件，接管后解绑，不进入程序逐帧路径。
- wasm、字体及延后资源有明确失败。字体成功安装前保留 run dependency；失败不假装就绪、不移除 partial 标记、不提前写 ready。
- 网络／可重试状态有界自动尝试；显式 retry 只重试失败任务，不重复成功下载或再次初始化 main。不可恢复的 runtime／launcher 错误明确要求重新加载，静态正文仍保留。
- 字体计划在应用 bootstrap 设置页面语言之后制定，preRun 在启动字体请求前再次核对加载中的语言切换。浏览器偏好不能覆盖页面选择；重计划不遗留重复字体、pending 或 later 项。
- 4 秒延后资源 fallback 不是已呈现的证据，必须保留 native 首帧 hook；只有 native 报告真正呈现时同步发 presented。接管仍等待当前目标的语义镜像及像素，不人为延长加载演出。

### 初始排版与后加载字体

实图检查发现系统无合适 sans-serif 时，加载前的英文落到衬线字体，且标题断行与交互页不一致。首页静态正文现使用同源 Inter 初始子集，显式保留 ASCII、站点常用符号与标准 Latin 连字；完整 Inter 在首帧后补齐。中文沿用当前页面语言决定的初始／完整字体策略。两种语言的首页标题沿用交互页的明确两行构图；桌面导航保持 flex，900px 以下的静态导航先显示单行菜单。

完整字体到达后不能被已有子集抢先匹配，也不能使原有 FaceId 失效。文本引擎先查请求字体族内所有 face 的实际覆盖，再回退到其他字体族；Web 宿主把完整 face 插入同族块之后，保留初始 face 及引用。真实 Inter 子集／完整 face 与竞争 Noto 回退的原生回归覆盖同族、通用族、大小写、旧引用与度量稳定性。初始浏览器探针对普通单词零差，却在 `:-)`、`UI (CPU)`、`A-B`、`2x3` 的两种字重发现 477–2,124 个通道差异，证实仅保留 cmap／复合轮廓不够。生成器现将所有 GSUB lookup 的可达输出与复合轮廓交替求闭包，保留原 glyph ID；上下文条件保守忽略，引用的 lookup 仍全部扫描，允许多保留而不清空实际替代轮廓。single／multiple／alternate／ligature／reverse／extension 与 context 结构有边界验证，未知格式明确报错。原生新增三项回归覆盖真实 Inter 排版／逐 glyph 像素、合成 lookup 链与畸形表；7 项字体子集检查通过，Noto 仍小于原文件四分之一，幂等检查保留。浏览器另比对九组文本 × 两种字重的完整／初始位图；该组文本不构成所有 OpenType 功能、字体格式或任意输入的全称证明。

## 4. 同轮修复布局根因

自动宽度 flex 容器原先先冻结自然高度，再在最终放置时应用 min/max 和百分比宽度，子行因此换行而父行高度没有重算。旧实现实跑 8 个新增用例有 6 个失败。官网窄屏导航原有的“窗口宽度减 32”绕过现恢复为 `100%`，保留导航独占一行的设计。

**浅层通过的两次候选均被深层探针推翻，不能作为最终修复证据。** 第一版按实际宽度重测高度，8 个新增和 19 个原有用例通过；增加 4／8／12／16 层非 stretch、自动宽度嵌套后，4 个深层用例全部失败，16 层首次布局达 10,053 次、缓存命中 30,309 次，并出现将换行后最长行当作包含宽度而逐层缩窄的问题。第二版将两阶段接入缓存，但 intrinsic 查询未完整传给子树，且无关的父高度占用缓存键：12 层首次布局达 9,569,108 次，16 层触发 30 秒超时。这两个候选已由最终方案替换，没有放宽几何断言或工作量预算来接受它们。

最终方案先求未换行的 max-content 宽度贡献，再按实际可用宽度及原包含块解析自身 min/max，确定 used width，随后求同一包含宽度下的自然高度。两阶段都经过 `Engine::layout` 的尺寸约束与缓存；私有 `intrinsic_width` 模式完整传入 flex／grid／stack 子请求，只取宽度贡献，不把其中的高度当作正常自然高度，也不为该贡献遍历绝对定位子树。公开 `Engine`／`MeasureFn` 接口不变，私有测量缓存仍为 8 槽。

缓存归一化只忽略与**本节点**尺寸无关的父引用：本节点 `width`／`min_width`／`max_width` 全部不是百分比时，缓存键省略 `parent_width`；高度轴同理。只要该轴任一上述尺寸是百分比，就保留相应父引用。实际布局请求及百分比解析仍使用完整包含块，缓存键继续区分节点请求尺寸、available 约束和 intrinsic 模式；后代的百分比以本节点实际 content-box 为基准。

最终 GCC 16、dev、`MCPP_JOBS=1` 实跑 `mcpp test -p openmui.layout --timeout 10`：原有 19 项，加 8 项浅层和 4 项深层回归，共 **31 项通过**；原大树布局 hash `6030294bb8dd27d9` 未改。深层树每层有 padding、footer 和 gap，底部为 `100%` 换行行及三个真实测量叶子，同时检查每层／外层 footer、resize 和内容变化。下表每格依次是 `layouts / measures / cache_hits`：

| 嵌套深度 | 首次布局 | resize | 内容变化 |
| --- | --- | --- | --- |
| 4 | 56 / 15 / 31 | 36 / 3 / 43 | 45 / 9 / 42 |
| 8 | 92 / 15 / 67 | 68 / 3 / 83 | 77 / 9 / 82 |
| 12 | 128 / 15 / 103 | 100 / 3 / 123 | 109 / 9 / 122 |
| 16 | 164 / 15 / 139 | 132 / 3 / 163 | 141 / 9 / 162 |

四个深度的不变帧均为 `0 / 0 / 1`。[回归测试](../../modules/content/layout/tests/percent_wrap_test.cpp)保留原线性次数预算：树节点数 `n = 2 × depth + 6`，前三阶段分别要求 `layouts ≤ 12n + 24`、`measures ≤ 4n`、`cache_hits ≤ 48n`；16 层对应 480／152／1,824，未提高阈值。这证明该组深层树在所测首次布局、resize、内容变化下满足预算，**不构成所有布局全局 O(n) 或零分配承诺**。缓存命中在临时存储创建之前返回；缓存失效的实际 flex pass 仍会分配临时向量，并可能测量子树。其他树形、更多约束组合及最终其他配置／平台验证仍按各自门禁记录。

## 5. 验证与未完成边界

实际浏览器加载阶段审图：[英文桌面](../../site/media/loading-home-en-1280.png)、[减少动态效果的中文手机](../../site/media/loading-home-zh-390.png)。两张是 Chromium 在 wasm 被真实挂起时的截图，与原生确定性媒体及首 CPU 呈现像素比较分别记录；不是预录界面冒充交互。

检查必须覆盖真正 C++ 生成的 HTML，不能只手工提取源码拼 fixture。首次真实执行发现缺失 `</script>` 的生成错误；已修复并补相邻脚本边界断言，原失败证据保留。最终真实生成器的两个 fixture 共 69 项 Node 检查通过，包含原生 fetch／HTTP gzip／ReadableStream／WebAssembly，以及 bootstrap 时序、两向语言切换、失败重试与呈现 hook。新增 13 项覆盖所有语言都使用初始 Inter 子集、失败时保留依赖、显式重试仅初始化一次和首帧后完整字体安装；它们不代替浏览器实际排版与字形核验。

首帧模块已有 7 项原生检查，验证 PNG 与独立生产帧、裁切源像素、精确时间、减少动态效果、真实几何和 IO 失败。官网原生回归在本轮布局修复后通过，已有页面及 59 帧固定值保留。最终 release／sanitizer、真实 Chrome 图片／加载／交接、交付预算和样张结果写入总方案 §15 的对应记录。

**没有因本轮而关闭：** 全站字体按页拆分、完整中文输入字体按编辑入口加载、所有详情的构建期预览、重实验室／影片的独立程序、任意 viewport 的无跳变排版、真实 GPU／移动设备，以及完整工程导出与 R3–R6。英文打开后的完整中文字体仍采用原有延后策略，不把“只请求当前预览图”说成所有资源和 wasm 代码都已按页拆分。首个可读首屏、静态批次字节、程序首帧代理、真实可交互、字体完成须分别测量，不能互相替代。
