# omui.native.fuzzy

Fuzzy matching as a finder does it, for C++ (`omui::fuzzy`, the `:matching` partition) and for scripts: the official native module that every host registers (the player). Its contract, [`native/fuzzy.native.omui.ts`](native/fuzzy.native.omui.ts), is all that is written about the interface. The partition `src/generated/fuzzy_native.cppm` and the stubs in `stubs/` are generated by `omui-gen native`, and tools/gen's test keeps them current.

```ts
import { fuzzy } from "openmui:native/fuzzy";
const best = await fuzzy.rank(query, files, 20);   // Match[]: index, text, score, positions, segments
```

The conformance scenario `spec/conformance/S/finder.scenario.omui.json` calls it from a handler as a person types and from its steps, and requires the trace pinned beside it (M3 acceptance ⑥).

## Matching (C++)

Fuzzy matching as a finder does it, for command palettes, file finders and long lists filtered as a person types. It depends only on the standard library and `mlibs.unicode`. It was the independent package `mlibs.fuzzy`; this package was its one consumer, so it lives here (convergence plan §9.3).

```cpp
import omui.native.fuzzy;

auto best = omui::fuzzy::rank("mcfg", files, 20);  // best first, with the runs to highlight
```

- A query matches when its characters appear in the candidate in order.
- The best alignment is found by dynamic programming, as fzf's is:
  - a match is worth more at the start of a word, a camel hump or a path segment;
  - a run carries the bonus of where it began;
  - gaps cost an affine penalty.
- **Smart case**: a lowercase query matches either case; one with a capital matches exactly. Case folding is Unicode's simple mapping.
- **Words**: words of the query, separated by spaces, must all match, and their scores add.
- **Ranking order**: by score, then the shorter candidate, then the earlier. An empty query keeps the list as it is.
- **What a match gives**: code-point positions and the candidate's runs (`segments`), so a view highlights without counting bytes.
- **Determinism and speed**: everything is integer arithmetic over code points, so the same input ranks the same everywhere. Long lists are scored on several threads with the same answer; the test pins a hash of 20 000 ranked paths.
